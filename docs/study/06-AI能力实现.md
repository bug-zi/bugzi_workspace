# 06 - AI 能力实现

> 目标：理解 LLM 客户端 v2（路由/记账/活动/取消）、MCP 客户端，以及架在它们之上的 30+ 业务流程。读完你应能独立加一个新的 AI 功能。
> （260919 依当前代码更新：四个 AI 流程 → 六大模块域 30+ 流程；咽喉点、jobId、频道会话、画像注入都是新的）

## 1. AI 层的五个文件与依赖方向

```
electron/ai/
├── llm.ts         最底层：OpenAI 兼容客户端 v2（唯一咽喉点 chatCompletion）
├── mcp.ts         最底层：MCP 协议客户端（Streamable HTTP + bearer 鉴权）
├── mcpResearch.ts  AI 辅助 MCP 配置研究（registry API / 厂商文档 / 模型知识）
├── jobs.ts        jobId → AbortController 注册表（取消体系后端，不知道任何业务）
└── services.ts    业务编排层：~60 个导出函数，组合 llm/mcp + db/files
                         ↑
                  ipc.ts 只 import services 层（和 llm 的诊断函数）
```

分层规则：**llm.ts/mcp.ts 不 import 业务**（纯协议客户端可复用），业务编排全在 services.ts。对 settings 的读取（配置获取）是可容忍的 pragmatic 妥协。

## 2. LLM 客户端 v2（llm.ts）—— 一切调用的咽喉点

`chatCompletion(opts)` 是全项目唯一入口（260910 重构），调用方透明获得四件事：

### ① 模型池溢出路由 pickConfigFrom

```
默认配置未满（在途 < maxConcurrent）→ 用默认
否则 → 挑在途最低的可用备选配置
全满 → 仍回默认（不排队，交给 429 重试兜底）
```

每套 LLM 配置可设 `maxConcurrent`（>0 生效，缺省不限）——中转服务账号有并发上限时，多配置池自动分流。纯函数设计（传入 `inflightOf` 回调），便于脚本单测。

### ② 使用记账 recordUsage（静默容错）

每次逻辑调用写一行 `llm_usage`：scene（场景标签）、configName、model、ok、durationMs、prompt/completion tokens。上游没报 usage 时按字符粗估（中文 ~2 字符/token）并打 `tokens_estimated` 标记。记账失败只 console.warn，**绝不影响调用本身**。个人档「LLM 使用统计」按场景聚合展示（`llmUsage:stats/records`）。

### ③ 活动广播 broadcastActivity

调用起止各发一次 `llm:activity`（在途清单：scene/配置名/起始时刻/jobId）——右栏 AI 活动面板据此显示"谁在跑、跑了多久"，**有 jobId 的在途调用可点取消**。

### ④ 429 自动重试

中转账号并发超限属瞬态错误：尊重 `Retry-After` 头，否则指数退避 2s/4s/8s，最多 3 次；一次逻辑调用只记一行（耗时含重试等待）。退避等待与 AbortSignal race——**取消立即中断，不等计时**。

### 其他要点

- **net.fetch 而非 Node 全局 fetch**：undici 有写死的 headersTimeout 300s 且无法调整——非流式 LLM 调用响应头要等整段生成完，慢中转大 prompt 超 5 分钟即 `UND_ERR_HEADERS_TIMEOUT` 被掐（260909 推理角泵排障定位）。Chromium 网络栈无此上限，且天然跟随系统代理。
- **thinking 参数按模型家族映射**：仅 glm 系发 `thinking: {type}`，其他模型不发——防 OpenAI 严格端点对未知参数 400，也防溢出路由把调用甩给非 glm 配置时炸请求。
- **signal 取消**：任何阶段抛「已取消」，渲染层静默处理。
- `normalizeChatUrl` 不变：怎么填都能用（base / 带 /v1 / 完整端点三态归一）。
- **诊断路径不经咽喉点**：`testLlmConnection`（max_tokens:1 探活）和 `listUpstreamModels`（GET /v1/models，个人档拉模型列表）不路由不记账。

## 3. jobs.ts——取消体系的注册表

```ts
beginJob(jobId) → AbortController   // IPC 层进入时登记
cancelJob(jobId) → boolean          // ai:cancel 统一取消；任务不存在返回 false（重复点无害）
runPumpJob(label, fn)               // 泵任务包装：自动登记 jobId（pump-<label>-<seq>），
                                    //   取消语义 = 跳过当前张/批，泵循环继续
ensureNotCancelled(signal)          // 阶段间检查点，已取消即抛「已取消」
```

渲染层约定：每个慢 AI 调用先生成 jobId 传下去；`LlmActivity` 面板从 `llm:activity` 载荷里拿 jobId 发 `ai:cancel`。**取消是全局统一的，不是各模块各写一套**。

## 4. MCP 客户端（mcp.ts）与 AI 辅助配置（mcpResearch.ts）

协议栈不变（Streamable HTTP）：initialize（可能回 SSE，parseSseResponse 兼容双格式）→ initialized 通知 → tools/list → tools/call；`mcp-session-id` 会话头透传；`findSearchTool` 按名启发式 `/search|query|fetch/i`。

新增：**bearer 鉴权**（McpConfig 加 `authType`/`apiKey`，请求带 Authorization 头）；辩真之外，`mcp:research` 让 AI 帮你配 MCP——输入服务商名，AI 查官方 Registry API / 厂商文档 / 自身知识，产出 `McpResearch`（端点模板、所需密钥清单+申请入口、文档链接、来源与说明），用户填 key 后一键存配置。

## 5. 业务流程总览（按模块域）

`services.ts` 约 60 个导出函数，配 `LLM_SCENE_LABELS`（shared/types.ts）看最清楚——每个场景一个标签，统计页与活动面板共用：

| 域 | 流程（scene 标签） |
|---|---|
| 边栏 | `ai:chat`（频道对话）、`ai:compact`（上下文压缩） |
| 格言库 | `motto:generate`（风格仿写 10 条） |
| 万象库 | `wiki:card`（两段式知识卡）、`wiki:suggest`（词条构思）、`wiki:quiz`（测一测出题） |
| 辩真 | `verify:check`（关键词→MCP 检索→综合可信度） |
| 问答 | `qa`（单轮问答存档，安静模式不推频道） |
| 学习库 | `learn:tree`（建树）、`learn:card`（知识卡）、`learn:expand`（主题展开）、`learn:quiz`/`learn:quizGrade`（出卷/批改）、`learn:task`/`learn:taskReview`（实战任务/点评）、深挖（dig） |
| 灵感泉 | `inspiration:diverge`（来5条）、`inspiration:refine`（自评） |
| 文笔坊 | `wenbi:copilot`（起稿/续写/润色/改写建议卡） |
| 致知己 | `zhijiji:v0`（AI 初始化/出题带星/补评） |
| 推理角 | 海龟汤：`soup-compose/review/ask/guess/report/backfill`；思维墙：`wall-compose/review/judge` |
| 预言家 | 分析说明（prophet:analyze） |
| 信息源 | `feed:summary`（按需总结缓存） |
| MCP | `mcp:research` |

三个横切机制先讲清，再看代表流程。

### 横切一：上下文注入 profileDigest

`aiChat` 及多数业务 prompt 注入**我的画像**（profile_facts 表 manual+ai 两源）摘要——"用户是谁"贯穿所有 AI 功能。配套 `lookupProfileFacts(keyword)` 按关键词检索画像条目做精准注入。致知己模块的一切答案沉淀，最终都通过画像反哺其他模块的 AI 上下文。

### 横切二：频道制会话（ai_sessions）

按 `AiChannel`（assistant/motto/wiki/zhijiji/verify/learn/prophet 七频道）分会话，各频道独立激活会话（settings 每频道一个 key）。`aiChat` 流程：

```
appendAiMessage('user', …)                    ← 先落库留痕
history = 激活会话最近 N 条（排除 system）
system = 模块感知 + 画像摘要（debugzi 人设）
chatCompletion(…, signal, scene='ai:chat')
appendAiMessage('assistant', …)
```

配套：`aiSession:compact`（长会话压缩成摘要替换旧消息，`ai:compact` 场景）、`aiSession:archive`（软删 + 写 recycle_bin 'ai_session'，可恢复/彻底删连消息）。

### 横切三：预生成泵（与 services.ts 协作）

`reasoningStock` / `wikiStock` / `learnStock` / `wikiQuizStock` 四个泵在后台调 services 的生成函数补池，经 `runPumpJob` 包装可取消、随 `llm:activity` 可见。**泵的存在让"AI 生成很慢"对用户不可见**：打开每日一题/待学习区时，题/卡已在池里。

## 6. 代表流程精读

### generateMottos（结构化输出处理的最佳样本，升级版）

```
① 取风格样本：正式区最新 50 条
② prompt：参考风格生成 10 条，JSON 数组，编撰/摘录二态（gen_kind）
③ chatCompletion(temperature=0.9, jsonMode=true, thinking:'disabled' 提速, signal, scene)
④ parseJsonArray：剥 ```json 围栏 → JSON.parse → 逐项校验字段
⑤ 失败重试一次（旧机制保留）
⑥ 查重入库：normalizeText 集合（含 mottos_tombstones 墓碑——已删除的格言不再复现）
⑦ 返回 { generated, inserted }
```

**normalizeText（db.ts）仍是查重的灵魂**：去空白 + 剥中英标点 + 转小写。墓碑表（v16）的加入解决了"删掉的格言 AI 又生成一遍"的循环。

### runVerification（辩真三段式，全项目最复杂单流程）

```
findSearchTool → 无工具 throw 'MCP_NOT_ENABLED'
LLM① 3 组中英检索词（temperature=0.5）
逐组 mcp.callTool（单组失败告知但继续，全失败才 throw）
LLM② 综合分析（temperature=0.3），末行「可信度：N%」
正则抽数值 clamp 0-100（抽不到默认 50），正文剥掉可信度行
INSERT verify_records（PENDING→回填）→ mdWrite 模板文档
onProgress 每步 → pushAiSystemMessage(…, channel='verify')  ← 直播到核查频道
return { recordId, credibility }
```

**temperature 阶梯**哲学不变：关键词 0.5、分析 0.3；格言 0.9、词条名 1.0——按任务性质逐处调，不设全局值。

### 文笔坊 copilotWriting（建议卡模式）

起稿/续写/润色/改写四种动作产出的不是"直接覆盖正文"，而是**建议卡**：渲染层逐段展示 diff 建议，用户逐条采纳后落回文章 md。AI 是协笔者不是代笔者——与致知己"AI 只追问不代笔"同一产品哲学的写作版。

## 7. 「未配置」体验的全链路（规则 7 的实现）

```
点「来10条格言」（按钮永不 disabled）
  → invoke mottos:generate
  → getDefaultLlm() throw LlmNotConfiguredError('LLM_NOT_CONFIGURED')
  → 渲染层 catch，includes 判断 → GoConfigDialog →「去配置」直达个人档
```

`LlmNotConfiguredError` 哨兵一路穿透不 catch——"未配置"是全局统一语义。MCP 版同理（`MCP_NOT_ENABLED`）。**配置检测发生在尝试时而非界面上**。

## 8. 如何新增一个 AI 功能（方法论总结）

以"给记账本加 AI 分类建议"为例，六步：

1. `services.ts` 写业务函数：构造 prompt → `chatCompletion({ scene: 'ledger:suggest', signal })` → 处理输出 → 落库。
2. `LLM_SCENE_LABELS` 加场景标签（统计页/活动面板显示中文名）。
3. `ipc.ts` 注册 `ipcMain.handle('ledger:aiSuggest', (_e, jobId, …) => beginJob/endJob 包裹)`——慢流程首参 jobId。
4. `preload.ts` 对应命名空间加方法；**同步** `api.d.ts`。
5. 模块组件：`try { … } catch (e) { 已取消→静默；LLM_NOT_CONFIGURED→setGoConfig；其余→setFailMsg }`。
6. 长流程加 `onProgress`，内部 `pushAiSystemMessage` 推频道；后台化则考虑纳入某个泵。
