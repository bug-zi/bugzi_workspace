# 05 - 数据存储设计

> 目标：掌握双存储模型、46 版迁移史、回收站 19 来源机制、数据目录切换。读完你应能回答"任何一条数据住在哪、活多久、怎么没的"。
> （260919 依当前代码更新：9 张表 → ~45 张表；新增数据目录迁移与部分事务）

## 1. 双存储模型：什么进 DB，什么进文件

总原则：**结构化数据存 SQLite，文档性内容存真实文件**。判断标准是"你要不要对它做查询/过滤/排序"：

| 数据 | 存储 | 理由 |
|---|---|---|
| 各模块列表行（格言/词条/灵感/流水/书籍/订阅…） | SQLite 各表 | 要过滤、查重、排序 |
| 长文内容（格言笔记/知识卡/答案版本/对局记录/文章…） | `md/<域>/<id>.md` | 自由编辑、可用任何编辑器打开 |
| 学习库知识卡 | `md/learn/<id>.md`（扁平） | 同 wiki 惯例 |
| 思维墙每日记录 | `md/wall/<日期>.md`（按天命名） | 一天一份 |
| 画布 | `canvas/<id>.excalidraw` | **标准 Excalidraw JSON**，官方工具可互导 |
| 电子书 / 封面 / 音乐 | `books/` `covers/` `music/` | 原文件复制入库，DB 存相对路径 |
| 导入字体 | `fonts/`（文件系统为真相源） | DB 无表，`font:list` 扫目录 |
| 背景图 / 头像 | `bg/` / 根目录 | settings 记文件名 |
| AI 会话消息 | SQLite `ai_messages` | 按会话按序读 |
| 设置（LLM/MCP/终端/音源状态…JSON） | SQLite `settings` | 键值字符串 |

**文件名 = DB 行 id**（`3.md` 对应 id=3），例外：思维墙按日期、致知己 `{qid}-v{seq}.md`（版本序号稳定不重命名）、学习库树文档 `tree-<domainId>.md`。

一个微妙点保留至今：**md_path 字段先插 PENDING 再 UPDATE**——id 自增，插入前不知道，只能先插拿到 id 再回填。看到 md_path 为 `'PENDING'` 的行，说明创建流程中断过（半成品态）。

## 2. 数据目录布局

`initDb()`（db.ts）启动建目录：

```
<数据目录>/                     ← 默认 D:\Paper\app_output\bugzi_workspace（可迁移）
├── bugzi.db                   ← SQLite（WAL + foreign_keys ON）
├── avatar.png                 ← 头像
├── md/
│   ├── mottos/ wiki/ inspirations/ verify/ qa/ prophet/
│   ├── zhijiji/（<qid>-v<seq>.md） turtle/（对局记录） wall/（每日） wall/bank/（题解析）
│   ├── drafts/ learn/（+ task/） wenbi/journal/ wenbi/article/
├── canvas/                    ← *.excalidraw
├── books/  covers/  music/    ← 电子书 / 封面 / 曲目（复制入库）
├── fonts/                     ← 导入字体（font:import 时建）
└── bg/                        ← 背景图
```

两条 PRAGMA 不变：`journal_mode = WAL`（写不阻塞读）；`foreign_keys = ON`（SQLite 默认**关**外键，必须显式开）。注意全库惯例是**多数表不建 FK 约束**（级联删除由服务层显式负责，见 §6）。

### 数据目录可迁移（storage.ts）

- 默认目录 = 内置 D 盘路径；个人档「存储位置」可 `storage:pickDir` 选新目录 → `storage:migrate` 整目录拷贝（先 `closeDb()` 做 WAL checkpoint 落盘）→ 写 `data_home.json` 指针到系统默认 userData → `storage:relaunch` 重启生效。
- 启动时 `applyDataDirAtStartup()` 读指针定位；指针损坏/目标不存在回退系统默认，**保证永远能启动**。
- 深意：所有相对路径（DB 里的 md_path、file_path）都因此**可整体搬家**——"路径一律相对 userData"是库可迁移的前提。

## 3. 版本化迁移（46 版）

没有 migration 库，手写最小方案（db.ts 的 `migrate()`）：

```ts
const version = Number((d.prepare('PRAGMA user_version').get() as any).user_version ?? 0)
if (version < 1) { /* 全部 v1 表 + 种子 */ d.exec('PRAGMA user_version = 1') }
if (version < 2) { /* … */ }
// …直到
if (version < 46) { /* 经验书分类夹 */ d.exec('PRAGMA user_version = 46') }
```

- `user_version` PRAGMA 当版本号；加表/加列就追加 `if (version < N+1)`，老库自动升级；`CREATE TABLE IF NOT EXISTS` 幂等兜底。
- **版本号会被并行功能撞车顺延**——注释里多次出现"设计原写 v31，撞车顺延为 v32/v34→v35/v44→v45"。这是单开发者 + 多会话并行的真实痕迹。
- 迁移里既有加列（ALTER TABLE ADD COLUMN），也有**数据修正型迁移**（v2 修背景图扩展名 bug、v8/v11 剥旧模板头、v10 批量改名「AI 编撰」→「debugzi」、v23 删旧种子题）——**schema 迁移和数据迁移共用同一机制**，靠注释讲清为什么。

**种子数据**：v1 五个初始板块 + theme/schedule 两默认设置；后续版本各有种子（v13/v22 题库题、v46 预置分类夹）。种子只在对应版本分支跑——已有库不会重复插入。

## 5. settings 表的"万物皆字符串"设计

`electron/db/settings.ts` 极小：`getSetting` / `setSetting`（UPSERT）/ `getJsonSetting<T>`（解析失败回退默认值）。

- 值一律 TEXT：数字/布尔/复杂结构全序列化字符串，读取端转型。
- key 常量集中在 `shared/types.ts` 的 `SettingsKeys`（现在 40+ 个键，每个键注释里都有立项来源）。
- `getJsonSetting` 的**解析失败回退**很重要：配置 JSON 被改坏 App 不崩，表现为"未配置/默认态"，用户能进个人档修。
- 值得认识的几族 key：AI 会话激活态（`ai_active_session_*` 每频道一个）、面板布局（`right_panel_expanded`/`*_width`）、幂等标记（`last_motto_run`/`wiki_daily_learn_date`）、音源状态（`noise_state`/`music_state`/`noise_play_queue`——重启记参数默认暂停）。

## 6. 回收站机制（19 来源）

`electron/services/recycle.ts` 撑起全部语义：

### 入站 discardToRecycle

```sql
UPDATE <业务表> SET deleted_at = ? WHERE id = ?          -- ① 软删
INSERT INTO recycle_bin (source, item_id, payload, …)   -- ② 快照
```

**双写**不变：软删保恢复零丢失，快照保回收站自治（显示/清理不反查业务表）。`summaryOf` 直接 JSON.parse payload 取 content/term/title/claim。

### 恢复 restoreFromRecycle

19 来源 switch 分派，各自规则不同（回最初级区/原位置）：格言→草稿区、灵感→草稿区、学习节点→todo 态、文章→写作台构思区等。**特殊联动**：格言恢复会写墓碑表反向删除（防恢复后查重复现错乱）。细节以 `restoreFromRecycle` 函数体为准——每来源一小段，是理解"各模块最初级区"的最佳索引。

### 彻底删除 hardDelete

先按 `MD_COLUMN` 映射找附属文件列（多数是 `md_path`；`canvases` 是 `path`；**无文件来源显式标 null**：zhijiji 版本连删、ai_session 连删全部消息、learn 卡片 md 无表列派生清理、twelve 连删想法碎片…），再跑来源特判级联（wiki 连高光、ledger_account 查余额、mottos 连笔记与墓碑），最后删业务行 + recycle_bin 行 + unlink 附属文件。**新模块接入回收站 = 在 RECYCLE_MAP / MD_COLUMN 各加一行 + 补特判**，通用链路零改动。

### 超期清理 cleanupExpired

`created_at <= (now - 3天)` 逐条 hardDelete。ISO 字符串字典序 = 时间序，TEXT 比较天然正确。触发：App 启动 + 每日零点（scheduler）。信息源另有独立 30 天已读清理（`cleanupOldArticles`，收藏的永不清）。

### 软删粒度原则

**子资源不做独立软删**：wiki_highlights、zhijiji_versions、turtle_messages、twelve_thoughts、book_notes 都没有 deleted_at——生命周期完全由父资源决定，父级彻底删时级联 DELETE。回收站粒度选在"用户感知的单位"上。

## 7. md 文件服务与路径安全

`electron/services/files.ts` 是 md 操作唯一出口：`mdRead/mdWrite/mdDelete/mdCreate/pruneEmptyDir`，每个操作必经 `resolveUnderUserData(relPath)`——绝对路径必须等于 root 或以 root\、root/ 开头，否则 throw `PATH_OUT_OF_USERDATA`。md 路径来自渲染层（IPC 参数），路径校验把"任意文件读写"降级为"数据目录内读写"。细节：`mdCreate` 存在不覆盖；`mdDelete` ENOENT 静默幂等；Windows 感知两种分隔符。

同类防线在 `explorer.ts`（资源管理器）也有：所有 `explorer:read*` 通道对 root 做同样的限定检查——**渲染层可浏览的是用户自己选定的根，不是整个磁盘**。
