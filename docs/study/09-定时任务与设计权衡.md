# 09 - 定时任务与设计权衡

> 目标：理解 scheduler 与四个预生成泵的机制、"错过即跳过"的产品哲学；盘点全项目的设计决策、技术债现状。这是收官篇，也是"如果你要接手开发"的交接篇。
> （260919 依当前代码更新：两个定时器 → 两定时器 + 四泵 + 启动错峰队列；技术债部分偿还）

## 1. 定时任务（electron/services/scheduler.ts）

### 两个定时器（机制不变）

| 任务 | 触发 | 动作 |
|---|---|---|
| 格言定时生成 | 每天用户设定时刻（默认 22:00，settings.motto_schedule） | generateMottos() + 记 last_motto_run |
| 零点清理 | 每天 00:00:05 + App 启动时 | cleanupExpired()（回收站 3 天超期）+ cleanupOldArticles()（信息源 30 天已读） |

实现仍是 setTimeout 链三件套：`msUntilNext`（目标时刻已过自动 +1 天）、执行后自重排（不用 setInterval）、`unref()`（不阻止进程退出）。**改设置即重排**：`settings:set` 处理器里发现 key 是 motto_schedule 就调 `scheduleMottoTask()`（ipc.ts，注释「定时设置变更 → 重排格言任务」）。

「错过即跳过」幂等（`alreadyRanToday` 按本地日期查 last_motto_run）与静默失败哲学（定时任务不弹窗，只 `console.warn`）都未变——后台任务的错误不打扰用户，代价是失败无人知晓除非看日志。零点 5 秒偏移也还在（避开整点任务高峰）。

**零点清理的新增负载**：跨天常驻时零点顺带 `ensureDailyLearn()`（万象库每日批次）与 `ensureLearnStock()`（学习库队列定档）——两者内部幂等 + 静默失败，属于"日期翻转类"任务的天然钩子。

### 四个预生成泵（不在 scheduler 里，在 main.ts）

| 泵 | 维护什么 | 触发时机 |
|---|---|---|
| `reasoningStock` | 海龟汤 fresh 池 + 思维墙题池（低于 5 补到 10） | 启动 +10s / 消耗后 / 进模块 |
| `wikiStock` | 万象库每日批次（5-10 张板块均摊，settings 幂等）+ 每板块 3 张后库 | 启动 +10s / 零点 / 进模块 |
| `learnStock` | 学习库每日队列定档（纯 SQL）+ 今日新卡 | 启动 +10s / 零点 / 进模块 |
| `wikiQuizStock` | 万象库测一测题库 | 启动 +10s / 消耗后 |

**为什么泵不在 scheduler**：泵不是"到点做什么"而是"库存低于水位就补"——触发源是事件（启动/消耗/进模块）而非时刻。唯一与时刻有关的是"每日批次"幂等标记（本地日期比对），也用不上排程。五个 `setTimeout(…, 10_000)` 错峰是启动序列的一部分（03 篇 §4），全部 unref + 内部自 catch 永不抛错，LLM 未配置静默跳过（队列照常定档，配置后下次触发补齐）。

泵与 jobId 体系的接口：经 `runPumpJob(label, fn)` 包装——泵任务有 jobId、出现在 AI 活动面板、可被用户取消（取消 = 跳过当前张/批，循环继续）。

## 2. 设计权衡盘点（为什么它是这个样子）

| 决策 | 备选方案 | 为什么选现在这个 |
|---|---|---|
| node:sqlite 而非 better-sqlite3 | 引第三方（原生编译） | Node 内置零依赖，Windows 免编译坑；代价是 API 较新 |
| 全量拉取+setState | React Query/虚拟化 | 个人数据量级下全量是正确复杂度；广播 + 重拉保"DB 为准" |
| 回收站软删+快照双写 | 仅软删/仅快照 | 软删保恢复零成本，快照保回收站自治 |
| md 存真实文件而非 BLOB | 全 DB | 用户可用任何编辑器打开自己的笔记；库可整体迁移 |
| LLM JSON 用 prompt 约定+剥围栏 | jsonMode 一把梭 | jsonMode 非所有兼容端支持，剥围栏兼容面最大 |
| 无状态库 | Redux/Zustand | 跨模块协调靠 Shell props + 事件；音频引擎用 useSyncExternalStore 外部 store |
| IPC 手工镜像类型 | 自动推导 | tsconfig 进程边界下自动推导要引 electron 类型进渲染层（技术债 #1 仍在） |
| keep-alive 常驻挂载 | 条件渲染卸载 | AI 生成不因切页中断；刷新改由激活事件驱动（07 篇 §1） |
| 模块间深链用 window 事件 | 全局路由/总线库 | 三个 CustomEvent 常量解决，零抽象 |
| 泵预生成（空间换时间） | 现场生成+骨架屏 | "AI 慢"与"秒开"的矛盾；池空兜底现场生成保永可用 |
| net.fetch 替代 Node fetch | undici | undici headersTimeout 300s 写死掐长调用；Chromium 栈跟随系统代理 |
| node-pty + xterm | child_process 伪终端 | 真实 shell 体验；代价是唯一原生模块（asarUnpack + npmRebuild:false 伺候） |
| electron-updater + GitHub Releases | 自建更新服务 | 个人项目零运维；latest.yml 即协议 |
| 数据目录 D 盘默认 + 指针迁移 | 系统默认 userData | 开发者要求 + 大数据量（书/音乐）不挤 C 盘；指针文件保可发现 |

## 3. 技术债与已知问题（接手先读，260919 现状）

原清单四笔债，两笔部分偿还，两笔仍在，新增一笔：

1. **preload/api.d.ts 双份类型手工同步**（仍在，头号债）。活证据：api.d.ts 的 `ModuleId` 至今残留已删除的 `'verify'`。每加通道要改两处，漏了就是运行时才炸的漂移。修法：渲染层 `import type { Api } from '../../electron/preload'` 或生成脚本。**改动小收益大，首选还的债**。
2. **回收站链路无事务**（部分偿还）。discard 的软删+快照、恢复链路仍未包 BEGIN/COMMIT，断电留幽灵数据；但 books/favorites/challenge/learn 领域删除/建树/池转正等关键多步写已包。修法：recycle.ts 同款包一层。
3. **shared/types.ts 与 api.d.ts 行类型重复**（仍在）——同源不同步风险，与债 1 一起还。
4. **ai_messages 无限增长**——已缓解：会话制 + compact 压缩 + 归档/彻底删 + 消息级删除。表仍会涨，但用户有了治理工具（产品上有意持久保存）。
5. ~~主进程无重入防护~~ **已被 jobId 体系部分覆盖**：每次调用有身份、可观测可取消；语义级防重（同一动作连点）仍靠渲染层 generating 态。
6. **keep-alive 带来的新纪律**：模块 effect 只跑一次、事件监听必须清理、重活推迟到激活回调——违反即内存/行为泄漏，且不再有"卸载重置"兜底。写新模块时对照 07 篇 §8 三条。
7. **LLM 无流式输出**——仍是体验提升最明显的单项；chatCompletion 加 stream:true + SSE 解析（mcp.ts 的 parseSseResponse 可复用思路），但会牵动活动面板时长口径与记账粒度，动之前想清楚。

低危毛边存量（重构时顺手修）：万象高光 `md.replace` 首处匹配、灵感拖拽 normalizeSort 时序依赖。

## 5. 给接手者的最后三句话

1. **先读 specs 与优化建议区再改代码**：代码里 `specs §x.y`、`优化建议区第 N 轮`、`DB vN`、`问题疑惑区 xxx#A` 注释都是需求回溯锚点——先判断"实现偏差"还是"需求就该这样"。
2. **改主进程记得 typecheck 两遍都能过**：`npm run typecheck` 是唯一自动闸门，别绕过。
3. **所有新交互先过"宪法"**：删除有确认吗？图标是 Material Symbols 吗？颜色走变量吗？未配置弹引导不置灰吗？长任务有 jobId 吗？新模块接回收站了吗（RECYCLE_MAP + MD_COLUMN）？——这几问答不上来就别提改动。

## 6. 结业练习（综合）

实现一个小需求走完全链路：**给总导览热力图加"点击某天看当日三源明细"浮层**。

提示路线：
- 数据已在手（`overview:heatmap` 返回 learn/wall/challenge 三布尔 + level），先判断要不要加 IPC——大概率不用，浮层需要明细则考虑 `challenge:daily`/`learn:daily` 是否够用，不够再议新通道（参数：日期字符串）。
- UI 按宪法来：浮层用 `.dialog-overlay` 同款样式类、颜色走变量、无 emoji 图标。
- 思考 keep-alive 纪律：总导览常驻挂载，热力图数据何时刷新？（激活回调 + 挑战打卡后的本地联动。）
- 做完后自查：需要二次确认吗（否——非破坏性）、需要去配置引导吗（否——不碰 LLM）、需要 jobId 吗（否——纯读）。

如果你能独立完成并答对三个"否"，这套笔记的使命就完成了。
