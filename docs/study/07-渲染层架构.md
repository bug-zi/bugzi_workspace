# 07 - 渲染层架构

> 目标：掌握 React 代码的组织方式、keep-alive 模块路由、右缘四面板、双主题系统、全局组件与音频引擎。读完你应能新增一个页面级交互而不错位。
> （260919 依当前代码更新：条件渲染卸载 → keep-alive；单 AI 边栏 → 四面板互斥；新增音频引擎与生成队列）

## 1. 组件树全景

```
renderer.tsx
└─ <App>                                    src/App.tsx
   ├─ <ThemeProvider>                       主题/设置/背景 Context（最外层）
   │  └─ <ToastProvider>                    toast Context
   │     └─ <Shell>                         ★ 布局 + 模块路由 + 面板状态 + 快捷键
   │        ├─ .app-bg                      全窗背景图层
   │        ├─ <nav .sidebar>               12 模块按钮 + 音乐吧控件（记账本/回收站之间）
   │        ├─ .app-body
   │        │  ├─ .app-body-row
   │        │  │  ├─ <main .main-area>      ★ keep-alive：12 模块常驻，.module-hidden 隐藏
   │        │  │  │    + {module==='noise' && <NoisePage/>}   ← 唯一不 keep-alive 的页
   │        │  │  └─ .right-col             右缘四面板互斥（见 §3）
   │        │  └─ <TerminalPanel/>          底部终端（常驻挂载，open=false 仅 display:none）
   │        └─ 快捷按钮组                    四面板全收起时：主题/终端/音源播放/AI 活动
   └─ <WelcomeGuide>                        首启引导（firstLaunch 时）
```

**模块路由 = 一个 useState**（`App.tsx` 的 `MainView` = `ModuleId | 'noise'`，默认 `'zonglan'`）。没有 URL、没有 history——桌面 App 无路由需求。但与旧版的本质区别是 **keep-alive**：

```
{MODULES.map(m => (
  <div className={m.id === module ? 'module-live' : 'module-live module-hidden'}
       aria-hidden={m.id !== module}>
    {…模块组件…}
  </div>
))}
```

切模块只加 `module-hidden`（display:none）不卸载。**为什么改**：AI 生成任务（学习库建树、海龟汤对局、写作台协笔）不再因切页中断（问题疑惑区万象库#A）。代价与配套：

- 模块**挂载只发生一次**，"挂载时 load"不再等于"每次进模块刷新"→ 新 hook `useModuleActivated(模块id, 回调)` 监听 `MODULE_ACTIVATED_EVENT` 自行刷新。
- 切走时可能要暂停（海龟汤净用时计时）→ `MODULE_DEACTIVATED_EVENT`（detail=旧模块 id）。
- 深链导航（总导览跳转）→ `MODULE_NAVIGATE_EVENT`（detail：module/target/payload），目标模块经 `useModuleNavigate` 切内部视图。三个事件都定义在 `App.tsx` 顶部导出。

**NoisePage 是唯一例外**：白噪音引擎在组件外（`src/services/`），页面卸载播放不断，故无需 keep-alive。

## 2. Shell 层的跨模块协调（App.tsx 的核心价值）

Shell 是**唯一**能协调"模块 ↔ 面板 ↔ 终端"的层：

### ① openAiWith(prefill?, { auto?, channel? }) —— 模块请求打开 AI 面板

```ts
switchRightPanel('ai')                    // 右缘切到 AI 面板
setAiForceOpen(v => !v)                   // 强制展开信号
setAiPending({ text, channel, auto })     // 预填 + 频道 + 是否自动发送
```

频道解析：显式 `opts.channel` 优先（辩真板块直连核查频道）→ `CHANNEL_BY_MODULE` 映射（wiki→wiki、zhijiji→zhijiji）→ 默认 assistant。**数据自下而上（props 回调），状态归面板所有**。

### ② bumpAi / aiVersion —— 通知边栏"消息有更新"

模块收到 `ai:message` 推送 → `bumpAi()` → Shell 的 `aiVersion+1` → AiSidebar 的 `messagesVersion` prop → 边栏重载。模块和边栏互不持有引用，全靠 Shell 中转。

### ③ turtleGame —— 海龟汤对局上下文

TurtlePanel 进出对局派发 `TURTLE_GAME_EVENT`，Shell 持有 `turtleGame` state 传给 DraftSidebar——草稿本切海龟汤频道、新建以汤名命名的草稿。**App 持有保证面板收起时不丢上下文**。

### ④ activateModule / switchRightPanel

模块切换统一走 `activateModule`（发激活/失活事件）；右缘面板互斥切换统一走 `switchRightPanel`（写 settings 持久化）。所有跨域动作收口在这两个函数。

这套"回调上浮 + 状态集中 Shell"仍是没状态库时的标准解法。App.tsx props 密集但数据流向一目了然。

## 3. 右缘四面板互斥（260916 定型的布局）

```ts
const [rightPanel, setRightPanel] = useState<'ai' | 'draft' | 'files' | 'canvas' | null>('ai')
```

- `ai` = debugzi 边栏（**常驻挂载**保持生成态，仅 CSS 收起）；`draft`/`files`/`canvas` 按需挂载。
- 展开态持久化到 settings `right_panel_expanded`，重启恢复。
- 右缘细条四个图标入口；四面板全收起（null）时右下角才显示：主题切换、终端呼出（Ctrl+J）、音源快捷播放/暂停、`LlmActivity` AI 活动指示——**"展开即隐藏"治展开态右侧通条不美观**（优化建议区第 29 轮）。

`AiSidebar` 内部：频道 tab、会话列表（重命名/删除/归档/清空/压缩）、`ChannelChatPanel` 对话体、消息级编辑删除、**三选处置条**（`ChatDisposition`：继续对话/保存对话→封装 md 卡落模块原生载体/归档对话→回收站）——260917 的"终结式保存/归档后自动切新会话"在这里收口。

## 4. 双主题系统（规则 2 的实现，未变的部分简述）

CSS 变量 + `data-theme` 属性：切主题 = 改 `<html>` 一个属性，全部颜色瞬时联动；组件只引用 `--color-*` 变量，没有任何组件写死颜色（规则 4 的落法）。字体三件套 `--font-size/--font-family/--font-weight` 由 `ThemeProvider.applyFontVars` 写内联变量——改设置不需要重渲染 React 树。

新增一块：**导入字体**（`theme/customFonts.ts` + `fonts.ts`）。个人档导入 ttf/otf/woff/woff2 → 主进程存 `fonts/` → 渲染层 `registerCustomFontFaces()` 启动时经 `bzres://fonts/` 加载并 `new FontFace(...).add(document.fonts)` 注册 → 全局字体与 epub 阅读器浮层即可选用。**字体是运行时注册的，不是 CSS @font-face 静态声明**——因为字体列表是用户数据不是构建产物。

ThemeProvider 的背景探测回退不变：`fetch(bzres://bg/…)` 探 404 回退纯色（bzres 的 `corsEnabled: true` 就是为这个 fetch）。`firstLaunch` 判定依旧朴素：`!user_name`——**用业务数据当状态位，不另设 flag**。

## 6. 渲染层引擎（src/services/，纯浏览器能力）

**这是渲染层代码里最"非 CRUD"的一块**，四个成员：

- `noiseEngine`：Web Audio 纯合成白噪音。多场景（场景注册表 `noiseScenes.ts`）× 多层声源（噪声源/滤波/LFO 调制），混音参数即 state；`subscribe/getSnapshot` 实现 store 协议供 `useSyncExternalStore` 消费——**不用 React state 管音频**，因为播放态变化频率高且与渲染无关。
- `musicEngine`：轻音乐播放（audio 元素 + 歌单循环模式）；同样暴露 subscribe 协议。
- `audioExclusive`：双音源互斥——谁在播控谁，都停着控上次音源。左栏控件文案、右栏快捷按钮、页面播放钮三处 UI 全靠这层口径对齐。
- `learnGenQueue`：学习库生成任务队列（**3 并行线**），可视化排队/逐项取消——它是"AI 调用调度器"的渲染层实现，与主进程 jobId 体系配合。

App.tsx 用 `useSyncExternalStore(noiseEngine.subscribe, noiseEngine.getSnapshot)` 订阅播放态——React 18+ 的外部 store 惯用法，值得抄。

## 7. 三栏布局 CSS 要点（不变 + 一处新增）

```
.app-shell { display:flex }
  .sidebar    { 固定窄条 }
  .app-body   { flex:1 纵向容器：app-body-row（中栏+右栏）+ TerminalPanel }
    .main-area  { flex:1; min-width:0 }    ← min-width:0 仍是 flex 溢出救星
    .right-col  { 四面板互斥容器 }
```

新增认知：`.module-hidden { display:none }` 的 keep-alive 容器意味着**所有模块的 effect 在启动时就全部跑一遍**（12 个模块同时挂载）——这就是为什么加载函数必须便宜（一次 list 查询），也是 `useModuleActivated` 存在的理由（重活推迟到激活时）。

## 8. 读代码时的三个易错点

1. **keep-alive 下的 effect**：模块 effect 只跑一次，别在 effect 里读"当前激活"假设；需要刷新就挂 `useModuleActivated`。
2. **useCallback 依赖**：`load` 空依赖保证引用稳定；若 load 读了 state 会链式循环刷新。keep-alive 放大了这个错误的伤害（原来切页卸载还能"重置"，现在一直活着）。
3. **事件订阅必须清理**：`window.addEventListener`（三个模块事件/TURTLE_GAME_EVENT）与 `api.onXxx` 一样，useEffect 返回 cleanup；常驻挂载下泄漏不再被卸载兜底。
