### 260902｜node_modules 是干什么的

**问**：D:\Code\myapp\bugzi_workspace\node_modules 这个文件夹是干什么的？

**答**：npm 存放第三方依赖包的目录。`package.json` 声明项目要用哪些包（react、electron、vite 等 13 个），`npm install` 时 npm 把这些包及其层层嵌套的依赖从 registry 下载到这里（本项目实测约 500MB，大头是 Electron 的浏览器内核）。关键认知：

- **可删可重建**：删掉整个目录没关系，`npm install` 会按 package.json + `.npmrc`（已配国内镜像 + legacy-peer-deps）重新生成。因此它被写进 `.gitignore` 不进 git，克隆者拿到干净代码后自行安装。
- **只在开发/构建时用**：`npm run dev` / `build` / `typecheck` 从这里加载工具；构建产物在 `out/`（同样 gitignore）。
- package.json 声明 13 个包、node_modules 里却有几百个文件夹，是「包又依赖别的包」的依赖树展开。

### 260902｜根目录裸露的配置文件是什么、为什么放根目录

**问**：electron.vite.config.ts、tsconfig.json 等这些直接裸露在根目录下的文件是什么？为什么没有被收拢到子文件夹中而是直接放在根目录下？

**答**：逐个认人（结合本项目实际内容）：


| 文件                      | 性质         | 作用                                                                                                                                                                          |
| --------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json`            | 手写         | 项目「身份证」：名字、版本、`scripts` 命令、依赖清单，npm 一切操作的入口                                                                                                      |
| `package-lock.json`       | npm 自动生成 | 锁定每个包的精确版本，保证换电脑重装出的依赖和现在一模一样                                                                                                                    |
| `electron.vite.config.ts` | 手写         | electron-vite 构建配置：怎么打包主进程（electron/）、preload、渲染层（src/）                                                                                                  |
| `tsconfig.json`           | 手写         | TypeScript 配置。本项目是空壳（`"files": []`），用「项目引用」拆成 `tsconfig.node.json`（管 electron/）+ `tsconfig.web.json`（管 src/），`npm run typecheck` 就是分别跑这两个 |
| `tsconfig.*.tsbuildinfo`  | tsc 自动生成 | 增量编译缓存（记住上次检查到哪，只查改过的文件），已 gitignore                                                                                                                |

放根目录是 Node.js 生态的**硬约定**：npm、tsc、vite 等工具启动时都从当前目录向上查找自己的配置文件，而「项目根」就是 package.json 所在那层。地位等同 Rust 的 `Cargo.toml`、Go 的 `go.mod`、Java 的 `pom.xml`。理论上可用参数指定别的路径，但会跟工具链、IDE、CI 对着干，没有收益。换个角度：`src/`、`electron/`、`docs/` 是**写的内容**，根目录散落的是**项目级配置与元数据**——配置固定待在根上，代码目录保持干净。

### 260902｜格言笔记 md 文档存储在哪个目录

**问**：项目计划中说给格言库-正式区的每句格言配置了一个 md 文档，我想知道文档存储在项目的哪个目录下？

**答**：md 文档**不存在项目目录下**，而是存在操作系统的「用户数据目录」（userData）里，和 SQLite 数据库（bugzi.db）、头像、背景图放在一起。这是桌面应用的标准做法——数据与代码分离，重装/更新应用不会丢数据。

- `electron/db/db.ts:21-23`——首次启动时在 userData 下创建 5 个子目录：`md/mottos`（格言笔记）、`md/inspirations`（灵感文档）、`md/wiki`（万象卡片）、`md/verify`（辩真记录）、`bg`（背景图）
- `electron/db/db.ts:46`——mottos 表有 `note_path` 字段，存的是**相对 userData 的路径**，如 `md/mottos/3.md`

本机（Windows，应用名 `bugzi_workspace`）实际路径：

```
C:\Users\Administrator\AppData\Roaming\bugzi_workspace\md\mottos\3.md
```

开发模式 `npm run dev` 和打包后的应用共用这个目录。想直接看文件可在 PowerShell 跑：`explorer "$env:APPDATA\bugzi_workspace\md\mottos"`。

为什么不放项目目录里：① 项目目录开发中经常被清理重建，放 userData 数据不丢；② Electron 打包后项目目录是只读 asar 包，md 需要「实时编辑实时渲染」必须写在可写位置；③ 与 bugzi.db、头像、背景图同根，备份迁移只需拷一个目录。
