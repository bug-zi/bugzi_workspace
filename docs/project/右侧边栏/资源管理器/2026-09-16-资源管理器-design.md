# 资源管理器侧边栏设计（新功能开发区待完成 → 待实施）

- **状态**：设计定稿（brainstorming 五项澄清完毕，待写实施计划）
- **来源**：新功能开发区待完成条目「右侧接入一个可以打开文件夹，查看文件夹下文件和代码的资源管理器.（放在debugzi下面和草稿本上面之间的位置）」

## 需求

右栏第四面板「资源管理器」：打开本机任意文件夹，浏览其文件树，查看文件内容与代码。纯只读、纯本地、零 AI、零联动。

## 商讨定稿的五项关键决策

1. **文件夹来源：单个文件夹**——系统目录选择弹窗选取，记住上次打开的目录，重启直接回到上次位置。否决多文件夹收藏（要书签管理位，超出「随开随看」定位）与固定盘符浏览（层级深翻起来累）。
2. **纯只读**——只能查看不能编辑。否决可查看可编辑（要做行号/保存/脏标记，工作量明显变大，且当前诉求是「查看」）。
3. **代码展示：语法高亮**——引入轻量 `highlight.js`，只在代码查看区按语言着色；`.md` 文件走全局 MdView 渲染。否决纯文本展示（长代码读起来吃力）。代价是新增一个前端依赖（本地单机应用不敏感）。
4. **零联动**——不做划选问 AI、不做终端入口、不做任何模块联动，就是一个纯查看的文件树 + 代码阅读器。后续想要再加。
5. **实现：自研轻量树**——主进程 4 个 IPC（选文件夹/读目录/读文件/读图片）+ 渲染层自写递归树组件，风格与现有面板完全一致。否决 react-arborist 等树组件库（几十 KB + 双主题定制成本，只读场景用不到虚拟滚动/拖拽）。

## 面板结构与交互

```
头部：folder_open 图标 + 「资源管理器」 + 收起键
浏览态：工具行（当前文件夹名 · 刷新 · 换文件夹）+ 文件树（懒加载）
查看态：工具行（文件名 · 面包屑 · 返回钮）+ 文件内容区（按类型分流）
```

- **右栏四面板互斥**：`rightPanel: 'ai' | 'draft' | 'files' | 'canvas' | null`；都收起时右缘细条**四图标**，顺序按开发者指定：debugzi `forum` → 资源管理器 `folder_open` → 草稿本 `edit_note` → 画布 `draw`。资源管理器与草稿本/画布一样按需挂载，debugzi 仍常驻挂载不卸载；展开态持久化沿用 `settings.right_panel_expanded`（新增 `'files'` 值）。
- **单栏两态**：右栏窄（280–560px），不做树+查看器左右分栏，浏览态/查看态整区切换。返回钮回浏览态且保留树展开状态（内存态，不落盘）。
- **文件树**：懒加载——点开文件夹才读该层目录（node_modules 等深目录不卡）；文件夹在前、文件在后，各自按名称排序，`.` 开头隐藏文件排同层末尾；文件夹图标区分展开/收起（`folder_open`/`folder`），文件按类型给图标。
- **文件类型分流**（按扩展名，判定顺序如下）：
  - 维护一张**可预览扩展名白名单**（代码/文本：js/ts/tsx/jsx/json/css/scss/html/htm/xml/yml/yaml/toml/ini/cfg/conf/env/sql/sh/bat/ps1/py/java/kt/c/h/cpp/hpp/cs/go/rs/rb/php/swift/vue/svelte/log/txt 等，实施计划中定稿为常量清单），命中 → highlight.js 高亮展示（只读、等宽、行号列）；
  - `.md` → 复用全局 MdView 渲染（阅读体验优先）；
  - 图片（png/jpg/jpeg/gif/webp/svg/bmp）→ 直接预览；
  - 白名单外/无扩展名 → 查看区提示无法预览（配合主进程二进制探测与 1MB 上限，三重防线口径一致）。
- **刷新按钮**：外部变更靠手动刷新（不做 fs watcher）；刷新重读当前展开路径。
- **左缘 7px 拖宽 280–560px**，持久化 `explorer_width`（同画布/草稿本模式）。

## 数据与接口

- **零 DB 迁移**。settings 新键三个：`explorer_root_path`（上次文件夹绝对路径）、`explorer_last_file`（上次打开的文件绝对路径，重启直接回查看态）、`explorer_width`（面板宽度）。
- **主进程**：新增 `electron/services/explorer.ts` 服务（`services/files.ts` 已被 md 读写服务占用，故以 explorer 命名），IPC 四条（root 逐调用显式传入，主进程无状态）：
  - `explorer:pickFolder` → `dialog.showOpenDialog({ properties: ['openDirectory'] })`，返回所选绝对路径（取消返回 null）；
  - `explorer:readDir(root, dirPath)` → 单层条目数组 `{ name, path, type: 'file' | 'dir' }`（排序在渲染层做，主进程只按 `fs.readdir withFileTypes` 原样返回）；
  - `explorer:readText(root, filePath)` → 文本内容 string，utf-8 读取；**1MB 上限**，超出抛 `TOO_LARGE`；
  - `explorer:readImage(root, filePath)` → base64 data URL，**5MB 上限**，超出抛 `TOO_LARGE`。
- **路径安全**：所有 readDir/readText/readImage 入参经 `path.resolve` 后必须位于传入 root 内（`startsWith(root + sep)` 校验），越权一律抛 `PATH_OUT_OF_ROOT`——防止渲染层被注入后读任意盘文件。
- **二进制探测**：readText 读入后检查是否含 null byte，含则抛 `BINARY` 拒绝。
- **preload**：`api.explorer` 暴露 `pickFolder/readDir/readText/readImage`。
- **依赖**：新增 `highlight.js`（经 `highlight.js/lib/common` 常用语言子集入口；高亮配色以 CSS 变量自定义为主题色相近色系，不用其自带高饱和主题，符合全局色彩规则）。

## 错误处理

- 上次文件夹已被删/移动 → 展开面板时树区显示「文件夹不存在」空态 + 「重新选择文件夹」按钮，并清掉 `explorer_root_path`。
- 目录无权限 / 读取失败 → toast 报错，树区保留已有内容。
- 上次文件已失效 → 静默回落浏览态。
- 二进制/超大文件 → 查看区行内提示，不弹窗不崩。
- 纯本地零 AI 零联网，无 LLM/MCP 置灰逻辑；只读无删除操作，不涉回收站与二次确认。
