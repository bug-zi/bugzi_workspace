# debugzi 统一会话流（频道降级为会话标签）设计

> 创建于 2026-09-21 01:25（会话内定稿）。源自优化建议区待完成区「debugzi 子模块繁杂沉重，统筹项目优化侧边栏」。落地后本文移入 `debugzi/archive/`，并同步更新 `debugzi/design.md` 与 `右侧边栏.md`。

## 背景与痛点

优化建议区待完成条目：右侧边栏 debugzi 有很多子模块（频道），看着繁杂沉重，要求统筹整个项目、兼顾 debugzi 涉及的各模块，给出优化方案。

brainstorming 摸底（现状事实）：

- **7 个频道 pill 常驻**头部下方（助手 / 格言·解读 / 学习·问答 / 万象·问答 / 致知己·追问 / 辩真·核查 / 致知己·预言家），每个「图标+文字」，280–560px 边栏宽度下折 2~3 行。
- 7 个频道中 **6 个是场景频道**，几乎全部由主栏模块动作自动切入（格言「AI 解读」、万象「问 AI」划词、致知己「追问」、辩真验证系统消息推送、学习库划词问 AI 拓展坞）；**只有「助手」是用户主动打开使用**。
- 会话按频道隔离存储（`ai_sessions.channel` + 每频道一个激活 settings 键）：找历史会话要先切对频道再翻列表。

开发者勾选痛点（浏览器可视化多选）：**A 频道条占空间、视觉重；B 频道概念太多、记不住；D 会话两层结构（频道 × 多会话）难找**。C「右缘入口多」未勾选——右缘细条 4 图标、主题按钮、活动指示**均不动**。

## 决策记录（会话内逐条与开发者确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 优化方向 | **方案 A「统一会话流」**：常驻频道条整体删除，频道从一级 UI 概念降级为会话的属性标签。否掉方案 B「频道收进头部下拉」（只治占空间，B/D 未解）与方案 C「助手常驻 + 场景折叠组」（D 未解，概念仍在） |
| 2 | 会话列表 | **全部会话跨场景平铺一个列表**（`updated_at` 倒序），每条带场景徽章；不加过滤/搜索（YAGNI，列表长了以后有需要再说） |
| 3 | 手动新会话 | **「＋」只开助手会话**；场景会话的唯一入口是模块动作（从对应模块带上下文进来）。理由：手动空开的场景会话与助手会话实质差别只剩人设，保持「＋」语义单一 |
| 4 | 模块动作行为 | **不变**：自动切到该场景最近活跃会话（无效则该频道最近会话，再无则新建场景会话）——per-channel 激活键保留继续服务此定位 |
| 5 | 当前会话指示 | 头部 debugzi 旁一枚**轻量场景小 pill**（纯指示不可点）；助手会话不显示（助手即默认态） |
| 6 | 启动恢复 | 恢复**最后聊过的会话**（新全局 settings 键）；边栏、拓展坞任何一处切换会话都更新它（IM 心智） |
| 7 | 人设口径 | **主进程按会话 id 查 `ai_sessions.channel` 注入人设**，不再信任渲染层传参——会话与人设不可能不一致 |

## §1 布局变更（渲染层 AiSidebar）

- **删除**：常驻频道条（`.ai-channels` 区块与样式）、`activeChannel` state 及切换逻辑。`CHANNELS` 清单保留，用途收窄为「场景徽章 + tooltip」渲染源（图标与 label 沿用）。
- **头部**：`forum 图标 + debugzi + 〔场景小pill〕+ 会话列表按钮 + 收起按钮`。场景 pill 显示当前会话场景 label（channel ≠ assistant 时渲染），title 悬停说明「当前会话场景：××（人设与历史独立）」；助手会话不渲染。
- **会话浮层**：标题「会话」；列表 = 全量会话；行结构 = 场景徽章（7 场景各自图标，助手用 `forum`，统一样式直径小圆标）+ 标题 + 相对时间 + hover 重命名/删除。选中态、浮层开关行为不变。
- **空态文案**更新：由「『××』频道（感知当前模块：××）」改为助手身份表述（如「新对话将由 debugzi 以助手身份回答（感知当前模块：××）」）。
- 场景 label 沿用现名：助手 / 格言·解读 / 学习·问答 / 万象·问答 / 致知己·追问 / 辩真·核查 / 致知己·预言家。

## §2 会话定位与切换（激活键双轨）

- 新增 `SettingsKeys.AiActiveSessionGlobal`：**边栏当前会话**的唯一事实源。
- per-channel `ACTIVE_SESSION_KEYS`（7 个）**保留**，主进程与渲染层镜像不动：服务模块动作定位与拓展坞定位。
- **边栏切换会话**：写全局键 + 写该会话所属频道的 per-channel 键——后者保证「用户刚在边栏聊了某万象会话，去万象库点问 AI 仍接上它」的延续语义。
- **拓展坞**（ChannelChatPanel：学习库弹窗拓展坞 / 致知己追问栏）：现有 per-channel 键写入不动，**追加写全局键**——保证「启动恢复最后聊过的会话」在两承载面口径一致。
- **启动**：读全局键 → 全量列表校验存在 → 无效回退全量最近会话 → 空库则无激活会话（发消息时自动新建助手会话）。
- **删除激活会话**：回退全量最近会话（不再限定频道）。

## §3 模块动作与系统消息

- **模块动作直发**（`pending: { text, channel, auto }` 机制与 `CHANNEL_BY_MODULE` 映射不变）：边栏收到后定位该场景会话（per-channel 激活键 → 校验有效性 → 无则该频道最近会话 → 无则新建场景会话）→ 切换（写双键）→ `auto` 时自动发送。与现状行为一致，只是「切频道」在 UI 上表现为「切会话」。
- **系统消息推送**（辩真验证过程 `pushAiSystemMessage` / 预言家分析 `appendAssistantToChannelSession`）：落库口径不变（该场景激活会话）。边栏收到 `'ai:message'` 事件后**直接跟随切换到 `msg.session_id`**（与普通切换同口径写双键，重启恢复口径一致）并刷新——统一流下「当前会话」全局唯一，推送必达可见；这是相对现状的自然收益（现状推送落某频道后，边栏若停在别的频道则不可见）。App 层触发展开边栏的行为不变。
- **人设注入**：`aiChat` 内部按 `sessionId` 查 `ai_sessions.channel` 取 `CHANNEL_PERSONAS`；IPC `ai:chat` 的 channel 参数降级为兜底（会话查不到时）或顺手清理，以实施时最小改动为准。「用户当前所在模块」system prompt 注入不变。

## §4 三选条与斜杠命令

- **三选条**（第 47 轮：继续对话 / 保存对话 / 归档对话）显隐判断源从「activeChannel」改为「**当前会话的 channel**」：仍限 learn / wiki / zhijiji 三场景会话；助手、格言·解读、辩真·核查、预言家会话不挂条。挂条位置（最新一条 assistant 下方）与终结式语义不变。
- **保存 / 归档成功后自动切新会话**：切到的是**助手新会话**（与「＋」语义一致）。
- `/clear`、`/compact` 作用于当前会话，不变；`/compact` 生成的新会话继承原会话 channel（现状已按原会话 channel 建新会话，保持）。

## §5 技术面

- **零 DB 迁移**：`ai_sessions.channel` 本来就有；新增 1 个 settings 键（全局激活会话）。
- **主进程小改**：会话列表支持全量查询（`listAiSessions` 增全量口径或 IPC 参数可省）；`aiChat` 人设按会话查。其余（画像记忆化、`/compact`、回收站 AI 会话块、预言家/辩真推送链路）不动。
- **渲染层**：`AiSidebar.tsx` 重排（删频道条与 activeChannel、全会话列表、场景徽章、头部 pill、双键写入、pending 定位、`ai:message` 跟随切换）；`ChannelChatPanel.tsx` 追加全局键写入；三选条判断源改会话 channel。
- **不动**：草稿本、右缘细条 4 入口、主题按钮、LlmActivity、拓展坞交互本身、模块映射、`ChatDisposition` 保存/归档链路。

## §6 冒烟清单

1. 频道条消失；头部场景 pill 跟随当前会话场景变化；助手会话无 pill。
2. 会话浮层全量平铺、徽章正确、切换流畅；重启恢复最后聊过的会话。
3. 五条模块动作路径各验：格言「AI 解读」、万象「问 AI」划词、致知己「追问」、辩真验证推送、学习库划词（拓展坞）——均自动切入对应场景会话；场景无会话时自动新建。
4. 拓展坞与边栏同一会话两处一致；拓展坞切会话后边栏跟随（重启后恢复到拓展坞最后会话）。
5. 「＋」只开助手会话；人设抽查（万象会话讲解员口吻、致知己会话追问者口吻、助手通用口吻）。
6. 三选条仅 learn/wiki/zhijiji 会话出现；保存/归档后自动切助手新会话；归档会话入回收站「AI 会话」块可恢复。
7. `/clear` `/compact`、会话重命名、删除（删激活会话回退全量最近）。
8. LLM 未配置「去配置」直达；双主题目检。
