# docs/project 内 spec/plan 存放与归档机制

superpowers 工作流（brainstorming / writing-plans）会话产出的**设计记录（spec）与实施计划（plan）**不设独立集中目录，按所属模块就地存放（260907 起，原 `docs/superpowers/` 已解散迁入）。维护方：AI（机制正本即本文档；`CLAUDE.md` 文档体系表有对应条目）。

## 存放位置

| 文档所属 | 存放目录 | 示例 |
|---|---|---|
| idea 阶段模块（尚无正式 design.md） | `docs/project/idea/<模块>/` | `idea/文笔坊/2026-09-07-文笔坊-design.md` |
| 已立项模块 | `docs/project/左侧边栏/<模块>/` | `左侧边栏/推理角/2026-09-07-reasoning-question-bank-design.md` |
| 右侧边栏相关改动（AI 助手、草稿本等右侧栏功能，多跨模块） | `docs/project/右侧边栏/` | `右侧边栏/2026-09-06-ai-name-debugzi-design.md` |

- 文件命名不变：`YYYY-MM-DD-<主题>-design.md`（spec）、`YYYY-MM-DD-<主题>.md`（plan）；日期前缀保证唯一，**归档不改名**。
- spec 与 plan 同目录混放（plan 头部 `**Spec:**` 字段互指），不设 specs/plans 子分目录。
- `idea/` 目录维护权属开发者——AI 产出的 spec/plan 文件存于其中时**只动自己产出的文件**，不碰开发者的 design.md 等原始想法文档。

## 归档

落地或废弃后移入所属目录的 `archive/` 子目录（spec 与 plan 共用同一个 archive/）：

| 判定 | 依据 | 动作 |
|---|---|---|
| 落地归档 | spec 状态行或日终日志明确记录「实施完成」（typecheck 通过即算，**不等人工冒烟**——260907 开发者定稿） | 移入 archive/，状态行追加归档记录 |
| 废弃归档 | **开发者明确说**「废弃 / 被新设计取代」（AI 不自行判定废弃） | 移入 archive/，状态行标注「已废弃（原因）」 |
| 留守 | 待实现、brainstorming / 执行进行中 | 不动 |
| 拿不准 | 依据不明 | 不动，报告开发者 |

配套规则：spec 落地归档时，其对应 plan（`**Spec:**` 字段指向该文档者）一并归档。模块升级路径：idea 阶段模块正式立项（design.md 迁入 `左侧边栏/`）时，其 spec/plan 一并迁入该模块新目录。

## 触发时机（全自动，无需开发者口令）

AI 在以下固定动作时**顺带清点**：

1. **写 / 追加日终日志时**——记录「实施完成」的那一刻就是归档时刻；
2. **写新 spec / plan 时**（清点其所属目录）。

开发者也可随时说「归档一下」触发即时清点（兜底）。

## 归档动作（固定四步）

1. `mv` 至所属目录的 `archive/`，文件名不变；
2. 文档顶部状态区追加一行：`- 已归档：YYMMDD 随 <功能> 落地`（废弃则 `- 已归档：YYMMDD 废弃（<原因>）`）；
3. 全库检索该文件旧路径，更新**活动文档**（模块 designs-specs、CLAUDE.md、本 README）中的路径引用；**历史日志（docs/log/）不改**，同批移动的关联引用（如归档 plan 指向归档 spec）顺手更新；
4. 当天日终日志记一笔。

## 回改通道

人工冒烟后若需回改已归档文档：直接在 archive/ 内改，或移回所属目录（状态行同步改回），日志记录。**归档只是位置变化，文件永不删除。**
