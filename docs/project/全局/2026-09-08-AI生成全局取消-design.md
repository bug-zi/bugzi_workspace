# AI 生成全局取消（jobId + AbortController 统一机制）

- **日期**：2026-09-08
- **状态**：设计已与开发者确认（方案 A + 两节设计逐节通过），待写实施计划
- **来源**：开发者反馈——文笔坊 copilot 误触「AI 起稿/续写/润色/改写」后无法取消只能干等；要求**全项目所有 AI 生成均可手动取消**
- **关联**：文笔坊/designs-specs.md §4（copilot，直接诱因）、样式/designs-specs.md（按钮/Toast 规范）

## 背景与问题

全项目约 28 处 `chatCompletion` 调用（electron/ai/services.ts 25 处 + ipc.ts ai:chat 1 处 + mcpResearch.ts 3 处），`ChatOptions.signal` **已声明但 fetch 从未接线**；所有「生成中…」loading 态均无取消入口。LLM 慢时用户被锁死在等待里。

## 关键决策（会话确认）

| # | 决策点 | 结论 | 被否选项 |
|---|---|---|---|
| 1 | 范围 | **全部纳入**：长生成 + debugzi 对话 + 海龟汤提问/猜汤底、思维墙作答等短判答，无死角 | 仅长流程；长流程+对话 |
| 2 | 机制 | **方案 A：通用 jobId + 统一取消通道**（渲染层生成 jobId 随调用传入 → 主进程注册表挂 AbortController → signal 穿透 services → fetch 真接线 → `ai:cancel(jobId)` 随时掐断） | 逐通道取消（N 套重复）；渲染层直传 AbortSignal（IPC 不可序列化，死路） |
| 3 | 取消语义 | **未写库的一律作废、已写库的保留**；无确认弹窗；取消后立即可重试 | 弹确认；部分结果补完 |
| 4 | 后台任务 | 定时格言任务、启动期 trick_note 回填等**无 UI 等待态的任务不接**（无处取消） | 全量接入 |

## 机制层设计

### 1. 新增 `electron/ai/jobs.ts`（任务注册表）

```ts
// AI 任务注册表：渲染层 jobId → AbortController；统一取消通道 ai:cancel 的后端
const jobs = new Map<string, AbortController>()

export function beginJob(jobId: string): AbortController {
  const ac = new AbortController()
  jobs.set(jobId, ac)
  return ac
}
export function endJob(jobId: string): void {
  jobs.delete(jobId)
}
export function cancelJob(jobId: string): boolean {
  const ac = jobs.get(jobId)
  if (!ac) return false
  ac.abort()
  jobs.delete(jobId)
  return true
}
```

### 2. llm.ts `chatCompletion` 真接线（既有声明补实现）

- 请求前 `opts.signal?.throwIfAborted()`；
- `fetch(url, { …, signal: opts.signal })`；
- 429 退避等待改为与 abort race（取消立即中断，不等退避计时）；
- 异常归一：捕获 `AbortError` / `signal.aborted` → `throw new Error('已取消')`（渲染层以此识别，不弹错误框）。

### 3. 统一取消通道 + handler 改造模式

`ipc.ts` 新增：`ipcMain.handle('ai:cancel', (_e, jobId: string) => cancelJob(jobId))`。

全部可取消 handler 统一模式（jobId 为**首个参数**）：

```ts
ipcMain.handle('mottos:generate', async (_e, jobId: string) => {
  const ac = beginJob(jobId)
  try {
    return await generateMottos(ac.signal)
  } finally {
    endJob(jobId)
  }
})
```

## UI 层设计

### 1. 统一交互模式

各模块 loading 态从布尔升级为**持 jobId**：

```ts
const [genJob, setGenJob] = useState<string | null>(null)
const doGenerate = async (): Promise<void> => {
  if (genJob) return
  const jobId = crypto.randomUUID()
  setGenJob(jobId)
  try {
    const r = await window.api.mottos.generate(jobId)
    /* 成功路径不变 */
  } catch (e) {
    const msg = (e as Error).message
    if (msg.includes('已取消')) toast('已取消')        // 取消：轻提示，不走错误弹窗
    else /* 原失败路径不变（GoConfig/错误弹窗/toast） */
  } finally {
    setGenJob(null)
  }
}
const cancelGenerate = (): void => {
  if (genJob) void window.api.ai.cancel(genJob)
}
```

- 生成中：原按钮维持禁用+文案不变，**旁挂「取消」按钮**（icon `stop_circle`，`btn` 样式，title「取消本次生成」）；
- MdDialog copilot：工具行的「协笔生成中…」文字替换为「取消」按钮（同一 jobId 由 MdDialog 内部持有——copilot.request 调用方不变，MdDialog 生成 jobId 传入 request，扩展位签名调整：`request(action, ctx, jobId)` 由 WritingPanel 包装）；
- AiSidebar：发送后等待回复期间，消息流尾部 assistant 占位处给「停止生成」小按钮（同 jobId）；
- 取消无确认弹窗（无产出可失去），按钮立即恢复可重试。

### 2. 取消语义（防歧义，写死）

| 流程 | 取消后 |
|---|---|
| 格言/灵感生成（批末统一入库） | 整批作废，不入库 |
| 海龟汤出题（逐碗落库） | 已入库的碗保留，未完成碗作废 |
| 思维墙出题 / 练习 / 题库作答 | 无写库前作废即无痕；已写详情 md 的终态操作（作答）取消仅在判答 LLM 段生效——判答已落库则不再可取消（按钮只在等待态存在，天然满足） |
| 辩真验证 | 已推送边栏的进度消息保留（历史事实），最终验证记录不落库 |
| debugzi 对话 | 用户消息保留（已入库），不产生 assistant 回复、不加错误占位，等待态消除 |
| copilot | 建议卡不出现，编辑态原样 |
| llm:test / mcp:test / mcp:research | 测试结果不显示，按钮恢复 |

## 明确不做

- 不做「取消后保留部分草稿/续跑」——作废即干净作废。
- 不给定时任务/后台回填加取消（无 UI 等待态）。
- 不改各流程的成功路径与解析容错逻辑（signal 只加在等待段）。
