# 账本（Ledger）设计文档

> 立项讨论：260908 · 状态：已立项（开发者逐节审核通过，specs 见 `docs/project/左侧边栏/账本/designs-specs.md`）
> 来源：《新功能开发区.md》待完成项「左侧边栏增加一个账本的功能」

---

## 1. 背景与定位

左侧边栏新增第 12 个功能模块「账本」：记录资金流水变化的轻量记账工具。

核心诉求（开发者原话归纳）：

1. 知道自己手头有多少钱；
2. 一个月下来的开支大概是多少；
3. 大概用在了哪些方面。

定位：**轻量、纯本地、零 AI**。不追求精细记账，不引入图表库、账单导入、预算管理、转账、多币种等重功能。

## 2. 需求决策记录（260908 澄清结论）

| 决策点 | 结论 |
| --- | --- |
| 记录模式 | 逐笔记流水（金额+分类+账户+可选备注），账户余额自动滚存 |
| 账户 | 多账户（预设：现金/微信/支付宝/银行卡），可增删改名，无转账概念 |
| 分类 | 单级；预设支出（餐饮/交通/购物/居住/娱乐/医疗/学习/其他）与收入（工资/理财/副业/红包/其他）分类，可增删改名 |
| 统计呈现 | 数字卡片（总资产/月收入/月支出）+ 分类占比条（主题色，无图表库） |
| 删除流转 | 入回收站，回收站来源块由八块变九块（新增「账本」块） |
| AI | 纯本地零 AI，不接 LLM/MCP |
| 模块组织 | 单主视图一体页（方案 A，见 §3） |

## 3. 方案选型

- **方案 A（采纳）单主视图一体页**：一个主页面 = 顶部统计卡片区 + 当月流水列表 + 「记一笔」弹窗；账户/分类管理收进「管理」弹窗。零导航直达主流程，开发面最小，贴合轻量定位。
- 方案 B（否）流水/月报双板块：报表空间大但多一层导航，对轻量需求偏重。
- 方案 C（否）流水 SQLite + 月度 md 月记：统计实时计算，md 月记是冗余快照，不符合 YAGNI。

## 5. 数据模型

### 5.1 表结构（三张，金额一律存「分」INTEGER）

```text
ledger_accounts
  id INTEGER PK
  name TEXT NOT NULL
  initial_balance_cents INTEGER NOT NULL DEFAULT 0   -- 期初余额
  sort INTEGER NOT NULL DEFAULT 0
  created_at TEXT NOT NULL
  deleted_at TEXT                                    -- 软删除标记（回收站）

ledger_categories
  id INTEGER PK
  name TEXT NOT NULL
  kind TEXT NOT NULL CHECK (kind IN ('expense','income'))
  sort INTEGER NOT NULL DEFAULT 0
  created_at TEXT NOT NULL
  deleted_at TEXT

ledger_tx
  id INTEGER PK
  date TEXT NOT NULL                                 -- 'YYYY-MM-DD'，精确到天
  type TEXT NOT NULL CHECK (type IN ('expense','income'))
  amount_cents INTEGER NOT NULL CHECK (amount_cents > 0)
  category_id INTEGER                                -- 可空 = 未分类
  account_id INTEGER NOT NULL
  note TEXT                                          -- 选填备注
  created_at TEXT NOT NULL
  deleted_at TEXT
```

### 5.2 关键设计

- **金额存分不存元**：SQLite REAL 浮点累加产生精度脏数据（0.1+0.2 类问题）；汇总与滚存全是整数加减，永无误差。UI 输入元（最多两位小数），落库 ×100，展示 ÷100。
- **余额不落字段、实时聚合**：账户余额 = `initial_balance_cents + SUM(未删收入) − SUM(未删支出)`；总资产 = 各账户余额合计。本地数据量小，直接聚合，删除/恢复后数字自动正确，无对账逻辑。
- **流水日期精确到天**：不记时分（不用很细致）。

### 5.3 预设种子（首次建表写入）

- 账户：现金、微信、支付宝、银行卡（期初余额 0，可改名增删）。
- 支出分类：餐饮/交通/购物/居住/娱乐/医疗/学习/其他。
- 收入分类：工资/理财/副业/红包/其他。

## 6. 界面与交互

### 6.1 主页面（单页自上而下）

```text
┌──────────────────────────────────────────────┐
│ 账本                        [管理] [＋记一笔]  │
├──────────────────────────────────────────────┤
│ [总资产 ¥12,345.67]  [< 2026年9月 >]          │
│ [本月收入 ¥8,000.00]  [本月支出 ¥2,345.67]    │
├──────────────────────────────────────────────┤
│ 餐饮  ████████████░░░░  ¥820.00  35%         │
│ 交通  █████░░░░░░░░░░░  ¥300.00  13%         │
├──────────────────────────────────────────────┤
│ ── 9月8日 今天 ────────── 支出 ¥86.00 ──      │
│   午饭 · 微信 · 公司楼下        -¥36.00   ⋯   │
│   地铁 · 微信                   -¥8.00    ⋯   │
│ ── 9月7日 昨天 ────────── 支出 ¥120.00 ──     │
│   ...                                        │
└──────────────────────────────────────────────┘
```

- **卡片区**：总资产卡实时（各账户余额合计，不随月份变）；收入/支出卡随月份切换。
- **月份切换**：`<`/`>` 箭头 + 当前月份显示；同时过滤占比条与流水列表。
- **占比条**：当月支出按分类汇总排行（分类名 + 占比条 + 金额 + 百分比）；纯 div 宽度百分比 + 主题色 CSS 变量，无图表库。点击某分类行 → 下方流水列表筛选至该分类（再次点击或点「全部」取消筛选）。
- **流水列表**：按日分组倒序，组头带当日支出小计（含今天/昨天相对称呼）；每行 = 分类 · 账户 · 备注 + 金额（支出加负号；颜色仅用主题文字色，禁彩亮色）；行尾 `⋯` 复用既有 `ActionMenu` 组件（编辑/删除）。
- **空状态**：所选月份无流水时，列表区显示一句引导文案。

### 6.2 记一笔弹窗（新增/编辑复用）

金额输入（数字键盘友好，回车提交）→ 支出/收入切换（默认支出）→ 分类宫格点选（随收支切换显示对应组）→ 账户点选 → 日期（默认今天，可改）→ 备注选填。

编辑模式（点流水行或 ActionMenu 编辑进入）：字段同上预填；弹窗内额外提供「删除」按钮，走 `ConfirmDialog` 二次确认。

### 6.3 管理弹窗（顶部「管理」进入，tab 切换）

- **账户 tab**：每行 名称 · 当前余额 · 操作（改名/删/改期初余额）。新建与编辑账户均可设**期初余额**（默认 0）——存量资金一次性录入，余额 = 期初 + 流水滚存。
- **分类 tab**：支出、收入两组列表，可增/改名/删。

### 6.4 样式约束（全局硬性规则）

- 双主题适配：浅色樱花粉+黑字 / 深色宝蓝+白字，背景 bg-light/bg-dark。
- 禁 emoji 图标（Material Symbols）；组件/按键/弹窗禁彩亮颜色，占比条与强调色一律主题色系。

## 7. 删除流转（回收站衔接）

`RecycleSource` 新增 `'ledger_tx' | 'ledger_account' | 'ledger_category'` 三项，`TABLES` 映射到三张表；回收站 UI 聚合显示为第九块「账本」，块内条目文案：流水 → `{日期} {分类名|未分类} {±金额}`；账户 → `账户：{名称}`；分类 → `{支出|收入}分类：{名称}`。

| 删什么 | 入回收站 | 恢复 | 3 天后彻底删 |
| --- | --- | --- | --- |
| 流水 | 软删 + 快照 | 仅清 `deleted_at`，原日期/账户/分类不变 | 删行 |
| 账户 | 软删；**名下流水一并软删但不单独入站**（站内只见账户一条） | **级联恢复**：清账户标记时一并清名下流水标记 | **级联物理删**：删账户行 + 名下流水行 |
| 分类 | 软删；若有流水在用，其 `category_id` 断开置空（显示「未分类」），流水本身不动 | 分类回列表；历史流水保持未分类，不自动回挂 | 删行 |

- 删账户/删使用中分类的 `ConfirmDialog` 文案写明后果（如「该账户下有 12 笔流水，将一并移入回收站」）。
- 账户在回收站期间其流水同处软删，账本列表不会出现「流水挂着已删账户」的断链展示。
- `hardDelete`/`restoreFromRecycle` 需为 `ledger_account` 增加级联特判；`ledger_tx`、`ledger_category` 走默认路径（无附属 md）。
- 超期清理沿用既有 `cleanupExpired()`（启动 + 每日零点），无需新增。

## 8. 错误处理与边界

- 金额校验：> 0、最多两位小数、上限 9,999,999,999 分（约 1 亿元）防手滑。
- 日期校验：合法日历日。
- 名称校验：账户名非空、不与现有未删账户重名；分类名同 kind 内非空不重名；违规即 Toast 拒绝。
- IPC 异常按现有模式 Toast 提示。
- 本模块无网络、无 AI、无外部文件依赖，错误面很小。

## 9. 验证方式（跟随项目现状，无测试框架）

- `npm run typecheck` + `npm run build` 必过。
- 手动验证清单：
  1. 记一笔 → 卡片/占比条/流水列表/账户余额全联动；
  2. 月份切换过滤正确；总资产不随月份变；
  3. 新建账户设期初余额 → 该账户余额与总资产立即体现；
  4. 占比条点击分类 → 流水列表筛选至该分类，取消筛选恢复；
  5. 流水删除 → 入回收站账本块 → 恢复后原样回来；
  6. 删带流水的账户 → 账户一条入站、流水消失 → 恢复后流水一并回来；
  7. 删使用中分类 → 流水显示「未分类」，恢复分类后不自动回挂；
  8. 浅深主题切换下占比条/卡片/弹窗外观正常；
  9. 金额精度：0.1 + 0.2 累计显示 0.30。

## 10. 明确不做（YAGNI）

转账、账单导入（微信/支付宝 CSV）、预算与超支提醒、图表库、多币种、周期性自动记账、AI 总结、借贷/应收。后续需要时再议。
