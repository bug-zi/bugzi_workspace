# 回收站「全部列表 + 来源筛选下拉」— 设计

> 创建于 2026-09-26 11:33
> 来源：优化建议区第 58 轮任务 4（15 个来源页签太多太乱）

## 一、方案（RecycleModule.tsx + recycle.css 纯渲染层，零主进程改动）

### 1. 页签行删除，默认「全部」

- 移除 `.recycle-tabs` 15 页签行；默认视图 `filter = 'all'`，列表 = `rows` 原序（created_at 倒序）全量混排。
- 混排可辨识性：行首来源前缀小字 `srcTag`（已有，覆盖全部来源），无需新信息。

### 2. 头部工具条 + 筛选下拉

- module-header 下加一行工具条：
  - 左：「共 N 条」计数 + 「3 天后自动彻底删除」说明（原 module-sub 文案迁入）。
  - 右：「筛选 ▾」按钮（`filter_list` 图标 + 当前筛选名，锚定 ActionMenu）——菜单项：全部(N) + 各来源(N)（顺序沿用 TABS 现顺序），当前项 `check` 图标，来源项 label 带「（N）」计数；菜单超长走 ActionMenu 既有滚动能力。
- 下拉交互完全对齐播客台订阅筛选先例（第 56 轮 PodcastModule filterMenuAnchor 模式：anchorEl 锚定、点项自动收起、当前打勾）。

### 3. 不变的部分

- `tabOf` 归组逻辑保留（筛选按组过滤，推理角/文笔坊/记账本等混排来源仍归并一组）；恢复/彻底删除操作与二次确认弹窗、`recycle:changed` 事件刷新、keep-alive 激活刷新、超期天数文案全部照旧。
- `TABS` 数组保留为筛选菜单数据源（label 复用）；页签样式类不再使用。

## 二、验收

- typecheck 双配置通过。
- 冒烟：默认全部混排倒序、来源前缀可辨；筛选下拉切换各组计数正确；恢复/彻底删除回归；其他模块丢弃时实时刷新；空态与双主题目检。
