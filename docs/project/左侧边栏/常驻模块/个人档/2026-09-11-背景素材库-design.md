# 设计：背景素材库——多图上传与切换、浅色/深色独立（优化建议区第 36 轮·任务 2）

> 创建于 2026-09-11 00:59
> 来源：docs/project/优化建议区.md 待完成区「个人中心中原来只能上传一张作为项目背景，我希望升级成背景素材库，用户可以上传多张背景图片，然后在这里切换背景图片。并且浅色模式/深色模式背景图片应该独立分开。」

## 背景与决策记录

现状为单图覆盖式：`image:pick` IPC 把图固定命名 `bg-light.ext` / `bg-dark.ext` 存 `userData/bg/`，新传删旧，settings 键 `bg_bg-light` / `bg_bg-dark` 记文件名，`bzres://bg/<file>` 引用，ThemeProvider fetch 探测 404 回退纯色。升级为素材库，经澄清确认的决策：

| 决策点 | 结论 |
| --- | --- |
| 素材组织 | **两个独立素材组**——浅色库 + 深色库分开管理，上传时选归入哪组，各组内切换当前背景 |
| 存储 | **A. 文件系统为真相源**——`userData/bg/light/`、`userData/bg/dark/` 两目录，唯一文件名，列表 = 扫目录；零 DB 迁移、无 DB 行与文件不一致隐患 |
| UI 形态 | **乙. 弹窗管理器**——个人档「背景素材库」一节 +「管理素材库」按钮开弹窗管理 |
| 当前使用键 | 沿用现有 settings 键 `bg_bg-light` / `bg_bg-dark` → bzres 协议零改动；ThemeProvider.applyBg 拼 URL 须补组段（260911 修复：原「ThemeProvider 零改动」为误判——文件迁入 `bg/<group>/` 后旧 URL `bzres://bg/<file>` 404 回退纯色，见 docs/log/260911.md） |
| 上传后行为 | 单张上传自动设为当前背景；多张只入库不切换（toast 区分提示） |
| 删除在用图 | settings 置空回退纯色背景（与探测 404 回退行为同口径），确认文案提示 |
| 上限 | 每组 20 张，超出拒绝整批上传 |
| 格式 | png/jpg/jpeg/webp/gif/bmp（同现状 image:pick） |

## 设计

### 存储与迁移（主进程）

- 目录：`userData/bg/light/`、`userData/bg/dark/`。
- 文件名：`<13位时间戳>-<随机4位>.<原扩展名>`；文件名排序即上传时间序，列表新上传在前（倒序）。
- **一次性迁移（幂等，registerIpc 注册时执行）**：某组目录为空/不存在 且 旧文件 `bg/bg-light.{ext}` 存在（六扩展循环探测）→ mkdir + rename 移入对应组，**文件名保持原名**（settings 已指向它，零额外改动）；目录已有素材则跳过。迁移失败静默（旧图仍在原地，不影响任何现有行为）。

### IPC（`image:` 系列扩展，avatar 路径不动；ipc.ts + preload.ts + api.d.ts 三处同步）

| 通道 | 入参 | 返回 | 行为 |
| --- | --- | --- | --- |
| `image:bgList` | `group: 'light' \| 'dark'` | `string[]` 文件名数组 | 扫目录过滤图片扩展，倒序（新在前）；目录缺失自动创建并返回空数组 |
| `image:bgUpload` | `group` | `{ list: string[]; applied: string \| null }` | 对话框可**多选** → 上限校验（现有数+选中数 > 20 拒绝整批）→ 逐张复制唯一名入组；**单张**成功后自动写 settings 设为当前（`applied` = 文件名），多张 `applied: null` |
| `image:bgUse` | `group, file` | `boolean` | 校验文件存在 → 写 `bg_bg-{group}` settings；渲染层随后 `refreshBg()` 即时生效 |
| `image:bgDelete` | `group, file` | `{ list: string[]; wasUsing: boolean }` | 删文件；若删的是当前使用图 → settings 置空（回退纯色），`wasUsing: true` 供渲染层 refreshBg |

渲染层约定：upload 得 `applied` 非空、或 delete 得 `wasUsing`、或 use 成功后，调 `refreshBg()` 即时生效并 toast。

### UI（ProfileModule + 新组件 `src/modules/profile/BgLibraryDialog.tsx`）

- 个人档原「背景图（浅色）/（深色）」两行设置项 → 替换为一节：label「背景素材库」+ 按钮「管理素材库…」开弹窗。
- 弹窗（ConfirmDialog 同款遮罩风格，模块目录内实现）：
  - 顶部浅色/深色 pill 切换（recycle-tab 同款），切换即拉对应组列表；**弹窗打开默认选中当前主题对应的组**。
  - 缩略图网格：`bzres://bg/<group>/<file>` 预览；当前使用图主题色描边 + 「使用中」角标；**点图即设为当前**（成功 toast + 描边转移 + refreshBg）。
  - 每格 hover 出删除按钮（右上角）→ 二次确认；在用图确认文案追加「该图正在使用，删除后回退纯色背景」。
  - 「+ 上传」按钮：走 `image:bgUpload`，完成后刷新网格；单张「已设为当前背景」/ 多张「已加入 N 张素材」toast。
  - 空态：「还没有背景素材，上传一张试试」+ 上传按钮。

### 错误处理

- 上传复制失败 / 删除失败：toast 报错，已成功的张数保留（不回滚已入库文件）。
- 列表扫描异常：返回空数组，弹窗显示空态。
- 旧 `image:pick` 的 `bg-light` / `bg-dark` 分支删除（avatar 分支保留）。

## 零改动区

bzres 协议（`bg/` 下子路径天然支持）、头像上传、主题切换链路、双主题背景变量。~~ThemeProvider（applyBg/refreshBg）~~——260911 勘误：applyBg 拼 URL 原为 `bzres://bg/<file>`，文件迁入组目录后 404，已修复为 `bzres://bg/<group>/<file>` 组目录优先 + 旧根路径兜底探测（协议本身支持子路径 ≠ applyBg 的 URL 串会自动带组段，此为本轮漏改根因）；refreshBg 确实零改动。
