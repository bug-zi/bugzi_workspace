# 快捷键配置（个人档）设计

> 日期：2026-09-29 ｜ 来源：新功能开发区待完成项 ｜ 状态：已实施

## 一、需求

个人档模块新增「快捷键」栏目，位置在「App 设置」与「终端」之间：展示当前应用的快捷键信息，并可直接按键重设。快捷键只在 App 应用内生效（不做系统全局热键）。首期六条：

| 功能 | 默认组合 |
|---|---|
| 打开 / 关闭终端 | Ctrl+J |
| 新建终端标签 | Ctrl+Shift+J |
| 打开 / 关闭日志库 | Ctrl+E（260929 增补定档：原 Ctrl+A 让位给模式切换） |
| 切换深色 / 浅色模式 | Ctrl+Space |
| 切换学习 / 生活模式 | Ctrl+A（260929 增补，开发者指令） |
| 播放 / 暂停音乐 | Ctrl+Q |

## 二、brainstorm 决策（260929 开发者拍板）

1. **输入框内不触发**：焦点在 input/textarea/select/contenteditable 时不触发任何应用快捷键，保留全选等原生编辑行为（VS Code 口径）。
2. **Ctrl+Q 走活跃音源口径**：与右栏快捷播放钮同逻辑——轻音乐在播控轻音乐，白噪音在播控白噪音，都没播则拉起白噪音。
3. **冲突拒绝并提示**：重设的组合已被其他功能占用时，toast 提示「与 XX 冲突」并保持在录入态，保持每个组合唯一。

## 三、补充设计决策

4. **终端面板内只保留终端两条**：终端拥有键盘（bash readline 的 Ctrl+A=行首、Ctrl+Space=set-mark、Ctrl+Q=流控恢复）。焦点在终端面板内时，仅「终端开关 / 新建终端」两条仍触发（面板级控制，同 VS Code commandsToSkipShell 口径，保持现状零行为变化），其余三条交还 shell。
5. **存储**：settings 键 `keybindings`，JSON 存覆盖项 `{ actionId: accelerator }`，缺省即默认；不迁移 DB（settings 表通用键值）。
6. **分发**：渲染层统一注册表 `src/services/keybindings.ts`（动作元信息 / 默认值 / KeyboardEvent 匹配 / 录入捕获标志 / 存取）。App Shell 启动加载 + 监听 `bugzi:keybindings-changed` 自定义事件重载，零轮询；个人档保存后派发同一事件。
7. **主进程菜单解锁（关键前提）**：Electron 默认应用菜单在 `autoHideMenuBar` 隐藏态下**仍注册加速器**，且菜单加速器在主进程层抢先于渲染层 keydown——Ctrl+Q（默认 Quit）与 Ctrl+A（默认 selectAll）会被直接吞掉，应用内快捷键永远收不到。改为 `Menu.setApplicationMenu(null)` 释放按键；DevTools 快捷键（Ctrl+Shift+I / F12）经 `before-input-event` 手动保留供开发调试。附带收益：xterm 终端内 Ctrl+A 也将真正到达 shell（此前被菜单 selectAll 截走）。
8. **录入交互**：行内「修改」（铅笔）→ 徽章变录入态「按下新组合键…（Esc 取消）」；须含 Ctrl 或 Alt 修饰（裸键会劫持打字，纯修饰键按下忽略继续等待）；capture 阶段监听 + `isCapturing()` 双保险避免录入时触发全局分发；冲突 toast 后留在录入态可继续按；成功即存即生效 + toast；有覆盖的行显示「恢复默认」按钮。
9. **固定快捷键说明行**：栏尾注明仅应用内生效、输入框内不触发、终端内 Ctrl+Shift+C/V 复制粘贴、信息源阅读 Ctrl+滚轮缩放、Ctrl+Space 可能被系统输入法占用（无效时需在输入法设置解绑）。

## 五、行为边界

- 焦点在可编辑元素 → 五条全部不触发；焦点在终端面板 → 仅终端两条触发。
- 录入期间（capture 态）全局分发静默。
- 快捷键只控 App 内行为，不注册 `globalShortcut`（系统级），重启后覆盖项持久生效。
