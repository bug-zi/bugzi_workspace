# 总导览·每日挑战与热力图 设计记录

> 创建于 2026-09-16 02:04
> 来源：`docs/project/新功能开发区.md` 待完成区任务一、任务二（开发者 260916 提出，当日 brainstorm 商定）。
> 定位：总导览新增「每日挑战」卡片（用户自填挑战池、本地随机日定一条、打卡完成）与「GitHub 式热力图」（近一年每日任务完成度四档着色）。本文件为实施设计记录。

## 一、需求结论（brainstorm 摘要）

| 维度 | 结论 |
|---|---|
| 抽取机制 | **本地随机**——程序抽签，不调 LLM；总导览保持纯渲染零 AI 架构 |
| 每日流转 | **日定一条 + 打卡**——进总导览时无当日记录则随机定档写入；点「完成」打卡；「换一条」重抽但完成状态保留（完成记在当天，不跟具体某条挑战） |
| 打卡可逆 | 完成后可撤销（toggle，误点可救）；热力图随实时记录保持一致（与学习每日要求/每日一题的不可逆口径**不同**，设计上接受差异） |
| 池管理 | 总导览页内管理弹窗：列表 + 添加 + 行内编辑 + 删除（二次确认，全局规则） |
| 热力图口径 | **固定三任务**：学习库每日要求（learn_daily.done）+ 每日一题（wall_puzzles 当日有非 answering 记录）+ 每日挑战（challenge_daily.done）；完成件数 0/1/2/3 → 四档颜色 |
| 热力图范围 | **近一年整图**——53 列周 × 7 行，起始对齐周一，横贯总导览卡片宽度 |
| 热力图位置 | 总导览底部、格言轮播上方，独立 card |
| 数据层 | **方案 A**——挑战两张新表（DB v43，设计时拟 v42、实施时 v42 已被同日并行会话藏阅阁文件夹占用故顺延），热力图不建汇总表，读时聚合三源，一个 IPC 查全年 |

## 二、数据（DB v43）

```sql
CREATE TABLE challenge_pool (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  content TEXT NOT NULL,
  created_at TEXT NOT NULL
);

CREATE TABLE challenge_daily (
  date TEXT PRIMARY KEY,          -- 本地 YYYY-MM-DD
  challenge_id INTEGER NOT NULL,  -- 当日定档的池条目 id
  done INTEGER NOT NULL DEFAULT 0
);
```

- 挑战条目删除**不级联**每日行：读每日时 LEFT JOIN 池，条目已删显示「（已删除的挑战）」，done 历史保留（热力图不受影响）。
- `learn_daily` v40 重建后仅新结构数据，热力图早期日期学习项为 0 件属正常，不回填。

## 三、服务与 IPC

新 `electron/services/challenge.ts`：

- `ensureDaily(date)`：无当日行则从池随机定一条写入（事务内 check-and-set，防并发重复定档）；池空则不建行。
- `getDaily(date)`：每日行 + LEFT JOIN 池取内容。
- `swapDaily(date)`：从池重抽一条（排除当前 challenge_id，池仅 1 条时前端置灰不调）；**done 保留**。
- `setDone(date, done)`：显式落库 0/1（check-and-set 惯例）。
- `listPool()` / `addPool(content)`（trim 非空）/ `updatePool(id, content)` / `removePool(id)`。

新 `electron/services/overview.ts`：

- `heatmap(from, to)`：三查询聚合——
  - `SELECT date, done FROM learn_daily WHERE date BETWEEN ? AND ?`
  - `SELECT date FROM wall_puzzles WHERE date BETWEEN ? AND ? AND status != 'answering'`
  - `SELECT date, done FROM challenge_daily WHERE date BETWEEN ? AND ?`
  - 合并为 `{ date, learn: boolean, wall: boolean, challenge: boolean, level: 0-3 }[]`（level = 完成件数）。

IPC 通道（沿用 `域:动作` 命名）：`challenge:daily`（ensure+get 合一）、`challenge:swap`、`challenge:setDone`、`challenge:listPool`、`challenge:add`、`challenge:update`、`challenge:remove`、`overview:heatmap`。preload 暴露 `window.api.challenge.*` 与 `window.api.overview.*`，`api.d.ts` 同步类型。

## 四、总导览 UI（OverviewModule + 两新组件）

**今日挑战 card**（插在每日一题卡之后、续读卡之前；图标 `fitness_center`）：

- 主行：当日挑战内容（未定档且池空 → 引导文案「还没有挑战项目 · 去添加」点击开管理弹窗）。
- 状态行：已完成显示 `check_circle` 主题色 + 「已完成」；未完成显示「待打卡」。
- 操作：「完成/撤销」按钮（toggle）；「换一条」icon-btn（池 <2 条置灰）；「管理」icon-btn 开弹窗。
- `loadChallenges()` 并入 `loadAll` 逐块 catch 惯例；跨午夜在下次模块激活时刷新（同现有各块口径，不加实时翻日监听）。

**ChallengeManageDialog**（新组件，样式参照记账本账户/分类管理弹窗惯例）：

- 挑战项列表：行内「编辑」icon 切输入态保存，「删除」icon **二次确认**后删。
- 底部添加行：输入框 + 添加按钮（Enter 可提交），空内容不提交。

**HeatmapCard**（新组件，纯自研 div grid，零第三方库）：

- 布局：列 = 周（53 列）、行 = 周一至周日；顶部月标签（该月首列上方标月份）、左侧标「一 / 三 / 五」；格子 10px、间隙 3px；未来日期不渲染。
- 颜色四档走主题色系 CSS 变量（zonglan.css 内按 `data-theme` 定义）：浅色樱花粉 30%/60%/100% 渐进、深色宝蓝渐进，0 档中性底——不违「禁彩亮」规则。
- hover 详情位：卡片标题行右侧一行小字，默认显示今日三任务完成态，hover 格子时切换为该日详情（固定信息行实现，不做跟随浮层）。
- 图例：卡片右下「少 □□□□ 多」四格。
- 数据范围：从今天回推至对齐周一的 53 周起点，一次 `overview:heatmap` 拉全年。
- **即时联动**：挑战卡打卡/撤销/换一条后重拉热力图（OverviewModule 持有热力图 state 下传）。

## 五、容错与边界

- 池空：挑战卡引导态；ensureDaily 不建行；热力图挑战项恒未完成。
- 换一条在池 <2 时置灰。
- 逐块独立 catch：挑战/热力图任一加载失败只影响本块显示，不拖垮总导览（沿现有惯例）。
- 纯本地零 AI、零新依赖、零 LLM 依赖。
