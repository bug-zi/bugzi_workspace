## 一、需求原文拆解

1. 测一测改**题库制**：凡正式入库（learned）的知识都预生成 1-2 题，点测一测直接从题库抽题，不再现场临时生成。
2. **毕业机制**：一道题答对 2 次即移除出题库；答错则该题答对次数 −1。
3. **补充机制**：一个知识的题目被毕业完成后，再补充新题入题库。
4. **熟练度区分**：某知识的题目被毕业移除的次数 = 掌握程度指标（毕业三四次 = 掌握好；零次一次 = 不熟）。
5. （备选方案中的）**中断续答**：经商讨定稿**不做**——题库秒开后续答价值大减（见决策表）。

### 已商定决策（brainstorming 260916）

| 决策点 | 结论 |
| --- | --- |
| 整体模式 | **纯题库制，不续答**：每轮抽 5 题答完即记账；中途退出无损失——已提交的题已记账，未答的下轮重抽。不保留半途答卷 |
| 抽题策略 | **偏向低熟练度**：优先抽 `quiz_graduated`（毕业次数）低的词条的题，同级随机；同词条一轮最多 1 题 |
| 熟练度展示 | **卡片弹窗 + 答题页**两处：标题旁「测毕 N」胶囊（N≥1 才显示）+ 答题页来源词条旁同款胶囊 |
| 记账时机 | **每题提交即记**（fire-and-forget）：答对 +1（达 2 同事务删题 + 词条毕业数 +1）、答错 −1 地板 0 |
| 出题机制 | **后台补充泵**（照 reasoningStock 静默惯例，项目已有三泵先例）：点测一测永远秒开 |
| 池空兜底 | 现场生成一轮（现有 generateWikiQuiz 路径保留），**兜底题也入库**——记账全链路单一口径 |
| 泵轻提示 | **不做**：主进程主动维护泵维持静默（260915 第 43 轮定过口径） |

## 二、数据模型（DB v41）

```sql
CREATE TABLE wiki_quiz_bank (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  entry_id INTEGER NOT NULL,          -- 来源词条 wiki_entries.id
  question TEXT NOT NULL,
  options TEXT NOT NULL,              -- JSON 数组 4 项
  answer INTEGER NOT NULL,            -- 正确项下标 0..3
  explanation TEXT NOT NULL,          -- 题目解析（提交后展示，第 43 轮口径）
  correct_count INTEGER NOT NULL DEFAULT 0,  -- 答对净次数；达 2 毕业删行
  created_at TEXT NOT NULL
);
ALTER TABLE wiki_entries ADD COLUMN quiz_graduated INTEGER NOT NULL DEFAULT 0;
```

- `quiz_graduated` = 该词条题目毕业移除累计次数，**即熟练度**，永续累计不清零。
- `wiki_quiz_bank` 无 deleted_at：题不进回收站（派生产物，毕业即删、词条彻底删时级联删）。
- `shared/types.ts` + `src/renderer/api.d.ts` 同步类型（题库行、词条行加 `quiz_graduated`）。

## 三、出题与补充泵（新服务 `electron/services/wikiQuizStock.ts`）

- **水位**：每个 learned 词条常备 **2 题**在库（出 1-2 题取 2——同轮可换题防背答案，单词条出题一次 LLM 调用两题不增成本）。
- **触发三处**（照 reasoningStock）：启动延迟 10s / 每轮抽题消耗后 / 进万象库模块（新 IPC `wiki:quizStockCheck`）。
- **每批**：挑在库题数 < 2 的 learned 词条（按 entry id 顺序，**每次触发最多 5 个词条**防启动风暴），逐词条读卡文（截 1200 字同现状）调 LLM 各出 2 题；prompt 注入该词条现有在库题干清单，要求新题换角度防重复。
- **容错**：单词条失败跳过不废批；LLM 未配置静默跳过；`pumping` 单例防重入；每批完成推 `wiki:stockChanged`（渲染层渐进刷新）。
- **入库解析**：复用 `parseQuizArray` 同款容错口径。

## 四、抽题与作答（`WikiModule.tsx` 测一测链路改造）

- **`wiki:quizDraw`**（替代日常路径的 `wiki:quiz`）：单事务内抽 5 题——`ORDER BY 词条 quiz_graduated ASC, 随机`，同词条最多 1 题；不足 5 抽多少测多少；**0 题**时兜底现场生成（现有 generateWikiQuiz 保留），兜底 5 题照常入库后同链路作答。
- **作答交互零变化**：第 43 轮提交制全套保留（预选可改/提交锁定/解析框/查看相关知识点卡片）。
- **`wiki:quizRecord(bankId, isCorrect)`**：每题提交时 fire-and-forget 记账——答对 `correct_count + 1`，达 2 同事务 `DELETE` 题行 + `quiz_graduated + 1`；答错 `max(0, correct_count − 1)`。
- 成绩总结页（`quizScore` 前端现算保留——题面本就含 answer 用于亮答案）与「再来一轮」（再抽 5 题）照旧。

## 五、熟练度展示

- **卡片弹窗**：MdDialog 标题旁独立小胶囊「测毕 N」（`quiz_graduated ≥ 1` 才渲染，0 保持干净），与板块胶囊同款主题色软底样式。`titleTag` prop 类型扩为 `string | string[]`（字符串用法对既有 8 个使用方零影响，数组渲染多胶囊），WikiModule 传 `[板块名, 熟练度]`。
- **答题页**：quiz-meta 行「来源词条『X』」后同款胶囊显示该词条当前熟练度。
- 词条行查询（板块页/总览/笔记本等 wiki 卡片 SELECT）补带 `quiz_graduated` 列。

## 六、边界

| 场景 | 处理 |
| --- | --- |
| 词条彻底删除 | recycle.hardDelete wiki 分支级联 `DELETE FROM wiki_quiz_bank WHERE entry_id = ?` |
| 词条软删在站期间 | 抽题与泵均排除 `deleted_at IS NOT NULL` 词条的题（恢复后题自动回归可用） |
| 词条 md 后续编辑 | 题目轻微过时不处理（题考核心知识，滞后可接受） |
| 学习库每日小测 | learn_quiz 与测一测无关，零改动 |
| 兜底生成时 LLM 未配置 | 沿用现状「去配置」提示路径 |
