# 万象库·知识问答标签页 设计记录

> 创建于 2026-09-12 19:53
> 来源：`docs/project/新功能开发区.md` 待完成区（开发者 260912 提出）。
> 定位：万象库子功能（非新模块），直接开发；本文件为实施设计记录，落地后随 specs 修订一并归档。

## 一、需求原文拆解

1. **第三标签页**：万象库顶部 tab 从「百科 | 辩真」扩为「百科 | 辩真 | 问答」（问答追加在辩真后，辩真位置不动）。
2. **内容定位**：放偏科普的知识问题（如「我很好奇流量价格是怎么降下来的」）——区别于致知己·十二问题的生活思考题。
3. **问 AI**：输入问题，AI 联网搜索后回答。

### 已商定决策（brainstorming 260912）

| 决策点 | 结论 |
| --- | --- |
| 追问处理 | **单轮问答存档**：问一条存一条；想继续追问去右栏「万象·问答」频道接着聊，追问不与记录绑定 |
| 过程呈现 | **安静模式**：搜索/生成过程不推右栏频道、边栏不自动展开，仅面板内显示进行中状态 |
| 搜索依赖 | **强制搜索**（同辩真）：必须 MCP 联网检索；MCP 未启用提示去配置，不提供纯 LLM 降级回答 |
| 百科联动 | **不联动**：不做「转存为百科词条」入口（与预言家×沉淀区联动不做的先例一致） |
| 实现方案 | **独立新表 `qa_records` + 第三 tab 面板**（完全照搬辩真模式，不复用 verify_records / 频道消息） |

## 二、UI 与交互（`src/modules/wiki/QaPanel.tsx`，仿 VerifyPanel）

- **tab 结构**：`WikiModule.tsx` tab 状态 `'wiki' | 'verify'` 扩为 `'wiki' | 'verify' | 'qa'`；三 tab 均沿用 keep-alive 隐藏切换（`.module-live` / `.module-hidden`），问答进行中切 tab 不中断任务。
- **输入区**：多行输入框卡片，占位「输入一个偏科普的知识问题，AI 联网搜索后回答（需 LLM + MCP）…（Ctrl+Enter 提问）」+「提问」按钮。
- **进行中**：按钮变「提问中…」+「取消」按钮（主进程 jobId 可取消，同辩真）。
- **记录列表**：按时间倒序，每行 = 问题 + 提问时间；行操作「查看」「回收站」。
- **查看**：全局 MdDialog 弹窗渲染回答 md（默认渲染态、双击编辑）；保留**划词问 AI**（划选文字推右栏「万象·问答」频道，与百科卡片划词行为一致）。
- **允许重复提问**：不做辩真式重复拦截——知识会更新，每次搜索结果不同。
- **删除**：移入回收站「万象库」块（新 source `qa`），ConfirmDialog 二次确认；回收站可恢复、3 天自动彻底删。

## 三、数据模型（DB v37）

```sql
CREATE TABLE IF NOT EXISTS qa_records (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  question TEXT NOT NULL,
  answer TEXT NOT NULL,
  md_path TEXT NOT NULL,
  created_at TEXT NOT NULL,
  deleted_at TEXT
);
```

- 无可信度字段（问答不是核查）。
- `answer` 字段仅存生成时的初始回答（列表与弹窗展示一律读 md 快照，同辩真 analysis 的口径——用户在弹窗中双击编辑后以 md 为准，DB 字段不回写）。
- 回答 md 快照：`md/qa/{id}.md`——`# 问：{question}` + 提问时间 + 回答正文（含 Markdown 来源链接）+ 检索关键词列表。
- `shared/types.ts` 新增 `QaRecord` 接口；回收站 source 枚举加 `'qa'`，`RecycleModule.tabOf` 中 `'qa'` 归「万象库」块（同 `verify`），标题格式化与恢复分支补齐（恢复 = `deleted_at` 置空，回问答列表）。

## 四、IPC 与 preload

- `qa:list`：未删记录倒序全量。
- `qa:get`：单条（弹窗刷新用）。
- `qa:run(jobId, question)`：`beginJob/endJob` 包裹，长任务可取消。
- `qa:discard`：入回收站（source `qa`）+ 推 `recycle:changed`。
- preload 挂 `window.api.qa.{list, get, run, discard}`。

## 五、后端流程（`electron/ai/services.ts` 新增 `runQaAnswer`，骨架复用 `runVerification`）

1. `findSearchTool`（动态 import 防循环依赖）找 MCP 搜索工具；未找到 → 抛 `MCP_NOT_ENABLED` 口径错误。
2. LLM 生成 3 组中英文检索关键词（scene `qa:ask`，同辩真风格）。
3. 逐组 MCP 检索（`mcp.callTool(tool, { query: kw })`）；单组失败跳过，全部失败抛「全部检索失败」。
4. LLM 综合资料生成回答（温度 0.3，scene `qa:ask`，**不注入画像**——科普问答与用户画像无关）：Markdown 结构化、通俗讲清机制、引用来源以 Markdown 链接列出。
5. 写 `qa_records`（md_path 先 `PENDING` 后回填，同辩真）+ `mdWrite` 快照，返回 `{ recordId }`。

**安静模式落实**：`qa:run` 的 onProgress 不接 `pushAiSystemMessage`（辩真是接的），进度仅 console 记录；渲染层自显示进行中状态。

## 六、错误处理（全部沿用辩真现成模式）

| 场景 | 处理 |
| --- | --- |
| LLM 未配置 | `LLM_NOT_CONFIGURED` → GoConfigDialog 直达个人档 |
| MCP 未启用 | `McpNotEnabledError`（message `MCP_NOT_ENABLED`，`findSearchTool` 抛出）→ GoConfigDialog（mcp） |
| MCP 启用但无 search 类工具 | 通用失败弹窗显示「未找到可用的搜索工具…」错误信息 |
| 全部检索失败 / LLM 空返回 | 失败弹窗显示错误信息 + 重试按钮 |
| 用户取消 | 「已取消」toast；取消在写库前拦截，不落半截记录 |

## 七、测试与验收

- `npm run typecheck` 双 tsconfig 通过。
- 运行时冒烟（开发者验证）：提问 → 生成回答 → 列表回看 → MdDialog 双击编辑 → 划词问 AI 进「万象·问答」频道 → 删除入回收站 → 恢复 → 取消中断不落库。
