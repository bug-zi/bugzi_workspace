## 1. 数据表

```sql
CREATE TABLE mottos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  content TEXT NOT NULL,        -- 格言正文
  source TEXT NOT NULL,         -- 出处（书名/作者/「AI 编撰」等）
  status TEXT NOT NULL DEFAULT 'draft',  -- 'draft' | 'settled' | 'formal'
  note_path TEXT,               -- 仅正式区：笔记 md 文件路径（md/mottos/<id>.md）
  origin TEXT NOT NULL DEFAULT 'manual', -- 'manual' | 'ai'（手动录入或 AI 生成）
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT               -- 非空 = 已进回收站
);
```

## 2. 页面结构

- 三区并列或纵向排布（实现时定，推荐纵向三个可折叠区块：草稿区 / 沉淀区 / 正式区），每区块标题显示条数。
- 每条格言一行式列表组件：格言正文 + 出处 + 操作按键（按键见 §4）。正文过长截断省略，悬浮显示全文。
- 草稿区区块标题旁：**「来10条格言」按钮** + **定时设置图标**。
- 正式区区块标题旁：**「+ 新增格言」** + **「批量导入」**。

## 3. AI 生成（核心功能）

### 3.1 生成逻辑

- Prompt 构造：取正式区全部格言（正文+出处）作为风格样本，指示 LLM：「参考这些格言的风格与题材，生成 10 条新格言；可摘取现实书籍作品名言，也可自行编撰；每条必须标明出处（编撰的标『AI 编撰』）；以 JSON 数组返回 [{content, source} × 10]」。
- 主进程 `window.api.mottos.generate()` 调默认 LLM（样式 specs §4 的 ai 层），JSON 解析失败自动重试一次。
- **入库前查重**：与三区已有格言按正文规范化比对（去首尾空白+标点统一后完全一致视为重复）；重复条丢弃不入库，实际入库数 = 10 − 重复数；生成完毕 toast「本次生成 10 条，去重后入库 N 条」。

### 3.2 触发方式

- **手动**：「来10条格言」按钮。生成中按钮 loading 不可重复点击，完成后草稿区顶部插入新条目。
- **定时**（design.md：暂定每晚 10 点，可调整）：时间存 settings 表（key=`motto_schedule`，默认 "22:00"）。主进程排程到点触发，与手动同一逻辑。**App 未运行时错过即跳过，不补生成**（总需求文档第 10 条）。
- 定时设置弹窗：时间选择器（HH:mm）+ 保存。

### 3.3 失败处理

- LLM 未配置：弹窗「请先在个人中心配置 LLM」+「去配置」直达（总需求文档第 8 条）。
- 网络/调用失败：弹窗提示原因 + 「重试」按钮；定时任务失败静默记录日志，下次定时再试。

## 4. 各区操作明细

| 区 | 操作 | 行为 |
|---|---|---|
| 草稿区 | 加入沉淀区 | status → settled，条目移入沉淀区区块 |
| 草稿区/沉淀区/正式区 | 丢弃 | 二次确认（「放入回收站，3 天后自动彻底删除」）→ 进回收站格言板块 |
| 沉淀区 | 加入正式区 | status → formal，**同时创建笔记文档** `md/mottos/<id>.md`（正文空白；句子+出处由弹窗标题区展示，见 §5） |
| 正式区 | 笔记 | 打开 MdDialog（title=格言正文，subtitle=`—— {出处}`，filePath=note_path） |
| 正式区 | （列表行双击或编辑键） | 编辑正文与出处（弹窗表单，即时保存） |

- 正式区手动维护：「+ 新增格言」弹窗表单（正文+出处）直接入库为 formal 并建笔记文档；「批量导入」弹窗：多行文本，每行一条，支持 `格言 —— 出处` 或 `格言——出处` 分隔（无分隔则出处留空待补），逐行解析、逐条查重，预览确认后批量入库。
- 回收站恢复的格言：status 重置为 draft 回草稿区（见回收站 specs §3）。

## 5. 笔记文档

- 仅正式区条目有；随格言存在：进回收站时封存（文件保留、入口不可达），恢复还原，彻底删除时 md 文件一并删除（回收站 specs 已约定）。
- MdDialog 交互：渲染态 ⇄ 双击编辑，见样式 specs §5。
- 正文不含格言句子与出处（优化建议区调整）：句子=弹窗标题、出处=标题下小字副标题行 `—— {出处}`（与列表行同款格式），正文从空白开始供用户自写；DB v8 迁移剥离存量笔记旧模板头（`# {句子}\n\n> {出处}`，头部以下自写内容保留、已自行改写的不动），`mottos:setStatus` 转正时对仍带旧头的笔记兜底剥离。

## 7. v2.0 增量（design.md v2.0 四项）

> 交互决策（design.md 未明示处，AI 按惯例定，开发者审核）：标签行内管理 + 顶部筛选条；搜索全局三区；去重完善三项全做。

### 7.1 标签（分类与筛选）

- **数据**：`mottos` 表加 `tags TEXT NOT NULL DEFAULT '[]'`（JSON 字符串数组，DB v4 迁移）；每条格言 0..n 个标签，标签为自由文本（非预设体系），同名标签自动归并。
- **行内编辑（三区通用）**：每行操作区新增「标签」图标键，点击在该行下方就地展开标签编辑条：已有标签胶囊（点 × 删除）+ 输入框（回车确认添加；输入去首尾空白、空忽略、与已有同名去重）+ **快速添加已有标签**（虚线胶囊列出其他格言已用而本条未打的标签，最多 8 个，点击即加）；再点图标或点击他处收起。草稿/沉淀/正式三区均可打标签（AI 生成落草稿区后即可就地分类）。
- **行上展示**：出处右侧以小胶囊显示该条标签（超过 3 个显示前 3 个 + `+n`，悬浮 title 显示全部）。
- **筛选入口（两处）**：① **吸顶导航栏右侧标签图标**（与区导航同条，滚动时常驻可用）：点击弹出标签浮层（亚克力材质，聚合三区全部标签+计数，**单行横排**、超宽横向滚动），点选即筛选并收起浮层，图标上显示当前筛选的标签名；② 顶部标签汇总条：快速导航下方，聚合全部标签（按使用条数降序，同数按名称排），点击单选切换。两处均**单选**、再次点击取消；无任何标签时顶部条不渲染（导航栏图标仍可点，浮层提示「还没有任何标签」）。筛选与搜索叠加（AND）。
- **弹窗标签输入**：新增格言弹窗与正式区编辑弹窗增加「标签」输入框，支持用逗号（,，）或顿号（、）分隔多个；输入框下方提供**快速添加已有标签**虚线胶囊（点击以顿号衔接追加）；批量导入默认无标签（导入后行内补）。

### 7.2 搜索

- **入口**：**吸顶导航栏右侧搜索图标**（与区导航、标签图标同条，滚动时常驻随时可用）：点击展开输入框（自动聚焦，实时过滤）；再点图标收起并清空，Esc 清空失焦。design.md 原文交互：「一个搜索图标，点击在搜索框中输入关键词」。
- **匹配**：关键词不区分大小写，匹配**正文 / 出处 / 标签**任一即保留；实时过滤（输入即生效，无需回车）。
- **范围**：**全局三区**同时过滤，各区仅显示命中条目，无命中的区显示「无匹配」空态；关闭搜索恢复全量。

### 7.3 「来10条格言」= 5 条摘录 + 5 条编撰

- **Prompt**：一次 LLM 调用返回 `{"mottos":[{"content":"…","source":"…","kind":"excerpt|composed"}]}`，恰好 5 条 `excerpt`（现实书籍作品摘录，source 标真实出处）+ 5 条 `composed`（AI 编撰，source 标「AI 编撰」）。风格样本沿用 v1（正式区最近 50 条）。
- **解析容错**：kind 缺失/非法时按 source 含「AI 编撰」推断为 composed；不强制校验 5+5 比例（prompt 强约束，以模型返回为准）。
- **入库**：混排插入草稿区区首（沿用 v1 规则），`origin='ai'` 并落 `gen_kind` 列（excerpt/composed，DB v6；存量 AI 行按出处含「AI…编撰」回填）。**行上 AI 徽章仅编撰（composed）条显示，现实摘录（excerpt）条不打徽章**（开发者指令）；手动录入条无徽章不变。
- **返回值**：`{ generated, inserted, excerptInserted, composedInserted }`；toast：`本次生成 10 条（摘录 X + 编撰 Y），去重后入库 N 条`。定时生成走同一入口，自动生效。

### 7.4 去重逻辑完善

1. **LLM 主动避开**：生成 prompt 附三区+回收站全部已有格言正文清单（按行，最多 500 条防超长），明确要求「不得与清单中任何一条重复或仅作微小改写」。
2. **包含判重**：入库比对时，`normalizeText` 规范化后 (a) 完全一致，或 (b) 一方为另一方子串且**双方规范化长度均 ≥ 6**（防短句误杀）→ 判重丢弃；批内（同一次生成）同样适用。
3. **范围含回收站**：生成查重的比对集合去掉 `deleted_at` 过滤（三区 + 回收站），避免丢弃的格言过几天又被生成回来。手动新增/批量导入查重仍只查未删除区（用户明确重录应允许）。
- **配套 IPC**：新增 `mottos:checkDuplicate(content)`（未删除范围内按 §7.4.2 判重，供手动新增/批量导入复用）；批量导入查重从渲染层空白归一升级为调用此接口。
