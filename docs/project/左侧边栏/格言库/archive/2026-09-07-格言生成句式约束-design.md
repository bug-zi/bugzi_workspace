# 格言生成句式约束（优化建议区第 23 轮）

- **日期**：2026-09-07
- **状态**：已实施并归档（260907）——实施记录见 `docs/log/260907.md`，实施计划见 `docs/project/左侧边栏/格言库/archive/2026-09-07-格言生成句式约束.md`
- **来源**：优化建议区待完成——「格言区由AI生成的格言其实也需要加一些约束，比如说禁止使用"不是...而是"句型」
- **关联**：第 18/22 轮（灵感泉 prompt 规范 v1/v2）的同类工作，本轮轮到格言库

## 背景与问题

`generateMottos()`（electron/ai/services.ts）当前 prompt 对句式**零约束**：画像摘要 + 正式区 50 条风格样本 + 去重清单 + 「5 摘录 + 5 编撰」指令。temperature 0.9 下，模型编撰条大量产出「不是...而是」式对仗套话——这是 AI 写中文格言最泛滥的句式家族，同类还有一大家子。单点禁令容易被模型「绕开句式、保留腔调」，故一轮到位建完整禁用清单。

## 三项已确认决策

1. **完整禁用清单**：prompt 明确列出 7 类禁用句式 + 代码侧正则兜底校验（经探讨确认，不做单点禁令）。
2. **只约束编撰条（composed）**：摘录条（excerpt）是现实真实名言，句式客观存在（如罗丹「生活中不是缺少美，而是缺少发现的美」），prompt 与正则均豁免——避免 AI 为避句式跳过/篡改真名言，也避免正则误杀。
3. **命中直接剔除、不补足**：与现有查重跳过逻辑（入库循环 `continue`）完全同构，`inserted < generated` 为代码天然支持状态，不为小概率不足额增加复杂度（不做备选补生成、不做二次调用）。

## 禁用句式清单（7 类）

| # | 句式家族 | AI 典型输出示例 |
|---|---|---|
| 1 | 不是/并非 A，而是 B | 「成长不是妥协，而是懂得取舍」 |
| 2 | 与其（说）A，不如（说）B | 「与其追逐风口，不如深耕自己」 |
| 3 | 真正的 A，（从来）是/不是/都是 B | 「真正的强大，从来不是无视眼泪」 |
| 4 | 所谓 A，不过是/只是 B | 「所谓成熟，不过是把哭声调成静音」 |
| 5 | A，才算/才配 B；唯有 A，才 B（排他强调） | 「熬过去，才算是一个人的成人礼」 |
| 6 | 所有/一切 A，都 B（全称断言） | 「所有的惊喜，都在路上」 |
| 7 | 愿你 A（祝福腔） | 「愿你走出半生，归来仍是少年」 |

## 实施方案

### 1. prompt 层约束（electron/ai/services.ts · generateMottos）

在生成指令「恰好 5 条由你自行编撰（kind 为 "composed"，source 标「debugzi」）」之后追加一段：

```
你自行编撰的 5 条（kind 为 "composed"）额外遵守句式禁令——以下 7 类对仗套话一律禁止：
1. 「不是A，而是B」「并非A，而是B」
2. 「与其A，不如B」「与其说A，不如说B」
3. 「真正的A，是/从来不是B」
4. 「所谓A，不过是B」
5. 「……，才算……」「唯有A，才B」类排他强调
6. 「所有/一切A，都B」全称断言
7. 「愿你……」祝福腔
编撰条请像正式区样本那样平实、具体、有画面，靠内容本身立住，不要靠句式端着。
摘录条（kind 为 "excerpt"）不受此限，如实引用原文。
```

正面要求（「平实、具体、有画面」）与禁令同段给出，防止模型绕开字面句式、保留腔调。

### 2. 代码侧正则兜底（同文件）

新增常量与辅助函数（放在格言生成区）：

```ts
/** 编撰条禁用句式（优化建议区第23轮）：与 prompt 禁令一一对应，仅校验 composed 条 */
const COMPOSED_BANNED_PATTERNS: RegExp[] = [
  /(?:不是|并非)[^，,。；;！？\n]{1,24}[，,][^，,。；;！？\n]{0,16}而是/, // 1 不是/并非A，而是B
  /与其说?[^，,。；;！？\n]{0,24}[，,][^，,。；;！？\n]{0,12}不如说?/,   // 2 与其A，不如B
  /真正的[^，,。；;！？\n]{1,16}[，,][^。；;！？\n]{0,10}(?:从来)?(?:不是|是|都是)/, // 3
  /所谓[^，,。；;！？\n]{1,16}[，,](?:不过是|只是)/,                        // 4 所谓A，不过是B
  /[，,](?:才算|才配)/,                                                    // 5a ……，才算/才配
  /唯有[^，,。；;！？\n]{1,16}[，,]才/,                                     // 5b 唯有A，才B
  /(?:所有|一切)[^，,。；;！？\n]{1,20}[，,]都/,                            // 6 全称断言
  /愿你/                                                                   // 7 愿你祝福腔（误伤率极低，从宽抓）
]
```

正则为草案，实施时按实际语料打磨容差；「愿你」几乎必为祝福腔，从宽抓。

入库循环（现 services.ts `for (const it of items)` 处）在查重跳过旁并列加一道：

```ts
const kind = mottoKind(it.kind, it.source)
if (kind === 'composed' && COMPOSED_BANNED_PATTERNS.some((p) => p.test(it.content))) {
  patternRejected++
  continue
}
```

先判 kind 再校验句式——摘录条天然豁免。

### 3. 计数透明

`GenerateMottosResult` 新增 `patternRejected: number` 字段；MottosModule 生成完成 toast 在 `patternRejected > 0` 时附加「N 条因句式违规未入库」，让开发者知道兜底在工作。

### 4. 明确不做的事

- 摘录条不管；剔除后不补足（已确认）
- 不做两阶段自评/管线（一句话场景用不上灵感泉那套重炮）
- 清单写死为代码常量，不做用户可配置（正则不给用户配）
- 存量库不清洗（已入库的编撰条不动，开发者可自行编辑/删除）
