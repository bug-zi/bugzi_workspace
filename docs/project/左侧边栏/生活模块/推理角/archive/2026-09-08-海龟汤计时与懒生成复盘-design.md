# 设计：海龟汤计时净用时 + 复盘报告懒生成

> **状态：设计中（260908 会话内批准，待实施）**

- **日期**：2026-09-08（260908）
- **来源**：`docs/project/优化建议区.md` 待完成区两条——①「海龟汤的计时功能要优化一下」；②「海龟汤放弃汤的时候要直接显示汤底，用户点击查看报告的时候再去生成报告」
- **流程**：brainstorming——开发者逐项确认（计时痛点=挂机不计时 → 懒生成范围=破汤弃汤统一 → 计时方案=主进程记账 + 报告方案=查看时 ensure），260908 会话内批准
- **规模**：DB v18 两列加列（`turtle_games`）+ `finishTurtleGame` 拆分 + 1 个新 IPC（`turtle:report`）+ 2 个轻 IPC（`turtle:timerStart/timerPause`）+ TurtlePanel 计时器重写与 `openReport` 单点改造 + App.tsx 补派活事件；无新表、无新 UI 组件、无设置项

## 背景与痛点

**计时（现状）**：对局头部「问 N · 用时 m:ss」由渲染层每秒 `Date.now() - started_at` 计算，终局把墙钟时长落 `duration_ms`。两个虚高来源：

1. **App 内挂机照走**：切到其他模块（keep-alive 不卸载）、最小化/遮挡窗口，计时不停；
2. **离线时段照算**：中途关 App 重开续局，`started_at` 不变，离线间隙全计入——跨天恢复对局用时爆炸。

**报告（现状）**：弃汤点「放弃并看汤底」→ `finishTurtleGame` **先同步等 LLM 生成局终点评**（几秒到十几秒）→ 写复盘 md → 才返回汤底上屏。「看汤底」被「点评生成」阻塞。破汤链路同构（判汤 1 趟 LLM 后，又等点评 1 趟才见汤底）。

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 计时口径 | **净用时**：挂机（切模块/最小化/被完全遮挡/关 App）不计时，回来自动继续；统计「净思考用时」 |
| 计时架构 | **主进程记账**：`active_ms` 累计 + 当前段起点在 DB，渲染层只发 start/pause 边界事件；终局自动结算、退出兜底结算、崩溃残留段下次开局丢弃自愈 |
| 失焦口径 | 窗口**失焦但可见仍计时**（玩家可能正盯着汤面思考/用草稿本记线索）；只有「看不见对局」才停 |
| 存量数据 | 旧记录 `duration_ms` 不追溯（维持原墙钟口径）；存量 playing 局 `active_ms` 从 0 起算，历史墙钟不并入 |
| 懒生成范围 | **破汤弃汤统一**：终局即刻显示汤底，复盘 md 都改为点「查看复盘」时生成 |
| 懒生成语义 | **ensure**：`md_path` 已存在直接返回（旧记录零变化），无则现场生成；失败不落半截数据、可重试 |
| 否决方案 | ①渲染层累计随交互上报（Electron 退出无可靠上报时机，末段必丢）；②终局先写无点评 md 查看时回写补点评（md 弹窗可编辑，回写有覆盖用户改动风险）；③终局后台预生成点评（每次弃汤都烧 LLM，违背「点了才生成」诉求） |

## 一、计时：主进程记账（净用时）

### 活跃判定（渲染层）

`active = 推理角模块激活 && document.visibilityState === 'visible' && 对局 status === 'playing'`

- **start 边界**（false→true）：进入对局视图（`openSoup` 成功）、切回推理角（`MODULE_ACTIVATED_EVENT`）、窗口恢复可见（`visibilitychange`→visible）；
- **pause 边界**（true→false）：返回汤库（`backToLibrary`）、切走模块、窗口最小化/被完全遮挡（Chromium 在 Windows 含原生遮挡检测）、App 退出（主进程兜底）。

**App.tsx 补失活事件**：现只有 `MODULE_ACTIVATED_EVENT`；新增 `MODULE_DEACTIVATED_EVENT`，`activateModule` 用 moduleRef 捕获**旧**模块 id 一并派发（ref 方案防 React strict-mode 双触发；不放 setState updater 里做副作用）。TurtlePanel 全模块常驻挂载（App 启动即 mount、初始非激活），本地 `moduleActive` 初值 false，由激活/失活事件对维护。

**用时显示**：渲染层本地段模型——`baseActiveMs`（种子来自 payload 新增 `activeMs`）+ 当前活跃段增量（活跃起点 `Date.now()` 起），每秒跳动；失活时把段增量并入 base。终局回看直接取 `durationMs`（现状逻辑不变）。显示与主进程记账允许亚秒级 IPC 延迟漂移，展示无碍、真相以主进程结算为准。

### 主进程记账（ipc.ts）

- **DB v18**（`electron/db/db.ts`，v17 已被文笔坊占用）：`ALTER TABLE turtle_games ADD COLUMN active_ms INTEGER NOT NULL DEFAULT 0` + `ADD COLUMN segment_start_at TEXT`（NULL=暂停中）。
- **`turtle:timerStart(gameId)`**：局须为 playing；`segment_start_at` 已非空 → no-op（幂等，防重复 start 造成段起点回拨）；为空 → 置 now。
- **`turtle:timerPause(gameId)`**：`segment_start_at` 非空 → `active_ms += now - segment_start_at`，置 NULL；为空 → no-op。
- **`turtle:openSoup` 恢复对局路径**：无条件清空 `segment_start_at`——同 run 内恢复前必有 pause 已结算（清空幂等无害）；跨 run 恢复即**崩溃自愈**（异常退出残留的开段直接丢弃，不把离线时间计入）。
- **`finishTurtleGame`**：终局先按 pause 语义结算开段，`duration_ms = active_ms`。
- **`settleTurtleTimers()`**（ipc.ts 导出）：所有 playing 且开段的局批量结算；`electron/main.ts` 挂 `app.on('before-quit')` 正常退出兜底。崩溃（无 before-quit）丢当前段，自愈机制兜底，不做补偿。

边界说明：同 run 内存在多局 playing 的可能（开 A 返回再开 B）——计时按 gameId 独立记账，渲染层只为**当前对局视图**发边界事件，A 在返回汤库时已 pause。

## 二、报告懒生成：终局秒回 + 查看时 ensure

### 主进程

- **`finishTurtleGame` 拆分**：删除 `soupReview` 调用与 md 写盘，只落——notice 消息（弃汤链路）、结算计时、`UPDATE turtle_games SET status/ended_at/duration_ms`（`md_path` 保持 NULL）、`UPDATE turtle_soups SET status`。**秒回**。`services.ts` 的 `soupReview` 函数本身不动（调用方换人）。
- **新 IPC `turtle:report(jobId, gameId)`**（ensure 语义，接 `beginJob/endJob` 可取消）：
  1. 局不存在/已删 → NOT_FOUND；status=playing → 抛 PLAYING；
  2. `md_path` 已存在 → 直接返回路径（旧记录零变化、秒开）；
  3. 读汤 + 问答全程（拼 transcript 的 `fmtMsg` 逻辑从 `finishTurtleGame` 提出共用）→ `soupReview(...)`（带 signal；LLM 未配置/失败 → 抛错，`md_path` 仍 NULL，**可重试**）；
  4. 拼 md（模板照旧：题头 + 净用时 + 汤面 + 汤底 + 问答全程 + 最终推理 + AI 点评）→ `mdWrite` → `UPDATE md_path` → 返回路径。
  - 渲染层单飞（按钮 busy）防并发双击；主进程不另加锁。

### 渲染层（TurtlePanel）

- **`openRecord` → `openReport(gameId, title, subtitle, knownPath?)` 单点改造**，三个入口统一走它：
  1. 对局内 revealed 区「查看复盘」按钮（`revealed.mdPath`，可为 null）；
  2. 库视图「对局记录」列表行（`r.md_path`，未看过的是 null）；
  3. 终局汤回看（`openSoup` payload 的 `mdPath`，同入口①）。
- `knownPath` 非空 → 直接开 MdDialog；为空 → 按钮/行点击进入 `reportBusy` 态（「复盘生成中…」转圈 + 取消键，沿用 ask 的 jobId + `ai.cancel` 模式），成功开弹窗，失败走 `handleErr`（LLM 未配置弹去配置，其余 toast/failMsg），按钮复原可重试。
- **汤底即刻显示**：破汤（guess 判定 solved 后）与弃汤（abandon 秒回后）`setRevealed(bottom)` 直接上屏，不再等任何 LLM。
- **文案**：放弃确认弹窗正文改「放弃后本局记为『弃汤』并**立即揭示汤底**；复盘报告（含 AI 卡点点评）点『查看复盘』时生成。该汤不可再玩。」；记录列表行 `md_path` 为空时 `row-sub` 追加「· 复盘待生成」小字。

## 三、数据与类型

- **preload.ts**：`turtle` 命名空间新增 `timerStart(gameId)` / `timerPause(gameId)` / `report(jobId, gameId): Promise<string>`。
- **api.d.ts**：`TurtleGamePayload` 增 `activeMs?: number`（playing 态渲染层计时种子）；终局分支 `mdPath` 类型改 `string | null`；`TurtleGameRecordRow.md_path` 改可空（列表「复盘待生成」标记依据）。
- **回收站**：`hardDelete` reasoning_game 分支对 `md_path` 判空跳过删文件（实现时核实现有判空）。

## 四、验证

`npm run typecheck` + 冒烟清单：

1. 重启 dev 触发 v18 迁移（两列出现、存量数据无损）；
2. 开局计时跳动；切模块/最小化暂停、切回/恢复续跳；失焦但可见仍走；
3. 对局中途关 App 重开续局——离线时段不计入，用时从暂停值续跳；
4. 弃汤秒出汤底（无 LLM 等待）；「查看复盘」生成报告（转圈可取消、失败可重试、成功开弹窗）；
5. 破汤同链路（判定返回即见汤底与 verdict，不再二次等待）；
6. 记录列表：未看过的局显「复盘待生成」，点行生成并打开；旧记录（已有 md）直接秒开；已生成的再开秒开；
7. 复盘 md 内「用时」为净用时；旧 md 不变。
