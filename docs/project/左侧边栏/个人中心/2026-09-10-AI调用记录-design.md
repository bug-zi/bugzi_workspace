# AI 使用 · 调用记录（最近 30 条）设计记录（2026-09-10）

## 背景

个人档「AI 使用」zone 现仅展示聚合统计（数字卡 + 按场景聚合表，时间范围今日/本月/全部）。
260910 落地的 LLM 记账已在主进程咽喉点把每次调用明细全量写入 `llm_usage` 表（DB v27），
但明细无任何 UI 出口。开发者要求：每次调用情况在 AI 使用模块可见，展示最近 30 条，可展开/收起。

## 需求澄清结论（已确认）

1. **保留策略**：数据库不动（继续只增不删，聚合统计不受影响），仅 UI 查询展示最近 30 条明细。
2. **折叠粒度**：区块级——「调用记录」子区块整体收起/展开，默认收起，不做行级二级展开。
3. **范围联动**：固定最近 30 条，不随顶部今日/本月/全部切换变化。

## 决策（方案 A，已确认）

「调用记录」作为子区块嵌在现有「AI 使用」zone 内部（统计表格下方），非独立 zone
（备选 B 独立 zone 否决：语义上就是 AI 使用的一部分，拆开零碎且多一套 zone-header）。

### 1. 数据层与 IPC

- **数据库零改动**：`llm_usage` 表已含全部字段，无迁移、无清理任务。
- **新增 IPC** `llmUsage:records`（`electron/ipc.ts`，紧挨现有 `llmUsage:stats`）：
  `SELECT id, created_at, scene, config_name, model, ok, duration_ms, prompt_tokens, completion_tokens, tokens_estimated, error_brief FROM llm_usage ORDER BY id DESC LIMIT 30`，
  snake_case → camelCase 映射，`ok` / `tokens_estimated` 转 boolean。
- **类型**：`src/shared/types.ts` 新增 `LlmUsageRecord`：
  `id / createdAt / scene / configName / model / ok / durationMs / promptTokens / completionTokens / tokensEstimated / errorBrief`。
- **preload**：`llmUsage` 命名空间下新增 `records(): Promise<LlmUsageRecord[]>`。

### 2. UI 与交互（ProfileModule）

- **折叠**：标题行常驻（`expand_more` / `expand_less` 图标 + 「调用记录」+ N 条徽标），
  点击整行切换；`useState(true)` 默认收起、内存态不持久化（同画像 zone 折叠范式）。
- **表格 6 列**：`时间 | 场景 | 模型 | 结果 | 耗时 | token`
  - 时间：今天 `HH:mm:ss`，更早 `MM-dd HH:mm`（滚动 30 条可能跨天）。
  - 场景：复用 `LLM_SCENE_LABELS`，未收录显示原串。
  - 模型：显示 model 名，超长 CSS 截断；hover title 显示「配置名 · 模型」
    （260910 混用/溢出路由落地后可看出每次调用走了哪个池子）。
  - 结果：「成功」灰细字 / 「失败」danger 色。
  - 耗时：同聚合表（`ms` / `s` 一位小数）。
  - token：`prompt + completion` 合计（万位缩写同 `fmtTokens`），估算行带 `≈`；
    hover title 显示分项「输入 X / 输出 Y」。
- **失败行错误摘要**：失败记录在主行下方渲染整行（colSpan 6）红系小字 `errorBrief`。
- **空态**：展开后 empty-state「还没有 AI 调用记录」（收起时徽标显示 0）。

### 3. 刷新机制

- 进模块首载一次；
- AI 空闲回调（现有 `onActivity` items 为空）时连同 stats 一起重拉；
- zone 头手动刷新按钮两者都刷；
- **usageRange 切换只刷 stats**（记录与范围无关）。

### 4. 样式（App.css）

新增 `.llm-usage-records`（子区块容器 + 与统计表的分隔）、`.llm-usage-records-toggle`
（标题行按钮：无边框、hover 微背景）、`.llm-usage-records-table`（复用 `.llm-usage-table`
基础 + 时间/模型列 ellipsis）、`.llm-usage-record-error`（错误摘要行）。
遵守全局规则：主题相近色系、material symbols 图标、禁止 emoji。

## 改动范围

`electron/ipc.ts`（+1 handler 约 25 行）、`electron/preload.ts`（+1 方法）、
`src/shared/types.ts`（+1 interface）、`src/modules/profile/ProfileModule.tsx`
（records state + 加载 + 子区块渲染，约 70 行）、`src/App.css`（约 30 行）。
无 DB / 主进程服务改动。

  记录渲染、失败行错误摘要、折叠/徽标、切时间范围记录不动。

## 修订（2026-09-10 同日，开发者反馈）

**原方案落地后开发者修订**：折叠子区块改为**显示模式切换**——两类记录不好同时呈现，
zone 头加「按类别 / 按时间」chip 组，两视图互斥切换：

- **按类别**（默认）：原有场景聚合视图（数字卡 + 今日/本月/全部范围 chip + 聚合表），行为不变。
- **按时间**：最近 30 条调用明细直出（六列表格 + 失败错误行 + 空态，复用原明细实现）；
  与时间范围无关 → 该视图下隐藏范围 chip；数字卡为范围口径与明细无关 → 一并隐藏。
  刷新按钮两视图常驻（同时刷统计与记录）。
- 原折叠子区块（`.llm-usage-records` 容器 + toggle 标题行 + `recordsCollapsed` state）删除，
  相关 CSS 一并清理；`usageView: 'scene' | 'time'` 内存态不持久化，默认 `'scene'`。
- 数据层/IPC/preload（`llmUsage:records`、`LlmUsageRecord`）零改动。

**排障补记（同日）**：冒烟见「还没有AI调用记录」空态，取证确认库内有数据、构建产物含 handler——
系运行中 dev 实例主进程/preload 旧代码导致 invoke 失败，被静默 catch 伪装成空态。修复：
`recordsError` state 失败可见化（错误空态含具体信息，与「无记录」区分）+ 切到按时间视图自动重拉自愈。
