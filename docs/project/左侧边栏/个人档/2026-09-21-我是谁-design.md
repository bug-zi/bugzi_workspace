# 个人档·我是谁 设计记录

> 创建于 2026-09-21 01:16
> 来源：`docs/project/新功能开发区.md` 待完成区任务（开发者 260921 提出，当日 brainstorm 商定）。
> 定位：个人档「我的画像」之下新增「我是谁」功能模块——AI 基于项目数据形成对用户的了解，每天启动后台生成 3-4 个问题供用户选择性回答，回答经自动提炼、逐条确认后沉淀进画像（profile_facts）。本文件为实施设计记录。

## 一、需求结论（brainstorm 摘要）

| 维度 | 结论 |
|---|---|
| 生成时机 | **启动后台生成**，作为每日任务（同万象待学习区 ensureDailyLearn 模式）；settings 日期幂等，一天只生成一批 |
| 总导览呈现 | **紧凑状态行 + 直达**——只显一行状态（如「我是谁 · 今日 4 问 · 已答 2」），点击深链个人档「我是谁」区作答；不堆交互 |
| 数据源 | **广谱跨模块聚合**——画像全文 + 致知己 + 格言 + 万象 + 学习库 + 灵感泉 + 推理角/记账/阅读/信息源轻量信号，各源限条数控 token；每日仅一次出题调用 |
| 入档方式 | **自动提炼 + 逐条确认**——提交回答后自动一次 LLM 提炼候选画像条目，用户逐条「加入画像 / 忽略」（同边栏 PROFILE_SUGGEST 确认范式），防 AI 提炼跑偏污染画像 |
| 跨天处理 | **未答作废、待确认保留**——次日生成新一批后旧未答不再显示；已答但候选未处理完的保留到处理完；全历史留库供防重复 |
| 实现载体 | **方案 A**——新表 `whoami_questions`（DB v47）+ 独立服务 `whoami.ts`；否决 settings JSON（结构化状态难管）与右栏频道制（跳过/统计/候选确认在聊天流里别扭） |

## 二、数据（DB v47）

```sql
CREATE TABLE whoami_questions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  date TEXT NOT NULL,           -- 批次日期 YYYY-MM-DD（本地）
  question TEXT NOT NULL,
  answer TEXT,                  -- NULL = 未答
  skipped INTEGER DEFAULT 0,    -- 当天主动跳过
  answered_at TEXT,
  suggestions TEXT,             -- JSON [{category, content}] 提炼的候选画像条目
  resolved INTEGER DEFAULT 0,   -- 候选已处理完（含提炼出零条的直接置 1）
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- 历史行**永不删**（表极小）：显示只取当日行，历史自然供「防重复提问」注入。
- 每日幂等标记：settings 键 `whoami_daily_date`（同 `WikiDailyLearnDate` 模式；LLM 未配置不记日期，当天配置好后下次触发仍可生成）。
- 提炼入档写既有 `profile_facts` 表（source='ai'），零画像侧改动。

## 三、服务与 IPC

新 `electron/services/whoami.ts`：

- `ensureWhoamiDaily()`：启动时调度（与 `ensureDailyLearn` 同一启动序列）。当日已有题即跳过；数量 = `3 + Math.floor(Math.random()*2)`（3 或 4）；**一次 LLM 调用出全部题目**，解析失败或零题不记日期、下次触发重试；LLM 未配置 warn 跳过不记日期。
- `aggregateWhoamiContext()`：广谱聚合（各源独立可空、限条数）——
  - 画像全文（80 字/条）
  - 致知己：沉淀区答案版本 + 十二问题题目与最近想法（合计 30）
  - 格言正式区（30，40 字）
  - 万象词条按板块聚合（50）
  - 学习库最近已学节点（30）
  - 灵感泉手写灵感（30）
  - 推理角：近 30 天每日一题完成计数（一句话）
  - 记账：本月支出 top3 分类（一句话）
  - 书架：在读书名（5）
  - 信息源：订阅源名单（求知信号）
  - 近期已问问题（40，prompt 明令不重问）
  - 画像类别清单（prompt 指令：**优先问画像未覆盖的空白**，深化而非重复）
- 出题：chatCompletion JSON 模式返回 N 个问题（同 parseJsonArray 范式，兼容对象包裹）。
- 提炼：提交回答后一次调用，「问题 + 回答 + 现有画像类别」→ 0~2 条候选 `{category, content}`（类别限 PROFILE_CATEGORIES 十类）存 suggestions。
- 跨天清理语义：不删行——查询恒以 `date = 今日` 过滤即天然作废旧未答；已答未 resolved 的旧行在「待确认」查询口径中保留展示（处理完消失）。

IPC 通道（沿用 `域:动作` 命名）：

| 通道 | 职责 |
|---|---|
| `whoami:get` | 当日题列表 + 状态（总导览与个人档共用，含已答未 resolved 的往日候选） |
| `whoami:generate` | 手动生成今日问题（兜底：启动时 LLM 未配置、之后配好了） |
| `whoami:answer` | 存回答（立即落库返回，回答不因提炼失败而丢） |
| `whoami:extract` | 对已答未提炼的行跑提炼（`whoami:answer` 落库后前端紧接着调用；提炼失败后「重试」也走此通道） |
| `whoami:resolve` | 单条候选「加入画像」（INSERT profile_facts source='ai'）/「忽略」；全部处理完置 resolved=1 |

preload 暴露 `window.api.whoami.*`，`api.d.ts` 同步类型。

## 四、渲染层

**ProfileModule 新增「我是谁」zone**（置于「我的画像」zone 正下方；可折叠，徽标 = 当日未答数）：

- 题目行三态：
  - **待答**：问题文本 + 输入框（Enter 提交）+「跳过」按钮；跳过后该题灰色收起
  - **已答·提炼中**：回答文本 + loading
  - **已答·候选待确认**：回答 + 候选条目列表（类别徽标 + 内容），每条「加入画像 / 忽略」；处理完收起为「已答 ✓」摘要行
- 提炼失败：该题下显示「重试」小按钮（不静默丢答案）。
- 今日无题时 zone 内显示「生成今日问题」按钮。
- 回答提交即定稿不可改（要改去画像区改对应条目）；总导览深链进入时自动展开本区。

**总导览紧凑状态行**（置于每日挑战卡之后）：

- 一行式「我是谁 · 今日 N 问 · 已答 M」，有未答时主题色提示，另有往日候选未确认时附「X 条候选待确认」；点击经 `MODULE_NAVIGATE_EVENT` 深链 profile 模块并展开我是谁区（profile 新增深链参数）。
- 当日无题整行不显示（安静模式）；纯渲染逐块独立 catch 原则不变。

## 五、错误处理与边界

- LLM 未配置：全局规则——按钮不置灰，点击 toast 提示并「去配置」直达个人档；启动生成静默跳过不记日期。
- 生成失败：启动静默 warn；手动按钮 toast 错误信息。
- 与边栏 PROFILE_SUGGEST / PROFILE_LOOKUP 协议互不干扰；除复用 profile_facts 写入外不碰画像既有链路。
- 画像条目后续手动删改不受影响（我是谁不追踪条目回删）；删除 profile_facts 不联动 whoami 行。
- 跨午夜：不加实时翻日监听，下次进模块/次日启动自然切新批次（同现有各模块口径）。
