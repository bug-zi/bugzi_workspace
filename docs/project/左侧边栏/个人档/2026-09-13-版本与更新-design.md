# 设计：个人档「版本与更新」——应用内检测与一键更新

> 创建于 2026-09-13 00:01
> 来源：开发者咨询「exe 安装包想同步更新，像有些应用可以直接在应用里更新」——260912 会话对齐：路线 A（electron-updater 完整自动更新）、托管 GitHub Releases、自动化程度选「启动静默检查 + 手动下载」。

## 背景与决策记录

项目用 electron-builder NSIS 打包（`npm run dist`），此前无 publish 配置、无更新通道。GitHub 仓库 `bug-zi/bugzi_workspace` 已确认**公开**（Releases 匿名可读，零 token）。经澄清确认的决策：

| 决策点 | 结论 |
| --- | --- |
| 方案路线 | **A. electron-updater 完整自动更新**（B 轻量「检测+跳浏览器下载」否决——GitHub 为一等公民后 A 成本与 B 持平、体验更好） |
| 托管点 | **GitHub Releases**（公开仓库；国内访问波动由超时/重试/静默策略消化，见错误处理） |
| 自动化程度 | **启动静默检查 + 手动下载**——启动后台查一次仅提示；下载、安装均手动点按钮触发 |
| 下载取消 | **不做**（electron-updater 无干净取消 API）；失败回 available 态可无限重试 |
| 安装方式 | 下载完成后显式「重启并安装」按钮 → `quitAndInstall(true, true)` 静默安装 + 自动重启；不做退出时自动装（托盘关闭行为下易意外） |
| 开发模式 | `!app.isPackaged` 时检查返回 `disabled`，按钮点击 toast「开发模式下不可用」 |
| 用户数据 | 更新只覆盖程序目录，userData（DB/md/图）不受影响——NSIS 覆盖安装 + 数据目录分离，天然安全 |

## 设计

### 1. 打包配置（electron-builder.yml）

```yaml
publish:
  provider: github
  owner: bug-zi
  repo: bugzi_workspace
```

- 打包产物自动多出 `latest.yml`（版本清单：版本号/文件名/sha512）与 `.blockmap`（差量索引）；NSIS 原生支持**差量更新**——小版本升级只下载变化块。
- 打包态 App 内自动携带 `app-update.yml`（electron-builder 由 publish 配置生成），electron-updater 零显式 setFeedURL。
- 新增运行时依赖 `electron-updater`（dependencies；`.npmrc` legacy-peer-deps + 国内镜像直接装）。

### 2. 主进程 `electron/services/updater.ts`

状态机（全内存，不落 settings/DB）：

```
idle → checking → available {version, releaseDate} → downloading {percent} → downloaded
                 ↘ (已是最新/失败 → 回 idle，结果经返回值/toast 传达)
disabled 为 dev 模式特态
```

- **initUpdater(getWin)**：`autoDownload: false`、`autoInstallOnAppQuit: false`（一切显式控制）、`requestTimeout: 15s`（api.github.com 国内波动）；订阅 electron-updater 事件驱动状态机，任何变化 `webContents.send('app:updateEvent', snapshot)` 实时推送。
- **启动静默检查**：打包态下启动后延迟 ~5s 查一次；`available` → 推送状态 + 渲染层 toast「发现新版本 vX.Y.Z」（当次会话一次）；任何失败完全静默。
- **手动检查**：`await checkForUpdates()` 直接返回终态结果 `{ status: 'up-to-date' | 'available' | 'error' | 'disabled', version?, releaseDate? }`，渲染层据此 toast/切态。
- **下载**：`downloadUpdate()` → downloading 态，`download-progress` 事件推 `percent`；`update-downloaded` → downloaded。失败回 available 态并推送，可重试。
- **安装**：`quitAndInstall(true, true)`（静默 + 装完自动重启）。**托盘兼容（260913 计划期勘误）**：原拟导出 `isInstallingUpdate()` 标志放行关闭拦截；核实 main.ts 后无需新增——quitAndInstall 内部走 `app.quit()` → `before-quit`（已置 `quitting = true`）→ close 拦截判 `!quitting` 天然放行，托盘模式零改动兼容。
- 模块对外仅暴露 `initUpdater / checkForUpdates / downloadUpdate / installUpdate / getState / isInstallingUpdate`，IPC 层只做通道转发。

### 3. IPC（ipc.ts + preload.ts + api.d.ts 三处同步；挂在 `app:` 家族，同 `app:setLaunchOnBoot` 风格）

| 通道 | 入参 | 返回 | 行为 |
| --- | --- | --- | --- |
| `app:updateState` | — | `{ currentVersion, state }` | 状态快照（卡片挂载时同步；state 含 disabled） |
| `app:updateCheck` | — | 手动检查结果对象（见上） | 手动检查，await 终态 |
| `app:updateDownload` | — | `true` | 开始下载（进度走事件推送） |
| `app:updateInstall` | — | `true` | quitAndInstall(true, true)，此后进程退出 |
| `app:updateEvent`（推送） | — | `{ currentVersion, state }` | 状态机任何变化实时推送 |

`window.api.updater = { getState, check, download, install, onUpdateEvent(listener) }`。

### 4. 渲染层（ProfileModule 设置区末尾、关闭行为之后新增「版本」小节）

| 状态 | UI |
| --- | --- |
| idle | 当前版本号（如 `v1.0.0`）+「检查更新」按钮 |
| checking | 按钮 loading「检查中…」 |
| up-to-date | toast「已是最新版本」→ 回 idle |
| available | 「发现新版本 vX.Y.Z（YYYY-MM-DD）」+「下载更新」按钮 |
| downloading | 进度条 + 百分比 |
| downloaded | 「重启并安装」主题色强调按钮 |
| disabled（dev） | 版本号正常显示；点检查 toast「开发模式下不可用」 |

- 小节挂载时 `app:updateState` 同步快照，之后以 `onUpdateEvent` 为准（单一数据源，避免多事件源竞态）。
- 启动静默检查推来的 available 状态直接让小节进入 available 态；toast 一次性由主进程「启动检查」标记控制推送侧只推一次提示事件，渲染层收到即 toast「发现新版本 vX.Y.Z」。
- 样式沿用个人档既有分区/按钮/进度条语言，主题色系，无新组件文件（状态行 + 按钮在 ProfileModule 内即可，若代码超 ~80 行则抽 `UpdateCard.tsx` 到 `src/modules/profile/`）。

### 5. 发版流程（开发者每次手动执行，AI 至多给命令）

1. `package.json` 改 `version`（如 `1.0.1`）
2. `npm run dist`
3. `gh release create v1.0.1 release/*.exe release/*.blockmap release/latest.yml --title "..." --notes "..."` 发布

### 6. 错误处理与安全

- sha512 校验 electron-updater 内置（latest.yml），包损坏/篡改自动拒装。
- 检查失败：静默检查完全静默；手动检查 toast「检查失败，请稍后再试」（15s 超时同文案）；匿名 API 限流 60 次/时远够个人使用，超限同文案。
- 下载失败/中断：回 available 态推送 + toast，可重试（差量断点由 blockmap 支撑）。
- 检查/下载任何异常绝不影响 App 其他功能（模块内 try/catch 隔离，状态机兜底回 idle/available）。

## 零改动区

DB（零表变更、零版本号递增）、settings（零新键，状态全内存）、托盘既有逻辑（勘误后连放行判断都不需要，完全零改动）、bzres、白噪音、其余全部模块；`npm run dev` 行为不变。

## 冒烟清单

1. dev 模式：个人档版本小节正常显示版本号，点「检查更新」toast「开发模式下不可用」。
2. 真实链路：发测试版 v1.0.1 到 Releases → 机器装回 v1.0.0 → 启动 ~5s 后静默检查出「发现新版本 v1.0.1」提示，小节进 available 态。
3. 点「下载更新」进度条推进到 100% → 出「重启并安装」→ 点击后静默安装、App 自动重启，个人档版本小节变 v1.0.1，用户数据完好。
4. 已是最新时手动检查 → toast「已是最新版本」。
5. 断网：静默检查无感知；手动检查 toast 失败文案；关闭行为=最小化到托盘时执行更新重启不卡死。
6. `npm run typecheck` 双配置 + `build` + `dist` 通过。
