# 藏书架书签优化：章节名 label + 改名 + 备注

- **日期**：2026-09-10
- **状态**：设计定稿，待立项实施（落地后本文件移入 `archive/`）
- **来源**：优化建议区待完成条目「藏书架——新增的标签功能只能粗略显示书名……默认显示当前所在章节，可以手动改标签名，或者在标签中写一些备注」+ 本日 brainstorming 会话定稿
- **关联**：`2026-09-10-书架v2-design.md`（书签 v1 形态，其 §二 label 口径与「明确不做：书签备注/改名」被本轮推翻）、`archive/2026-09-08-书架优化-design.md`、designs-specs.md §8/§9

## 背景

书架 v2.0（260910）落地手动书签后开发者实际使用反馈：label「只能粗略显示书名」——现状 epub 按 `locate.href` 与目录 href **精确字符串匹配**取章节名，匹配失败（目录 href 带锚点/路径差异、当前文件未被目录直接引用）即兜底「约 X%」；且 label 生成后不可改、无备注。本轮三件事：默认 label 改为可靠解析的**当前章节名 + 位置**；支持**手动改名**；支持**写备注**。

## 关键决策记录（会话中逐项确认）

| # | 决策点 | 结论 | 被否掉的选项 |
|---|---|---|---|
| 1 | 加书签动线 | **秒加不动**（一键入库 + toast），改名/备注去侧栏书签页签后编辑 | 加完立即弹编辑框（每次多一步）；秒加 + 自动开书签页签（侧栏被动打开） |
| 2 | 默认 label 口径 | **章节名 + 位置后缀**：epub `章节名 · 42%`（无章节 `约 42%`）、pdf `章节名 · 第 56 页`（无章节 `第 56 页`）——同章节多书签可区分 | 纯章节名（同章节多书签重名，只能靠时间/备注区分） |
| 3 | 编辑交互形态 | **侧栏书签行内展开编辑**（hover 铅笔 → 行内 label 输入 + 备注 textarea + 保存/取消） | 小弹窗表单（为改一个书签名起全局弹窗略重、盖住阅读区） |
| 4 | 存量书签 | **不迁移**：label 想精修手动改，note 天然空串 | 批量重算存量 label（收益小、解析受当时位置信息限制） |

## 一、章节解析修复（默认 label 的根基）

pdf 现状 `tocAnchorAt`（DFS 序最后一个 page ≤ 当前的目录锚点）本就是区间语义，**不动**；epub 对齐该思路：

- **`ReaderTocItem` 增可选 `spineIndex?: number`**（epub 专属）：EpubReader 目录上报时（`Promise.all(navigation, spine)` 都就绪后），每个目录项 href 去锚点（`#` 前部分）经 `book.spine.get()` 解析 spine 序号；解析失败的项该字段缺省（区间判定自然跳过）。深度剪枝等既有逻辑不变。
- **`ReaderLocate` 增可选 `spineIndex?: number`**：EpubReader `relocated` 已取 `loc.start.index`（现只进 `spineIdxRef`），随 `onLocate({ href, spineIndex })` 一并上报。
- **模块层新 `epubChapterAt(flat, spineIndex)`**：DFS 拍平后最后一个 `spineIndex ≤ 当前` 的目录项 → 章节名；与 `tocAnchorAt` 同构。spineIndex 缺省（加载竞态）→ 视为解析不到，走位置兜底。
- 侧栏目录高亮（activeLabel）逻辑**不动**（现状能用，不扩范围）。

## 二、label 生成（addBookmark 改写）

- epub：章节名取 `epubChapterAt(flattenToc(toc), locate?.spineIndex)`；百分比取 `getCurrent().percent`（入库时刻口径）。→ `章节名 · N%` / `约 N%`。
- pdf：章节名取 `tocAnchorAt(toc, page)`（现状逻辑）；页码同现状。→ `章节名 · 第 N 页` / `第 N 页`。
- 同位置去重、toast 文案、入库/跳转/删除流程全部不变。

## 三、DB v30 与 IPC（版本号若被并行会话占用则顺延，v18/v19/v28 先例）

```sql
ALTER TABLE book_marks ADD COLUMN note TEXT NOT NULL DEFAULT '';  -- 备注；空串 = 无备注
```

- 类型：`BookMark` 加 `note: string`（shared/types.ts + api.d.ts 两处惯例）。
- 新 IPC：`books:markUpdate(markId, m: { label?: string; note?: string }) => Promise<BookMark>`——部分更新只传要改的字段（`setReadingPref` 惯例），UPDATE 后回读整行返回，渲染层直接 merge 进 marks；books.ts / ipc.ts / preload.ts / api.d.ts 四处同步。
- 既有 `markAdd` 入库时写 `note: ''`（或列默认值兜底，渲染层不显式传）。

## 四、侧栏书签页签：行内展开编辑（ReaderSidebar）

- **常态行**：label 主行 + 备注小字（非空时，复用笔记页签 `.bk-note-text` 样式层级）+ 底部「书签 · relTime」。行点击跳转不变。
- **编辑入口**：行 hover 出「编辑」铅笔按钮（`edit`，删除键左侧；草稿本/AI 会话 hover 惯例）。
- **编辑态**：该行原地展开——
  - label 单行输入（预填现值）+ 备注 textarea（预填，placeholder「写点备注…可留空」，约 2 行高）；
  - 保存 / 取消按钮；label 框 Enter=保存、Esc=取消；**label trim 后为空则保存禁用**（不允许无名书签）；textarea 内 Enter 换行不误触；
  - 编辑态中点行不触发跳转（stopPropagation）；
  - 切走页签/收起侧栏时未保存草稿丢弃（备注价值低，不落半截数据，草稿本「编辑中切换自动落袋」不适用——那边是长文写作）。
- **保存**：经新 prop `onUpdateMark(id, { label, note })` 上行 → 模块层 `markUpdate` IPC → 本地 `setMarks` merge；失败 toast「保存失败」。侧栏自身只持编辑态（editingId + 草稿），不碰 IPC。
- 删除二次确认弹窗文案不变（引用 label 照旧）。

## 明确不做

加书签时弹编辑；存量 label 批量重算；目录高亮逻辑改动；书签并入笔记总览/导出；书签数量上限；书签跳页签高亮定位。

## 反馈修订（260910 冒烟后）：锚点级章节解析 + 百分比重算

冒烟反馈：数学女孩（套装全 4 册 epub）读在「第 3 章　ω 的华尔兹」，书签 label 却是「网络资料 · 100%」。systematic-debugging 定位双根因，均实证：

- **根因一（章节名）**：该书 spine 仅 5 个文件（一册一个大 html），NCX 195 个 navPoint 几乎全是同文件锚点（`text00001.html#nav_point_N`）。§一的 href 剥锚点解析使同文件条目共享 spineIndex，区间判定必取 DFS 序最后一个同文件条目——第 1 册的最后一条恰是「网络资料」（nav_point_139），覆盖一切更早的真章节。**修法**：锚点级解析——EpubReader 加载目录后留存拍平列表（flatTocRef），relocated 时 `chapterHrefAt()`：取同 spineIndex 的目录项，有锚点者用 `rendition.getRange(当前 CFI)` 的 Range 与锚点元素 `range.comparePoint(el, 0) ≤ 0` 判定「当前所在章」（最后一个早于当前位置的锚点）；命中则 locate.href 上报锚点 href，模块加书签按 href 精确命中；锚点/Range 不可解析依次回落同文件无锚点条目（册名）→ §一文件粒度区间 → 「约 N%」。侧栏目录高亮因 locate.href 升级为锚点 href 而对锚点书顺带生效（§明确不做中「目录高亮逻辑改动」未改高亮代码本身，属解析升级的免费副产品）。
- **根因二（百分比）**：该书 `locations.generate(800)` 跑完但产出零条目（total = -1）；此时 epub.js `locationFromCfi` 返回 -1、`percentageFromLocation(-1)` = -1/-1 = **1**，`l.start.percentage` 携带假 100% 被原实现的 `?? 0` 兜底采信（两本 epub 的 DB progress_percent 均 100% 同源；隔离实例插桩实证 `locLen:0, locTotal:-1, percent:1`）。**修法**：弃用 `l.start.percentage`；locations 有产出（length>0）时用 `percentageFromCfi`（已在真实 epub.js 模块上以形态保真数据验证口径正确：靠前点 2.9%、末尾 1）；否则 spine 粒度粗估 `spineIndex/(spineItems.length-1)` 兜底（本册=1/4≈25%）。阅读条、进度落库、书签百分比三处同口径修正。
- **取证台**：第 33 轮同款隔离第二实例（临时 userData + DB WAL 快照 + CDP WebSocket 探针真实点击）复现并取证，排障插桩已随修复移除，真实库零污染；`verify` 脚本对 epub.js 真实模块的 compare/percentageFromCfi 行为验证后即删。
- **顺带发现（未修，另立案）**：①生产构建（out/ 产物）下 epub 渲染整体不可用——rendition manager 建不起来（`Rendition.resize` 抛 manager undefined），疑 `src/index.html` CSP（`default-src 'self'`，frame-src 回落）拦 epub.js 渲染 iframe；dev server 不复现，v1.0 起潜伏，首次真正运行 build 产物（本轮排障 rig）时暴露；②ResizeObserver 回调 `renditionRef.current?.resize(w, h)`（优化第1轮遗留）无 try/catch，挂载竞态下抛未捕获异常。
- **实况**：开发者实测通过；typecheck 双配置 + build 通过；改动集中在 `EpubReader.tsx`（relocated 百分比与锚点解析、flatTocRef、chapterHrefAt）与 `BookshelfModule.tsx`（addBookmark 精确命中优先）。
