# 设计：海龟汤逻辑严密性优化——推演式审题 v3

> 创建于 2026-09-08 21:18

- **日期**：2026-09-08（260908）
- **来源**：`docs/project/左侧边栏/推理角/海龟汤修改反馈2.md`（开发者试玩第一轮优化后产出的三碗汤：《定时饭》《三档》《井里的歌》，点评逐碗拆解逻辑硬伤）
- **流程**：brainstorming——开发者逐项确认（范围 → 严格度取舍 → 存量处置 → 方案三选一 → 设计两节），260908 会话内批准
- **规模**：仅改 `electron/ai/services.ts` 三个函数（`buildSoupPrompt` 质量标准重写、`reviewSoup` 推演式重写、`generateSoups` 重出上限 1→2）；无 DB 改动、无 UI 改动、无新表新列、无定时任务

## 背景与根因

260907 第一轮优化建立了「出题 → 逐碗审题 → 打回重出 1 次 → 复审」管线，但反馈 2 的三碗汤**全部通过了该审题管线**。对照三份点评，根因在两端：

1. **出题端**：质量标准 6 条偏叙事层（线索隐藏/回收/可判定），无一条强制对诡计做现实推演——「听起来像 clever mystery」就写出来了；
2. **审题端**：「逻辑硬伤」只有一句抽象表述（因果链断裂/自相矛盾/悬空/巧合），且立场「默认放行，拿不准算过」——审题人不会主动排时间轴、不做物理推演、不走死者行为链。

反馈 2 点出的问题归纳为七类现有 checklist 完全没覆盖的硬伤：

| # | 硬伤类别 | 反馈实例 |
| --- | --- | --- |
| 1 | 科学/物理可行性 | 毒物在电饭煲高温下分解失效；单颗螺母无法让吊扇整体坠落；浴室声音被听成从地下传来 |
| 2 | 时间线自洽 | 外卖 7 点下单 7:30 送达 vs 7 点前投毒保温半小时；「延迟发作」与「吃到一半即死」矛盾 |
| 3 | 死者/受害者行为合理 | 吃到一半起身反锁门；已知风扇异响仍开三档；无防备独闯地下室 |
| 4 | 作案计划可控 | 震动脱落时机随机 = 凶手靠运气；当面拆吊扇风险极高 |
| 5 | 汤面断言有据 | 现场毫无他杀证据却写「警方确认是他杀」（强行设定） |
| 6 | 公平可推导 | 凶手经汤面零铺垫的「维修通道」离开（出题人脑补，玩家无从盘问） |
| 7 | 无伪线索 | 「收音机没开」——汤底给不出因果必要的正当解释的刻意误导 |

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 范围 | **只改出题链路**（出题 prompt + 审题管线）；裁判判答按现状不动 |
| 严格度取舍 | **严格优先**：打回重出上限提到 2 次，复审不过才弃碗；接受手动入口最坏等待变长 |
| 存量汤处置 | **存量不动**（近 200 碗含反馈 2 三碗问题汤），只管新汤；不做存量逻辑重审 |
| 技术路线 | **方案 A：单趟推演式审题**（管线结构不变、零新增调用趟数），否决 B（双审分工，串行调用翻倍）与 C（大纲先行重构，改动面过大、留作 A 失效后的升级路径） |

## 出题端：质量标准 v3（`buildSoupPrompt` 重写）

现有 6 条重组为「叙事层 4 + 现实逻辑层 7」共 11 条。「对手不降智」并入人物行为合理；「本格自洽」拆进诡计现实可行（无超自然）与计划可控（防巧合堆砌），消除抽象表述。每条现实逻辑红线配自检问句；例子只用一行抽象表述、**不给完整案情**（防题材锚定，沿用第一轮不设类型清单的理由）。

**叙事层**（原有保留）：常识可解 / 线索自然隐藏 / 汤底逐一回收 / 可判定性。

**现实逻辑层**（新增）：

| # | 红线 | 自检问句 |
| --- | --- | --- |
| ⑤ | 诡计现实可行（含无超自然）：核心诡计在现实物理/化学/机械/医学/空间声学条件下逐步执行都成立 | 「把诡计在现实里走一遍——有没有一个环节根本行不通或概率极低（如毒物经不起烹饪高温、单颗零件让重型机械整体脱落）？」 |
| ⑥ | 时间线自洽 | 「把所有事件标上时刻排成一条轴——有没有两个事件塞不进同一条轴，或必须压缩到不可能的时长？」 |
| ⑦ | 人物行为合理：不止对手，死者/证人的每个关键动作也要有符合身份与处境的动机 | 「分别以死者、对手、证人的视角走一遍动作链——一个正常人处在他的处境会这么做吗？」 |
| ⑧ | 计划可控：对手计划不依赖不可控随机事件命中（兼防巧合堆砌） | 「复盘对手的计划——有没有一步是『碰巧才会成功』？」 |
| ⑨ | 汤面断言有据：汤面中警方/权威结论须与汤底一致且有合理依据 | 「按汤底现场，警方真的会得出汤面写的那个结论吗？现场毫无他杀证据就不得写『确认他杀』。」 |
| ⑩ | 公平可推导：汤底玩家必须得知的关键事实（路线/机关/身份/手法），从汤面信息出发经「是/否」盘问可达 | 「对每个关键事实找一条从汤面出发的提问路径——找不到的就是出题人脑补。」 |
| ⑪ | 无伪线索：汤面每个细节在汤底有因果上必要的解释 | 「汤底解释了但没有因果必要的刻意误导细节（如某电器没开）＝伪线索，不合格。」 |

## 审题端：五步推演式审查（`reviewSoup` 重写）

- **立场拆分**：主观质量（线索还能更巧、难度感觉）维持「默认放行」；**逻辑与公平类翻转为「推演没做不许下结论，推演中说不通的环节就是硬伤」**——不再适用「拿不准算过」。
- **流程三步**：
  1. 第一步（保留）：只读汤面，玩家视角记录第一直觉猜测、最想盘问的 3 个问题、一眼注意到的异常；
  2. 第二步（核心改造）：读汤底与裁判解析后，**依次做五步推演并把过程写进输出的 `steps` 数组**——①排时间轴（逐事件标时刻）②物理推演（诡计在现实条件逐步执行）③行为链推演（死者/对手/证人各走一遍动作链找动机）④计划可控性复盘（标出依赖运气的环节）⑤公平性对照（汤底关键事实逐条找从汤面出发的是/否提问可达路径；汤面细节反向逐个过一遍找伪线索；核对汤面断言与汤底证据）；
  3. 第三步：对照硬伤清单下结论。
- **硬伤清单**扩为五类：常识门槛（原有）/ 现实逻辑硬伤（物理不可行·时间线矛盾·人物降智·计划靠运气·断言无据，从推演中来）/ 公平性硬伤（关键事实不可达·伪线索）/ 同构（原有）/ 极端报菜名（原有）。
- **校准示例**：反馈 2 三碗坏汤压缩成三行注入审题 prompt（**仅审题端**——出题端给完整案例会锚定题材）：电饭煲毒饭（高温失活 + 延迟矛盾）、单螺母坠扇（机械不成立 + 时机不可控）、浴室声传楼梯井（声学不成立 + 维修通道无中生有）。
- **JSON 返回**扩为 `{"steps":["…×5"],"verdict":"pass|fail","ratedDifficulty":"…","problems":[…]}`——`steps` 只强迫推演先行，解析时仅看 verdict/problems/ratedDifficulty 判定，`steps` 缺失/畸形不影响判定。

## 管线参数（`generateSoups` 重出循环）

- 结构不变：出题 3 碗 → 逐碗串行审 → 打回携问题清单重出（**上限 1 次 → 2 次**）→ 弃碗不弃批 → 3 碗全灭抛错。
- 重出循环改为小循环：每碗最多「初审 1 + 重出×2 + 复审×2」共 5 趟机会；每次重出携带**当次**审题 problems + 已保留碗 trick_note（批内互避），仍不给原碗内容（防锚定修补）。
- 难度处理零改动：random 模式按审题人重评档落库；指定偏好档不符计入打回，重出后仍不符按实落库。
- 调用趟数：中位 4~7 趟（与现状相当）；最坏 16 趟（3 碗全打回且都重出满 2 次）。串行调用惯例不变（中转通道并发限制）。

## 边界与错误处理（全部沿用现有口径）

| 场景 | 行为 |
| --- | --- |
| 出题/重出 JSON 解析失败 | 重试一次，仍失败抛错/弃碗（现状） |
| 审题调用/解析失败 | `reviewSoupSafe` 重试一次，两次失败弃碗（现状） |
| `steps` 字段缺失/畸形 | 不影响判定，仅看 verdict/problems/ratedDifficulty |
| 3 碗全灭 | 抛错；手动入口 toast 报错、泵静默（现状） |
| LLM 未配置 / 取消 / 手动与泵并发 | 全部现状口径，零改动 |
