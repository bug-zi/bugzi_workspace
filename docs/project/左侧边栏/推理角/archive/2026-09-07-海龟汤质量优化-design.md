## 背景与痛点

`generateSoups`（`electron/ai/services.ts`）现状为**单阶段生成**：一次 prompt 出 3 碗，4 条质量标准写在同一 prompt 里让 LLM 自查；避免清单只避「汤名 + 题材」，不避诡计思路；难度纯自评。开发者试玩反馈暴露 5 个问题：

| # | 问题 | 对应反馈 |
| --- | --- | --- |
| 1 | **难度失衡**：《昨日离场》线索过于明显、没有挑战——难度自评无人复核 | 坏汤 1 |
| 2 | **专业知识门槛**：《北窗》需过硬地理知识才可解——推理让位于知识检索 | 坏汤 2 |
| 3 | **反派降智**：《蓝饭盒》绑匪不知过敏、不查护具——为让主角识破而让对手犯蠢 | 蓝饭盒不足① |
| 4 | **汤面报菜名**：异常线索密集罗列（蓝饭盒 4 个异常扎堆），刻意感重 | 蓝饭盒不足② |
| 5 | **类型重复**：连续两批都在时间/历法上做把戏——机制上无跨批多样性约束 | 反馈末段 |

反馈中的衍生想法（万象库新增「刑侦推理解谜」知识库）**明确不在本轮范围**，另开一轮。

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 范围 | 只做海龟汤出题质量；万象库刑侦知识库另议 |
| 质量把关 | **两阶段管线**：出题 → 独立审题（照思维墙每日一题先例），不过打回重出 |
| 避免重复路线 | **不设诡计类型枚举**（硬类型会诱导 LLM 对着标签凑情节，杀掉巧思——开发者明确否决类型轮换）；采用**诡计摘要避开**：每碗落库一句核心诡计概括，生成与审题注入近期摘要清单，同构即避开/打回 |
| 审题粒度 | **逐碗审 + 并行**（`Promise.allSettled`）：每碗独享审题上下文、审得最深；并行抹平延迟。整批审（注意力稀释）与整批重出（浪费合格碗）均已否决 |
| 历史回填 | 一次性回填：启动后后台一趟 LLM 为存量汤补 trick_note |
| 落库策略 | 复审不过**弃碗不弃批**：合格碗照常入库、返回实际数；3 碗全灭才抛错 |

## 出题标准 v2（generateSoups 出题 prompt 重写）

原 4 条自检标准保留 3 条（汤底逐一回收、本格自洽、可判定），「铺足抓手」重述，新增 4 条——每条配一个**可操作自检问句**：

| # | 标准 | 自检问句 | 堵哪个洞 |
| --- | --- | --- | --- |
| ① 常识可解 | 解题所需知识限于日常生活常识；专业知识可作佐证、不得作解题钥匙 | 「一个观察敏锐的普通人，不查任何资料，只凭盘问能否逼近汤底？」 | 《北窗》 |
| ② 对手不降智 | 涉及对手计划时，破绽须源于**固有盲区**（信息差、未预料变量、成本权衡），不得是与其缜密程度不相称的低级疏忽 | 「对手再谨慎一点，这个诡计还会漏吗？」若「多检查一步就不会漏」→ 不合格 | 《蓝饭盒》 |
| ③ 线索自然隐藏 | 汤面至少 3 个可盘问的具体事实，以平常口吻**织入叙事**；至多一半是显性异常，**至少一条是隐性线索**（表面平常，汤底揭示后含义才反转） | 「把汤面里的异常挑出来——如果一眼能挑出全部，就不合格」 | 报菜名 |
| ④ 难度有定义 | easy = 单层反转、线索较显眼；medium = 双层反转或线索有伪装、需先排除误导；hard = 多层反转或强误导、关键线索全隐性 | 自评难度必须对照定义给出 | 《昨日离场》 |

**巧思总纲**（替代原「可借鉴推理母题」的类型化表述，呼应「好汤不受类型束缚」）：

> 好汤的标志是：真相揭示后，玩家回看汤面，发现每个寻常细节都另有含义。核心诡计应让多个寻常细节咬合成一个不寻常的真相。不设类型清单，思路不受任何分类束缚。

**产出结构**：每碗在原三件套 + difficulty + theme 之外新增 `trick_note`（核心诡计一句话概括，如「用前一天的旧录像伪造离场记录」）。trick_note **纯内部机制，不进任何 UI**（防剧透，终局点评也不露出）。

**避免清单升级**：

- 现有近 200 碗「汤名 + 题材」清单保留不动；
- 新增**近 9 碗 trick_note 清单**（`WHERE trick_note IS NOT NULL ORDER BY id DESC LIMIT 9`），要求新 3 碗核心思路与清单明显不同；
- 批内协调为软约束：「3 碗核心诡计思路彼此明显不同」，不提任何类型词。

## 审题管线（逐碗并行审 + 单碗打回）

**调用结构**：出题 1 趟（温度 0.9，产 3 碗）→ **3 趟审题并行**（温度 0.2，照思维墙审题惯例）→ 不合格碗各自重出 1 趟 → 复审 1 趟 → 合格碗落库。全程最多 3 轮串行往返。

**半盲审查流程**（防「默认命题人正确」）：每碗独立审题上下文，材料 = 该碗三件套 + 自评难度 + trick_note + 近期 9 碗摘要清单 + 同批另两碗 trick_note。两步走：

1. **先只读汤面**，以玩家视角记下：第一直觉猜测方向、最想盘问的 3 个问题、一眼注意到的异常——「抓手够不够、异常是否扎眼」的一手证据；
2. **再读汤底与裁判解析**，逐项六查：

| 查项 | 判据 |
| --- | --- |
| 常识可解 | 第一步玩家视角的推理方向是否全部走在生活常识内 |
| 对手不降智 | 「再谨慎一点还会漏吗」测试，独立重推演因果链 |
| 难度复核 | 对照三档定义**独立重评**，以审题人评定为准 |
| 线索自然 | 结合第一步「一眼注意到的异常」数量——异常全部一眼可见 → 报菜名，打回 |
| 回收/自洽/可判定 | 汤面元素逐一有交代；无巧合堆砌；判断句可答 |
| 同构 | trick_note 与近期清单、同批另两碗明显不同 |

**难度冲突处理**：

- **random 模式**（泵调用、难度错开）：以审题人重评落库，不打回；
- **用户指定难度偏好**（手动选 easy/medium/hard）：重评档与偏好档不符 → 该碗不合格打回重出（避免「点了困难模式端上来一碗简单的」）。

**打回与落库**：

- 打回重出 prompt = 出题要求 v2 全文 + 审题人问题清单（「重新出题必须全部规避」）+ 保留碗 trick_note（批内互避）+ 待补难度档——**不给原碗内容**，避免锚定原稿修补（照思维墙打回惯例）；待补难度档 = 用户偏好档（指定模式）或审题人重评后的档位（random 模式，维持批内难度错开）；
- 复审仍不过 → **放弃该碗**（不陪葬整批）；合格碗照常入库，返回实际 `{generated, inserted}`；3 碗全灭才抛错；
- `parseSoupArray`「恰好 3 碗」解析口径不变——失败发生在审题段，不在解析段；出题 JSON 解析失败「重试一次，仍失败抛错」口径也不变。

## 数据模型与历史回填

- **加列**：`turtle_soups` 加 `trick_note TEXT`（可空）。
- **DB 版本协调**：题库预生成 spec（`2026-09-07-reasoning-question-bank-design.md`）已规划 v14（wall_pool 表），两者均未实施——**谁先落地谁占 v14，后者顺延 v15**。
- **一次性回填** `backfillTrickNotes()`：`main.ts` 启动延迟 10s 后 fire-and-forget 检查 `trick_note IS NULL` 的汤（全量：含已玩过的、含回收站软删的——软删汤的思路同样算「已用过」），**一趟 LLM 调用批量**生成 `{id, trick_note}` 数组，逐行 UPDATE。失败 console.warn 下次启动再试；LLM 未配置静默跳过；跑完即无、不建定时器。

## 与题库预生成 spec 的关系

泵调 `generateSoups('random')` 零改动自动获得新管线（每批 1 → 最多 5 趟调用，后台 fire-and-forget 无碍）。两个 spec 实施顺序任意、互不阻塞。手动「来 3 碗汤」按钮保留原样（难度偏好 + 前台 loading）。

## 边界与错误处理

| 场景 | 行为 |
| --- | --- |
| 出题 JSON 解析失败 | 重试一次，仍失败抛错不落库（现有口径） |
| 单碗审题调用/解析失败 | 该碗**放弃**（故障与汤质量无关，不值得打回），合格碗照落 |
| 3 碗全灭 | 抛错；手动入口 toast 报错，泵静默下次补 |
| LLM 未配置 | 手动入口照全局规则 8 弹「去配置」；回填静默跳过 |
| 手动与泵并发 | 沿用题库 spec 口径：各自独立插库，最坏多 3 碗，可接受 |
