# 学习库·深挖结果确认后写入知识卡 设计记录

> 创建于 2026-09-12 19:38
> 来源：`docs/project/优化建议区.md` 待完成区第 2 条（开发者 260912 提出，当日 brainstorm 定稿）。
> 定位：学习库 v2.0 三件套「深挖模式」的交互改版——v2.0 设计（§四）原定「深挖结果不回写卡片（YAGNI）」，本设计应开发者要求反转该决定：深挖结果确认后直接写入当前知识卡。

## 一、现状与问题

- 现状：卡片弹窗（MdDialog studyBar）「深挖」按钮 → 前端读卡文拼四角度 prompt → `onOpenAi(prefill, { auto: true })` 自动发右栏「学习·问答」频道。结果只存在于对话历史，卡片本身无沉淀。
- 痛点：深挖产出是学习资料，散落在对话里不利于复习回顾；开发者希望「直接加到当前知识卡中去」。

## 二、已确认决策（brainstorm 定稿）

| 维度 | 结论 |
|---|---|
| 入卡方式 | **确认后写入**：生成完先展示，用户点「写入卡片」才落库；可重新生成、可放弃。不满意不落库，卡片不被污染 |
| 写入格式 | **日期小节累加**：卡片 md 末尾追加 `## 深挖（YYMMDD）` 二级标题 + AI 内容；多次深挖多次累加各成一节，日期可追溯；写入后在卡片里随意编辑删改 |
| 右栏关系 | 「深挖」按钮**不再自动发右栏**——入卡成为深挖主路径；想对话追问仍可手动问 AI（「学习·问答」频道照常可用，零改动） |
| 生成位置 | 卡片弹窗内闭环（弹窗内结果区展示），不依赖右栏时序 |

## 三、交互流

1. 点「深挖」→ 卡片弹窗内出现**深挖结果区**：生成中 loading（可取消，走全局 jobId 取消机制）。
2. 生成完成 → 结果区 MdView 渲染展示，底部操作：**「写入卡片」**（主题色主键）/「重新生成」/「放弃」（关闭结果区）。
3. 点写入 → 主进程原子完成「读卡文全文 → 末尾追加 `## 深挖（YYMMDD）` + AI 内容 → 写回」→ 弹窗刷新渲染新内容，toast「已写入卡片」。
4. 小节标题日期取当日 `YYMMDD`（项目惯例口径）；同日多次深挖各成一节，不做合并。

## 四、技术设计

### 4.1 IPC（electron/ipc.ts 新增两通道）

| 接口 | 说明 |
|---|---|
| `learn:dig(nodeId, jobId)` | 读 `md/learn/<id>.md` 卡文 → 四角度深挖 prompt（沿用现有前端模板文案，搬进主进程）→ LLM 生成 → 返回 `{ content }`；jobId 可取消；LLM 未配置 throw `LLM_NOT_CONFIGURED` |
| `learn:digApply(nodeId, content)` | 主进程原子写入：读卡文全文 → 追加 `\n\n## 深挖（YYMMDD）\n\n${content}` → 写回 md → 返回更新后全文（弹窗刷新用） |

写入收敛在主进程单点，避免渲染层读-改-写的并发竞态。

### 4.2 渲染层

- `LearnModule.tsx`：`onDig` 重写为调 `learn:dig`，管理深挖结果区状态（生成中/结果/错误）；持有 jobId 供取消；写入调 `learn:digApply` 后刷新弹窗 md。
- `MdDialog.tsx`：studyBar 扩展位增加深挖结果区渲染（具体形态实施时取侵入最小者——同 v2.0 设计 §七口径，其他模块调用方零影响）。
- `preload.ts` / `api.d.ts`：两通道透传。
- `electron/ai/services.ts`：新增 `digLearnCard` prompt 函数（四角度模板迁移，文案不变）。

### 4.3 全局规则核对

- LLM 未配置：深挖按钮不置灰，点击提示 +「去配置」（全局规则）✓
- 生成中可取消（全局取消机制，停止按钮）✓；失败行内可重试（同既有 handleAiError 三分支口径）✓
- 禁 emoji，Material Symbols 图标（沿用 `travel_explore`）✓；组件色系走主题变量 ✓

## 五、不做（YAGNI）

- 卡片列表/知识树上不加「已深挖」标识。
- 深挖模板自定义、角度多选。
- 深挖历史管理（写入即进卡片 md，卡片自身可编辑）。
- 右栏自动发送保留（入卡为主路径，追问走手动）。

## 六、验证点

- `npm run typecheck` 双配置 + `npm run build` 通过。
- 冒烟：深挖 → 取消 → 重试 → 写入卡片 → 弹窗刷新见「## 深挖（日期）」小节 → 再次深挖累加第二节 → 在卡片编辑态删改深挖内容正常 → 其他模块 MdDialog 零影响。
- 失败路径：LLM 未配置提示去配置；生成失败可重试；取消后状态复位可再点。
- 老卡（正文自由、可能已有各级标题）追加不破坏原内容（末尾追加语义）。
