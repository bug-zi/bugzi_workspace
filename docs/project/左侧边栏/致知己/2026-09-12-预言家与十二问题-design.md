# 致知己·预言家与十二问题 设计记录

> 创建于 2026-09-12 17:57
> 来源：`docs/project/新功能开发区.md` 待完成区第 2、3 条（开发者 260912 提出并商定）。
> 定位：致知己模块子功能（非新模块），模块内改三 tab；本文件为实施设计记录，落地后归档。
> 已确认决策：预言家用户下判断（AI 不下结论）；判断后与沉淀区**暂不联动**（留待以后）；十二问题用户自定义 12 题、多条带日期想法、可选问 AI（默认零 AI）；预言家多轮对话走**频道制**（方案 A）；首个 tab 定名「沉淀」。

## 一、需求原文拆解

1. **预言家**（致知己新标签页）：输入一个预测/推断（如"根据流量价格的发展预测未来 Token 会越来越便宜"），问推断是否合理；AI 联网搜索资料，给出充分全面的说明；AI 具备多轮对话能力（可对其理由提出质疑）；最后用户下判断；与致知己原初区域的联动本期不做。
2. **十二问题**（致知己新标签页）：关于输出——把自己对问题的想法写下来，记入自己的思维库；用户自定义 12 个开放性问题，每题下多条带日期想法；每题可选「问 AI」（追问频道，AI 只帮想透不代笔）。

## 二、总体结构：致知己改三 tab

- 模块头部下方加 tab 栏，三键：**沉淀 ｜ 预言家 ｜ 十二问题**；默认「沉淀」（现有问题+多版本答案列表原样成为沉淀 tab 内容，零改动）。
- 样式沿用 `recycle-tabs` / `recycle-tab`（万象库百科｜辩真同款）；tab 选择不持久化（推理角/万象库惯例）。
- 图标（Material Symbols，禁 emoji）：预言家 `auto_awesome`、十二问题 `tag`；沉淀沿用 `self_improvement`。

## 三、预言家

### 3.1 列表页

- 头部右侧「+ 新预言」按钮；列表按最近更新倒序。
- 每行显示：预言观点（claim）、状态徽标（`讨论中` / `已判断·合理` / `已判断·不合理` / `已判断·存疑`）、判断摘要（已判断时展示判断理由前若干字）、更新时间。
- 行点击打开详情弹窗；行尾删除按钮（二次确认进回收站）。

### 3.2 新预言

- 弹窗输入：预言观点（必填）+ 补充说明（可选，如预测的背景/自己的初步理由）。
- 创建成功即自动开始 AI 分析（无需再点）；分析进行中条目状态为 `讨论中`。

### 3.3 AI 分析流程（主进程服务端跑，复用辩真链路）

1. MCP `findSearchTool` 找搜索工具；MCP 未配置 → 全局规则：弹窗提示 + 「去配置」直达个人档（按钮不置灰）。
2. LLM 生成 3 组检索关键词（中英文混合，`scene: 'prophet:analyze'`）。
3. 逐组 MCP 检索（复用 `runVerification` 的关键词→检索→综合骨架，新函数不复用记录写入）。
4. LLM 综合资料输出「充分全面的说明」，结构约定为 Markdown：① 观点重述 ② 支持依据（引用资料与数据）③ 反对/风险依据 ④ 推演逻辑链（从已知到预测的推理路径）⑤ 不确定性与关键变量 ⑥ 结论倾向（仅供参考，最终判断留给用户）。引用来源以 Markdown 链接列出。
5. 进度经 onProgress 推「致知己·预言家」频道 system 消息（同辩真），右栏自动展开切到该频道。
6. 分析全文作为 assistant 消息推入该频道激活会话（无激活会话则自动新建，同 `appendSystemToChannelSession` 模式），同时写 md 快照挂条目。
7. 失败处理：检索全部失败/LLM 失败 → toast 报错，条目保留为 `讨论中`，可从详情重试「重新分析」（覆盖 md 快照与频道内重新推入新说明）。

### 3.4 多轮对话

- 对话发生在右栏「致知己·预言家」频道（普通 `ai:chat`，会话历史自带上下文）；用户在频道里直接质疑、追问。
- 频道人设：*当前频道是「致知己·预言家」，你是预言分析师：围绕用户的预测/推断，基于检索资料给出充分全面的说明与推演；欢迎质疑，逐条回应，证据不足时明说；绝不替用户下最终结论，判断由用户自己做。*
- 条目详情弹窗内提供「回到频道」按钮：展开右栏并切到预言家频道（不自动发消息）。

### 3.5 下判断

- 详情弹窗内判断区：三选一按钮组（合理 `reasonable` / 不合理 `unreasonable` / 存疑 `uncertain`）+ 判断理由输入（可选）。
- 提交后：status 置 `judged`、judgment/judgment_note/judged_at 落库，列表徽标更新；可重新选择覆盖（judged_at 更新）。
- `讨论中` 状态也可先判断（不强制等分析完成）。

### 3.6 详情弹窗

- 复用 MdDialog（同辩真记录详情模式）：默认渲染态展示 md 快照，双击切换编辑态（md 内含「我的补充说明」与「AI 分析」两部分，作为条目自己的快照可整体编辑）。
- 弹窗操作条（MdDialog 扩展位，同致知己版本条模式）：判断区（3.5）+「回到频道」+「重新分析」。

### 3.7 删除与回收站

- 删除条目：二次确认后进回收站致知己块；频道会话不跟随删除（对话历史保留在频道）。
- md 快照封存/恢复/彻底删同致知己问题模式。

## 四、十二问题

### 4.1 列表页

- 问题卡片纵向列表：题目、想法条数、最近想法时间；顶部「+ 新问题」按钮。
- **12 题上限**：满 12 题后「+ 新问题」置灰，提示「十二问题已满，先删一题再添加」。
- 删除问题：二次确认后连想法一起进回收站致知己块。

### 4.2 想法记录

- 点开一题 → 想法流（按时间倒序）：每条独立成段带时间戳，MdView 渲染（支持简单 markdown）；底部输入框逐条记录（Enter 提交，Shift+Enter 换行），提交即落库上屏。
- 删除单条想法：二次确认后**彻底删**（碎片数据不入回收站，同信息源处理惯例）。
- 「问 AI」按钮（每题行内）：按「让 AI 追问」同款 autoAsk 模式——自动展开右栏切「致知己·追问」频道，带入题目+最近 5 条想法，AI 以较真的朋友人设帮想透（只提问不代笔）；LLM 未配置走全局规则。

### 4.3 不做（YAGNI）

- 不做 AI 帮拟题/初始化（保持零 AI 手写定位，需要时手动改题）。
- 不做想法沉淀成长文 md（碎片流即终态）。
- 不做问题拖拽排序（ord 按创建序，本期不做排序交互）。

## 五、存储与迁移（DB v36 一次迁移）

| 表 | 字段 | 说明 |
|---|---|---|
| `prophet_records` | id、claim、note、status(`open`/`judged`)、judgment(`reasonable`/`unreasonable`/`uncertain`)、judgment_note、judged_at、analysis_md_path、created_at、updated_at、deleted_at | 判断可空可改；md 快照 `md/prophet/<id>.md` |
| `twelve_questions` | id、title、ord、created_at、updated_at、deleted_at | 用户自定义，≤12 条（应用层限制） |
| `twelve_thoughts` | id、question_id、content、created_at | 碎片存 SQLite（同 profile_facts 模式），不落 md；无软删列——单条想法二次确认后彻底删，删题时想法随题走题目级回收 |

- 频道制扩展（零迁移，channel 为 TEXT）：`AiChannel` 联合类型加 `'prophet'`；`CHANNEL_PERSONAS` 加人设；`AiActiveSessionProphet` settings 键；ai_sessions 存量数据不动。
- 回收站：致知己块扩展三个来源子类（question 现有 / prophet / twelve），恢复各回各 tab 区；3 天自动清理照旧。

## 七、验证点

- typecheck 双配置通过。
- 冒烟：建预言→自动分析→右栏预言家频道出现进度与说明→频道内质疑多轮→详情下判断→徽标更新→改判断→删条目进回收站→恢复。
- 冒烟：建 12 题→第 13 题被拒→记想法（渲染+倒序）→删想法彻底删→问 AI 带上下文进追问频道→删题进回收站→恢复后想法还原。
- 失败路径：未配 LLM 点问 AI/新预言；未配 MCP 开始分析——均走全局提示不崩溃。
- 分析中断（取消/失败）后「重新分析」可用。
