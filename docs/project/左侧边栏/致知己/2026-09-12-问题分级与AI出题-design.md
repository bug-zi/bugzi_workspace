# 致知己·沉淀区问题分级（星级 + 来源）与 AI 出题 设计记录

> 创建于 2026-09-12 19:57
> 来源：`docs/project/优化建议区.md` 待完成区第 1 条（开发者 260912 提出，当日 brainstorm 定稿）。
> 定位：致知己「沉淀」tab 的问题库增强——问题来源分流（手动/AI）+ 四维标准星级分级；十二问题暂不接入但字段设计预留平移。

## 一、需求与现状

- 开发者原述：问题来源分级设计——按评判标准打星级；出处分两类（手动输入 / AI 生成）；具体方案共同商定。
- 现状：致知己三 tab（沉淀/预言家/十二问题）所有问题均手动创建，无 AI 出题能力，无星级字段。
- 范围决策：**先落沉淀区，预留扩展**（十二问题将来接入时平移同套字段）。

## 二、已确认决策（brainstorm 定稿）

| 维度 | 结论 |
|---|---|
| 范围 | 先沉淀区，字段设计预留扩展 |
| AI 出题形态 | **候选勾选采纳**：一次生成 5 条候选 → 弹窗预览勾选 → 采纳的才入库标 `ai` 来源（灵感泉/万象库审核范式） |
| 星级归属 | **AI 初评 + 用户可调**：入库时 AI 按统一标准评星（手动创建的也评），列表上随时手动改星 |
| 评级体系 | **1–5 星 + 四维标准**，AI 附一句评语（悬停可见，让标准透明） |

## 三、四维评星标准（写入 prompt）

1. **开放性**：无标准答案，越问越深（封闭问题/事实题低分）。
2. **自我认知价值**：回答它能否照见自己的价值观、思维模式、行为倾向。
3. **可演化性**：答案值得随时间重写多个版本（一次性问题低分）。
4. **具体度**：不空泛，落到具体领域/情境（「我是谁」式大而空低分）。

AI 综合四维给 1–5 星 + 一句评语（为什么是这个星级）。

## 四、数据模型

`zhijiji_questions` 新增三列（一次 DB 迁移，版本号实施时定稿，当前 v36 已被预言家与十二问题占用，顺延起算，撞车顺延）：

| 列 | 类型 | 说明 |
|---|---|---|
| `origin` | TEXT NOT NULL DEFAULT 'manual' | `manual` 手动 / `ai` AI 生成；存量迁移全部标 `manual` |
| `stars` | INTEGER | 1–5，可空（NULL = 未评星）；用户可随时改 |
| `star_note` | TEXT | AI 评星评语（一句），可空 |

- 迁移幂等：存量行只补 `origin='manual'` 默认值，stars 保持 NULL 不强行评。
- 预留扩展：三列语义通用，`twelve_questions` 将来接入加同款列即可。

## 五、AI 出题（新增能力）

- **入口**：沉淀区头部新增「AI 出题」按钮（LLM 未配置不置灰，点击走全局提示 + 去配置）。
- **流程**：一次 LLM 调用生成 **5 条候选问题**（生成时就带每条 1–5 星 + 评语）→ 候选弹窗预览（题目 + 星星 + 评语 + 勾选框，全不勾则「采纳」禁用）→ 采纳的入库（`origin='ai'`、stars/star_note 落库），放弃的不留痕。
- **出题 prompt 依据**：用户画像摘要（记忆化口径同生成类功能）+ 已有问题清单（避免重复）+ 高星问题特征（评语中体现的方向偏好，越出越像用户重视的方向）。
- 生成走 jobId 全局取消机制；失败可重试；候选弹窗可 Esc/外点关闭。

## 六、AI 评星（手动问题）

- **新问题**：手动创建入库后**后台异步评星**（独立单题评星调用，不阻塞创建流程），评完渲染层刷新出现星星；失败静默（列表该题无星，可手动补评/改星）。
- **存量补评**：沉淀区列表提供「AI 补评」入口（仅在存在未评星问题时显示），一次 LLM 调用批量评完全部 NULL 星题，完成后刷新。
- **手动改星**：列表星星控件点击弹出改星（1–5 直选），即点即存；AI 评语不因手动改星清除（评语是 AI 的理由，星级是用户的判断，二者独立）。

## 七、列表呈现

- 问题行新增：**来源小标识**（手动 `person` / AI `auto_awesome`，Material Symbols，悬停 title 说明）、**星级星星**（`star` 图标 ×n 或数字+图标轻量呈现，实施时取与行布局协调者；未评星灰显占位）、星星悬停显示评语。
- 头部加**星级筛选/排序**轻控件（如「全部 / ★4+ / ★5 / 未评」筛选 pill 或下拉；默认仍按更新倒序，不强制星级排序）。
- 问题详情弹窗（版本条）不动；出处分流不影响答案版本体系。

## 八、IPC 与服务清单（electron）

| 接口 | 说明 |
|---|---|
| `zhiji:suggestQuestions(jobId)` | 出 5 条候选（带星+评语），返回候选数组；jobId 可取消 |
| `zhiji:rateQuestion(questionId)` | 单题 AI 评星（手动新问题异步评星用），返回 {stars, star_note} |
| `zhiji:ratePending()` | 批量补评：取全部 stars IS NULL 行一次调用评完并落库，返回更新行数 |
| `zhiji:setStars(questionId, stars)` | 手动改星落库（1–5；传 null 清除） |
| `zhiji:adoptQuestions(candidates)` | 候选采纳批量入库（origin='ai'） |

AI 层新增 prompt：`suggestZhijiQuestions`（出题+评星一体）、`rateZhijiQuestions`（批量评星，单题复用传数组）。出题/评星均注入画像压缩摘要（每条 60 字截断口径同生成类功能）。

## 九、容错与边界

- LLM 未配置：AI 出题/AI 补评入口不置灰，点击全局提示 + 去配置 ✓。
- 出题失败/取消：候选弹窗关闭，可重试 ✓。
- 补评失败：行内 toast 报错，未评状态保持，可再点 ✓。
- 异步评星与用户手动改星竞态：评星落库仅写 stars 为 NULL 的行（`WHERE stars IS NULL`），不覆盖用户已改的星 ✓。
- 满页问题量大时批量补评一次调用 token 可控（评语一句、输入仅标题，无正文）✓。

## 十、不做（YAGNI）

- 十二问题/预言家不接入（预留字段，不平移 UI）。
- 星级不参与 AI 追问/画像注入（纯管理属性）。
- 不做评星历史记录/星级修改轨迹。
- 不做 AI 出题定时化（手动触发）。
- 出处分流不改变回收站/恢复逻辑（恢复回沉淀区，origin 随行保留）。

## 十一、验证点

- `npm run typecheck` 双配置 + `npm run build` 通过。
- 冒烟：重启 dev 触发迁移（存量题 origin=manual、无星）→ AI 出题 5 候选带星评语 → 勾选采纳入库标 AI → 手动建题后台自动评星 → AI 补评存量无星题 → 手动改星即时生效且不被异步评星覆盖 → 星级筛选/排序 → 双主题目检 → LLM 未配置全链路提示。
