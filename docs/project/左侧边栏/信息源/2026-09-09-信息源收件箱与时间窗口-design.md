# 信息源——收件箱模式 + 时间窗口加载 + 老数据瘦身（优化建议区第 28 轮）

> 创建于 2026-09-09（brainstorming 会话定稿）

## 背景与诊断

开发者优化建议：「信息源需要好好优化一下——比如说已读之后的归档机制，选择性加载机制（按时间来规定）」。

现状确认（`electron/services/feed.ts` + `FeedModule.tsx`）：

- `listArticles` 每次进模块**全量 SELECT** 该源（或全部）的所有文章——无 LIMIT、无时间过滤，且逐条 `stripTags` 算预览，随文章积累线性变慢
- 已读文章只是不加粗，**永远混在列表里**，列表越用越长
- `articles` 表只增不减（含抓回的整篇 HTML 正文与 AI 总结），DB 单向膨胀

三个澄清决定（本轮商定）：主列表**收件箱模式**（只显示未读，读完即消失）；**30 天时间窗口**加载（窗口外「加载更早」触达）；老数据**清正文保轻行**（180 天前删正文/总结，保留标题轻行）。

## 设计

### 1. 收件箱模式（渲染层 + 查询层）

- 主列表默认「**收件箱**」视图：只显示未读文章，读完即从列表消失（`openArticle` 内置标已读，回列表时该行自然消失）
- 列表头部加「收件箱 | 已归档」切换：已归档视图显示已读文章（时间倒序）
- 源筛选（左栏选源 / 全部文章）对两个视图都生效；源行未读徽标、未读数逻辑不变
- 「全部标已读」作用于**全部未读**（不限当前 30 天窗口），标完收件箱即清空
- 已读文章不进回收站（保持现口径）；无「标未读」回退操作

### 2. 时间窗口加载（查询层）

- `listArticles(feedId, view, sinceDays)` 增参：`view: 'unread' | 'archive'`、`sinceDays`（默认 30）
- 查询条件：`COALESCE(published_at, fetched_at) >= now - sinceDays 天` + 未读/已读分支（`read_at IS NULL` / `IS NOT NULL`）
- 返回体附带 `remaining`（窗口外剩余篇数）——同一条件去掉时间过滤的 COUNT
- 渲染层：列表底部在 `remaining > 0` 时显示「加载更早 30 天 · 还剩 N 篇」，点击 `sinceDays += 30` 重查（可连续点）；切视图/切源时窗口重置为 30
- 顺带治全量性能病：预览 `stripTags` 只对窗口内文章计算

### 3. 老数据瘦身（主进程定时任务）

- 复用现有定时器机制（启动 + 每日零点检查，同回收站 3 天清理先例），新增清理任务：
- **180 天前**的文章（按 `COALESCE(published_at, fetched_at)` 口径）：置空 `content_feed_html` / `content_fetched_html` / `summary_text`（及 `summary_at`），**保留**标题/链接/作者/时间/已读状态——归档区仍能翻到、能「去原文」
- 兜底细节：老文章被点开时 `extractArticle` 懒抓逻辑天然兜底（正文为空 + 有 url 会重新抓网页），链接失效静默走摘要兜底——「物理清理」实际是删缓存，真想看还能抓回

### 4. 不做的事

- 不改抓取（fetchAllFeeds/超时/去重）、AI 总结、阅读视图逻辑
- 不做已读进回收站、不做标未读回退

## 改动范围

- `electron/services/feed.ts`：`listArticles` 签名与查询、`ArticleSummary` 附 `remaining`
- `electron/ipc.ts` + `src/preload/index.ts` + `src/renderer/api.d.ts`：`articles:list` 通道透传新参数（三处手工同步）
- `electron/` 定时器（回收站清理同址）：新增 180 天正文清理任务
- `src/modules/feed/FeedModule.tsx` + `feed.css`：收件箱/已归档切换、窗口状态、「加载更早」按钮、空状态（收件箱无未读时提示）
- 零 DB 迁移（无新表新列，只用现有字段）

## 验证口径

- 冒烟：读完一篇文章回列表行消失；已归档视图能翻到已读；窗口外文章「加载更早」能触达；「全部标已读」后收件箱清空且窗口外未读也清空；源筛选两视图均生效
- typecheck 通过
