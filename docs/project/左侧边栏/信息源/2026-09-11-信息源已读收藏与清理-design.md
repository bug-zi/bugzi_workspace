# 信息源——显式已读双态按钮 + 文章收藏 + 30 天彻底清理

> 创建于 2026-09-11 12:01（brainstorming 会话定稿）

## 背景与需求

开发者三项优化需求（260911 会话）：

1. **归档保留期 180 天 → 30 天，且彻底删除**：归档文章大多数不会看第二遍，置空正文保留轻行的策略不要了，超期整行删掉。
2. **显式已读**：现在打开文章即自动标已读（`openArticle` 内置写入 `read_at`），开发者希望判定已读的唯一途径是用户点击「已读」按钮；且按钮为双态——已读态显示「再看看」，点击回到收件箱（相当于标未读回退，补上第 28 轮「不做的事」里欠的口子）。
3. **文章收藏**：收藏的文章不进归档、永不被清理，取消收藏后按已读状态回到收件箱或已归档。

两个澄清决定（本轮商定）：

- **删除范围 = 已读 + 未收藏 + 超 30 天**。未读文章无论多老都保留（待读积压由用户自主处理）；收藏文章永不清除。
- **收藏方案 = A（模块内收藏页）**。B（并入收藏夹模块）被否：`fav_items` 是纯链接条目（name/url/desc），与 articles 行无关联，正文缓存带不过去、取消收藏要靠 URL 反查、双份数据需同步；C（A+B 都做）同步成本最高收益最低。articles 表加 `favorited_at` 字段单一数据源，实现最小。

## 设计

### 1. 数据模型（DB v34）

- `ALTER TABLE articles ADD COLUMN favorited_at TEXT`（null=未收藏）
- 不加索引（信息源数据量小）；无新表；不涉回收站（信息源删除本就不入回收站）

### 2. 显式已读（双态按钮）

- **`openArticle` 不再写 `read_at`**，只保留懒抓正文与全量返回——打开 ≠ 已读
- 新 IPC `articles.setRead(id, read)`：`true` → `read_at = now`；`false` → `read_at = NULL`

| 文章状态 | 按钮显示（icon） | 点击效果 |
|---|---|---|
| 未读（收件箱 / 收藏页） | `已读`（mark_email_read） | 标已读，行从收件箱消失→进归档 |
| 已读（已归档 / 收藏页） | `再看看`（move_to_inbox） | `read_at` 清空，行从归档消失→回收件箱 |

- 按钮位置三处：收件箱行、已归档行、收藏页行（右侧操作区，`stopPropagation` 不触发行点击打开），以及**阅读视图头部**（读完顺手点，返回列表即见新状态）
- 「全部标已读」保留，范围 = 当前筛选（全部/当前源）的非收藏未读文章（收藏的不在收件箱，不波及）
- 点击即时生效，无二次确认（非破坏性、可逆）

### 3. 文章收藏（方案 A）

- 每行加星标按钮（`star`；实心=已收藏 `font-variation-settings:'FILL' 1`，空心=未收藏），阅读视图头部同款
- 新 IPC `articles.setFavorite(id, fav)`：`true` → `favorited_at = now`；`false` → `favorited_at = NULL`
- **收藏**：行从收件箱/归档消失，只出现在收藏页
- **取消收藏**：按当前已读状态回到收件箱（未读）或已归档（已读）——由双态按钮状态决定
- 顶部 tab 三页：**收件箱 | 已归档 | 收藏**；收藏页按 `favorited_at` 倒序**全量**列出（不设时间窗口、无「加载更早」——人工策展量少）
- 收藏页内文章照常点击打开内置阅读视图；正文/AI 总结缓存随行保留；已读/再看看与星标照常可用
- 未读徽标计数（`feeds.list` 子查询与「全部文章」总数）排除收藏文章

### 4. 30 天彻底清理

- `cleanupOldArticleBodies`（置空正文保留行）改造为 `cleanupOldArticles`（整行 DELETE）：

```sql
DELETE FROM articles
WHERE read_at IS NOT NULL        -- 已读
  AND favorited_at IS NULL       -- 未收藏
  AND COALESCE(published_at, fetched_at) < 30 天前
```

- 调用时机不变：启动 + 每日零点（scheduler.ts），静默，日志文案更新为「信息源 30 天已读文章清理 N 条」
- 已归档页「加载更早 30 天」按钮**移除**（归档天然 ≤30 天，remaining 恒 0）；收件页**保留**（未读老文章不删，需要翻旧账入口）
- 边界：取消收藏一篇超 30 天的已读文章 → 回归档，下次清理删除，属预期行为

### 5. 列表查询与类型

- `FeedView` 扩为 `'unread' | 'archive' | 'favorite'`
- `listArticles`：unread/archive 分支加 `AND favorited_at IS NULL`；favorite 分支 `WHERE favorited_at IS NOT NULL ORDER BY favorited_at DESC`——**收藏页不筛源**（左栏选源对收藏页无效，保持全量策展视角），`sinceDays` 参数对该分支忽略
- `ArticleSummary` 加 `favorited: boolean`（三端手工同步：types.ts / api.d.ts / 渲染层）

### 6. 样式与全局规则遵循

- 双态按钮与星标均为小号（图标+文字），主题色系、无彩色亮色；星标收藏态主题色实心
- 全部 material symbols 图标，无 emoji
- 空态文案：收藏页「还没有收藏的文章」；收件箱/已归档沿用现有文案

## 验证口径

- 迁移 v34 后旧库无损
- 三 tab 切换与筛选：收藏页不受左栏选源影响
- 双态按钮双向流转（列表行 + 阅读视图内各验一遍）：已读→归档、再看看→收件箱
- 收藏/取消收藏回归路径：未读收藏→取消→收件箱；已读收藏→取消→已归档
- 「全部标已读」不波及收藏未读文章；未读徽标不含收藏
- SQL 造数验证清理：40 天前已读未收藏文被删（启动时），40 天前未读/收藏文保留
- typecheck 通过

## 补充需求：拉取入库 7 天窗口（同日追加，13:01）

**需求**（开发者冒烟反馈）：拉取会把源的历史文章全部拉进来；希望拉取订阅源时最多只拉最近 7 天的文章。

**设计**：

- 新常量 `FETCH_WINDOW_DAYS = 7`；`fetchFeed` 入库循环跳过 `publishedIso` 早于 `now − 7 天` 的条目（按条目自身发布时间，ISO 字符串比较）。
- **无日期条目照常入库**（视作新发）：跳过会让无 pubDate 的源永远拉不到文章；guid 去重防重复。边界：首次订阅「全员无日期」的长历史源仍会全量进，罕见，接受。
- 只影响**拉取入库门槛**：已在库的老文章不动；「添加订阅」立即拉取同生效；未读老文章的 30 天清理规则不变。

**改动**：仅 `electron/services/feed.ts`（常量 + 循环内一行过滤）。
