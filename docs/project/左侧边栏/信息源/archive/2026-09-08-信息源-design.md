## 背景与定位

> **信息源 = 精简版 Folo：RSS 订阅聚合 + AI 总结置顶 + 内置阅读。**

收集关注博主的更新文章，AI 读文章生成中文总结放在开头，然后读原文。初始预置三个源，可随时添加：

1. `https://weekly.tw93.fun/rss.xml`
2. `https://aiznb.com/weekly/atom.xml`
3. `https://ursb.me/blog/feed.xml`

## 关键决策记录（会话中逐项确认）

| # | 决策点 | 结论 | 被否掉的选项 |
|---|---|---|---|
| 1 | AI 总结时机 | **打开文章时按需总结 + 缓存**（下次秒开） | 拉新后自动总结（token 耗在可能永不点开的文章上）；按需 + 手动批量按钮（多一套交互与状态） |
| 2 | 原文阅读 | **内置阅读视图**：RSS 自带全文优先，不足时主进程抓网页正文（readability 系解析）；抓到的正文一套数据两用——喂 AI 总结 + 阅读视图渲染 | 只渲染 RSS 内容 + 外链兜底（AI 只能总结摘要，效果打折）；webview 嵌原网页（广告/样式不可控、双主题无从适配） |
| 3 | 拉取节奏 | 进模块自动拉全部源 + 顶栏手动刷新 | 加定时自动拉（博客/周刊更新低频，YAGNI，进 v2）；纯手动（每次多一下点击） |
| 4 | 已读管理 | 基础已读/未读：点开即标已读、未读加粗、一键全部标已读 | +收藏/稍后读（多一层状态与筛选 UI）；不做已读状态（源多了分不清看过没） |
| 5 | 删除流转 | 删源（连文章）二次确认后**彻底删除，不入回收站**；回收站保持现有八块（与书架同决策） | 入回收站新增来源块 |
| 6 | 边栏位置 | 文笔坊后追加（书架之后）：…文笔坊→书架→**信息源**→回收站→个人中心 | — |
| 7 | 技术路线 | **主进程全本地**：原生 fetch + fast-xml-parser（RSS 2.0/Atom 通吃）+ @mozilla/readability + linkedom 抓正文；AI 总结复用现有 LLM 服务 | 走 MCP 拉取/总结（依赖 MCP 配置，与「未配置降级」规则冲突，机械拉取没必要绕 LLM）；渲染进程直接 fetch（跨域受限，违背主进程服务层架构） |

## 模块结构（主栏内三段式）

```
src/modules/feed/
├─ 左窄栏：源列表
│   ├─ 「全部文章」聚合项（总未读数）
│   ├─ 各源项：源名 + 未读数徽标 + 拉取失败标红
│   └─ 底部「添加订阅」按钮
├─ 文章列表（中栏）：标题 + 源名 + 摘要前几字 + 时间；未读加粗，按发布时间倒序
│   └─ 顶栏：刷新按钮 | 全部标已读
└─ 阅读视图（点文章进入，主栏切换）
    ├─ AI 总结卡（置顶，主题色边框卡片）
    ├─ 标题 / 源名 / 时间 / 「去原文」按钮
    └─ 正文：消毒后 HTML，排版复用 MdView 样式
```

## 数据与拉取

- SQLite 两张表：
  - `feeds`：`id, title, feed_url, site_url, last_fetched_at, fetch_error, created_at`
  - `articles`：`id, feed_id, guid(去重键，无 guid 用 link 哈希), title, url, author, published_at, fetched_at, content_feed_html(RSS 自带), content_fetched_html(抓取正文), read_at, summary_text, summary_at`
- **拉取**：进模块自动拉全部源 + 手动刷新；每源超时 15 秒；单源失败标红可查错误，不影响其他源。文章按 guid upsert 去重。
- **正文两级策略**：RSS 自带全文够长（>500 字符）直接用；否则主进程 fetch 网页 → readability + linkedom 提取正文。抓取失败兜底显示 RSS 摘要 + 「去原文」外链。
- **首次进入模块**自动预置上述三个源。
- 文章**不自动清理**（个人量级：三个源一年几百篇，SQLite 毫无压力）。
- 主进程新增 `FeedService`（拉取/解析/抓正文/总结调度），IPC 通道以 `feeds:` 为前缀。

## AI 总结（按需 + 缓存）

- 打开文章时若无缓存总结 → 取全文（feed 全文或抓取正文；两者皆无则现抓一次）→ 送现有 LLM 服务生成中文总结（约 150-300 字）→ 存库，下次秒开。
- 总结期间卡片显示加载态；失败显示原因 + 重试按钮。
- **LLM 未配置**：按全局规则——不置灰，点开文章弹「去配置」直达个人中心。
- system prompt 只含文章标题与正文，不注入画像（外部文章与自我认知无关）。

## 订阅管理与边界

- **添加订阅**：弹窗输入 URL → 后台拉一次验证并取源名 → 确认入库。
- **删除源**：二次确认（ConfirmDialog 全局组件），连源带文章彻底删除。
- **「去原文」**：`shell.openExternal` 跳系统浏览器。
- 文内远程图片需放宽 CSP `img-src` 允许 https:，其余安全策略不动（正文渲染前仍过 dompurify 消毒）。
- 拉取/解析全在主进程：网络错误、RSS 2.0/Atom 格式差异、时间格式不一（RFC822/ISO 混杂）均在 Service 层兜住，渲染层只见结构化数据。
- 图标取 Material Symbols（禁 emoji），候选 `rss_feed`，最终以样式设计文档风格为准。

## 明确不做的事（v1）

- 收藏/稍后读（决策 #4，进 v2 备选）。
- 定时自动拉取（决策 #3，进 v2 备选）。
- 单篇文章手动删除（源级删除已够；文章不清理不占地方）。
- 文章全文搜索、标签分类、OPML 批量导入。
- 不新增 AI 边栏频道（五频道保持不变；总结在阅读视图内闭环）。

## v2 备选

1. 定时自动拉取（接现有定时器服务，App 未运行错过即跳过，同格言库规则）。
2. 收藏/稍后读标记与筛选。
3. OPML 导入导出。
4. 未读文章列表虚拟滚动（源多文章量大时）。
