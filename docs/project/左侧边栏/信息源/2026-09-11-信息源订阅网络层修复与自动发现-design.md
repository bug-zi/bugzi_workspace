# 信息源订阅网络层修复与首页自动发现 设计记录（2026-09-11，优化建议区第 37 轮）

## 背景

开发者反馈：接入 `https://feeds.feedburner.com/ruanyifeng`（阮一峰的网络日志）显示 Error，且「获取订阅的方式有点窄了」，要求优化升级订阅能力。

## 根因（systematic-debugging 取证）

- 该 URL 返回完全正常的 RSS 2.0（HTTP 200 / text/xml / 137KB / 6 条目），项目同款 fast-xml-parser 配置实测解析正常——**网络内容与解析层均无问题**。
- 复现 Error：主进程 node 全局 `fetch`（undici）直连 feedburner 报 `ConnectTimeoutError`；同机 curl 秒通——curl 走了 `https_proxy` 环境变量。
- 开发者机器运行系统代理 `127.0.0.1:7890`（注册表 ProxyEnable=1）；feedburner 属 Google 服务，需代理可达。**undici 既不读系统代理也不读环境变量代理** → 直连超时 → 添加订阅弹窗显示 Error。
- 三个预置源（tw93/aiznb/ursb）均国内直连可达，故此洞此前未暴露。
- Electron 实测对照（隔离脚本）：global fetch 复现同款超时；**`net.fetch` OK 200**（Chromium 网络栈自动跟随系统代理）。
- 先例：`electron/ai/llm.ts` 260909 已全量迁移 `net.fetch`（注释明示「Chromium 栈天然跟随系统代理」+ undici headersTimeout 硬伤）——信息源模块当时被遗漏。

## 决策（开发者拍板）

1. **网络层换 net.fetch**：fetchFeed / probeFeed / extractArticle 三处拉取统一走 `httpGet()` 内部件（net.fetch + 原有浏览器 UA + 15s AbortSignal.timeout）。对齐 llm.ts 既定约定；用户浏览器能打开的站点，订阅/拉取、抓正文全部可达。
2. **首页自动发现**：订阅入口放宽为「RSS/Atom 链接或网站首页」。probeFeed 双路径——content-type 为 HTML → linkedom 解析 `<link rel="alternate">`（type 含 rss/atom/feed 优先；全站缺 type 退 href 关键词启发）发现 feed 直链，逐个试解析（最多前 3 个防怪站链一堆打满超时）；非 HTML 走原 feed 解析路径零变化，解析失败兜底当 HTML 探测（content-type 标错误的怪站）。**addFeed 存发现的 feedUrl 而非用户输入**（首页地址存库会让后续拉取永远打在 HTML 上）；首页/直链两种输法归一到同一 feed_url，去重口径自然对齐。
3. **错误文案友好化**：`friendlyError()` 映射——域名解析失败 / 连接超时 / 代理连接失败 / 连接被拒绝 → 可读中文，连接类错误附「应用自动跟随系统代理，需代理的站点请确认系统代理已开启」提示；HTTP 状态码与格式错误原样透传（本就可读）。probeFeed 抛出与 fetch_error 入库两处统一生效。

**被否方案**：undici EnvHttpProxyAgent（只读环境变量——GUI 图标启动不继承终端代理变量，生产场景失效）；手动读注册表代理 + ProxyAgent（平台相关代码多，Chromium 网络栈已内建且更完备：PAC / 自动检测 / 直连回退）；JSON Feed 解析（开发者选择不加，主流博客罕见）。

## 实施

- `electron/services/feed.ts`：`import { net } from 'electron'`；新内部件 `httpGet` / `friendlyError` / `discoverFeedLinks` / `probeViaLinks`；probeFeed 重构，返回 `FeedProbe { title, siteUrl, feedUrl }`（siteUrl 取用户输入页的 origin）；addFeed `clean = probed.feedUrl`；三处 fetch 调用点换 httpGet；fetchFeed catch 记库改 friendlyError。
- `electron/preload.ts` + `src/renderer/api.d.ts`：probe 返回类型补 `feedUrl`，注释同步。
- `src/modules/feed/FeedModule.tsx`：placeholder 放宽「RSS/Atom 链接或网站首页，如 …」；验证通过行下新增「实际订阅源：…」（feedUrl ≠ 输入时显示，复用 `.feed-probe-line` 样式）；probed state 类型同步。
- 零 DB 迁移；零新增依赖（linkedom 本就是正文抓取依赖）。

## 验证

- typecheck 双配置 + 生产 build 通过。
- Electron E2E（esbuild 打包真实 feed.ts 实跑三用例）：feedburner 直链 0.9s 通过（用户原始失败用例）；博客首页 `www.ruanyifeng.com/blog/` 0.8s 自动发现同一 feed；不存在域名 0.2s 返回可读中文文案。
