## 一、需求原文拆解

1. **每日批次**：每天自动随机生成 5-10 条知识卡片（数量每天随机），尽可能平均分到已有板块；在启动项目时生成。
2. **学会了组件**：阅读待学习卡片时有「学会了」组件，点击才把卡片加进板块；不点就一直留在待学习区。「随机来一条」「手动输入生成」的卡片同样先进待学习区。
3. **状态可逆**：「学会了」点击后变「已学会」（已入板块态）；从「已学会」再点击变回「学会了」（回待学习态）。
4. **预生成后库**：仿推理角预生成机制——每板块预生成 3 张知识卡片在后库等待；点「随机来一条」从后库立刻抽出一张显示（不等待）；后库存量 < 3 立刻补充。
5. **位置**：待学习板块放板块列表最上面（经济学上方）；笔记本仍在最下面。

## 二、数据模型（DB v31）

```sql
ALTER TABLE wiki_entries ADD COLUMN state TEXT NOT NULL DEFAULT 'learned';
CREATE INDEX IF NOT EXISTS idx_wiki_entries_state ON wiki_entries(state);
```

- `state` 三态：`pool`（后库储备，用户不可见）｜`learn`（待学习区）｜`learned`（已学会，正式词条）。
- 存量行默认 `learned`，行为零变化。
- settings 新 key：`wiki_daily_learn_date`（每日批次最近执行日，本地日期 `YYYY-MM-DD`）。

### 状态机

```
            抽卡（随机来一条）            学会了
  pool ────────────────────────▶ learn ────────────────▶ learned
                                    ▲                       │
                                    └─────── 已学会 ◀───────┘
```

- `pool → learn`：唯一入口是抽卡（wiki:generate 池优先）。
- `learn → learned` / `learned → learn`：学会了/已学会 切换（`wiki:setLearned`）。
- 丢弃（learn/learned 态均可）：走既有回收站流程；恢复仅清 `deleted_at`，state 原样保留 → 待学习卡恢复后自然回待学习区。
- 池卡（pool）永不进回收站、无任何 UI 入口；板块删除时随板块物理清理（见 §六）。

## 三、后库泵（`electron/services/wikiStock.ts`，仿 reasoningStock.ts）

- **常量**：`POOL_TARGET = 3`（每板块）。判定：任一板块池存量 < 3 → 该板块补到 3。
- **三触发**（与推理角同款）：main.ts 启动延迟 10s ／ 抽卡消耗后（ipc 内 fire-and-forget）／ 进入万象库模块（`wiki:stockCheck`，覆盖 LLM 事后才配置好的场景）。
- **单飞标志** `pumping` 防重入；LLM 未配置 → console.warn 静默跳过。
- **并行策略**：板块间并行（Promise.allSettled 各自容错）、板块内逐张串行；每张 = 构思词条名 + 生成卡片两次 LLM 调用，insert state='pool'。单张失败（含 CONFLICT 撞词）warn 后终止该板块本轮补充，待下次触发（不做退避重试——wiki 侧触发点密度高于推理角，YAGNI）。
- 每张入库后 `BrowserWindow.getAllWindows()[0]?.webContents.send('wiki:stockChanged')`（照 reasoning:stockChanged 模式）。
- 每张生成前重查板块存在（防批次进行中板块被删产生孤儿卡）。

## 四、每日批次（同文件）

- **触发**：main.ts 启动延迟 10s（与泵并行）＋ scheduler.ts 午夜零点排程钩子（App 跨天常驻时也不断供）。
- **幂等**：settings `wiki_daily_learn_date` == 今日（本地日期）→ 跳过。
- **数量**：`5 + Math.floor(Math.random() * 6)` → 5..10。
- **均摊**：板块洗牌后 round-robin 分配配额（7 张 5 板块 → 2,2,1,1,1），逐张生成 insert state='learn'。
- **LLM 未配置**：静默跳过且**不记日期**（当天稍后配置好再启动仍可生成）。
- **失败口径**：只要成功 ≥1 张即记日期（部分成功也算当天已完成，防重试撞词重复）；零成功不记，下次触发重试整批。
- 单飞标志 `dailyRunning` 防重入；每张入库同样推 `wiki:stockChanged`。

## 五、抽卡（wiki:generate 改造，池优先）

- `term == null`（随机来一条 / 本板块随机来一条）：
  1. 指定板块 → 抽该板块最旧池卡；未指定 → 全体池卡均匀随机抽一张。
  2. 抽中 → `UPDATE state='learn'`（池行原地转正，id/md 不变）→ 秒回 `{ok:true, data}`；随后 fire-and-forget `ensureWikiStock()`（消耗后触发补充）。
  3. 池空 → 兜底现场生成（现状逻辑，state='learn'）。
- `term != null`（手动输入）：维持现场生成 + 查重拦截，state='learn'。
- 池优先路径不产生 CONFLICT（池卡入库时已查重）。

## 六、IPC 变更清单（electron/ipc.ts）

| 接口 | 变更 |
|---|---|
| `wiki:entries` | 加 `AND state='learned'`——板块页/计数只算已学会词条 |
| `wiki:learnEntries`（新） | `state='learn'` 联表板块名，`ORDER BY id DESC` |
| `wiki:setLearned`（新） | `(id, learned)` → `UPDATE state`（`WHERE state != 'pool'` 防误改池卡） |
| `wiki:stockCheck`（新） | fire-and-forget `ensureWikiStock()`，秒回 |
| `wiki:generate` | §五 池优先改造 |
| `wiki:deleteSection` | 删板块前先物理删该板块全部 pool 卡（含 md 文件）——池卡用户不可见，不可成为「看起来空却删不掉」的死局；learn/learned 仍阻删 |
| `wiki:quiz`（ai 层） | 取题口径加 `state='learned'`——只考已学会的 |

## 七、学会了/已学会 组件（MdDialog 新 prop `learnBar`）

```ts
/** 万象库待学习卡片（260910 待学习区）：底部操作条。learn 态三钮（直接删除/丢弃/学会了），
 *  learned 态单钮（已学会，点击移回待学习区）；onDiscard/onDelete 不传则不渲染（learned 态）。
 *  关闭/遮罩/Esc = 留在待学习区，不强制三选一（区别于旧 review 流）。 */
learnBar?: {
  learned: boolean
  onToggle: () => void
  onDiscard?: () => void
  onDelete?: () => void
}
```

- 渲染在 `dialog-footer`（复用 review 样式）；**不隐藏头部关闭钮**（review 会隐藏）。
- learn 态按钮：`直接删除`(btn-danger-deep，二次确认) ｜ `丢弃`(btn-danger，二次确认) ｜ `学会了`(btn-primary)。
- learned 态按钮：`已学会`(btn + task_alt 图标)。
- WikiModule 接线：切换后重取 entry 刷新按钮态 + 重载板块计数/待学习列表，toast「已加入板块 XX」/「已移回待学习区」。
- **旧「生成审核三选」（reviewing/review prop 的万象用法）下线**：新语义——生成即入待学习区，关闭=保留（toast 已留在待学习区），学会了才进板块；MdDialog 的 review prop 保留（组件层不删，别处未用）。

## 八、渲染层（WikiModule.tsx）

- 总览板块列表**最上加「待学习」行**（dashed 边框同笔记本款、`school` 图标、sub「学会了才进板块」、计数=待学习数），点击进 learn 视图（新 View kind `'learn'`）。
- learn 视图：zone 列表行 = 词条名 + 一句话定义 + 板块名小字（section_name）；行操作：查看（开卡片弹窗）/丢弃（回收站二次确认）；空态提示「每天自动来 5-10 张，或点随机来一条」。
- `useModuleActivated('wiki')` 回调追加 `wiki.stockCheck()` + 重载待学习列表；订阅 `wiki.onStockChanged` → 重载待学习列表与板块计数（泵/每日批次渐进到达）。
- 生成成功后开卡：learnBar 呈现（替代旧 reviewing 三选）。

## 九、不做（YAGNI）

- 不做后库存量 UI 展示、不做待学习区批量操作、不做按板块筛选待学习。
- 不做泵的瞬态退避重试/自愈重排（推理角那套保留在推理角；wiki 触发点更密）。
- 不为待学习卡做独立删除入口（丢弃走回收站即够）。
