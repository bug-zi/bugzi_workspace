# 播客台——工具栏单行合并 + 删除单集复活修复（design）

> 创建于 2026-09-26 00:18
> 来源：优化建议区第 56 轮（260926 提出并当日拍板）
> 关联：2026-09-24-播客台-design.md（模块本体）

## 一、问题清单

开发者冒烟反馈三条：

1. **组件位置不一致**：「收件箱」视图与「已归档」视图下组件位置不同，切换时来回跳，用着不顺畅。
2. **订阅筛选平铺会臃肿**：当前 3 个订阅排开显示尚可，将来十几个订阅时一排 chips 平铺换行很臃肿，需提前收束。
3. **Bug：删除的单集复活**：删除单集后切换到其他模块再切回来，该单集重新出现——甚至直接进入播客转写。

## 二、根因排查

### 2.1 组件位置跳动

`.pc-filter` 类全局带 `margin-left: auto`，单集流的视图 chips 组（收件箱/已归档/全部）复用了该类；而「清空收件箱」按钮只在收件箱视图且有未读时渲染。两视图下行内空闲空间分配不同：收件箱视图 chips 被按钮分走空间停在右中段，已归档/全部视图按钮消失、chips 瞬移到最右缘——每次切视图 chips 横向跳动。

### 2.2 订阅筛选平铺

`.pc-toolbar`（刷新/添加订阅/订阅 chips，flex-wrap）在订阅多时 chips 换行堆叠成多行。

### 2.3 删除复活（bug）

- `deleteEpisode`（podcast.ts）是**硬删行**（连 `dequeueTranscribe` 摘队列）。
- 切回播客台模块触发 `useModuleActivated → refresh() → fetchAllPodcastFeeds` 重新拉 RSS；`fetchPodcastFeed` 对每条 item 执行 `INSERT OR IGNORE INTO podcast_episodes ... UNIQUE(feed_id, guid)`——行已被删，唯一索引不再命中，**同一集被当作新集插回**：`read_at=NULL` 回收件箱、`transcript_state='none'`。
- 若该节目开了「自动转写新集」，增量新集分支立即 `enqueueTranscribe` → **复活且直接进转写**。转写中删除的集同理：fetchAll 复活新行后，仍在运行的 `processTranscribe` 的 UPDATE 落在新行上，状态被继续推进。

## 三、设计决策

经 brainstorming 一问拍板布局（三案对比：单行合并 / 两行钉位 / 信息源式左栏），开发者选**单行合并**。墓碑方案沿用格言库墓碑先例（优化建议区第 24 轮）。

### 3.1 删除墓碑（DB v60，bug 修复）

- **新表** `podcast_deleted_eps`：
  ```sql
  CREATE TABLE podcast_deleted_eps (
    feed_id INTEGER NOT NULL,
    guid TEXT NOT NULL,
    deleted_at TEXT NOT NULL,
    PRIMARY KEY (feed_id, guid)
  )
  ```
- **deleteEpisode**：删行前 `SELECT feed_id, guid` 取行标识 → `INSERT OR REPLACE INTO podcast_deleted_eps` 写墓碑（幂等）→ 照旧摘队列 + 硬删。
- **fetchPodcastFeed**：入库循环前一次查出该 feed 的墓碑 guid 集合（Set），循环内命中的 item 直接 `continue` 跳过（不计入 added、不触发自动转写）。
- **deletePodcastFeed（退订）**：随现有退订删除顺带 `DELETE FROM podcast_deleted_eps WHERE feed_id = ?`——退订再重订 = **全新开始**（重订生成新 feed_id，旧墓碑永远查不到，清掉保持表干净；若保留会出现「重订后旧删除的单集集体隐身」的反直觉）。
- **零新 IPC、零渲染层改动**（bug 部分全在主进程）；首拉（isFirst）不受影响（新 feed 无墓碑）。
- **转写竞态兜底**：`processTranscribe` 开头 `if (!ep) return` 行删防御已有；墓碑挡住 fetchAll 复活后，运行中的 UPDATE 落空行（changes=0）无害。

### 3.2 工具栏单行合并（纯渲染层）

删掉 `.pc-toolbar` / `.pc-viewbar` 两行，单集流 tab 头合成一行：

```
[刷新][+添加订阅] [收件箱 5][已归档][全部][清空收件箱]        [全部节目 ▾]
```

- **左组固定序**：刷新、添加订阅、视图 chips 组、清空收件箱。
  - 视图 chips 组新建 `.pc-views` 类（`display:flex; gap:6px`，**不带** auto margin）——紧跟固定宽度按钮之后，切视图零位移。
  - 清空收件箱缀组尾（仅 `view==='inbox' && inboxTotal>0` 渲染），出现/消失只影响其右侧，不挤动前项。
- **右侧订阅筛选下拉**（`margin-left:auto` 右对齐）：
  - 下拉按钮显示当前筛选：「全部节目」或节目名（复用 `.pc-filter-chip` 样式语言；`feedFilter != null` 时加 active 态高亮，全部时普通态）；点击弹 ActionMenu（`anchorEl` 锚定按钮，右缘对齐 + 底溢上翻既有规则）。
  - 菜单项 = 全部 + 各节目；当前筛选项打勾（icon `check`）；节目项附未读数；条目超长由 ActionMenu 既有 max-height 滚动承接（订阅几十个也不撑爆视口）。
  - 整行保留 `flex-wrap: wrap`：窄窗放不下时下拉按钮换行到第二行（降级可接受）。
- **语义保持不变**：收件箱计数（inboxTotal 全源未读合计）、清空收件箱动作范围（带 feedFilter）、「节目」页签的订阅卡片管理、单集行操作全部原样。

### 3.3 不做的事（YAGNI）

- 不动信息源（其头部页签 + 左栏源列表是另一套成熟交互，本轮只治播客台）。
- 不把订阅筛选持久化到 settings（会话内状态，wiki 双页签同口径）。
- 不给墓碑做清理/过期机制（每次手动删除一行，量级极小；退订时顺手清本 feed）。

## 四、改动面

| 层 | 文件 | 改动 |
|---|---|---|
| DB | `electron/db/db.ts` | v60 迁移：建 `podcast_deleted_eps` 表 |
| 主进程 | `electron/services/podcast.ts` | deleteEpisode 写墓碑；fetchPodcastFeed 跳墓碑；deletePodcastFeed 清墓碑 |
| 渲染层 | `src/modules/podcast/PodcastModule.tsx` | 单行工具栏：合并两行、订阅筛选改 ActionMenu 下拉 |

## 五、冒烟清单

1. **墓碑闭环**：删除单集 → 切走模块再切回（触发 fetchAll）→ 不复活；手动点刷新多次 → 不复活。
2. **自动转写节目**：开「自动转写新集」的节目里删除在转写中的集 → 不复活、不重入转写队列。
3. **退订重订**：退订节目（清墓碑）→ 重新订阅 → 首拉最近 10 集全新开始。
4. **已归档视图**：「再看看」回收件箱、归档/恢复回归。
5. **工具栏稳定性**：收件箱↔已归档↔全部 反复切换，chips 与下拉零位移；清空收件箱出现/消失不挤动前项。
6. **下拉筛选**：选某节目过滤正确、选「全部」恢复、当前项打勾、节目项未读数正确；菜单超长滚动。
7. **窄窗降级**：窗口缩窄时下拉换行不破版。
8. **双主题**目检：chips、下拉按钮、菜单全部主题色系无彩亮。
