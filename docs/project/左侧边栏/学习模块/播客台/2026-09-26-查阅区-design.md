# 播客台查阅区（阅读队列）— 设计

> 创建于 2026-09-26 15:36
> 来源：开发者需求——转写完成的单集进「查阅区」阅读，读完自行决定收藏或归档，不要打开即归档。

## 一、现状与问题

原收件箱制：未读未收藏全在收件箱，**打开阅读器即自动标已读** → 单集直接流到「已归档」——阅读中被归档、没有「读后决策」环节。

## 二、方案（零 DB 迁移，read_at/starred_at 既有列承载全部状态）

### 1. 五视图互斥出流（brainstorming 三项拍板）

| 视图 | 口径 |
|---|---|
| 收件箱 | 未读 && 未收藏 && **转写未完成**（新到 / 排队 / 失败） |
| **查阅区（新）** | 未读 && 未收藏 && **转写完成**（done）——转写完自动自收件箱出流至此（收藏出流同款机制） |
| 已归档 | 已读 && 未收藏 |
| 全部 | 全量 |
| 收藏 | starred_at 非空 |

- 未读总口径不变：feedsList unread、总导览「播客待读」= 收件箱 + 查阅区之和，零改动。
- `PodcastEpisodeView` 增 `'review'`；`listPodcastEpisodes` 按 `transcript_state =/!= 'done'` 拆分两区。
- 新 IPC `podcast:viewCounts(feedId)` → `{ inbox, review }`（chips 计数；`feedsList` unread 合计在新分界下不再等于收件箱数）。

### 2. 阅读器决策交互

- **删除「打开即标已读」**effect 与顶部「已读/再看看」键（与归档重复）。
- 新增**底部决策条** `.pc-reader-actions`（feed-reader-page flex 尾、恒可见）：左「收藏」星标 toggle（FILL 1 + 主题色，第 57 轮图标样式手法）+ 右「归档」主色键。
  - 归档（未读态）：标已读 → toast「已归档」→ 返回列表。
  - 已读集显示「移回查阅区」（undo 图标，标未读回流）——保留原「再看看」能力。
  - 关闭/返回不决策 → 留在查阅区可再读。
- 「清空收件箱」改名「全部标已读」，口径不变（收件箱与查阅区一起清，收藏不动），收件箱或查阅区有未读时显示。

## 三、验收

- typecheck 双配置通过。
- 桩实测：chips 五视图带计数、查阅区列表、阅读器顶部无已读键、底部收藏（FILL 填充+episodeStar）/归档（episodeRead(true)+toast+返回列表）。
- 冒烟：真实流转——新集进收件箱 → 转写完成出流查阅区 → 阅读后归档/收藏各验；「移回查阅区」回流；全部标已读两区齐清；双主题目检。
