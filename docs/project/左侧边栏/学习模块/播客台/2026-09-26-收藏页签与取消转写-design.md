# 播客台——收藏页签 + 取消转写（design）

> 创建于 2026-09-26 00:52
> 来源：优化建议区第 57 轮（260926 提出并当日拍板，同日第 56 轮工具栏合并的延续）
> 关联：2026-09-26-工具栏单行合并与删除墓碑-design.md（前一轮）；信息源收藏先例（feed.ts favorited_at，第 28 轮）

## 一、需求

1. **收藏夹页签**：播客台可收藏单集，收藏的集进收藏页签集中查看。
2. **取消转写**：误触把单集加进 ASR 转写队列后，可以选择取消转写。

## 二、拍板决策（brainstorming 两问）

- **收藏出流**（信息源同口径）：收藏的单集从收件箱消失、未读计数不计；已读态照常记录；取消收藏按已读态回流收件箱/已归档。
- **四页签保留全部**：收件箱｜已归档｜全部｜收藏（现有三 chips 原样，收藏追加末位；全部 = 全量含收藏）。

## 三、设计

### 3.1 收藏页签（DB v61）

- **迁移**：`podcast_episodes` 加 `starred_at TEXT`（NULL=未收藏；信息源 `favorited_at` 同款）。
- **单集流查询**（`listPodcastEpisodes` view 扩 `'starred'`）：
  - `inbox`：`read_at IS NULL AND starred_at IS NULL`（收藏出流）
  - `archived`：`read_at IS NOT NULL AND starred_at IS NULL`（收藏出流）
  - `all`：无条件（全量含收藏）
  - `starred`：`starred_at IS NOT NULL ORDER BY starred_at DESC, id DESC`（收藏时间倒序；feed 筛选条件照旧叠加）
- **联动口径**（全部排除收藏，防收藏集被误归档/计数虚高）：
  - `listPodcastFeeds` 的 unread 子查询加 `AND e.starred_at IS NULL`
  - `markAllEpisodesRead`（清空收件箱）WHERE 加 `AND starred_at IS NULL`
- **星标切换**：新函数 `setEpisodeStarred(id, starred)`（置 `nowIso()`/NULL）；IPC `podcast:episodeStar` 三件套。
- **类型**：`PodcastEpisodeSummary` 加 `starred: boolean`（mapEpisodeSummary 读 `!!r.starred_at`）；`view` 联合类型扩 `'starred'`——`src/shared/types.ts` + `src/renderer/api.d.ts` 两处。
- **UI**（PodcastModule.tsx）：
  - 视图 chips 追加「收藏」（「全部」之后末位），`view` state 类型扩 `'starred'`；
  - 行操作区**首位**加星标按钮：未收藏 `star`（描边态）、已收藏 `star` + `fontVariationSettings: "'FILL' 1"` + 主题色；title「收藏（移入收藏页签，收件箱不再显示）/ 取消收藏（按已读状态回流）」；
  - 操作后按当前视图重取（收藏/取消收藏在 inbox 视图 = 出流行消失，在 starred 视图取消 = 行消失，既有 `loadEpisodes(feedFilter, view)` 路径天然覆盖）；
  - starred 空态文案：「还没有收藏的单集——点单集行内的星标收藏」；
  - **删除不受星标影响**：收藏的集照旧可删（写墓碑）、退订连删，收藏列随行硬删。
- **收件箱计数 chip**（`inboxTotal`）随 feedsList 新口径自动不含收藏。

### 3.2 取消转写

- **主进程**新 `cancelTranscribe(episodeId)`：
  - 在跑（`activeTranscribes` 有登记）→ `cancelJob(active.jobId)`（ai/jobs.ts 既有全局取消；`processTranscribe` 既有 catch 在 aborted 时置 none 可重试）——与右栏 AI 面板「取消」同一 jobId，两入口等价；
  - 仅排队 → `dequeueTranscribe` 摘内存队列 + `transcript_state='queued'` 置回 `'none'`（防摘除后徽章卡 queued）；
  - 既不在队列也不在 active 的 queued 卡住态顺带自愈置 none；
  - 完成后 `notifyTaskChanged()` 渐进刷新。
- **IPC**：`podcast:transcribeCancel`（ipc.ts + preload.ts + api.d.ts 三件套）。
- **UI**：`queued` / `downloading` / `transcribing` 三态的行操作区加「取消转写」按钮（`stop_circle`，普通 icon-btn，取消无破坏不二次确认）；**行点击行为不变**（三忙碌态点击仍无操作——取消只走按钮，防行点击误取消）；取消后乐观置 none + toast「已取消转写，可重新触发」，另由 `podcast:taskChanged` 推送兜底重取。
- **polishing（排版中）不提供取消**：转写成果已落库、马上完稿，取消反而丢成果（其取消/失败保留原始转写的既有逻辑不动）。
- **费用口径**：RSS 自带文字稿直抓取消零成本；ASR 转写中取消，已消耗的 ASR 费用不退、产物不保留（回 none 重转需重新计费——主动取消的预期代价）。

## 五、冒烟清单

1. **收藏出流**：收件箱里收藏 → 行消失、收件箱计数 -1；收藏页签按收藏时间倒序、含已读与未读；取消收藏 → 按已读态回流对应视图。
2. **排除口径**：已归档视图不含收藏；全部视图含收藏；清空收件箱不动收藏集；未读计数（节目卡与收件箱 chip）不含收藏。
3. **组合**：节目筛选 × 四视图各自正确；星标按钮在四视图均可用。
4. **删除**：收藏的集可删（墓碑生效不复活）、退订连删无残留。
5. **取消转写**：排队中取消 → 徽章回「需 ASR/自带文字稿」、可重新点行触发；转写中取消 → 回 none 可重试；RSS 直抓的取消零等待；右栏 AI 面板取消钮回归同一集仍有效。
6. **polishing 不出取消钮**、done/failed/none 态无取消钮。
7. **双主题**目检：星标填充色、取消按钮、收藏 chip。
