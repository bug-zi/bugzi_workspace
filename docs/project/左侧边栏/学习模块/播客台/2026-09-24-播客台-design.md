# 播客台（学习区）设计记录

> 创建于 2026-09-24 02:08
> 来源：`docs/project/新功能开发区.md` 待完成区任务「学习区添加播客台模块（小宇宙或者酒馆的API）」（260924 brainstorm 商定）。
> 定位：**播客不是用来听的，是用来读的**——订阅播客节目，自动收新单集，拿到文字稿后读全文，配合 AI 导读卡与专属追问频道做学习。不做音频播放（开发者通勤时在手机小宇宙 App 听，本模块只负责「看」）。

## 一、需求结论（brainstorm 摘要）

| 维度 | 结论 |
|---|---|
| 数据源 | **iTunes 搜索 API（免鉴权）按节目名搜索一键订阅 + 手动贴 RSS 直链兜底**。小宇宙无官方开放 API；播客天然靠 RSS 分发，小宇宙上的节目基本都有公开 RSS，订 RSS 即订小宇宙节目，零逆向合规稳定 |
| 模块定位 | **读文字稿的学习模块**，非播放器：不做任何音频播放 UI 与音频引擎 |
| 文字稿来源 | **RSS 自带文字稿优先**（`<podcast:transcript>` 标签，有则直接抓），没有才 **ASR 云端转写**（下载音频 → OpenAI 兼容 `/audio/transcriptions`） |
| ASR 配置 | 个人档新增「ASR 配置」区（base URL + key + model），默认预填硅基流动 `openai/whisper-large-v3`（国内直连、限 50MB/1 小时、OpenAI 兼容格式）；未配置时按全局规则弹「去配置」 |
| 转写触发 | **订阅级「自动转写新集」开关（默认开）**：订阅之后入库的新集自动排队转写；**首次订阅的存量最近 10 集不自动转**（想读哪集手点哪集，防一订阅就烧 10 集费用） |
| AI 形态 | **导读卡**（打开阅读视图时生成、缓存复用，不重复生成）+ **右栏专属「播客·追问」频道**（多轮追问，论文库「文献」频道同款先例） |
| 删除语义 | 退订/删单集二次确认，**不入回收站**（信息源先例）；退订连删该节目全部单集与文字稿 |
| 音频播放 | 明确不做 |

## 二、页面结构（信息源同款三态骨架）

主视图双页签：**「单集流」（默认）｜「节目」**。

### 2.1 单集流（默认页签）
- 全部订阅的单集按发布时间倒序：节目名 · 标题 · 发布日期 · 时长 · 转写状态徽章 · 已读未读点
- 转写状态徽章：未转写（灰）/ 排队 / 下载中 / 转写中（转圈）/ 失败（红，行上出「重试」）；**已转写不显徽章**（无徽章 = 就绪可读）
- 行点击：已转写 → 直接开阅读视图；未转写/失败 → 先触发转写（无 ASR 配置弹「去配置」），行徽章转排队、列表经状态推送渐进刷新，转写完成后用户再点击进入阅读
- 行上次要操作：手动标已读/未读切换、删除单集（二次确认）、失败重试
- 顶部：刷新（拉全部源新集）+「＋添加订阅」+ 节目筛选（全部 | 各节目）

### 2.2 节目（管理页签）
- 订阅卡列表：封面 / 节目名 / 作者 / 未读数 / 「自动转写新集」开关（即开即生效，开启时顺带把该节目存量未转写集**不**自动入队——只对新集生效，存量仍手点）/ 退订（二次确认）
- 卡点击 → 筛选到该节目的单集流（同 2.1 视图带过滤）

### 2.3 添加订阅弹窗
- 双入口 tab：「搜节目」（默认）｜「RSS 直链」
- 搜节目：输入名字 → iTunes Search API（`https://itunes.apple.com/search?term=<词>&media=podcast&country=CN&limit=20`）→ 结果列表（封面/节目名/作者/单集数）→ 一键订阅（feedUrl 缺失的结果项置灰不可订）
- RSS 直链：粘贴地址 → probe 验证（能解析出频道名即通过，信息源同款交互）→ 订阅
- 订阅时勾选「自动转写新集」（默认开）
- 重复订阅拒绝（feed_url 唯一）

### 2.4 阅读视图
- 头部：返回 · 节目名/单集标题 · 发布日期 · 时长 · 已读态
- **AI 导读卡**置顶（无则显示「生成导读」按钮）：单集速览 / 核心要点 / 金句或值得记住的片段 / 延伸思考，四节 md；生成后缓存复用
- 文字稿全文 MdView 渲染；划词高亮**本期不做**（无笔记本载体，划词「问 AI」进播客频道）
- 「追问本集」按钮：带单集标题 + 文字稿摘要上下文跳右栏「播客」频道开聊
- 打开即标已读

## 三、数据模型（DB v53 两表 + settings 键，实际版本号以实施时递增为准）

```sql
-- 播客订阅
CREATE TABLE podcast_feeds (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,               -- 节目名（RSS channel title，可改名不回写覆盖）
  artist TEXT NOT NULL DEFAULT '',   -- 作者/主播
  artwork_url TEXT,                  -- 封面（iTunes 或 RSS channel image）
  feed_url TEXT NOT NULL UNIQUE,
  auto_transcribe INTEGER NOT NULL DEFAULT 1,  -- 自动转写新集开关
  created_at TEXT NOT NULL,
  last_fetched_at TEXT,
  fetch_error TEXT
);

-- 播客单集
CREATE TABLE podcast_episodes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  feed_id INTEGER NOT NULL REFERENCES podcast_feeds(id),
  guid TEXT NOT NULL,
  title TEXT NOT NULL,
  shownotes TEXT NOT NULL DEFAULT '',      -- RSS description/content:encoded 原文（兜底可读）
  published_at TEXT,                       -- ISO
  duration_sec INTEGER,                    -- itunes:duration 解析
  enclosure_url TEXT NOT NULL DEFAULT '',  -- 音频直链
  audio_bytes INTEGER,                     -- Content-Length 预检缓存（分片判定用）
  transcript_url TEXT,                     -- RSS podcast:transcript 直链（有则免 ASR）
  transcript_text TEXT,                    -- 文字稿全文（抓取或转写产物）
  transcript_source TEXT,                  -- 'rss' | 'asr' | NULL
  transcript_state TEXT NOT NULL DEFAULT 'none',
    -- none | queued | downloading | transcribing | done | failed
  transcript_error TEXT,
  summary_md TEXT,                         -- AI 导读卡（缓存）
  summary_at TEXT,
  read_at TEXT,                            -- 已读时间（NULL=未读）
  fetched_at TEXT NOT NULL
);
CREATE INDEX idx_pe_feed ON podcast_episodes(feed_id, published_at DESC);
CREATE UNIQUE INDEX idx_pe_guid ON podcast_episodes(feed_id, guid);
```

- 文字稿全文存 SQLite TEXT（单集 1–3 万字，信息源 content_feed_html 同量级先例，可接受）
- settings 新键：`asr_config`（JSON：`{ apiUrl, apiKey, model }`）、`ai_active_session_podcast`（播客频道激活会话，频道制惯例）

## 四、订阅与拉新管线（electron/services/podcast.ts）

- **RSS 解析**：新写 `parsePodcastFeed`（RSS 2.0 + itunes 命名空间，与信息源 parseFeed 字段差异大不强行抽公共；XML 处理手段同源借鉴）——channel 级 title/artist/image，item 级 guid/title/pubDate/enclosure/itunes:duration/description/content:encoded/`<podcast:transcript url type>`（可多条取 text/html > text/plain > srt > vtt > json 优先级）
- **拉源触发**：进模块自动 + 手动刷新（信息源同款）；`net.fetch` 走系统代理 + UA（信息源 httpGet 同款），错误映射可读中文记 `fetch_error`
- **首次订阅**：全量解析但只入库**最近 10 集**，全部停 `none` 态不自动转写；**后续增量**：按 (feed_id, guid) 去重全收，auto_transcribe=1 的节目新集自动入转写队列
- **iTunes 搜索**：主进程代理请求（渲染层直连有 CORS 与代理问题）；feedUrl 缺失时用 lookup API（`https://itunes.apple.com/lookup?id=<trackId>&entity=podcast`）补全

## 五、文字稿管线（主进程纯后台，串行队列，重启续跑）

- **队列**：主进程内存串行队列，一次处理一集（防并发打爆 ASR 与重复计费）；状态机 `none → queued → downloading → transcribing → done | failed`，每次状态变更推送 `podcast:taskChanged`（reasoning:stockChanged 同款渐进刷新）
- **处理步骤**：
  1. `transcript_url` 存在 → 直接抓文字稿文件（net.fetch），按类型解析为纯文本：text/plain、text/html（去标签）、application/srt、application/vtt（去序号/时间轴行）、application/json（取文本字段）；成功落 `source='rss'`，失败置 failed 记错误（不回退 ASR，重试即可）
  2. 无 transcript_url → 下载音频到临时文件（Content-Length 预检存 `audio_bytes`；**≤45MB 直传**；**超限按 mp3 帧同步字节（0xFFEx）切 ~40MB 分片**，逐片调 ASR、文本按序拼接，接缝允许轻微瑕疵）
  3. ASR 调用：OpenAI 兼容 `POST {apiUrl}/audio/transcriptions`（multipart：file + model），取 `text`；单片超时 10 分钟；全程零 LLM 参与
- **失败**：置 failed + 可读中文错误（网络/超时/服务报错/未配置 ASR），行上「重试」重新入队
- **重启恢复**：启动扫描 `queued/downloading/transcribing` 全部重置 `queued` 重入队
- **ASR 未配置**：手动触发弹「去配置」直达个人档；自动队列遇到未配置 → 该集置 failed、错误文案「ASR 未配置，去个人档配置后重试」（队列继续处理下一集）
- 临时音频文件用完即删（finally 兜底）

## 六、AI 侧（导读卡 + 追问频道）

- **AiChannel 加 `'podcast'`**：`src/shared/types.ts` 与 `src/renderer/api.d.ts` 两处 union、`SettingsKeys.AiActiveSessionPodcast`、`electron/ai/services.ts` ACTIVE_SESSION_KEYS、`src/components/AiSidebar.tsx` CHANNELS/ACTIVE_SESSION_KEYS、App.tsx `CHANNEL_BY_MODULE` 加 `podcast: 'podcast'`、MODULE_LABELS 补「播客台」
- **频道人设**：「播客学习伴读」——基于本集内容帮读者吃透观点与论据，可辩证补充，不代写笔记
- **导读卡生成**：阅读视图打开且 `summary_md` 为空时自动生成（LLM 未配置按全局规则弹「去配置」，不阻塞正文阅读）；输入 = shownotes + 文字稿全文（超 6 万字截断头部保留）+ 节目上下文；输出固定四节 md（速览/核心要点/金句片段/延伸思考）；生成中卡片位转圈，完成缓存
- **追问**：「追问本集」构造首条 user 消息（单集标题 + 文字稿 ≤2 万字上下文 + 提问引导）进 `podcast` 频道激活会话并自动开右栏；划词「问 AI」带选中文字进同频道

## 七、个人档「ASR 配置」区

- 新区块（LLM/MCP 配置同款卡片风格，提纲导航 PROFILE_NAV 加一项）：base URL / API Key / model 三项 + 保存；默认预填建议值 `https://api.siliconflow.cn/v1` + `openai/whisper-large-v3`（key 留空），仅首次展示预填、保存后即用户数据
- 不做「测试连接」按钮（ASR 测试需真实音频样本，v1 不值得）；配置完整性由触发转写时校验
- 读写走 settings 通用通道（`asr_config` JSON），主进程 `parseAsrConfig`（坏数据/缺字段逐项回落，TerminalSettings 同款手法）

## 十一、验收

- `npm run typecheck` 双 tsconfig 全绿 + `npm run build` 通过
- 冒烟清单：搜索订阅 → 首拉 10 集（不自动转写）→ 手点转写一篇（或 RSS 自带文字稿直接抓）→ 状态徽章流转 → 阅读视图导读卡生成 → 划词问 AI / 追问本集进「播客」频道 → 新集入库自动转写（开关开）→ 退订二次确认连删 → 总导览「播客待读」数与深链 → 重启后队列恢复
