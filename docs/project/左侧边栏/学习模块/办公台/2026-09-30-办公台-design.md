# 办公台（学习模块）设计

> 日期：2026-09-30 ｜ 来源：新功能开发区待完成项「工作台添加读写 Word，Excel 等文档的办公功能」｜ 状态：设计定稿，待出 specs 与实施

## 一、需求

新增「办公台」模块，提供 Word / Excel / PPT 等办公文档的读写能力：

1. **打开/查看已有文档**：把电脑里的 .docx/.xlsx/.pptx 等导入进来查看。
2. **新建并编辑文档**：在 App 内新建文档/表格，编辑后保存为 .docx/.xlsx 文件，可导出发给别人用 Office 打开。
3. **AI 帮我写文档（智能体式）**：输入需求，AI 直接在文档中生成/修改内容——不生成在对话里。

v1 格式范围：**docx / xlsx / pptx / txt / csv / md** 六种（csv 可作为 Excel 的导入来源；txt/csv/md 轻量顺带支持）。

## 二、brainstorm 决策（260930 开发者拍板）

1. **Word 编辑形态 = md 中转**：docx 导入转 Markdown，用现有 MdView/编辑态体系编辑，保存/导出时生成排版规范的 docx。丢失复杂排版（表格图片保留，字体字号颜色等不保真）。
2. **Excel 编辑深度 = 轻量网格编辑**：自研表格网格，多 sheet 查看、单元格值编辑、增删行列；不处理公式计算（打开显示文件里存的计算结果），不做重型表格组件。
3. **AI 交互 = 文档内指令条**：智能体式——输入需求 AI 直接把内容写入/修改当前打开的文档，实时看到文档在变；不在右栏对话里出结果。
4. **左栏布局 = 下固定槽位互换**：收藏夹从「常驻双模式」改为「生活模式专属」；学习模式下固定原收藏夹的位置放「办公台」。下固定其余项（音乐吧/回收站/个人档）不变双模式。
5. **列表组织 = 平铺 + 搜索筛选**：所有文档一个列表，头部搜索框 + 类型筛选下拉；v1 不做分类文件夹。
6. **核心架构 = 双轨真相源（方案 A）**：Word/PPT 导入时原件存档 + 转出 md 作为编辑真相源，App 内永远编辑 md，导出时从 md 重新生成；Excel 的 xlsx 本身就是真相源（SheetJS 直接读写）；原件永不改写。

## 三、模块定位与左栏改动

- 新模块 ModuleId `office`，名称「办公台」，学习模式专属；主栏 keep-alive 全量挂载；启动默认页仍为总导览。
- 下固定列表项支持可选 `mode` 属性按模式显隐：
  - 学习模式：**办公台**（下固定第一位）+ 音乐吧 / 回收站 / 个人档
  - 生活模式：**收藏夹**（下固定第一位）+ 音乐吧 / 回收站 / 个人档
- 收藏夹自身功能零改动，仅显隐变化。
- 模式切换时若当前打开的模块不属于新模式，按现有双模式惯例回落总导览。
- `MODULES` 数组、ModuleId 类型、`MODULE_NAVIGATE_EVENT` 深链、回收站来源组同步登记 `office`。

## 四、数据与文件存储

**DB v66 新表 `office_documents`**：

| 列 | 说明 |
|---|---|
| id | PK |
| name | 文档名（不含扩展名，可重命名） |
| kind | CHECK：docx / xlsx / pptx / txt / csv / md |
| source_name | 导入原始文件名（新建为 NULL） |
| size | 文件大小 |
| created_at / updated_at | 本地时间，同项目惯例 |

**DB v66 新表 `office_versions`**（AI 写入兜底，见第六节）：id / doc_id / snapshot（md 全文或网格 JSON）/ note（需求摘要）/ created_at；每文档保留最近 10 份，超出删最旧。

**文件存储 `userData/office/<id>/`，按 kind 双轨**：

| kind | 目录内容 |
|---|---|
| docx | `original.docx`（导入原件存档，永不改写）+ `content.md`（编辑真相源）+ `images/`（导入提取图片） |
| pptx | `original.pptx` + `content.md`（大纲真相源：`## 页标题` + 要点列表，导出按 `##` 切页） |
| xlsx | `book.xlsx`（真相源，SheetJS 直接读写） |
| txt / csv / md | `content.*`（直接编辑） |

- **导入**：系统多选对话框 → 复制入库 → 转换生成真相源；转换失败则该条目不入库（原子性），toast 原因；单文件上限 50MB；重名允许（各自独立 id）。
- **保存**：编辑自动落盘（textarea 防抖 + 失焦/切回列表前 flush），无手动保存按钮。
- **导出到电脑**：从真相源实时生成对应格式文件 → `showSaveDialog` 另存。
- **删除**：入回收站新增「办公台」组（软删目录 + 3 天自动彻底删，走回收站通用链路）；删除有二次确认（全局规则）。

## 五、模块界面与编辑视图

**主页 = 列表态**：

- 头部：新建按钮组（Word / Excel / PPT / 文本 / Markdown）+ 「导入」+ 搜索框 + 类型筛选下拉（全部 + 六类型各带计数，ActionMenu 同款）。
- 文档行：名称 + 类型徽章 + 大小 + 更新时间；行操作：打开（点行）/ 重命名 / 导出到电脑 / 删除（二次确认）。
- 空状态引导。

**文档视图 = 主栏内列表态 ⇄ 文档态切换，保留顶栏（返回 + 文档名 + 类型徽章 + 导出 + 历史版本）**：

| 格式 | 内容区 | 编辑形态 |
|---|---|---|
| docx / md | 渲染态 MdView（图片正常显示）⇄ 编辑态 textarea，顶栏按钮切换，默认渲染态 | md |
| txt | 恒编辑态纯文本 | 纯文本 |
| xlsx / csv | sheet 页签（多 sheet 切换）+ 自研轻量网格：行号 + 列标（A/B/C…）、单元格点击选中直接输入编辑、Enter/Tab/方向键导航、增删行列按钮 | 网格值 |
| pptx | 大纲编辑态（md）⇄ 预览态（每页一张 16:9 卡片渲染标题+要点，纯 div） | md 大纲 |

- **每类文档底部都有指令条**（见第六节）。
- 性能边界：>2000 行大表 toast 提示「大表建议用本机 Excel 编辑」，网格仍可打开；不做虚拟滚动。

## 六、AI 智能体管道

- **场景标签**：`office:doc`（docx/md/txt）、`office:sheet`（xlsx/csv）、`office:ppt`（pptx）；进 AI 用量统计口径；注入我的画像（照全局惯例）。
- **指令条交互**：
  - 输入需求回车 → 指令条生成态（loading，可取消——取消则不写入）。
  - 主进程单次调用 LLM（`chatCompletion`，全项目非流式，v1 同步）：生成中指令条显示进度指示，完成后文档一次性更新。
  - Word/PPT：LLM 返回 md → 写入前自动快照 → 写入 → 文档刷新；Excel：LLM 返回结构化二维表（表头+行 JSON）→ 快照当前 sheet → 重写网格（指令条上方提示「将重写当前工作表」）。
  - 失败 toast 原因，文档保持不变。
- **动作选择**：指令条右侧小下拉【改写整篇 ｜ 续写在末尾】默认改写整篇；编辑态存在选区时自动锁定为「改写选区」（空文档则按需求生成整篇）；该下拉仅文档类（docx/md/txt/pptx）显示，Excel 固定为「重写当前工作表」无动作下拉。
- **版本兜底**：每次 AI 写入前自动存一版到 `office_versions`；顶栏「历史版本」入口列出（时间 + 需求摘要），可一键恢复。
- **边界**：LLM 未配置时指令条不置灰，点击弹窗提示并「去配置」直达个人中心（全局规则）；不新增右栏 debugzi 频道，多轮修改 = 指令条多轮输入；不走超级工作台后台任务队列（交互式直调）。

## 七、技术选型与实现细节

**新增依赖（全部纯 JS，无需原生编译）**：

| 库 | 用途 |
|---|---|
| mammoth | docx → HTML 读取 + 图片提取（自定义 handler 存 `images/`） |
| turndown + turndown-plugin-gfm | HTML → md（表格支持） |
| docx | md → docx 导出生成 |
| xlsx（SheetJS） | xlsx / csv 读写 |
| pptxgenjs | 大纲 md → pptx 导出 |
| jszip（pptxgenjs 已依赖） | pptx 读取：解 zip 提取各 slide 的 `<a:t>` 文本组织成大纲（pptx 本质 zip+xml，不引重型库） |

md 解析复用项目已有 `marked.lexer`（tokens → docx/pptx 映射）。

**md ↔ docx 保真范围（明确）**：

- 保留：标题层级、段落、粗斜体删除线、有序/无序列表、表格、图片、引用、代码块、分隔线、链接。
- 丢弃：字体字号颜色、页眉页脚、批注、文本框、复杂嵌套排版（导出为「重新排版」的规范文档——md 中转方案的固有取舍）。

**导出排版**：宋体正文 / 黑体标题、A4 页边距、标题层级映射、中英文规范间距。

**图片链路**：bzres:// 协议已存在，新增 `office/<id>/images/` 路由；渲染态正常显示导入图片，导出 docx 时读文件嵌回。

**主进程**：新服务 `electron/services/office.ts`——IPC 一组：`office:list` / `office:import` / `office:create` / `office:rename` / `office:open`（读真相源）/ `office:save`（写真相源）/ `office:export` / `office:discard` / `office:restore`（回收站联动）/ `office:versions` / `office:restoreVersion` / `office:aiWrite`（交互式直调 LLM，不走后台任务队列）；格式转换封装 `electron/services/officeConvert.ts`。

**渲染层**：`src/modules/office/`——`OfficeModule`（列表态/文档态）、`DocGrid`（Excel 网格）、`SlidePreview`（PPT 预览）、`InstructionBar`（指令条）等。

## 九、行为边界

- 原件（original.*）永不改写；所有编辑只发生在真相源（content.md / book.xlsx / content.*）。
- 导出的 docx/pptx 为「从真相源重新排版生成」，与原复杂样式有差异。
- 公式不计算：网格显示 xlsx 里存的缓存计算结果，App 内改值后公式结果不重算（提示以文件内缓存为准）；要重算回本机 Excel。
- 删除、彻底删除均二次确认；回收站恢复回办公台列表。
- LLM 生成失败/取消不动文档；版本快照仅 AI 写入触发，手改不快照。
