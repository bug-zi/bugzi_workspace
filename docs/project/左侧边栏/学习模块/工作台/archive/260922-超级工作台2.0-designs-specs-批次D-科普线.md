## 0. 对实施计划的两点工程化细化（不偏离总纲决策）

1. **中文轻加工改逐块 JSON**：计划 D4 原文「LLM 输出 JSON {md, concepts}」单次输出。长科普文（>8k 字符）单次 JSON 输出必然截断，故改为**照 interpret.ts 逐块续跑模式**：每块返回 `{md, concepts:[{term}]}`，`## 第 N 部分` 幂等续跑，concepts 跨块聚合去重。产物仍为「完整加注版全文」，硬约束「不删减原文信息点」不变。
2. **`embed_science` 不在本批入队**：该任务类型批次 F1 才注册，本批若入队会以「任务类型未注册」失败。本批解读完成尾只做 D5 概念建链（纯 DB 匹配，不依赖向量）；F1 落地时再在完成尾挂 `embed_science` 入队。

## 3. 转正分流 + 全文抓取 `science.ts`（新文件）

- `papers.ts acceptDiscover` 改路由：行 `source_type === 'article'` → `scienceAcceptRow(row)`（science.ts），否则现状不变。**渲染层 `discoverAccept` 调用零改动**；返回类型放宽为 `{ paperId: number } | { scienceId: number }`（preload/api.d.ts 同步，LiteraturePanel 不使用返回值）。
- `scienceAcceptRow(row)`：事务内 discover 置 accepted → 插 `science_articles`（元信息平移、language 原值、discovery_id 回链、status 初始 'meta_only'）→ 返回 scienceId；随后 `enqueue('science_fetch', { refId: scienceId, trigger: 'auto' })`。
- `science_fetch` 任务（`registerTask({priority:10, singleton:true, maxRetries:1})`）：`politeFetch(url)` → linkedom `parseHTML` + `Readability` → `textContent` 纯文本（papers 同款，≥200 字符）→ 存 `science/{id}.txt`，置 ready + fulltext_path；**任一步失败置 meta_only 不抛错**。完成后按 language 自动入队解读：en → `science_translate`、zh → `science_light`（trigger 'auto'）。全文缓存原始纯文本同时作为 D4 轻加工的原料与 D1 计划「原文留档可对照」的载体。
- 服务函数：`listScienceArticles()`（联 domain_name，id DESC）、`getScienceArticle(id)`、`listScienceHighlights(articleId)`、`scienceRelated(articleId)`（照 paperRelated：knowledge_links 联表标题，本批 dst 可为 wiki/paper）。
- `deleteScienceArticle(id)`（彻底删，不入回收站）：先库后文件——删 interpretations（连带 md 产物文件）、science_highlights、embeddings（science_article）、knowledge_links（双向）、science_articles 行；删 `science/{id}.txt`（try/catch 留痕）。
- `retryFetch(id)`：meta_only 条目重跑抓取（成功置 ready 并照常入队解读；解读产物已存在则不重复入队）。

## 4. 科普解读 `interpretScience.ts`（新文件）+ 追问扩展

- 公共同 interpret.ts 惯例：`ensureAlive` / `tokenTracker`（scene 前缀 `agent:s`+）/ `chunkText` / `wrapMaterial` 包裹全文原料 / 全文缺失（meta_only 且无 txt）时——translate/light/lecture 均退化为**摘要版**并在卡头注明 `> ⚠ 全文缺失，以下基于摘要生成（可「重试抓取」后重新生成）`（不抛错，决策 #8 口径下轻加工无全文时只能退化）。
- **`science_translate`**（en 自动 + 可重生成）：① 术语表先行（复用机制：全文截 40k → JSON glossary 10-30 条 → 存 `science_articles.glossary`）；② 逐块翻译（system 注入术语表统一定译），`## 第 N 章` 幂等续跑；产物 `md/interpretations/sa-{id}-translate.md`，头 `# 解读：{title}` + 来源行 + 术语表；登记 `interpretations(owner_type='science_article', kind='translation')`。concepts 取 glossary 术语表（D5 建链输入）。**产物内不做 wiki:// 内嵌标注**（术语已由术语表统一，双链经「关联词条」chips 呈现）。
- **`science_light`**（zh 自动）：逐块 LLM `jsonMode` 返回 `{md, concepts:[{term}]}`——md 为该块**完整加注版全文**：结构导航（小节标题/要点提示）、术语首现括注简释、**概念以 `[术语](wiki://术语)` 内链标注**（仅确定是概念/术语的词，每块 ≤10 个，宁缺毋滥）、**硬约束「不删减原文信息点」**（科普不压缩红线）；`## 第 N 部分` 幂等续跑；concepts 跨块聚合去重（含 md 已标注 + 未标注但值得建链的术语，每块 ≤10）。产物 `md/interpretations/sa-{id}-light.md`，登记 kind=`'light'`；concepts 写 `science_articles.concepts`（`[{term, entry_id|null}]`，entry_id 由 D5 匹配回填）。
- **`science_lecture`**（按需，双语言可用）：逐块中文精讲（interpret.ts lecture 同构），产物 `sa-{id}-lecture.md`，kind=`'lecture'`；重复触发走 INTERPRET_EXISTS 确认重生成。
- 幂等入口 `runScienceInterpret(articleId, kind: 'translate'|'light'|'lecture', force)`：照 `runInterpret` 口径（running 抛「进行中」；done 且 !force 抛 `INTERPRET_EXISTS`）。
- 三个 runner 完成尾：调 `science.ts linkConcepts(articleId)`（D5）。
- **追问扩展**（`ask.ts`）：`startLiteratureAsk(owner: { type: 'paper' | 'science', id })`——science 分支注入：解读产物（translation || light 优先读 md）|| `science/{id}.txt` 节选 40k（wrapMaterial），标记 `<<<LIT:SA:{id}>>>`（`ai/services.ts:347` 的 `LIKE '%<<<LIT:%'` 匹配零改动）；标题/作者/链接元信息同 paper 版式。IPC `agent:askLiterature(type, id)`，preload 签名改 `askLiterature(type: 'paper' | 'science', id)`；LiteraturePanel 调用点同步迁移 `('paper', id)`。

## 5. 词条↔文章双向链接（`science.ts` + IPC + MdDialog）

- **自动建链 `linkConcepts(articleId)`**（translate/light 完成尾调用）：读 `concepts` JSON，逐 term 匹配 `wiki_entries`（`deleted_at IS NULL AND state != 'pool'`）：title 精确 = score 1 → 命中；否则 LIKE 双向模糊（`w.term LIKE '%'||term||'%' OR term LIKE '%'||w.term||'%'`，取 id 最小一条）= score 0.8。命中：`INSERT OR IGNORE knowledge_links(src='science_article', dst='wiki', origin='similarity', score)` + 回填 `concepts.entry_id`；未命中 entry_id 保持 null 待「建词条」。全量写回 concepts JSON。
- **「建词条」回写**：新 IPC `agent:scienceLinkManual(articleId, term, entryId)`——concepts 该 term 的 entry_id 回填 + `knowledge_links(science_article→wiki, origin='manual', score=1)` INSERT OR IGNORE（DDL CHECK 只有 manual/similarity，语义归位照确认项 #3：自动写入=similarity，人确认写入=manual）。
- **链接查询 IPC（批次 F 复用）**：
  - `agent:linksList(srcType, srcId)`：**双向合并**（`WHERE (src_type=? AND src_id=?) OR (dst_type=? AND dst_id=?)`），联表解析 peer 标题（paper→papers.title / wiki→wiki_entries.term / science_article→science_articles.title），返回 `{ link_id, peer_type, peer_id, title, origin, score }[]`，score DESC。
  - `agent:entitySearch(type: 'paper'|'science_article'|'wiki', q)`：LIKE 标题/词条名前 10 条 `{id, title}[]`（批次 F 扩 book/learn_node）。
  - `agent:linkAdd(srcType, srcId, dstType, dstId)` / `agent:linkDel(linkId)`：本批建好 IPC 层（UI 批次 F；linkAdd 直写 origin='manual'，UNIQUE 冲突静默跳过）。
- **MdDialog 可选 prop `onWikiLink?: (term: string) => void`**：渲染 effect 的链接拦截处增加 `wiki://` 前缀分支——`e.preventDefault()` + `onWikiLink?.(decodeURIComponent(href.slice(7)))`；prop 缺省时行为与现状完全一致（零波及）。
