# 学习库题库页签化与「已掌握」标签页 设计

> 创建于 2026-09-24 02:05
> 来源：优化建议区第 54 轮（260924）

## 背景与需求

题库面板顶部原为按钮条（去搜集/待审核/手动添加题/分类管理 + 视图切换「返回题库」），开发者提出四点：①「去搜集」位置应显示「题库」页签；②「待审核」改为页签直达、删「返回题库」；③新增「已掌握」页签（具体用法需设计）；④「去搜集」移至最右（原分类管理位）、分类管理移至手动添加题右侧。

## 决策（brainstorming 两问拍板）

1. **题库排除已掌握**：题库页签 = 待攻克区（待刷 + 复习中），毕业题只出现在「已掌握」页签，两处不重复出现同一题。
2. **回炉重刷双入口**：已掌握列表行 + 查看弹窗均提供「回炉重刷」（二次确认）——重置回待刷态重新进入 1/3/7/15 天复习轮转，用于发现自己又忘了的题。

## 设计

### 「已掌握」定义

`state='learned' && review_stage>=5` 的毕业题（走完 1/3/7/15 天四轮复习，与 learn_nodes 状态机口径同构）。

### 页签结构（InterviewBankPanel）

- 头部第一组 = 页签胶囊（recycle-tabs 样式，与学习库主 tab 视觉一致）：**题库｜待审核 (N)｜已掌握 (N)**，点击直达切换，无「返回题库」。
- 动作按钮：手动添加题、分类管理紧随页签；去搜集（primary）居最右（原分类管理位）。
- 分类胶囊行题库/已掌握两页签共用（共享 catId 选中态）；待审核页签不显。
- 渲染层派生 bankList/masteredList 过滤，零后端查询改动；搜集完成 toast 点击跳审核改切页签（语义不变）。

### 回炉重刷

- `interview:mark` 扩第四动作 `'reburn'`：仅毕业题可回炉（守卫拒绝其余状态），置 `state='todo', review_stage=0, next_review_at=NULL, learned_at=NULL`（与 schema todo 默认一致）；回炉后题目回待刷池，可被「随机来一条」抽中。
- 入口：已掌握行尾 replay 图标 + 对照态弹窗只读条内「回炉重刷」按钮；均经 ConfirmDialog 二次确认（明示清空复习进度）。
- preload/api.d.ts mark 签名同步联合类型；零 DB 迁移。

### 个人档提纲高亮修复（同轮另一条，未开 brainstorming）

keep-alive 下 ProfileModule 挂载于 display:none 隐藏态，挂载即执行的高亮首算中本模块各 zone rect 全 0，`0 - base ≤ 88` 恒真走到底误高亮末项「超级工作台」。修复：①onScroll 加隐藏守卫（pageRef 宽度为 0 跳过计算）；②useModuleActivated 激活时双 rAF 重算（激活事件先于 React 渲染提交，rAF 等布局）对齐真实滚动位置。

## 影响面

- 渲染层：`src/modules/learn/InterviewBankPanel.tsx`（页签化 + 已掌握 + 回炉）、`src/modules/profile/ProfileModule.tsx`（高亮修复）。
- 主进程：`electron/ipc.ts` interview:mark 扩 reburn；`electron/preload.ts` / `src/renderer/api.d.ts` 签名同步。
- 零 DB 迁移、零 AI 改动。
