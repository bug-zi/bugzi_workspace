# 学习库面经题库化（学习库 v3）设计记录

> 创建于 2026-09-24 00:32
> 来源：`docs/project/优化建议区.md` 待完成区任务（开发者 260924 提出，当日 brainstorm 商定）。
> 定位：学习库从「知识卡片浏览」改造为「面经题库刷题」——以 Go 后端开发面试准备为目标，AI 联网搜集真实面经拆题入库，刷题 = 先回忆再对照自评 + 间隔复习。本文件为实施设计记录。

## 一、需求结论（brainstorm 摘要）

| 维度 | 结论 |
|---|---|
| 学习目的 | 准备跳槽/面试（开发者明确：这是当前主线） |
| 目标岗位 | **Go 语言后端开发**（非 Java；分类/搜索词/考点一律按 Go 生态） |
| 题库覆盖 | 传统 Go 后端考点 + **AI 应用开发**（开发者点名 Eino；RAG/向量检索/function calling/MCP/Agent 也必考） |
| 题目来源 | **AI 联网搜集真实面经**（MCP 搜索 → 抓文章 → 拆题），不要凭空生成，不依赖手动收集 |
| 体系关系 | **题库为主体改造**：每日要求/打卡循环全部切到刷题；知识树降级为自学参考区原样保留 |
| 刷题形态 | **先回忆再对照自评**（Anki 式检索练习）：看题 → 自行回忆 → 翻开参考答案对照 → 自评；不做打字作答/AI 判卷 |
| 复习机制 | 复用现有间隔复习状态机 1/3/7/15 天 → 毕业，「会了/记住了」升档、「不会/忘记」回档 |
| 每日要求 | 每日刷 N 题打卡（goal 8-10 保持），连胜/热力图照旧 |
| 原小测处置 | LearnQuizZone「小测交卷」退出每日要求（刷题本身就是做题，冗余）；组件代码暂留不删 |

## 三、数据模型（DB v52，实际版本号以实施时递增为准）

```sql
-- 面试题分类（出厂 seed 15 类，sort 0-14）
CREATE TABLE interview_categories (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  sort INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);

-- 面试题（复习三列与 learn_nodes 同构，状态机逻辑直接复用）
CREATE TABLE interview_questions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  category_id INTEGER NOT NULL,
  question TEXT NOT NULL,            -- 题干
  question_norm TEXT NOT NULL,       -- 规范化题干（去空白/标点、小写，查重用）
  answer_path TEXT NOT NULL,         -- 参考答案 md/learn/interview/<id>.md
  source TEXT NOT NULL DEFAULT '',   -- 来源（面经文章标题/站点）
  state TEXT NOT NULL DEFAULT 'todo',          -- todo | learned
  review_stage INTEGER NOT NULL DEFAULT 0,     -- 0=未刷 1..4=复习四档 5=毕业
  next_review_at TEXT,                         -- 本地日期 YYYY-MM-DD；NULL=未刷/毕业
  learned_at TEXT,                             -- ISO 时间；今日刷题数统计依据
  deleted_at TEXT,                             -- 回收站软删
  created_at TEXT NOT NULL
);
CREATE INDEX idx_iq_category ON interview_questions(category_id, state);
CREATE INDEX idx_iq_review ON interview_questions(next_review_at);

-- 搜集待审核（收件箱；采纳才进 questions）
CREATE TABLE interview_intake (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  category_id INTEGER,               -- AI 建议分类（识别不了为 NULL，审核时可指定）
  question TEXT NOT NULL,
  question_norm TEXT NOT NULL,
  answer_path TEXT NOT NULL,         -- 暂存答案 md/learn/intake/<id>.md
  source TEXT NOT NULL DEFAULT '',
  batch_id INTEGER NOT NULL,         -- 搜集批次号
  status TEXT NOT NULL DEFAULT 'pending',  -- pending | adopted | discarded
  created_at TEXT NOT NULL
);
```

- **learn_daily 表零改动复用**：`goal` 语义改为「每日刷题数」（`8 + random(0..2)` 不变），`review_ids` 改存到期题目 id JSON 数组，`done` 与连胜推导照旧。历史 done 记录保留（打卡连续性不断）。
- **知识树零改动**：learn_nodes / learn_highlights / 全部现有数据原样保留；learn_nodes.learned_at 列保留（知识树自学仍用）。
- **答案 md**：`md/learn/interview/<题目id>.md`（要点式参考答案，见 §四）；intake 暂存 `md/learn/intake/<intakeId>.md`，采纳时移动为正式路径。
- **每日定档**：双触发不变（main.ts 启动延迟 + scheduler 午夜零点）——learn_daily 无今日行则定 goal + 算到期题目 review_ids（到期上限 10、超出顺延机制照旧）；幂等照旧。

## 四、搜集拆题流程（agent 任务队列）

新任务类型 `interview_collect`，走现有 agent 队列（enqueue/任务中心可见/可取消/预算卫兵，llm_usage 记账 scene `learn:interview-collect`）。一个批次：

1. **选关键词**：关键词池轮转（传统：「Golang 面试题 高频」「Go 后端面经」「Go 面经 GMP channel」…；AI 主线：「Go 面经 Eino」「Golang RAG LLM 面试」「Go Agent MCP 面试」…）；**todo 存量最少的分类优先**定向补弱（每次任务选 2-3 个关键词）。
2. **MCP 搜索**：`searchViaMcp`（electron/services/agent/sources/mcpSearch.ts 现成通道，findSearchTool 自动发现搜索类工具）逐关键词搜索，取面经文章链接。
3. **抓正文**：复用信息源 extractArticle（net.fetch + readability，自动跟随系统代理）。
4. **LLM 拆题**：从文章**提取真实出现的面试题**（不编题），材料答案不全时基于模型知识补全；答案整理为**要点式参考答案 md**（分点、精炼、8-15 行，适合「先回忆再对照」；代码/命令用代码块）；AI 同时标注建议分类（十五类枚举内）。
5. **norm 查重**：题干规范化后对 interview_questions + interview_intake 全量查重，命中跳过；同义改写不做语义去重（人工审核兜底）。
6. **入待审核**：intake 行 pending + 答案写盘；批次完成广播 → toast「面经搜集完成 N 题，点击审核」→ 点击跳审核面板（AI 后台任务完成轻提示全局范式）。

- **触发**：题库页「去搜集」按钮手动为主；进题库模块时 todo 总数 < 10 → toast 提醒「题库存量不足，去搜集一批」（不自动跑，防审核积压）。
- **容错**：单文章抓取/拆题失败跳过继续（留痕日志）；MCP 未启用/无搜索工具、LLM 未配置 → 全局规则提示「去配置」；批次全失败 toast 报错。
- **JSON 解析容错**：拆题输出解析参照灵感泉 parseInspirationArray 先例（字段缺失/格式漂移容错）。

## 五、刷题与复习流转

**状态机**（与 learn_nodes 逐字同构）：

```
新题(todo) ──会了──▶ learned(stage1, 次日复习) ──记住了──▶ +3天 → +7天 → +15天 → 毕业(stage5, 不再出现)
                          ▲                                  │
                          └────────── 忘记了（重置 stage1 次日再来）──┘
```

**刷题交互**（刷题弹窗内）：

1. 打开 → 只显示题干 + 分类徽章 + 来源，答案折叠，提示「先自己回忆/口述一遍」。
2. 点「查看参考答案」→ 展开（MdView 渲染答案 md），对照自己的回忆。
3. 底部自评条：
   - **新题（todo）**：「会了」＝学会了（state=learned、stage=1、learned_at=现在，计今日刷题数）｜「还不熟」＝保持 todo 不计数不落状态，明天题库/随机还会遇到（不会的题自然反复出现直到会了）。
   - **到期复习**：「记住了」升档｜「忘记了」重置 stage1 次日（照旧）。
   - 已学未到期 / 毕业：只读徽标 + 下次复习日期（照旧）。

**每日要求闭环**：

- done 联动 check-and-set：mark 动作（会了/记住了）后检查——今日新刷题数（learned_at=今日）≥ goal → done=1 → toast「今日要求完成！」。
- 连胜从 learn_daily.done 逐日回数推导（照旧）；总导览热力图读 learn_daily.done 零改动自动兼容。
- 复习不计入 goal（与原口径一致）。

**随机来一条**：题库 todo 池均匀随机抽 1 题秒开（题目入库即带答案，**无备学池泵**——搜集流程天然是备池动作）；刷完照常走状态机计入今日。

## 八、容错与边界

- **MCP 未启用 / 无搜索工具**：「去搜集」点击 → 全局规则弹窗提示「去配置」；已有题库刷题流转完全不受影响（零 MCP）。
- **LLM 未配置**：搜集/拆题/手动补答案不可用（去配置提示）；定档、刷题、状态机、打卡连胜完全不受影响。
- **抓取失败**：单文章跳过继续（反爬/超时常态），批次部分成功即可交付。
- **拆题质量**：审核环节兜底——不合格题丢弃，不污染题库。
- **重复搜集**：norm 查重保证同一题不重复入库；intake 中已 pending 的重复题也跳过。
- **删分类**：连带删题入回收站（明示计数）；分类删除后题目恢复需分类存在——沿用学习库「清空才能删」教训，改为**级联删除 + 确认弹窗明示**（学习库 v44 级联先例）。
- **当日未刷完**：无惩罚，次日重新定 goal（照旧）。
- **learn_daily 迁移**：表结构不变，无需迁移行；切换日起 goal 语义即新语义。

## 九、不做（YAGNI）

- 不做语义/向量去重（norm 去重 + 人工审核兜底）。
- 不做打字作答 / AI 判卷 / 选择题形态。
- 不做题目挂知识树节点（两套体系互不挂接）。
- 不做定时自动搜集（手动触发 + 阈值 toast 提醒）。
- 不做刷题统计报表 / 正确率曲线（热力图照旧）。
- 不做分类间拖拽移动（改分类走行菜单）。
- 不做毕业题「重新刷」专门入口（「忘记了」重置已覆盖遗忘场景）。
- 不做答案版本历史（答案 md 即正文，可随意改）。
- 不做题目划词高光（高光表强绑定 learn_nodes，题目不支持；「问 AI」可用）。
- LearnQuizZone 组件代码暂留不删（避免连带改动；页面移除其渲染）。
