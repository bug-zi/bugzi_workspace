# 论文库 / 万象库·科普：抓取三页签阅读设计（取文+翻译入管道 · 原文/导读卡/精读版）

> 创建于 2026-09-29 00:32

来源：开发者 260929 brainstorming 拍板——发现箱「接受」后统一「抓取中」管道（抓全文 → 非简中翻成简中 → 科普概念建链），**就绪才可打开**；打开即三页签：**原文（简中全文，默认）｜导读卡（大致内容+文章脉络）｜精读版（关键部分拆解）**，仅此三个页签。与 260928 三态化（`2026-09-28-转正状态呈现-design.md`，实际落地为 DB 两态 `ready/meta_only` + task_runs 派生「抓取中」）衔接：本设计沿用该状态机制，只换管道内容与门禁。

## 1. 现状与差距

| 模块 | 现有视图 | 现有管道 |
|---|---|---|
| 论文库 PaperReader | 导读卡（默认，接受后自动生成、可摘要退化）｜精讲｜精译｜原文 | 抓取藏在 make_digest（runner 内 ensureFulltext）；lecture/translate 按需 |
| 科普 ScienceReader | 解读版（默认；en=全文翻译／zh=轻加工，语言自动分流）｜精讲｜原文 | science_fetch 抓全文 → enqueueAutoInterpret 按语言分流解读；zh 轻加工=加注版全文（结构导航+术语括注+wiki://内链），概念建链挂解读产物尾部 |

差距：翻译是独立解读产物而非「原文」本体；zh 科普文章被打包成加注版；导读卡自动生成且论文可摘要退化；无打开门禁；精讲/精译/解读版三套产物与新需求的三页签不对位。

## 2. 目标流程（定稿）

```
发现箱「接受」
   │ INSERT meta_only + 入队 paper_fetch / science_fetch（trigger 'auto'）
   ▼
抓取中（meta_only 且该 ref 在队/在跑，列表徽章「抓取中」；行不可点开，点击 toast 提示）
   │ 幂等管道：readability 抓全文 → 非简中则 术语表+逐章翻译（translation 产物 = 原文中文版）
   │           → 科普概念提取 + 词条自动建链 → 置 ready
   ├── 成功 → ready 全文就绪（简中全文可读，行可点开）
   └── 失败 → meta_only 且无在队任务 = 抓取失败 → 行内「重试抓取」（论文另有「导入 PDF」）
   ▼
打开（仅 ready）→ 三页签：原文（默认，简中）｜导读卡｜精读版
```

## 3. 后端任务设计

### 3.1 paper_fetch（新，论文）

- runner：`ensureFulltext`（现有抓全文逻辑不动）→ `language==='en'` 且无 translation 产物 → 术语表先行+逐章翻译（复用现 runTranslate 主体，产物头改「原文（中文）」，kind=translation）→ 置 ready → `enqueue embed_index`（相关推荐，时点自导读卡前移至此）。
- **幂等**：已有全文与译文则秒回——accept、行内重试、导入 PDF 后补译三个入口共用同一任务。
- 触发变化：acceptDiscover 由自动入队 make_digest 改为入队 paper_fetch。

### 3.2 science_fetch（扩展，科普）

- runner：`ensureScienceFulltext` → en 无译文则翻译（复用 runScienceTranslate，产物头同上）→ **概念提取建链**（原挂解读产物尾部，改挂管道尾）：en 直接用 glossary 术语零 LLM 调用、zh 一次轻量 LLM 提取 3-8 个概念词 → `mergeScienceConcepts` + `linkConcepts` → 置 ready。
- `enqueueAutoInterpret`（en→translate／zh→light 语言分流）删除；`retryScienceFetch` 保留为行内重试入口（内部改走扩展后管道）。

### 3.3 make_digest 改按需 + prompt 换骨架（论文）；新增 science_digest（科普）

- make_digest 不再被 accept 自动入队，仅导读卡页签「生成」触发；runner 去掉 ensureFulltext 前置（管道已保证），改守卫「中文原文未就绪即报错」；**摘要退化路径删除**。
- 导读卡 prompt 两模块统一（原文已是简中，生成函数参数化 owner_type 共用一套）：`# 大致内容`（200-400 字概括）+ `# 文章脉络`（按原文行进顺序逐节梳理，每节一两句）。科普走新任务类型 science_digest。

### 3.4 deepread 精读版（新，两模块）

- kind=`deepread`；逐章切块续跑（沿用 chunkText + `## 第 N 部分` 幂等落盘标记，长文不炸）。
- prompt：从本部分中挑出关键部分与关键句（引用简中原文），逐条拆解分析——论证结构、术语含义、隐含假设、与全文主线的关系。
- 任务类型：论文 paper_deepread、科普 science_deepread；均要求 ready。

### 3.5 退役与 token 场景

- 注册删除：`lecture`、`translate`、`science_translate`、`science_light`、`science_lecture`；渲染层 queue 事件消费点同步清理。
- token 场景：沿用 `agent:digest`／`agent:translate`（并入 paper_fetch）／`agent:s-translate`（并入 science_fetch）；新增 `agent:deepread`（论文精读）、`agent:s-digest`、`agent:s-deepread`。llm_usage 记账口径不变。

## 4. 数据与迁移

- kind 收敛：`'digest' | 'translation' | 'deepread' | 'book_digest'`（`src/shared/types.ts` 与 `src/renderer/api.d.ts` 同步；`runInterpret` / 科普 `interpret` IPC 签名同步改）。DB 表结构零变更（kind 为 TEXT），无版本升级。
- 清理（bootstrap 幂等迁移：按 owner_type+kind 查 interpretations，删行并对 md_path 执行 mdDelete）：
  - papers：kind=`lecture`；
  - science_articles：kind=`lecture` + kind=`light`；
  - **translation 保留**——升格为「原文（中文版）」载体，旧译文直接复用，不重复花 token（此为本设计对「彻底清理旧产物」的收敛口径：翻译不再是待清理的旧解读，而是原文本体）。
- 随 light 退役的既有能力：加注版全文（结构导航/术语括注/wiki://概念内链）不再产出，zh 科普原文页签显示 readability 纯文本；存量 concepts 数据与词条链接不动。

## 5. 渲染层

### 5.1 列表（LiteraturePanel / SciencePanel）

- badge 三态：ready=全文就绪（主题色）／meta_only+在队或跑=抓取中…／meta_only+无任务=抓取失败。
- **门禁**：仅 ready 行可点开阅读视图；非 ready 点击 toast（抓取中提示稍候、失败提示行内重试）。
- 失败行内操作：重试抓取（论文→入队 paper_fetch；科普→retryScienceFetch）；论文另有「导入 PDF」（自 PaperReader 内迁来，导入成功后 en 自动入队补译）。
- fetchingIds 派生源：论文 `make_digest` → `paper_fetch`；科普 science_fetch 不变。

### 5.2 阅读器三页签（PaperReader / ScienceReader）

- 页签「原文｜导读卡｜精读版」，默认原文，样式沿用 recycle-tab。
- **原文**：en 显示 translation 产物、zh 显示 raw 全文缓存；只读；划词问 AI（右栏「文献」等频道照旧）；科普划词高光作用于原文。旧英文条目无译文：打开原文页签时自动入队对应 fetch 任务，页签显示译文生成中占位。
- **导读卡／精读版**：空态=「生成」按钮；生成中占位（activeTasks 派生，5s 轮询刷新沿用现状）；已有产物支持就地编辑与重新生成（二次确认）。旧导读卡为旧六段格式，可重新生成换新骨架。
- 两 Reader 保留各自侧栏能力（论文：相关推荐/知识链接；科普：建词条/词条回链/章节等），只动页签内容区。

### 5.3 任务中心（AgentCenterPage）

- 标签映射增：paper_fetch=抓取全文、paper_deepread=精读、science_digest=科普导读、science_deepread=科普精读；删 lecture/translate/science_translate/science_light/science_lecture。

## 6. 边界与取舍

- LLM 未配置：zh 条目抓取（readability）照常完成可读；en 翻译与导读/精读生成在 runner 内 `isLlmConfigured` 抛错，任务失败呈现，符合「未配置弹窗提示去配置」全局规则。
- 导读卡/精读版生成与打开同受 ready 门禁（打不开即不可生成）。
- 旧译文产物头部文案仍为「精译：/解读：」，仅观感差异，不迁移重写。
- 深读问答（ask.ts）上下文、知识网络相关推荐、KnowledgeLinksDialog 手动建链、词条回链跳转均不动；仅 embed_index 时点前移。
- MAX_CONCURRENT=2、singleton 语义、预算卫兵、任务队列启动恢复、自愈（ready 缺缓存回抓）全部沿用。
