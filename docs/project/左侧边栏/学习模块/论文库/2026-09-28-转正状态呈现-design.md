# 论文库 / 万象库·科普：转正后状态呈现设计（三态 + 自愈 + 解读生成中占位）

> 创建于 2026-09-28 01:39

来源：优化建议区第 60 轮第 4 条——「论文库和万象库-百科中的文章，从发现箱纳入到正式文章中之后，这个状态呈现还是有问题，『全文就绪』但是加载不出来等，具有误导性」。260928 与开发者 brainstorming 拍板：**三态+自愈** + **解读产物补生成中占位**，两模块统一口径。

## 1. 现状与病灶

| 模块 | 转正瞬间 | 抓取中 | 成功 | 失败 |
|---|---|---|---|---|
| 论文库 papers | INSERT 直接置 `ready`（全文未抓先标就绪）❌ | 徽章「全文就绪」但原文视图落到「缓存缺失」兜底 ❌ 误导 | `ready` + `papers/{id}.txt` 落盘 ✅ | `meta_only`（只有「手动传 PDF」无重试） |
| 科普 science_articles | INSERT `meta_only`（偏保守） | 徽章显「仅元信息」，看不出在抓 ⚠️ | `ready` ✅ | 留 `meta_only`，可重试 ✅ |

**死状态**：转正后抓取中途退出 App → 启动恢复把 task_runs 行终态化 → 论文永远停留「ready 但缓存缺失」，UI 无重试入口（仅手动传 PDF），即用户实测的「全文就绪但加载不出来」。

**解读产物**（导读卡/精讲/精译/科普解读·轻加工）：生成期间无任何占位，完成后凭空出现。

## 2. 状态机定稿（两模块统一）

```
转正（acceptDiscover）
   │ INSERT status='fetching'            ← 论文原为 'ready'、科普原为 'meta_only'，均改
   ▼
fetching 抓取中（含排队等待）             ← 列表徽章「抓取中」；阅读器原文页签占位说明
   │ make_digest / science_fetch 完成
   ├── 全文落盘成功 → ready 全文就绪      ← 缓存文件真实存在才标
   └── 失败 → meta_only 仅元信息          ← 「重试抓取」+「手动传 PDF」（论文补重试）
```

- **`fetching`（新增）**：徽章「抓取中」灰显；阅读器原文页签显「全文抓取中…（失败会自动降级为仅元信息，可重试）」占位。
- **`ready`**：徽章「全文就绪」主题色；原文/解读可读，口径不变。
- **`meta_only`**：徽章「仅元信息」；两模块都给「重试抓取」按钮（论文新增 `retryPaperFetch`，即 `ensureFulltext` + 成功后照常入链导读卡管道）+ 论文保留「手动传 PDF」。

## 3. 自愈（治存量与运行中死状态）

挂在两模块列表读取入口（`listPapers` / `listScienceArticles`，进模块即触发）：

1. `ready` 但缓存文件缺失 → 置 `fetching` 并重新入队抓取（`make_digest` / `science_fetch`，trigger 'auto'）——存量坏数据无感自愈；
2. `fetching` 但缓存文件已存在 → 置 `ready`（写盘成功与状态更新之间崩溃的补账）；
3. `fetching` 且文件缺失 → 查 `task_runs` 是否存在该 ref 的在队/在跑行（enqueue 即插 running 行，故「有行 = 队列中或进行中」），无行才补入队——不重复排队。

文件存在性为 stat 检查，量级几十篇，可忽略。

## 4. 解读产物「生成中」占位

- **判定源**：详情 IPC 载荷增加 `activeTasks: string[]`（该 owner 当前在队/在跑的任务类型，读 task_runs）——论文 `make_digest`/`lecture`/`translate`，科普 `science_fetch`/`science_translate`/`science_light`。
- **阅读器**：解读页签无产物行且对应任务在队/在跑 → 显「生成中…」占位（旋转图标）；已有 agent:status 事件自动 reload，完成即被产物替换。
- 列表行不加速度提示，保持克制（徽章三态已覆盖主体）。

## 5. 改动清单（概要）

- `src/shared/types.ts`：`PaperRow.status` / `ScienceArticleRow.status` 增 `'fetching'`；两 detail 载荷增 `activeTasks`。
- `electron/services/agent/papers.ts`：acceptDiscover 置 `fetching`；hydrate 透传；listPapers 挂自愈；新增 retryPaperFetch。
- `electron/services/agent/science.ts`：scienceAcceptRow 置 `fetching`；hydrate 透传；listScienceArticles 挂自愈（retryScienceFetch 已有）。
- `electron/ipc.ts`：两 detail 载荷补 activeTasks；papers 补 retry 通道（preload/api.d.ts 同步）。
- 渲染层：LiteraturePanel / PaperReader / SciencePanel / ScienceReader 徽章与占位、重试按钮。

## 6. 边界

- `generateDigest` 的 `metaOnly` 判定（status!=='ready' 时降级摘要生成）不受影响——make_digest runner 先抓全文后导读，跑导读时已终态。
- 深读问答上下文（ask.ts）读全文为 null 时本就安全降级。
- 零 DB 迁移（status 为 TEXT 无约束）。
