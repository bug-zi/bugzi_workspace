# 论文库 + 万象库科普「发现箱与正式区领域筛选」— 设计

> 创建于 2026-09-27 01:41
> 来源：开发者优化需求——发现箱与正式区（正式文献/正式文章）均默认全量平铺，无领域筛选，需补领域标签页便于快速筛选
> 范围：`src/modules/literature/LiteraturePanel.tsx`（论文库：发现箱 + 正式文献）与 `src/modules/wiki/SciencePanel.tsx`（万象库科普：发现箱 + 正式文章）两面板同构改造；数据层仅一处补列迁移

## 一、已确认决策

1. **papers 表补列迁移**（非间接映射）：正式文献自持领域，不依赖发现条目存活。
2. **标签集合口径**：全部 + 该轨道全量领域（含已停用，保证存量条目可筛）+ 未分类（锁定末位常驻），文笔坊经验书分类夹同款口径。
3. **筛选行位置与计数**：两子页签（发现箱｜正式文献/正式文章）共用一行领域 tab，放子页签行下方；每个领域 tab 带条目计数；切换子页签保持所选领域。

## 二、数据层（DB v63）

### 1. papers 加列 + 转正复制

- 迁移 v63：`ALTER TABLE papers ADD COLUMN domain_id INTEGER`（可空，无外键约束，随项目惯例）。
- `acceptDiscover`（electron/services/agent/papers.ts）INSERT papers 时补 `domain_id` 列，值取发现条目 `row.domain_id`——对齐科普 `scienceAcceptRow` 既有做法。

### 2. 存量回填

- 迁移内一条 UPDATE：`papers.domain_id ← discover_items.domain_id`（经 `papers.discovery_id` 关联；发现条目已删的留 NULL，归「未分类」）。

### 3. 删领域断链扩展

- `deleteDomain`（electron/services/agent/domains.ts）由只清 `discover_items` 扩为三表断链：`discover_items`、`papers`、`science_articles`（science_articles 此前遗留悬挂 domain_id，一并补齐）。
- 渲染层兜底口径：`domain_id` 为 NULL **或** 不在现存领域 id 集合中的条目，一律归「未分类」（历史悬挂数据自动归位，不丢条目）。

## 三、类型与查询

- `PaperRow` 补 `domain_id: number | null`：`src/shared/types.ts` 与 `src/renderer/api.d.ts` 两处同步（同文件串行改，防并行会话竞态）；`hydratePaper` 补解析；`listPapers` 的 `SELECT *` 已覆盖无需改 SQL。
- DiscoverItemRow / ScienceArticleRow 已有 `domain_id`（后者另有联表 `domain_name`），零改动。

## 四、渲染层（两面板同构）

### 1. 领域列表拆分

- `loadDomains` 现只留启用中领域供海选下拉；拆为两份：
  - `domainsEnabled`：该轨道 `enabled` 领域（海选下拉，现状不变）；
  - `domainsAll`：该轨道全量领域（领域 tab 数据源，含停用，按 id 排序）。

### 2. 筛选状态与 tab 行

- 新 state `domainFilter: 'all' | number | 'none'`（'all'=全部，'none'=未分类），默认 'all'。
- 领域 tab 行置于 `lit-toolbar` / `sci-toolbar` 的 recycle-tabs 下方：`全部(N)` → 各领域 tab（label 领域名 + `（N）`）→ `未分类(N)` 锁定末位。
- **计数口径**：每个 tab 的 N = 该领域在**当前子页签**（发现箱或正式区）筛选前列表中的条目数；「全部」= 列表总数。
- 筛选为纯渲染层过滤（列表量级小，不加 IPC）：
  - 论文库：发现箱按 `it.domain_id`、正式文献按 `p.domain_id`；
  - 科普：发现箱候选按 `it.domain_id`、正式文章按 `a.domain_id`。
- 匹配规则：`domainFilter === 'all'` 全量；`'none'` 取「NULL 或 id 不在 domainsAll 集合」；数字则精确匹配该 id。
- 切换「发现箱｜正式文献/正式文章」子页签时 `domainFilter` 保持不变（同一内容类型的连续浏览体验）。

### 3. 显示条件与空态

- 当前子页签筛选前列表为空 → 整行隐藏（无内容可筛不占空间）；列表非空即显示（无任何领域时仍有 全部/未分类 两 tab，覆盖删领域后场景）。
- 各列表空态文案照旧。

## 五、样式

- 复用 `recycle-tabs` / `recycle-tab` 形态加小号变体：新增单一修饰类 `.domain-tabs`（字号/内边距收紧）定义于 `src/App.css` 全局一处，两面板同用（`<div className="recycle-tabs domain-tabs">`），浅樱粉/深宝蓝主题色系，不引入彩亮色。
- 停用领域的 tab 不做置灰特殊态（与启用领域同权可筛，仅靠个人档管理入口控制后续海选）。

## 六、不做（YAGNI）

- 筛选状态不持久化（keep-alive 内保留，App 重启回「全部」，同万象库顶部页签口径）。
- 不做搜索框、不做语言/来源等二次筛选、不做两子页签各自独立记忆。
- 不在面板内提供领域增删改（管理仍在个人档「超级工作台」）。

## 七、验收

- `npm run typecheck` 双配置通过；`npm run build` 通过。
- 冒烟：
  - 论文库/科普两面板四个列表的领域 tab 计数正确、筛选即时生效、子页签切换保持筛选；
  - 发现箱「接受」转正后，正式区条目领域继承正确（新数据走复制链路）；
  - 存量库升级 v63 后老文献领域回填正确、发现条目已删的归「未分类」；
  - 个人档删一领域后，其条目归「未分类」、其余 tab 不受影响；
  - 停用领域仍可筛；空列表时筛选行隐藏；双主题目检。
- 验证后更新当日 `docs/log/260927.md` 与 README.md（若模块描述需补充领域筛选能力）。
