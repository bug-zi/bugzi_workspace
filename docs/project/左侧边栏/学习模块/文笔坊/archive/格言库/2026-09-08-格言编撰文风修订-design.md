# 格言编撰文风修订设计（2026-09-08）

> 优化建议区待完成条目：「格言库AI生成的句子过于口语化，没有格言的味道。需要进一步优化」
> 经 brainstorming 商讨定稿（方案 A + B），2026-09-08。

## 一、背景与诊断

第 23 轮（260907）句式约束禁掉了 7 类「端着」的对仗套话后，编撰条的正面引导只剩「平实、具体、有画面，靠内容本身立住」。开发者反馈新问题：**过于口语化，没有格言的味道**。

经澄清，失败表现为两类（恰好是两个旧指令各自的极端化）：

1. **像俗语大白话**——说得对但不像格言（「今日事今日毕，别拖」型叮嘱）；
2. **像散文描述**——有画面但没断言力，不能立住。

诊断：禁令全是「不要端着」，正面却没定义「格言文体长什么样」——AI 把「平实」执行成大白话、把「有画面」执行成散文。另经确认：**正式区样本干净**（以真实名言/开发者认可条目为主），问题纯粹在 prompt 正面引导缺失，属单点问题。

## 二、方案 A：prompt 精修——正面定义「格言文体」+ 正反例

把「平实、具体、有画面，靠内容本身立住」升级为五条文风标准，写入 `generateMottos` 的 `buildPrompt`（electron/ai/services.ts:408）编撰条段：

1. **凝练**：一句成型，一般不超 20 字，删一字则伤；
2. **断言**：是一个判断/主张，不是描述、不是叮嘱——说出来就站住，无需论证（打掉散文型）；
3. **普遍**：脱离具体情境依然成立，面向一类人生状况（打掉大白话叮嘱型）;
4. **可诵**：有顿挫节奏，读出声不拗口——但禁止空洞对仗（衔接第 23 轮禁令）；
5. **画面是载体不是目的**：用具体意象承载抽象道理，意象必须为断言服务。

正反例（写进 prompt，格式同第 22 轮灵感泉正反例）：

> ✅ 正例：「刀刃上没有多余的话，锋利就是全部语言。」——意象承载断言，站得住。
> ❌ 反例一（大白话型）：「今天的事别拖到明天，拖着拖着就忘了。」——是叮嘱不是格言，缺断言力与普遍性。
> ❌ 反例二（散文型）：「秋天的落叶铺满了小路，每一步都发出细碎的声响。」——有画面但无观点，画面成了目的。

成本：零（单趟不变）。正反例做法已在第 22 轮灵感泉被验证有效。

## 三、方案 B：口语化正则兜底

沿用第 23 轮 `COMPOSED_BANNED_PATTERNS` + `patternRejected` 机制，在其旁边加第二层兜底 `COLLOQUIAL_PATTERNS`（仅约束编撰条，摘录条豁免——真实名言不受限）：

| 维度 | 规则 | 说明 |
| --- | --- | --- |
| 句尾语气词 | `（呢|吧|啊|嘛|啦|呗|了）[。！？…」"]?$` | 句尾「了」是口语完成体标志；句中「了」（了解/乱了）不误杀 |
| 口语虚词 | 含「其实\|真的\|确实\|反正\|的话\|就是说」 | 大白话填充词，格言体几乎不用 |
| 句首叮嘱式 | `^（你要\|你应该\|你们\|别再\|记得\|赶紧\|千万）` | 叮嘱不是格言 |
| 编撰条限长 | `.{23,}` | 编撰条超 22 字剔除；摘录条不受限（真实名言可长） |

- 命中剔除，计数独立：`GenerateMottosResult` 新增 `colloquialRejected`（区别于第 23 轮 `patternRejected`），经 preload/api.d.ts 透传渲染层。
- toast 有剔除时附加「N 条因口语化未入库」（与既有句式剔除从句同款格式）。
- 正则需正反行为验证（第 23 轮同款做法）：每个维度写正例（应命中）+ 反例（不得误杀）跑一遍 ALL PASS 再入库。

## 五、冒烟清单

1. 手动「来10条格言」数批，观察编撰条：大白话/散文型应显著减少；凝练断言型占主导。
2. 口语化剔除路径：toast 出现「N 条因口语化未入库」的频率合理（非全员剔除）。
3. 摘录条不受新约束影响（真实名言带「了」/超长不误杀）。
4. 正则正反行为验证 ALL PASS（实施时跑，不依赖冒烟）。
