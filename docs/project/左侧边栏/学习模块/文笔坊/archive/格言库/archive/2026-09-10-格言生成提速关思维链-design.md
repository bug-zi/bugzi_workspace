# 格言生成提速——场景级关思维链设计（2026-09-10）

> 优化建议区待完成条目：「格言库生成的质量不错，但是速度太慢了！」
> 经 brainstorming 商讨定稿（方案 A），2026-09-10。

## 一、背景与诊断（实测定位）

开发者反馈：生成质量满意，唯速度太慢。llm_usage 记账（第31轮落地）中唯一一条 `motto:generate`：glm-5.3-flash，**249.7s**，prompt 4,739 tok，**completion 10,046 tok**——而 10 条格言的 JSON 实际仅约 700 字符（~300 token）。

三组对照实测（同 prompt 直连智谱官方 API，260910）：

| 组 | 耗时 | completion tokens | 思维链（reasoning_content） |
| --- | --- | --- | --- |
| A 现状（无参数） | 141.3s | 6,017 | 13,820 字 |
| B `thinking: {type:'disabled'}` | **8.3s** | 277 | 无 |
| C 显式 enabled | 208.2s | 7,843 | 19,660 字 |

**根因**：glm-5.3-flash 默认开启深度思考。格言生成的任务结构（对 102 条避免清单 + 51 条墓碑逐条自查 + 五条文体标准 / 7 类禁句式自检——第 23/24/27 轮质量约束逐轮叠加）恰好诱导模型把「逐条核对」全部写进思维链，6k~10k token 按 ~45 tok/s 解码即 2~4 分钟。质量是思考堆出来的，但思考过程无人消费。

次要因素：补足轮（第24轮）串行追加一趟完整调用，现状最坏 4+4 分钟。

非因素：prompt 4.7k token 的 prefill 秒级（glm TTFT <1s）；思维链在独立字段不污染 content，解析不会因它失败重试；DB/正则均毫秒级。

关思考后的质量看货（实测样例）：摘录 5 条全真（泰戈尔/木心/顾城/毛姆/莎士比亚）；编撰 5 条（「灯不问照多远，它只管亮着。」「雪落下来时，从不挑选屋顶。」「种子不催促春天。」等）符合第 27 轮文体标准形态。且代码侧三道闸（句式正则/口语化正则/墓碑+库内查重）与思考开关无关，退化条目进不了库。

## 二、方案（A：场景级关思维链）

经三案对比定 A（B 配置级 UI 开关表达不了场景差异且复杂度高，被否；C 思考预算折中留作后手）：

1. **`ChatOptions` 增 `thinking?: 'enabled' | 'disabled'`**（electron/ai/llm.ts）——缺省不发参数，全部现有调用点行为零变化。
2. **`chatWithConfig` 按模型家族附加请求体**：仅当 `opts.thinking` 显式传值 **且** `cfg.model` 匹配 `/^glm/i` 时，请求体加 `thinking: { type: opts.thinking }`；其余模型一律不发送。双防：OpenAI 严格端点对未知参数 400；第31轮溢出路由把格言调用甩给 gpt-5.6 配置时炸请求（甩到 gpt = 不发参数，按其默认行为跑，慢而不炸）。
3. **格言调用点标注**：`generateMottos` 内 `callAndParse` 的 `chatCompletion` 调用加一行 `thinking: 'disabled'`——生成轮、补足轮、解析失败重试共用此函数，一处标注全部生效。补足轮从「最坏再等 4 分钟」变「再等 ~8s」。

预期收益：单趟 141~250s → **~8s**；定时生成（每晚 10 点）同步受益；渲染层零改动。

## 三、实施位置清单

| 位置 | 改动 |
| --- | --- |
| `electron/ai/llm.ts` `ChatOptions` | 增 `thinking?: 'enabled' \| 'disabled'` 可选字段（含注释） |
| `electron/ai/llm.ts` `chatWithConfig` | 显式传值且 `/^glm/i` 匹配时附加 `body.thinking = { type }` |
| `electron/ai/services.ts` `callAndParse` | `chatCompletion` 调用加 `thinking: 'disabled'` |

## 四、边界与不做的事

- **上游忽略 thinking 参数**（中转透传不动）：content 仍为干净 JSON（思维链在独立字段），解析不受影响，行为退回现状慢速，不算故障。
- **不加 `max_tokens` 上限**：截断思维链会导致 JSON 破碎 → 解析重试 → 更慢，有害无益。
- **不动其他场景**：汤题/思维墙（题目质量依赖深度思考）、灵感泉两阶段、万象、AI 聊天等保持现状；机制通用，后续按需逐场景跟进。
- **不做配置级 UI 开关、不动 prompt**（质量口径已确认不动）。
- 咽喉点其余不动：路由/记账/活动指示/429 重试照旧；`llm_usage` 中 completion_tokens 骤降即验收证据。

## 五、冒烟清单

1. 「来10条格言」：~10s 内返回，toast 计数口径不变（generated/inserted/各剔除从句照常）。
2. 个人档「AI 使用」表：`motto:generate` 行 duration ~10s 级、completion ~300 tok（对照实施前 249.7s / 10,046 tok）。
3. 编撰条质量人工过目（对照第 27 轮五条标准），连续数批观察无系统性退化。
4. 补足轮触发时总时长仍为秒级（+~8s）。
5. 其他场景（汤题/思维墙/灵感泉）记账数据与行为无变化。

## 六、后手

若冒烟发现关思考后质量明显退化：切方案 C（思考预算 ~1024 tok，单趟 ~25s）或该场景回退 `thinking: 'enabled'`——均为一行改动。
