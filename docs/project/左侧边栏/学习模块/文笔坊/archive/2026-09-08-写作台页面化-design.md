# 写作台页面化 + 排版升级（优化建议区第 25 轮之二）

- **日期**：2026-09-08
- **状态**：已实施（260908 当轮落地，见优化建议区第 25 轮归档）
- **来源**：优化建议区待完成——「文笔坊的写作台中的文档排版需要进一步升级优化；同时由于是写文章区域，这是个长期过程，我希望不要以弹窗形式呈现，而是用页面形式呈现。」

## 背景与问题

写作台文章现为 MdDialog 弹窗（720px 宽 / 80vh 高），对「写文章」这一长期过程有三处不适：

1. **排版不适写文**：编辑态 textarea 用 Cascadia Code 等宽代码字体（代码风格定位）；正文无限宽、行距未为长文阅读优化。
2. **交互不适长写**：默认渲染态、需双击进编辑、点「完成」才保存——长期写作的心智负担。
3. **弹窗空间受限**：720px 弹窗对写作场景空间感不足，且与「弹窗=查看/轻编辑」的其他模块（格言笔记/知识卡等）定位混淆。

## 已确认决策（对话定稿）

| # | 决策 | 否决项 |
|---|---|---|
| 1 | 页面形态 = **模块内页面切换**：点卡片 → 主栏整体切为文章页，「← 看板」返回；与万象库测一测、推理角同构 | 沉浸全屏写作页（遮蔽左右栏，切 AI/草稿本不便） |
| 2 | 排版升级**四向全要**：编辑体验（正文字体/行高）+ 阅读排版（限宽/行距/标题层级）+ 打开即可写 + 细节授权（段距/引用/字数统计等由设计补全） | —— |
| 3 | 编辑形态 = **单栏编辑 ⇄ 预览切换**，进入默认编辑态并聚焦 | 双栏并排实时预览（每栏减半、长行受限） |
| 4 | 代码路径 = **全新 ArticlePage 组件** + Copilot 整套移植 + **删除 MdDialog copilot 扩展位**（写作台是其唯一使用方；浮生记 specs 明确零 AI，保留即死代码） | 共享「编辑器内核」组件（弹窗与页面交互模型不同——双击进编辑+完成保存 vs 打开即编辑+自动保存——且 MdDialog 编辑态与 versioned/review 扩展位深度交织，抽取大改殃及 8 个使用方） |
| 5 | 保存 = **自动保存**：停止输入 800ms 静默落盘（草稿本先例）+ 关键时机 flush；无「完成」按钮 | 手动保存按钮（长期写作易丢字） |
| 6 | 范围 = 仅写作台；**浮生记不动**（specs 定位随心记轻量，保持弹窗）；看板不动；**零后端改动、零 DB 迁移**（IPC 全复用） | —— |

## 实施方案

### 1. 结构与交互（WritingPanel + ArticlePage）

- `WritingPanel` 的 `openDoc` state 语义从「开弹窗」变「开页面」：非空时渲染 `<ArticlePage item={openDoc} …>`，为空渲染看板。新建文章创建成功后直接进文章页（原为开弹窗）。
- **ArticlePage 布局**（中间主栏内）：
  - 顶部 sticky 工具栏：`← 看板` 返回｜文章标题（行内可编辑，回车/失焦提交 `articleRename`， Esc 取消）｜当前区标签（如「写作区」，随 zone 显示）｜**编辑 ⇄ 预览**切换｜Copilot 按钮组（仅编辑态可用）｜字数统计「N 字」（去空白计，编辑态实时更新）
  - 正文区：限宽居中，编辑态与预览态同宽切换。
- **keep-alive 天然受益**：WenbiModule 已保活 WritingPanel（`module-live/module-hidden`），写到一半切浮生记/其他模块再回来，文章页原样保留（编辑态、滚动位置、草稿内容）。
- **返回看板**：flush 未保存草稿 → `load()` 刷新列表（标题/时间）→ 清 openDoc。
- 文章页内不放「丢弃/移动到」等危险操作（看板已有，避免误触；YAGNI）。

### 2. 排版规格

编辑态与预览态均限宽约 **46em（中文每行 ~40 字）居中**，样式挂 `.article-page` 专属类，不污染全局 md 弹窗样式。

**编辑态**（textarea）：
- 字体 `var(--font-family)`（跟随个人中心字体设置，弃用代码字体）；字号随全局设置；行高 2.0。
- 透明底、无边框、光标主题色；占满正文区高度、内部滚动。

**预览态**（复用 renderMd 渲染管线）：
- 行高 ~1.9；标题层级分明——h2 上间距 1.5em/下 0.5em，h3 递减，h1 预留（文章标题在工具栏，正文 h1 少见但样式给足）。
- 段落间距 1em；引用块主题色左边线 + 浅底；列表/代码块/表格沿现有 md 渲染风格微调。
- `==text==` 高光等渲染后处理逻辑与弹窗同源（复用 renderMd）。

### 3. 自动保存机制

- **防抖落盘**：输入停止 800ms 且内容有变化（dirty）→ `md.write` + `wenbi.articleTouch`。
- **flush 时机**：预览切换、返回看板、切换文章（keep-alive 下 openDoc 变更）、模块失活（WenbiModule 保活隐藏，WritingPanel 经 `props.active=false` 感知）。最坏丢字窗口即一个防抖周期（800ms），可接受。
- 标题 rename 独立于正文保存（现有 `articleRename` IPC，改后看板列表返回时刷新）。

### 4. Copilot 移植（MdDialog → ArticlePage）

- **搬**：textarea 选区跟踪（trackSel/selRef）、四动作请求（起稿/续写/润色/改写，`wenbi.copilot` IPC 不动）、建议卡 UI（预览卡+采纳/放弃）、采纳逻辑（润色/改写替换发起时选区；起稿/续写插发起时光标处——只改草稿，落盘仍走自动保存）。
- **删**（MdDialog 纯减法，其余 7 个使用方不受影响，typecheck 兜底）：`copilot` prop、taRef/selRef/copilotBusy/suggestion 状态、runCopilot/adoptSuggestion/trackSel、编辑态工具行 UI、建议卡 UI 及相关 CSS。
- LLM 未配置 → GoConfigDialog「去配置」分流；其余失败 toast（沿用现有 onCopilotError 逻辑）。

### 5. 错误处理

- md 读取失败 → 页内占位「（读取失败）」；rename/copilot 失败 → toast / 去配置。
- 自动保存失败 → toast 提示（不打断编辑，防抖窗口后自动重试由下次输入触发）。
