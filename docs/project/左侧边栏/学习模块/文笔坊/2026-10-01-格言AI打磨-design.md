# 设计：格言库「AI 打磨」——AI 编撰格言的二次改进

> 创建于 2026-10-01 11:32
> 来源：开发者口头需求——格言库中部分 AI 生成句子「角度观点有些意思，但文笔还差了些」，希望输入改进建议，AI 在原句基础上输出新句子供审核。

## 背景与决策记录

「来10条格言」产出的编撰条由代码侧三道闸（句式禁令/口语化/查重）兜底质量，但观点与文笔的匹配度只能靠用户事后判断。本设计补一个**行级二次改进**环节：用户对某条 AI 编撰格言输入改进建议，AI 基于原句重写出新句，用户审核后决定去向。经澄清确认的决策：

| 决策点 | 结论 |
| --- | --- |
| 审核处置 | 三选——「采纳替换原句 / 另存为新条目 / 放弃」 |
| 适用范围 | 仅 `gen_kind='composed'` 的 AI 编撰条（三区内均可）；摘录条是真实名言、手动条是用户手笔，均不显示入口 |
| 界面形态 | 方案 A——专用小弹窗 `MottoPolishDialog`（不走右栏会话、不复用 MdDialog copilot 位） |
| 入口 | 格言行 ActionMenu 新增「AI 打磨」项，与「AI 解读」并列 |
| 采纳替换前确认 | 加一次 ConfirmDialog 轻确认（旧句替换后无界面可找回） |
| 旧句去向 | 采纳替换时旧句写入墓碑表 `motto_tombstones`，防「来10条格言」复现已被淘汰的句子 |
| 多轮打磨 | 替换后 `gen_kind` 保持 `composed`，可再次从行菜单进弹窗继续打磨（轮次无上限，每次独立） |
| 数据层 | 零新表、零迁移 |

## 改动清单

### 1. 后端 `polishMotto`（`electron/ai/services.ts`）

```ts
export interface PolishMottoResult {
  content: string // 改进后的新句
  note: string    // 一句话改动说明
}
export async function polishMotto(
  mottoId: number,
  suggestion: string,
  signal?: AbortSignal
): Promise<PolishMottoResult>
```

- 前置校验：按 id 取行，不存在抛 `NOT_FOUND`；`gen_kind !== 'composed'` 抛 `NOT_COMPOSED`；`isLlmConfigured()` 不通过抛 `LLM_NOT_CONFIGURED`。
- **prompt 组成**：原句正文与出处 + 用户改进建议（trim 非空校验）+ 格言文体五条标准（凝练/断言/普遍/可诵/意象为载体）+ 句式禁令 7 类 + ≤22 字约束（与生成口径一致）+ 正式区风格样本（`status='formal'` 最近 10 条，样本与原句同现供参照）。
- **输出要求**：JSON 对象 `{"content":"改进后新句","note":"一句话说明改了什么"}`，`jsonMode: true`，解析失败自动重试一次（同 `generateMottos` 的 `callAndParse` 口径）。
- **代码侧闸门照常生效**（复用 `COMPOSED_BANNED_PATTERNS` / `COLLOQUIAL_PATTERNS` 常量）：
  1. 句式禁令 / 口语化检测 / 超长（>22 字）任一命中 → 重试一次，违规原因回喂 prompt（「你上一版命中了 X，请规避」）；
  2. 查重 `isDupMotto` 比对三区 + 回收站 + 全量墓碑 norms，**排除原句自身 id 对应的 norm**（改进句与原句天然相似，不得误杀）；命中同样回喂重试一次；
  3. 二次仍命中 → 抛 `POLISH_GATE_REJECTED`，渲染层行内报错，原句不动。
- 调用参数：`scene: 'motto:polish'`（自动纳入 AI 调用统计口径）、`thinking: 'disabled'`、`temperature: 0.7`（比创作 0.9 收敛——改进比创作更定向）。

### 2. IPC 通道（`electron/ipc.ts` + preload + api.d.ts）

| 通道 | 入参 | 行为 |
| --- | --- | --- |
| `mottos:polish` | jobId, mottoId, suggestion | `beginJob(jobId)` 取消令牌（同 `mottos:generate` 口径），调 `polishMotto` 返回 `PolishMottoResult`，`finally endJob` |
| `mottos:polishAdopt` | mottoId, content, mode: `'replace' \| 'save'` | 主进程原子落库（见下），渲染层一次调用完成审核处置 |

`mottos:polishAdopt` 行为：

- **`mode='replace'`**：读旧行 → `recordMottoTombstone(旧 content)` → `UPDATE mottos SET content=?, updated_at=? WHERE id=?`（`source`/`gen_kind`/`status`/`sort`/标签全部不动）→ 返回更新后整行。行不存在抛 `NOT_FOUND`。
- **`mode='save'`**：查重（三区 + 回收站 + 墓碑，排除原句自身 norm）→ 已存在抛 `DUPLICATE` → INSERT 新行 `status='draft'`（草稿区区首 `sort = MIN(sort)-1`，同 `mottoHeadSort` 口径）、`origin='ai'`、`gen_kind='composed'`、`source='debugzi'`、`tags='[]'`、`note_path=NULL`（转正时由 `mottos:setStatus` 建笔记）→ 返回新整行。
- preload `window.api.mottos` 挂 `polish / polishAdopt`；`api.d.ts` 补两方法签名与 `PolishMottoResult`；`src/shared/types.ts` 同步类型。

### 3. 渲染层（`src/modules/mottos/MottosModule.tsx` + 新组件 `MottoPolishDialog.tsx`）

- **菜单项**：`mottoMenuItems` 在「AI 解读」之后插入 `{ key: 'polish', icon: 'auto_fix_high', label: 'AI 打磨' }`，仅 `m.gen_kind === 'composed'` 时加入。
- **新组件 `src/modules/mottos/MottoPolishDialog.tsx`**，布局自上而下：
  1. **原句区**：正文 + 出处（只读展示，出处「debugzi」）；
  2. **建议输入**：textarea，placeholder「例：意象太散，聚焦一个画面；语气再冷些」；Enter 触发生成、Shift+Enter 换行；空内容不触发；
  3. **结果区**（生成完成后出现）：新句大字展示 + `note` 一行小字（主题色次级文本色）；
  4. **按钮行**：「采纳替换」（主按钮）、「另存为新条」、「放弃」；结果态另有「重新生成」（同一建议重跑，覆盖当前结果）。
- **状态流转**：待输入 → 生成中（loading 态 + 「取消」按钮，经 jobId 取消；取消后回到待输入态、保留已输入建议）→ 结果态 → 三选处置后关弹窗。
- **处置交互**：
  - 采纳替换 → ConfirmDialog（标题「替换原句」，正文「替换后原句不可恢复（已记入淘汰记录，不会再被生成）」，确认钮「替换」）→ `mottos:polishAdopt(id, 新句, 'replace')` → 就地更新列表行 → toast「已替换」→ 关弹窗；
  - 另存为新条 → `mottos:polishAdopt(id, 新句, 'save')` → 抛 `DUPLICATE` 时行内提示「库内已有相同或相近句子」→ 成功则列表头部插入新条（草稿区）→ toast「已存入草稿区」→ 关弹窗；
  - 放弃 → 直接关弹窗，零副作用。
- **LLM 未配置**：点菜单项即弹提示 + 「去配置」直达 `GoConfigDialog`（同全局规则，不置灰）。
- **失败处理**：闸门两次不过 / LLM 报错 → 结果区行内报错文案（不 toast 轰炸），原句与已输入建议保留，可直接改建议重试或放弃。
- **单例**：模块内 state 持有 `polishTarget: MottoRecord | null`，同一时刻至多一个打磨弹窗；生成中不允许再开第二行弹窗（菜单项生成中置灰或直接忽略）。
- **样式**：复用现有弹窗类与主题色 CSS 变量（同 ConfirmDialog/GoConfigDialog 的主题适配口径），零新彩亮色，双主题自适应，无 emoji。

### 4. 边界与错误处理

- 无新表、无迁移、无定时任务、无右栏频道改动；`scene: 'motto:polish'` 新增后自动进 AI 调用统计，无额外接线。
- 替换不触发回收站（不是删除——旧句经墓碑表留底，墓碑表无 UI，符合「淘汰即不可见」语义）。
- 另存行进草稿区而非原句所在区：与「来10条」落点口径一致，后续流转由用户在三区自主处置。
- 打磨过程不打断、不阻塞「来10条格言」等其他 AI 任务（独立 jobId + 独立 scene）。
- 单机单窗口，无并发冲突场景；替换与另存均为主进程同步事务式单语句/双语句操作。

## 验证

- `npm run typecheck` 双 tsconfig + `npm run build` 通过。
- 冒烟清单（开发者执行）：
  1. 三区内 AI 编撰条菜单可见「AI 打磨」，摘录条/手动条不可见；
  2. 输入建议 → 生成出新句与改动说明；Enter 生成、Shift+Enter 换行、空建议不触发；
  3. 取消：生成中点取消回到待输入态，建议保留；
  4. 重新生成：同建议重跑出新句；
  5. 采纳替换：确认弹窗 → 原句被替换、出处与标签不变、列表就地刷新；再次打磨新句可用（多轮）；
  6. 替换后点「来10条格言」多次，不复现已淘汰旧句（墓碑生效）；
  7. 另存为新条：草稿区区首出现新条（gen_kind=composed），原句保留；重复另存同句报「库内已有」；
  8. 放弃：关弹窗无任何变化；
  9. LLM 未配置：菜单点击弹「去配置」提示；
  10. 双主题目检（弹窗配色、按钮、结果区文字）。
