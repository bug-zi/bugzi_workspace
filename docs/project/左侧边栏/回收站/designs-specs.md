## 1. 数据表（全局，各模块共用）

```sql
CREATE TABLE recycle_bin (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source TEXT NOT NULL,        -- 'mottos'|'wiki'|'inspirations'|'verify'|'zhijiji'|'reasoning_soup'|'reasoning_game'|'drafts'|'wenbi_journal'|'wenbi_article'（八板块；推理角汤+对局、文笔坊浮生记+文章各两来源同页签）
  item_id INTEGER NOT NULL,    -- 来源模块条目 id
  payload TEXT NOT NULL,       -- JSON 快照：条目被丢弃时的完整字段（正文/标题/板块id等）
  created_at TEXT NOT NULL     -- 入站时间 ISO
);
```

- 条目进回收站时**不删除原表记录而是打删除标记**（原表 `deleted_at` 字段），恢复即清标记；彻底删除才真正 DELETE 原记录。payload 作为备份快照兜底。
- 附属 md 文件不动：恢复时原样可用，彻底删除时连同删除。

## 2. 页面结构

- 回收站页顶部板块页签（260908 八块：辩真并入万象库 + 记账本）：格言库 / 万象库〔含辩真〕 / 灵感泉 / 致知己 / 推理角 / 草稿本 / 文笔坊 / 记账本（带各自条目数角标；推理角页签内汤与对局记录两来源混排、文笔坊页签内浮生记与文章两来源混排、万象库页签内词条与辩真记录两来源混排、记账本页签内流水/账户/分类三来源混排，payload 摘要与来源小字区分）。
- 每页签下按入站时间倒序列表，一行一条：内容摘要（格言正文 / 词条名+一句话 / 灵感标题 / 观点摘要）+ 入站时间 + 剩余存活时间（「剩 2 天」「今天到期」）+ 操作区。
- 空板块显示空状态占位（图标 + 「暂无内容」文案）。

## 3. 操作

- **恢复**：无二次确认，点击即回到来源模块最初级区——格言库→草稿区（status='draft'）、灵感泉→草稿区、万象库→原板块、辩真→万象库辩真历史记录、致知己→主列表、推理角→汤恢复回汤库（状态不变）/对局记录恢复回记录列表、草稿本→原频道、文笔坊→浮生记回时间线/文章回构思区区末、记账本→流水回月度列表/账户与分类回对应列表。清 `deleted_at`、从 recycle_bin 移除、toast 提示已恢复回来源模块。
- **删除**：彻底删除、不可恢复。二次确认弹窗（总需求文档第 1 条）：文案明确「彻底删除后无法恢复，附属笔记/文档将一并删除」。确认后 DELETE 原记录 + 附属 md 文件 + recycle_bin 记录。
- 回收站内条目只读，不可编辑、不可再丢弃。

## 4. 3 天自动彻底删除

- 检查时机（总需求文档第 5 条）：App 启动时一次 + 运行期间每日零点一次（主进程 setTimeout 到下一个零点，跨零点运行则再次排程）。
- 满足 `created_at <= now - 3 天` 的条目按上面「删除」的彻底删除逻辑清理（自动清理无需弹窗确认，静默执行）。
- App 连续关闭多天：下次启动时一并清理，不弹补确认。

## 5. 各模块接入约定

各模块「丢弃」操作的统一实现：二次确认弹窗前置 → 写 recycle_bin 记录 + 原表打 `deleted_at` 标记。各模块列表查询一律过滤 `deleted_at IS NULL`。

## 6. 验收清单

- [ ] 八板块页签正确，各来源条目归入正确板块，角标计数正确
- [ ] 恢复：各来源模块验证一条，回到规定的最初级区，原列表可见
- [ ] 删除：二次确认弹窗 → 条目、附属 md、快照全部清除
- [ ] 剩余存活时间显示正确（按入站时间算 3 天）
- [ ] 手动改库时间模拟超期 → 启动清理生效；运行中跨零点清理生效
- [ ] 恢复/删除后各来源模块列表与回收站角标实时刷新
