## 一、需求结论（brainstorm 摘要）

| 维度 | 结论 |
|---|---|
| 形态 | 内嵌系统终端：xterm.js + node-pty 真实 shell（VS Code 内置终端同款技术栈） |
| 位置 | 全局底部面板：横跨「中栏 + 右栏」，左栏始终完整可见；快捷键呼出/收起 |
| 快捷键 | `Ctrl+J` 呼出/收起面板；`Ctrl+Shift+J` 新建终端标签（开发者拍板） |
| 首版范围 | ① 真终端基础能力 ② 多标签（上限 6） ③ 选中输出发右栏 AI ④ 目录记忆 + 双主题适配 |
| Claude Code | 纯手动敲命令即用，不做专门 UI、不做会话管理（开发者拍板：选 2） |
| 入口图标 | 右侧边栏底部，自上而下：终端 → 白噪音播放 → 主题，显隐跟随主题按钮（开发者拍板） |
| App 命令体系 | 不做（YAGNI；终端是「开发者的手」，与 App 数据零耦合） |

## 二、使用图景（终端带来什么）

1. **随身开 Claude Code 协作**：默认 cwd 即项目目录，敲 `claude` 直接开工；面板收起进程照跑，边用 App 边盯 AI 干活；多标签可并行 dev server / 多会话。
2. **项目开发一条龙**：`npm run dev` / `typecheck` / `build`；git 由开发者亲手在此敲（符合 git 纪律）。
3. **选中输出发 AI**：报错/看不懂的输出选中即送右栏助手频道解释，带上下文问答。
4. **多标签并行长任务**：进程不随切模块、收面板中断。
5. **通用终端技能**：ssh 服务器、网络诊断、文件整理、任意 PowerShell 脚本；也是命令行练习场。

## 三、架构与数据流

与白噪音「纯渲染层」不同，PTY 是系统能力，必须动主进程：

```
渲染层 TerminalPanel（xterm.js 显示/输入）
   │  window.api.terminal.create / write / resize / kill
   ▼
preload（contextBridge 扩展 terminal API 组，沿用现有 api.d.ts 模式）
   │  ipcRenderer.invoke / on
   ▼
主进程 electron/services/terminal.ts（新增 TerminalService）
   │  node-pty spawn（Windows 走 ConPTY）
   ▼
PowerShell 进程（每标签一个，真实 shell）
```

- **主进程 TerminalService**：按标签 id 管理 pty 实例（spawn / write / resize / kill），输出经 `terminal:data` 事件流式推回，进程退出推 `terminal:exit`。窗口关闭 / App 退出统一杀光所有 pty，不留僵尸 shell。
- **渲染层 TerminalPanel**：全局组件，挂在 `Shell` 三栏布局下方，横跨「中栏 + 右栏」；右栏保持可用（选中送 AI 需同屏）。
- **快捷键**：渲染层 keydown 监听（作用于本 App 窗口，不抢占系统全局快捷键）；实现前全局搜一遍现有 keydown 绑定防冲突，冲突则与开发者商定备选（如 `Alt+T`）。
- **收起 ≠ 退出**：收面板只隐藏 UI，shell 与 claude 会话继续跑。

## 四、面板交互与多标签

- **结构**（自上而下）：标签栏 → 终端区 → 可拖拽底边。
- **标签栏**：左页签（PowerShell 1 / 2 / 3…），右侧小操作排：`+` 新建、「问 AI」按钮、收起按钮。
- **多标签规则**：上限 6 个，每签一个独立 shell 进程；`Ctrl+Shift+J` 或 `+` 新建；页签 `×` 或中键关闭（有运行中进程时二次确认，对齐全局删除纪律）；进程自行退出 → 页签变「已退出（code N）」+ 一键重开。
- **非活动标签不卸载**：xterm 实例常驻仅 `display:none`；面板收起同理。
- **尺寸**：默认高约窗口 35%；底边拖拽 200px ～ 60% 窗口高，高度记忆；宽度随中栏自适应。
- **Shell 选择**：默认 PowerShell；个人档可改默认 shell（powershell / pwsh / cmd）；v1 不做单标签级切换（需要时在 PowerShell 里敲 `cmd`）。
- **基础操作**：回滚缓冲 5000 行；`Ctrl+Shift+C/V` 复制粘贴；右键菜单（复制 / 粘贴 / 全选 / 清屏 / 问 AI）；WebGL 渲染 + 老显卡自动降级 canvas；等宽字体（Cascadia Mono），字号跟随全局字体大小。
- **主题适配**：面板框线 / 页签 / 按钮走现有主题变量；xterm 终端区双主题各配一套（浅色粉调底 + 深字、深色深蓝底 + 浅字），ANSI 16 色两套各调一版。

## 五、选中输出发 AI

- **入口（两处同逻辑）**：① 选中后右键菜单「问 AI」；② 标签栏「问 AI」按钮（无选中置灰、有选中主题色点亮）。
- **数据流**：`getSelection()` 取纯文本（ANSI 色码已剥离）→ 复用现有「划词问 AI」右栏唤起机制（`openAiWith` 助手频道）→ 右栏展开切「助手」频道，输入框预填引用块。
- **预填格式**（不自动发送，开发者补问题再发）：

  > 我在 App 内置终端选中了以下内容，请帮我解释或排查：
  >
  > ```
  > （选中内容；超 8000 字符截断并注明「…已截断」）
  > ```

- 走 `assistant` 频道，会话历史按频道制持久保存；xterm 选中在外部点击时不清除，时序安全。

## 六、设置与目录记忆

- **存储**：settings 表 JSON 键 `terminal`，零 DB 迁移：`{ "shell": "powershell", "cwd": "D:\\Code\\myapp\\bugzi_workspace", "height": 380 }`。
- **默认 cwd**：出厂即 bugzi_workspace 项目目录（个人工作台自用硬编码合理），个人档可改。
- **默认 shell**：powershell（Win11 必装）；选 pwsh 未安装时新建标签 toast 提示并回落 powershell。
- **面板高度**：拖拽后写入；启动默认收起（pty 不跨重启存活）。
- **设置入口**：个人档 → App 设置新增「终端」小节：默认 shell 下拉 + 工作目录选择（Electron 原生目录对话框，主进程补一次性 IPC）。
- **字号**：跟随全局字体大小，不单独做设置项。

## 七、风险与验证

| 风险 | 说明 | 对策 |
|---|---|---|
| node-pty 原生编译 | 需按 Electron 版本编译，Windows 可能要求 VS Build Tools | 装完先跑 `npm run dev` 冒烟；失败换 prebuilt fork（node-pty-prebuilt-multiarch）；`.npmrc` 已有 legacy-peer-deps |
| claude TUI 渲染 | Ink 界面偶发重绘闪烁 | xterm + WebGL 即 VS Code 同款组合；实测有问题再降级 canvas 调参 |
| 高频输出洪峰 | dev server 刷屏时 IPC 压力 | 主进程对 `terminal:data` 合帧（毫秒级窗口批量发）；xterm write 自带背压 |
| 浅色主题可读性 | ANSI 16 色在粉色浅底可能刺眼 | 两主题各调 ANSI 色板；以「深色主题优先保证 claude 长时间使用」验收 |
| 快捷键冲突 | Ctrl+J 系可能撞现有绑定 | 实现前全局搜索 keydown；冲突找开发者定备选 |

**验证清单（完成后开发者冒烟）**：
1. `Ctrl+J` 呼出/收起、`Ctrl+Shift+J` 新标签；右栏底部图标同效
2. PowerShell 可交互、ANSI 颜色正常、中文不乱码（UTF-8）
3. 敲 `claude` 起 TUI 会话正常可用；`npm run typecheck` 刷屏不卡
4. 选中 → 问 AI → 右栏助手频道预填引用块
5. 双主题配色正常；高度拖拽记忆；收面板再开进程仍在
6. 关标签二次确认；App 退出后任务管理器无残留 shell 进程
7. `npm run typecheck` 双配置通过
