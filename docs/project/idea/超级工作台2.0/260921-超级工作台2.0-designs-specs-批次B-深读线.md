# 超级工作台 2.0 · 批次 B（深读线全管道）designs-specs.md

> 创建于 2026-09-21 23:18。基于总纲《260921-超级工作台2.0-design.md》§5.1 与《一期实施计划》批次 B 范围生成，依赖批次 A（DB v48 七表 / `electron/services/agent/` 引擎层 / 领域管理已就绪）。范围：`collect_deep` 海选巡检 → 发现箱 → 终选转正 → 全文抓取 → 导读卡（自动）→ 精讲/精译（按需）→ embedding 索引与相关推荐 + 信息源升双页签「订阅 | 文献」。**发现箱 UI、追问频道属本批 UI 与批次 C 分别交付；科普线（collect_science）留二期。**

## 0. 任务注册与触发

- 任务类型（`queue.registerTask`，各服务模块文件顶层自注册，`bootstrap.ts` 统一 side-effect import + 注册收集器）：

| type | priority | singleton | maxRetries | 触发 |
|---|---|---|---|---|
| `collect_deep` | 10 | true | 2 | 引擎每日错峰（`registerCollector` 回调，仅 deep 领域）/ IPC 手动 |
| `make_digest` | 10 | true | 1 | `acceptDiscover` 转正后自动入队 |
| `embed_index` | 20 | true | 1 | `make_digest` 尾部自动入队 |
| `lecture` / `translate` | 5 | true | 0 | IPC 按需（渲染层确认弹窗） |

- 搜集类派发前检查 `collectionAllowed()`（budget.ts）：超预算 → runner 内直接 return（console.info 留痕，任务行 done），按需类不受限。
- LLM 未配置：`isLlmConfigured()`（ai/services.ts）false → runner 抛 `LLM 未配置`（failed 留痕，任务中心可见，不弹窗）。

## 1. collect_deep 海选巡检（`collectDeep.ts`）

1. 载入 `refId` 领域；缺表行抛错。
2. 双渠道并行（`Promise.allSettled`，单渠道失败留痕不炸）：
   - `searchArxiv(domain.keywords)`（每关键词一次 Atom 查询，上限 3 关键词/轮）。
   - `searchViaMcp(\`${name} ${keywords.join(' ')} 最新论文 research\`)` 原始文本。
3. 海选 LLM 单调用（`jsonMode`，temperature 0.3，scene `agent:collect`）：两份材料分别 `wrapMaterial` 包裹（arXiv 候选序列化为紧凑 JSON 列表；MCP 原文截 30k 字符）。指令要点——
   - 角色：研究文献遴选助手，领域「{name}」（职业发展深读线）；
   - 挑选最值得深读的论文 0-8 条，**宁缺毋滥，无合适结果输出 `{"items":[]}` 合法**；
   - 输出字段：`{title, authors[], year, summary(≤120字), tags[], language, length_est, url, source, reason}`；
   - **url/source 必须来自资料原文，不得编造**；reason 为一句话推荐理由（相关性+价值）。
4. 解析：本地健壮 JSON 提取（首 `{` 尾 `}` 截取 + JSON.parse，失败重试一次纯 JSON 指令），逐条校验 url/title 非空且 url 在材料集合出现过（**防编造**：collectDeep 维护材料 url 白名单 Set，不在内即丢弃并 console.warn）。
5. 去重：`url_hash`（sha1(trim 后去尾斜杠)）命中 discover_items 跳过；embedding 可用时（enabled + embedTexts 成功）对 `title+summary` 向量化，与 `entity_type='discover'` 既有向量余弦 > 0.92 跳过，否则向量入 embeddings（discover）。
6. 入库 `discover_items`（source_type='paper'，status='discovered'，domain_id，source 记 'arxiv'/'mcp:{配置名}'——海选 LLM 回填的 source 若与渠道不符以材料白名单匹配结果为准）；UNIQUE 冲突逐条忽略。结束 console.info 本轮新增数。

## 2. 转正与全文抓取（`papers.ts`）

- `listDiscover(status?)`：ORDER BY id DESC；keywords/authors/tags 解 JSON。
- `rejectDiscover(id)`：status → 'rejected'（不物理删）。
- `acceptDiscover(id)`：事务内——discover 行读出置 'accepted'，插 `papers`（元信息平移，discovery_id 回链），返回 paperId；随后 `enqueue('make_digest', {refId: paperId, trigger:'auto'})`。
- `listPapers()` / `getPaper(id)`（含 interpretations 按 kind 全量 + 相关内容 knowledge_links 联表标题）。
- `make_digest` runner 前置：`ensureFulltext(paper)`——
  - `status='ready'` 且 txt 存在 → 直接用；
  - arXiv 链接（含 /abs/ 或 /pdf/）：规范化取 id → `politeFetchBinary('https://arxiv.org/pdf/{id}')` 存 `papers/{paperId}.pdf` → **pdfjs-dist legacy 构建**（动态 `import('pdfjs-dist/legacy/build/pdf.mjs')`，Node fake worker，`getDocument({data, isEvalSupported:false, useSystemFonts:false})`）逐页 getTextContent 拼文本（页间 `\n\n`）→ 存 `papers/{paperId}.txt`；
  - 非 arXiv：`politeFetch(url)` HTML → linkedom `parseHTML` + `Readability`（feed.ts 同款）→ `stripTags` 思路取纯文本 → 存 txt；
  - 任一步失败 → `status='meta_only'`（update papers），**不抛错**（降级合法），digest 走摘要版。
- `importManualPdf(paperId, srcAbsPath)`：读文件复制入 `papers/{paperId}.pdf` → 同款抽取 → 成功置 ready（供「手动传 PDF」兜底）。

## 3. 解读产物（`interpret.ts`：digest / lecture / translate）

- 公共：全文源 = `papers/{id}.txt` 读文件（`readFileSync`，userData 相对路径拼接），缺失/`meta_only` → 退化为 `summary`（digest）或抛错（lecture/translate 提示先传 PDF）；每次 LLM 调用前 `ensureNotCancelled` 等价检查 `ctx.signal.aborted`；token 记账用 `tokensSince(runStartIso, 'agent:<scene>')` 差值累加（`ctx.addTokens`）。
- **digest**（单调用，输入截 60k 字符）：固定骨架 md——`# 导读：{title}` + `> 来源：{url} ｜ {authors} ｜ {year}` + 六节二级标题：定位 / 它回答什么问题 / 用什么方法 / 得到什么结果 / 局限与边界 / 与你何干（结合领域关键词谈适用性，**不注入个人画像**）。meta_only 时卡头加 `> ⚠ 基于摘要生成（全文缺失，可手动传 PDF 后重生成）`。产物 `md/interpretations/{paperId}-digest.md`，interpretations 行（kind=digest, done, tokens_used），`papers.digest_md` 回填。已有 done 行重复触发 → 仅 force 时重生成（覆盖 md，旧行置 replaced 不存在——直接复用行更新 tokens/md_path）。
- **lecture**（逐章）：全文按段落边界切 ~10k 字符块（上限 20 块）；md 头部 `# 精讲：{title}` + 说明行；逐块 LLM（scene `agent:lecture`，指令：逐章中文重述讲解，保留关键术语、给出直觉解释与例子，输出 md）→ 以 `## 第 N 部分` 追加落盘（**每章写完即写文件**，中断重试按既有 `## 第 N 部分` 数续跑）；完成置 interpretations done。
- **translate**（术语表先行）：① 术语表调用——全文截 40k → 输出 JSON `{"glossary":[{"en":"...","zh":"定译"}]}` 10-30 条（含缩写/人名/方法名），存 `papers.glossary`；② 逐块翻译（scene `agent:translate`，system 注入术语表 JSON +「术语全文统一用定译」+ 原文走 wrapMaterial）→ `## 第 N 章` 追加；续跑口径同 lecture。
- lecture/translate 共用幂等入口：`runInterpret(paperId, kind, force)`——已有 running 行抛「任务进行中」；已有 done 且 !force 抛「已存在，需确认重生成」（渲染层 ConfirmDialog 转 force）。

## 4. embedding 索引与相关推荐（`embedIndex.ts`）

- `embed_index` runner（refId=paperId）：向量化「导读卡全文（digest_md 读文件）|| 摘要」→ `storeEmbedding('paper', id, vec)`；首次运行顺带补索引 `wiki_entries`（未删、缺 embeddings 行的，按 32 条/批 embedTexts，entity_type='wiki'，向量输入 `term + '：' + summary`）——失败静默留待下次。
- 相关推荐：`searchSimilar(vec, 10, ['paper','wiki'])` → 过滤自身、score ≥ 0.6 取前 3 → `INSERT OR IGNORE INTO knowledge_links`（src=paper 自身，dst 命中项，origin='similarity'）。
- EmbedUnavailableError → 任务行 done（error 备注留痕「embedding 跳过」——finishRun 语义只收终态；实现为 runner 正常返回 + console.warn，台账 error 列不写），**不重试不炸**。

## 6. 渲染层：信息源升双页签「订阅 | 文献」

- **FeedModule.tsx**：`module-header` 的 view tabs 前加主页签组 `订阅 | 文献`（`mainTab: 'feed' | 'literature'`，会话内 state 不持久）；mainTab='feed' 时现有 view tabs / 刷新 / 全部标已读照旧；='literature' 时隐藏 view tabs 与右侧两按钮（刷新按钮保留但改调 `agent:runCollect`?——不，文献区自带操作，头部仅保留页签与模块名）；`module-sub` 文献态显示待终选数；阅读视图 early-return 不变（文献区无阅读视图跳转）。深链：`useModuleNavigate('feed', target === 'literature' → setMainTab('literature'))`（批次 C 任务中心直达用，先行铺好）。
- **LiteraturePanel.tsx**（新组件 + `literature.css`）：内部两子页签「发现箱 | 正式文献」+ 头部动作——
  - 发现箱：`agent:discoverList()` 全量渲染，discovered 分区在上（列表行：标题 / 作者 · 年份 / 渠道徽章 / 语言 / reason 引言样式），行操作「接受」「拒绝」；accepted/rejected 折叠小计行（「已接受 N · 已拒绝 M」）。顶部「跑一轮海选」按钮——无 deep 领域时 toast 引导去个人档配置；多领域时下拉选择（原生 select）后 `agent:runCollect`，toast「已入队，进展见任务中心」。
  - 接受：`discoverAccept` → toast「已转正，导读卡生成中」；拒绝：直接调用（软状态无需确认）。
  - 正式文献：`agent:papers()` 列表（标题 / 状态徽章 ready=全文·meta_only=仅元信息 / 导读卡徽章 / 年份 / 来源）；点击开 **详情弹窗**（自绘 dialog-overlay + dialog，非 MdDialog——含元信息区 + 产物区）：产物三按钮（导读卡 / 精讲 / 精译），已生成→MdView 内嵌查看 + MdDialog 打开（可双击编辑，onChanged 后重读）；未生成→点击触发生成（digest 未生成直接跑；lecture/translate 已 done 需 ConfirmDialog 确认重生成转 force）；meta_only 显示「手动传 PDF」按钮（`agent:importPaperPdf`）；相关内容列表（related，点击 wiki 项 toast「二期打通词条跳转」/paper 项切详情）。
  - 样式：复用 module/recycle-tabs/badge/btn 体系 + literature.css 仅补列表行与详情布局；主题色系、零 emoji（Material Symbols：auto_stories / inventory_2 / school 等）。
- 文献区操作后 `agent:pendingCounts` 刷新头部计数。

## 7. 验收清单（批次 B）

1. 配置 deep 领域 → 文献页签「跑一轮海选」→ 控制台 `[agent]` 日志 → 发现箱出现条目（带推荐理由/渠道徽章）；无合适结果时提示本轮无发现而非硬凑。
2. 同 URL 二次海选不重复；LLM/MCP 未配置时任务行 failed 留痕「LLM 未配置」。
3. 「接受」→ 正式文献出现条目 → 稍后导读卡自动生成（MdView 打开六节骨架）；meta_only 时卡头有缺全文提示且「手动传 PDF」可用，传后可重生成。
4. 精讲/精译：生成中任务中心可见（本批先控制台/日志），产物 md 逐章落盘；中断 App 重启后重新点击可**续跑**不重头；精译术语表一致。
5. 已 done 的精讲再点 → 确认弹窗 → force 重生成。
6. Ollama 停用下接受新论文 → 主管道不受阻，控制台见「embedding 跳过」。
7. 信息源「订阅」页签全行为与升级前一致；`typecheck` / `build` 全绿。
