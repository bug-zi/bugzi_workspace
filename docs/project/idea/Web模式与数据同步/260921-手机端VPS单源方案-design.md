# 手机端 VPS 单源方案（设计）

> 创建于 2026-09-21 00:42，brainstorming 会话产出；立项后本文件移出 idea/ 归入正式目录。

## 背景与目标

面向「日常在手机端使用工作台」的方向性设计记录。**现阶段无紧迫手机端需求，暂不实施**，供未来立项参考。

与《260920-web模式与数据同步-design.md》目的不同：260920 是「手机端用 Claude Code 开发调试、网页端查看项目效果」的方案，本文件面向日常使用，两文档并存互补。

研讨结论：当前项目数据 = 单文件 SQLite（bugzi.db）+ md/ 多板块 + 素材（fonts 20M / music 15M / covers 1.2M）+ books 53M，单用户、两端作息错开。同步难题的正解不是"怎么同步"，而是**手机本地不持有数据**——数据只存一份于 VPS，同步问题被消灭而非解决，零同步代码、零冲突、零纪律。

## 备选方向盘点（研讨过程结论）

| 方向 | 结论 | 弃选原因 |
| --- | --- | --- |
| 1 单一数据源（VPS） | **选定** | —— |
| 2 双本地 + git 仓自动同步 | 弃 | git 仓膨胀（db 二进制每 commit 全量快照，年 +5~20GB）；nodejs-mobile 生态待验证，不可行则服务层须迁 SQLite 适配层，工程大 |
| 3 双本地 + 目录级自动同步（Syncthing 类） | 弃 | 安卓 scoped storage 下第三方同步 App 摸不到 App 私有目录；SQLite 活库有被同步写坏的窗口风险 |
| 4 记录级真同步（oplog/updated_at） | 弃 | 单用户错开场景下为不存在的问题付成本；**备忘**：未来若所有写收口到统一 DB 适配层，可顺手在适配层记 oplog，留作架构演进方向 |
| 5 分级同步·手机只做捕获+复习子集 | 弃 | 本方案下无必要，预裁剪不如先全量用再裁 |

## 总体架构

```
VPS（数据单源）                      客户端
├─ Node 服务（复用 260920 的垫片 + web/main.ts 设计）
│   /ipc + /bzres + SSE + HTTPS + 单人 token/密码鉴权   ←→  手机：先 PWA，后 Capacitor APK 壳
├─ 全部数据（bugzi.db、md/、bg/、fonts/、music/、canvas/、books/ 等）
├─ 定时任务（每晚 10 点格言生成，7×24 必中，不再"错过即跳过"）  ←→  PC：Electron 壳切「远程模式」
└─ 每日自动备份（数据目录单向往对象存储/PC 推送，无冲突）        或直接浏览器/PWA 访问
```

- **VPS**：Node 服务 + 全部数据 + HTTPS + 鉴权 + 定时任务 + 每日备份。
- **手机**：先 PWA（Service Worker 需受信证书），后 Capacitor APK 壳（WebView 指向 VPS，极薄）。
- **PC**：Electron 壳仍在（托盘/开机自启照旧），渲染层连 VPS 而非本地服务；桌面专属功能（内置终端等）按 260920 §3 策略隐藏。
- **红线：PC 不保留本地数据副本**。一旦两端各持一份数据，同步问题回归，本方案失效。

## 与 260920 文档的关系

- **复用**：electron 垫片、/ipc、/bzres、SSE、dialog 文件分支（`<input type=file>` 上传）、resUrl 收口、viewport 适配——「两端一套渲染层」的地基与服务器部署位置无关。
- **作废（就本方案而言）**：260920 §4 数据入仓 git 同步 → 改为一次性数据迁移 + 每日自动备份。260920 文档已于 260921 修订标注「应用数据暂不入仓」。

## 红利（相比双本地方案）

1. 零同步代码、零冲突、零使用纪律（不用记得 pull/push）
2. 书架手机可看（books 不再被排除在同步外）
3. 定时任务 7×24 必中
4. MCP 跑标准 Linux，比 Termux 可靠
5. nodejs-mobile 等验证 spike 全部不需要

## 风险与缓解

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| VPS 带宽 | 轻量云常见 3–6Mbps，书 53M/字体 20M/音乐 15M 首载慢 | 选大带宽档位；HTTP 缓存 + Service Worker 预缓存素材；书按需拉取 |
| 单点无副本 | 数据仅存 VPS，丢失即全丢 | **每日自动备份必做**：数据目录单向往对象存储或 PC 推送（单向无冲突） |
| 公网暴露 | 个人数据上公网 | HTTPS + 单人 token/密码鉴权；VPS 选型建议香港/海外轻量（免备案）+ 域名 + Let's Encrypt——注意安卓 PWA 要求受信证书，自签 IP 证书不可行 |
| 依赖在线 | 弱网/断网时不可用 | 已确认可接受；远期可为记账/灵感等 append-mostly 数据加离线捕获队列（迭代项，不进首版） |
| VPS 依赖 | 商家变动/续费中断 | 备份兜底，数据可整体迁回 PC 本地 |

## 手机端模块策略

不预裁剪：渲染层同一套，手机天然全模块可用。实际约束仅两条——书架阅读重（体验待验证）、桌面专属功能隐藏。策略：**先全量上线用一周，不顺手处经优化建议区迭代**；移动端适配首版最小（viewport 横屏），后续迭代。

## VPS 选型建议（供未来立项参考）

- 地区：香港/海外轻量（免备案，延时约 50–80ms 可接受）
- 配置：2C2G 起步足够（服务本身轻量）
- 带宽优先于配置：素材加载体验取决于此
- 域名一枚 + Let's Encrypt 免费证书；系统 Ubuntu LTS / Debian

## 实施阶段划分（供未来立项写计划参考）

1. Web 模式改造（260920 §1–§3：垫片、web 服务端、渲染层适配）——共同地基，先行；与 260920 开发调试场景共用
2. VPS 部署：Node 服务 + 域名 + HTTPS + 鉴权 + 定时任务
3. 数据一次性迁移：PC 数据目录打包上传 VPS；顺修 storage.ts `dataItemNames` 缺 books/covers/music/canvas/fonts 五类的 bug（迁移功能本身要用）
4. 客户端：手机 PWA（manifest + SW 预缓存）→ Capacitor APK 壳
5. PC Electron 远程模式
6. 每日备份：数据目录 → 对象存储/PC（单向脚本）
7. 移动端体验迭代（经优化建议区）
