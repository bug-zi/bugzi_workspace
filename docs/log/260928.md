### 1. AI 调用面板排队任务可置顶（纯渲染层）

- 排队区目前唯一数据源 = 学习库生成队列（learnGenQueue），`src/services/learnGenQueue.ts` 新增 `topLearnGen(id)`：`waiting` 数组移到队首（下一波派发最先跑）+ `items` 展示数组同步前插，且只插到 queued 段之前、不越过多条已在生成（loading）的项；已在队首为无操作。

### 2. 学习库知识卡片复制为 Markdown

- `MdDialog` 通用扩展：`headerAction.onClick` 签名扩为 `(content: string) => void`，回传当前正文 md 源文（编辑态传未保存草稿）；既有两处使用方（书架笔记导出 / 书籍导读重新生成）传零参闭包不受影响。

### 4. 论文库 / 万象库·科普：转正后状态三态化 + 自愈 + 解读生成中占位

- **病灶**：论文转正 INSERT 即置 `ready`（全文还没抓）——抓取窗口内徽章「全文就绪」但原文加载不出；抓取中途退 App 则启动恢复终态化任务后**永远停留就绪-无文件死状态**且无重试入口。科普转正确实是 `meta_only` 但列表看不出「在抓」。解读产物生成期间无任何占位。另实锤一处**渲染 bug**：ScienceReader（260927 弹窗→主栏重构）中解读产物与原文的 `mdText`/`sourceMd` 计算后从未上屏（`view!=='source'` 分支恒渲染 metaMd，source 分支恒「加载中…」）——即「全文就绪但加载不出来」的直接原因之一。
- **三态（派生，零 DB 迁移——两表 status 均带 CHECK 约束，不新增枚举值）**：`抓取中` = meta_only/ready 且 task_runs 存在抓取任务行（enqueue 即插 running 行，排队未派发也在内）；`全文就绪` = ready（缓存真实在盘）；`仅元信息` = meta_only 且无抓取任务。转正即入 `meta_only`（论文由 ready 改 meta_only，科普原样）。
- **主进程**：`queue.ts` 新 `activeTasks()`（task_runs running 行快照）；`ipc.ts` 新 `agent:activeTasks` / `agent:paperRetryFetch` 两通道，`agent:paperDetail`/`agent:scienceDetail` 载荷增 `active`（该 owner 在队/在跑任务类型去重集）；papers 新 `retryPaperFetch`（ensureFulltext 成功后照常入链导读卡，与科普 retryScienceFetch 同口径）；`listPapers`/`listScienceArticles` 挂**自愈**——ready 但缓存文件缺失→回 meta_only 并自动重新入队抓取（存量坏数据无感修复）。
- **渲染层**：LiteraturePanel / SciencePanel 列表徽章三态（loadPapers/loadArticles 并行拉 activeTasks；agent:status 入队事件也刷新以即时点亮「抓取中…」）；PaperReader / ScienceReader 徽章、原文页签三态占位（抓取中占位/仅元信息给「重试抓取」+「手动传 PDF」，科普重试钮抓取中禁用）；解读页签生成中（含排队段）显「…」与「已入队，排队生成中/生成中·进度」占位——在飞任务维持逐章落盘围观，排队任务不再静默；ScienceReader 修复内容上屏 bug（非 source 视图 mdText 优先、排队占位次之、metaMd 信息卡兜底；source 视图 fetching 占位优先）+ 原文加载 effect 补 status 依赖（抓取完成自动出内容）；PaperReader 内容 effect 同补 status 依赖（修存量手动传 PDF 完成后正文空白的边缘 bug）。**待冒烟**：转正一篇论文/科普看列表「抓取中…」→完成自动变「全文就绪」→原文可读；科普原文视图内容真实上屏（重构回归）；仅元信息条目重试抓取；转正后中途退 App 重进不出现死「就绪」；解读排队/生成两段占位与完成后自动替换；双主题。
