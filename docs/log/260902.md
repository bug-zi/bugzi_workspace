## 1.0 开发（260902 第四轮，AI 执行）

应开发者要求「完成项目的 1.0 开发」，基于 7 份 designs-specs.md 初始化全部代码。

### 技术选型落地

- **数据库**：node:sqlite（DatabaseSync）+ WAL + 外键，PRAGMA user_version 版本化迁移。弃 better-sqlite3 以避开 Windows 下原生 ABI 重编译；为此将 Electron 从 33 升至 44（需 Node ≥22.13，内置 node:sqlite）。
- **进程架构**：渲染层只做 UI，全部 IO（SQLite/md/LLM HTTP/MCP）在主进程；contextBridge 类型化 IPC，contextIsolation 开、nodeIntegration 关、sandbox 关（preload 需要 require）。
- **图片资源**：bzres:// 特权协议（app ready 前注册 scheme + protocol.handle）服务 userData 内头像/背景图，含路径穿越防护。
- **md 渲染**：marked + DOMPurify，`==高光==` 后处理为 `<mark>`；外链 shell.openExternal。
- **图标**：material-symbols npm 包本地 woff2（遵守禁 emoji 规则）。
- **LLM 客户端**：OpenAI 兼容 /v1/chat/completions，主进程 fetch + Bearer；jsonMode（response_format）；URL 规范化自动补 /v1/chat/completions。
- **MCP 客户端**：仅 Streamable HTTP 传输（JSON-RPC POST + mcp-session-id + SSE 响应解析）。
- **依赖坑**：vite@8 与 electron-vite@5 peer 声明（≤^7）冲突 + React 19 与 plugin-react peer 冲突，`.npmrc` 固化 `legacy-peer-deps=true` 解决（裸 npm install 即可）。

src/renderer/       api.d.ts 同步

## 问题疑惑区问题修复（260902 第六轮，AI 执行）

开发者首启冒烟后在《问题疑惑区.md》登记 3 个问题，全部定位修复：

1. **头像不显示**：bzres:// 协议处理器把 host（root）错误拼进磁盘路径，`bzres://root/avatar.png` 被解析为 `userData/root/avatar.png` → 404。重写解析：host 仅作命名空间（root=根目录、bg=背景目录），不计入路径。
2. **背景图更换不生效**（两个叠加 bug）：① image:pick 存背景图目标路径漏扩展名（存成 `bg/bg-light`）而 settings 记 `bg-light.png` → 永远 404，已修正为带扩展名存储；② index.html CSP `connect-src 'self'` 拦截 ThemeProvider 的 bzres: fetch 探测导致回退纯色，已放行 `bzres:`。另做 DB v2 迁移自愈：旧无扩展文件自动改名规范名 + 从项目根种子默认背景图（bg-light.png/bg-dark.png，不覆盖用户已传图）。
3. **格言笔记弹窗关闭键失效**：MdDialog 缺 onClose prop（关闭按钮 onClick 只处理编辑态而非编辑态渲染为空操作），遮罩/Esc 同样失效。补 onClose prop 并统一 close()（编辑态先保存草稿再关），5 处调用方（格言/万象/灵感/辩真×2）全部接上。

## 背景图问题第二层根因修复（260902 第七轮，AI 执行）

开发者反馈背景图仍未显示，二轮排查定案：scheme 未注册 `corsEnabled` 特权。dev 页面源为 http://localhost:5173，ThemeProvider 用 fetch(bzres://bg/...) 探测 404 属跨源请求，Chromium 直接拒绝（"Cross origin requests are only supported for protocol schemes: chrome, http, https..."）→ 探测 catch 回退纯色。头像走 <img> 标签不受 CORS 限制，故头像正常、背景异常，与现象吻合。

修复：`electron/services/bzres.ts` privileges 增加 `corsEnabled: true`；`src/theme/ThemeProvider.tsx` 探测逻辑容错（fetch 异常不再清空 url，CSS url() 加载本就不走 CORS）。

验证方法记录：写独立复现脚本 scripts/test-bzres.cjs（本地 http 页面源 + 可切换 privileges），复现 FETCH_FAIL → 加 corsEnabled 后 FETCH_OK，锁定根因；再以 `REMOTE_DEBUGGING_PORT=9222 npm run dev` 起真实 app，经 CDP（scripts/cdp-check.cjs）在渲染进程实测：cssVar 与 computedStyle 均为 url("bzres://bg/bg-light.png")、fetch status=200、IMG_OK。开发者重启实测确认背景正常显示。

清理：scripts/ 下 test-bzres.cjs、cdp-check.cjs、check-bg.cjs、capture-screen.ps1 为本次排查临时脚本，可留作诊断工具或删除。typecheck 通过。所有改动未提交，git 由开发者操作。
