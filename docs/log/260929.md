## 论文库全文抓取修复：PDF 直链不再被当 HTML 解析（docText 通用管线）

> 创建于 2026-09-29 00:27

**现象**：日志库报 `[agent:papers] 《Analysis of the Go runtime scheduler》全文抓取失败（meta_only）：正文过短`，但论文实际 8 页全文——开发者存疑。排查确认：该论文 URL 为哥大课程站 PDF 直链（`cs.columbia.edu/…/…GO.pdf`，响应连 Content-Type 都没有），而 `ensureFulltext` 只给 arXiv 链接留了 PDF 解析通道，其余一律 `politeFetch` 当 HTML → Readability，实测对这份 PDF 抽出 **0 字符**，触发 `<200`「正文过短」误降级 meta_only。元凶非论文内容短，而是抓取分支判定。

**修复**（新建 `electron/services/agent/docText.ts` 共用管线）：
1. `fetchDocText(url, { pdfSink?, asPdf? })`：`.pdf` 扩展名先验（无 Content-Type 的老站也命中）+ 响应 `%PDF-` 魔数兜底（覆盖 openreview.net/pdf?id=… 等无扩展名直链）→ 二进制下载 + pdfjs 逐页抽文本；其余 HTML + Readability。`asPdf` 供 arXiv 已归一 `/pdf/` 链接强制走 PDF 路径；`pdfSink` 传论文库落盘路径复用 `papers/{id}.pdf`，不传则临时文件用完即删（科普线）。
2. `extractPdfText` 自 papers.ts 迁入 docText.ts，booktext.ts 引用源同步改。
3. `papers.ensureFulltext` / `science.ensureScienceFulltext` 双调用方改走 `fetchDocText`，长度不足报错按来源分型（PDF → 「抽取文本过短（扫描版 PDF 无文本层？）」、HTML → 「正文过短」），日志可读性提升。

**验证**：一次性脚本实证旧行为（HTML 路径抽出 0 字符）与新路径（8 页 41,881 字符，正文抽样正确）；typecheck 双配置 + build 通过。存量 meta_only 论文（如该篇）重启 App 后点「重新抓取」即可转 ready。

- **docText.ts**：新增 DOM→Markdown 序列化器（linkedom 节点遍历、零新依赖，本地结构类型绕开其导出类型不友好问题）——标题 #、加粗/斜体/删除线/行内码、链接与图片（经 base URL 绝对化）、ul/ol 嵌套列表、blockquote、代码块、表格（首行表头）、hr，script/style/iframe/button 等剔除；`fetchDocText` HTML 分支返回 `md` 字段（text 纯文本仍作长度守卫与 LLM 输入）。**环境适配两坑**：linkedom 下 Readability 的 `content` 是序列化 HTML 字符串（非 Document，双形状兼容重解析）；片段重解析节点全挂 documentElement 而 body 为空（root 选择跳过空 body），包裹 DIV（readability-page-1）含块级子级时递归保结构。
