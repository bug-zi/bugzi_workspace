## 推理角出题效率与 LLM 混用/记账落地（优化建议区第31轮）

> 创建于 2026-09-10 00:35

**背景**（brainstorming 会话定稿，方案 A + 追加需求）：开发者反馈推理角出题慢（四处全中：池空兜底/后台建池/海龟汤交互/整体感知）且看不到 token 消耗与 AI 使用情况。摸底 + 实测定位——① gpt 中转（gpt-5.6）TTFT 高达 11.7s（历史「到处慢」主因），新配 glm-5.3-flash 官方端点 0.7s、4 路并发全 200、usage 上报完整，开发者已将 glm 设为默认；② 全链路 27 处 LLM 调用唯一咽喉点 `chatCompletion` 丢弃上游 usage（token 从未记账）；③ 补充泵三级全串行。设计文档 `docs/project/左侧边栏/推理角/2026-09-10-推理角出题效率与LLM混用记账-design.md`，实施计划同目录 `-plan.md`（落地后双双移入 archive/）。

**五件套实施**：

1. **模型池溢出路由（混用核心）**：`electron/ai/llm.ts` 重构——`pickConfigFrom` 纯函数（默认未满用默认 → 溢出到在途最低的有余量备选 → 全满仍回默认不排队）；`LlmConfig` 加可选 `maxConcurrent`（个人档 LLM 表单新增「并发上限」数字输入，留空不限=行为同旧版）；在途计数按配置 id 内存登记（起止 finally 增减）。质量红线零触碰：两阶段出题审题管线一行未改。
2. **llm_usage 记账（DB v27）**：新表 + created_at 索引；咽喉点每次**逻辑调用**落一行（429 重试只记最终趟、耗时含重试等待）；usage 缺失时按字符粗估（中文 ~2 字符/token）并打 `tokens_estimated` 标记；取消记 ok=0。**27 处调用点 scene 标注**（ipc 1 + mcpResearch 3 + services 22 + feed 1；新增 `ai:compact`、`wiki:suggest` 两标签，勘误入设计文档）；中文标签表 `LLM_SCENE_LABELS` 放 src/shared/types.ts 三端共用。
3. **补充泵并行化**：`reasoningStock.ts` 题池/汤库双路并发（原题池先汤库后）；题池内两道并行（`pickPairSpecs` 配对强制难度/题型互异、避免清单配对前快照共用；单道失败不废整泵、整对全败才跳出防死循环）。
4. **汤批审题并行**：`generateSoups` 首轮 3 碗审题 `Promise.all`（半盲互相独立），打回重出保持串行（「同批已保留碗」互避清单正确性）；MAX_REDO=2 语义、难度放宽口径（260907 二调）严格保持；对「来 3 碗汤」手动入口同样生效。
5. **可观测 UI**：个人档新增「AI 使用」区（今日/本月/全部 pill、调用次数+token 两张数字卡、分场景表格：次数/失败/平均耗时/token≈；AI 空闲时经 `llm:activity` 自动刷新）；左栏底部 `LlmActivity` 实时活动指示（空闲不渲染、忙时主题色呼吸圆点+场景聚合文案、纯指示不可点）；IPC 三处同步新增 `llmUsage:stats` + `llm:activity`。
