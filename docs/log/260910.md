## 第34轮反馈修订：书签章节名与百分比双根因修复（systematic-debugging 全程）

> 创建于 2026-09-10 23:27

**冒烟反馈**：数学女孩（套装全 4 册 epub）读在「第 3 章　ω 的华尔兹」，书签 label 却是「网络资料 · 100%」——章节名与百分比双错。

**取证过程（纸面推理 + 真机实证双轨）**：①DB WAL 快照（node:sqlite 只读）——书签行 cfi 与 progress_cfi 完全一致、两本 epub progress_percent 皆 100；②解包 epub 实态——spine 仅 5 个 itemref（一册一个大 html），NCX 195 个 navPoint 几乎全为 `text00001.html#nav_point_N` 同文件锚点，「第 3 章　ω 的华尔兹」`#nav_point_23` 与「网络资料」`#nav_point_139` 同文件且后者目录序更后；③epub.js 源码级推理（`Spine#get` 字符串 miss 返回 spineItems[0]、`Locations.percentageFromLocation(-1)` = -1/-1 = 1 等）+ 真实模块行为验证脚本（形态保真数据跑 `percentageFromCfi`：靠前点 2.9%、末尾 1，证管线本身正确；脚本验后即删）；④第 33 轮同款隔离第二实例 CDP 探针（临时 userData + DB 快照 + 真实点击）**完整复现**并插桩定位——`__dbg` 实测 `locLen:0, locTotal:-1, percent:1`，`__dbgAdd` 实测 tocSample 全部 spineIndex:1、chapter=网络资料，根因闭环；真实库零污染（指针写后 4 秒还原，收尾复核指向 D 盘原路径）。

**根因与修法**：

- **章节名（根因一）**：一册一文件、章靠锚点的书，href 剥锚点后同文件目录条目共享 spineIndex，文件粒度区间判定必取 DFS 序最后一个同文件条目（第 1 册末条「网络资料」）。**修法升锚点级解析**——EpubReader 目录加载后留存拍平列表 `flatTocRef`，relocated 时 `chapterHrefAt()`：同 spineIndex 候选项中，有锚点者以 `rendition.getRange(当前 CFI)` 的 Range 与锚点元素 `comparePoint(el,0) ≤ 0` 做**文档内定位**（最后一个早于当前位置的锚点=真章节），命中则 locate.href 携带锚点 href；模块加书签按 href 精确命中优先，锚点/Range 不可解析依次回落册名条目（同文件无锚点项）→ 文件粒度区间 → 「约 N%」。侧栏目录高亮因 locate.href 升级为锚点 href 对锚点书顺带生效（高亮代码零改动）。
- **百分比（根因二）**：该书 `locations.generate(800)` 跑完但零条目（total=-1），epub.js `percentageFromLocation(-1)` = -1/-1 = **1 假 100%** 经 `l.start.percentage` 带出，被原实现 `?? 0` 兜底采信。**修法**：relocated 弃用 `start.percentage`；locations 有产出走 `percentageFromCfi`（真模块验证口径正确）、否则 **spine 粒度粗估** `spineIndex/(spineItems.length-1)` 兜底（本册 1/4≈25%）。阅读条、进度落库、书签百分比三处同口径一并修正（存量 100% 假进度行随下次阅读自然覆盖）。

**验证**：typecheck 双配置 + build 通过；开发者实测通过（章节名与百分比恢复正常）。改动集中于 `EpubReader.tsx`（relocated 重写 + chapterHrefAt + flatTocRef）、`BookshelfModule.tsx`（addBookmark 精确命中优先）；排障临时插桩（window.__dbg/__dbgAdd）已全部移除。

**顺带发现（未修，建议另轮处理）**：①**生产构建下 epub 渲染整体不可用**——`npm run build` 产物（out/）里 rendition manager 建不起来（`Rendition.resize` 抛 manager undefined、relocated 不触发），疑 `src/index.html` CSP `default-src 'self'`（frame-src 回落）拦 epub.js 渲染 iframe；dev server 不复现，v1.0 起潜伏，本轮排障 rig 首次真正运行 build 产物时暴露——将来打包交付前必修；②ResizeObserver 回调 `renditionRef.current?.resize(w,h)`（优化第1轮遗留）无 try/catch，挂载竞态下抛未捕获异常。两处待开发者定夺是否立案。

**排障一笔（弯路存档）**：中途一度按「epub.js `Spine#get` miss 返回首项 → 未解析条目 spineIndex=0」立论，后被 NCX 实据推翻（该书全部条目正常解析、0 号兜底根本没触发）——**先取证再定因**的纪律再次生效；另 Windows python 存根会卡死 heredoc 管道（本轮一次超时根因），临时脚本一律用 node。
