**背景**（brainstorming 定稿，方案 A）：优化建议区新条目「格言库生成的质量不错，但是速度太慢了！」。第31轮 llm_usage 记账直接拿来定位——唯一一条 `motto:generate`：glm-5.3-flash **249.7s**、prompt 4,739 tok、**completion 10,046 tok**（10 条格言 JSON 实际仅 ~700 字符）。三组对照实测（同 prompt 直连智谱官方 API）：现状无参数 141.3s（reasoning_content 1.4 万字）、`thinking:{type:'disabled'}` **8.3s**（277 tok）、显式 enabled 208.2s（2.0 万字）——根因即 glm 默认深度思考把「对 102 条避免清单 + 51 墓碑逐条自查 + 文体标准自检」（第 23/24/27 轮质量约束叠加）全写在思维链里，6k~10k token 按 ~45 tok/s 解码占 95% 耗时。关思考样例质量经开发者看货认可（摘录全真、编撰符合第 27 轮文体形态），且有句式/口语化/查重三道代码侧闸兜底。范围拍板：本轮只治格言，机制通用、其他场景（汤题/思维墙等依赖思考质量的）后续按需跟进。设计文档 `docs/project/左侧边栏/格言库/2026-09-10-格言生成提速关思维链-design.md`，实施计划同目录无后缀 `.md`。
