> 创建于 2026-09-27 01:00

**方案**：主进程「落盘前转换 + 存量一次性迁移」双管齐下，渲染层零改动（划词高光的文本匹配机制不受影响）。

- 新增 `electron/services/t2s.ts`：`toSimplified`（opencc-js 繁→简，简体输入幂等直通、异常兜底原样）+ `simplifyJsonStrArray`（tags 等 JSON 字符串数组列逐项转换）。
- 新增 `electron/services/agent/scienceSimplify.ts`：存量数据一次性繁→简，`settings` 旗标 `science_t2s_v1` 守卫只跑一次。覆盖四类：
  1. 解读产物 `md/interpretations/sa-*.md`（translate/light/lecture）；
  2. `science_articles` 的 title/summary/tags/glossary/concepts；
  3. `discover_items`（source_type='article'）的 title/summary/tags/reason；
  4. `science_highlights.text`（与 md 正文同批转换，保持高亮/取消高光匹配一致）。
- `bootstrap.ts`：`app.whenReady` 后调用迁移（不占 db.ts 迁移版本号，避开热点文件）。
- 增量落盘点统一转换：`interpretScience.ts` 三条产线（翻译章块/术语表 zh/加注版 md+concepts/精讲，`parseLightChunk` 内单点转换）+ `headOf` 标题与术语表；`collectScience.ts` 海选入库 title/summary/tags/reason（近重复判定与向量也用转换后文本）；`science.ts` `scienceAcceptRow` 转正分流同口径。
- 提示词加固：翻译/加注/精讲/海选各 prompt 补「简体字、不要繁体字」硬约束（转换兜底在代码层，prompt 只是第一道）。

**验证**：`npm run typecheck` 通过；`npm run build` 通过（主 bundle 含 opencc 词典数据）；冒烟测试确认 `==标记==`/`[术语](wiki://术语)` 链接目标随正文同步转换、二次转换幂等、简体输入原样返回。首次启动后控制台会打一行迁移完成统计（解读 md/转正文章/发现箱/高光条数）。

- `ipc.ts`/`preload.ts`/`api.d.ts`：新增 `agent:scienceFulltext`（读 `science/{id}.txt` 缓存，复用既有 `readScienceFulltext`）。

## 论文库海选命中修复：MCP 白名单并入 + 检索词英化

> 创建于 2026-09-27 02:17

**背景**：开发者发现深读线海选「基本都收 0」——日志「候选 0，入选 5，新增 0」。排查出两个根因：①collectDeep 的 url 白名单只由 arXiv 候选构成（`urlWhitelist(candidates)`），MCP 搜索原始文本里的链接从不在白名单内——arXiv 一空白名单即空集，LLM 选什么都必被「丢弃编造 url 候选」拦截，MCP 渠道在深读线结构性无效（科普线 collectScience 早有 `whitelistFromText` 从原文抽链接，深读线漏了同款）；②arXiv 查询直接用中文领域词/关键词（`all:"Go语言开发"`），在 arXiv 结构上永远 0 命中，而论文检索基本只在英文文献圈有效。

**改动**（collectDeep.ts + collectScience.ts）：
- **检索词英化**：新增 `toEnglishTerms`——领域名+关键词含中文时先经一次 LLM 小调用（temperature 0、jsonMode、用量仍计 `agent:collect` 场景）转成最多 4 个英文研究向检索词（prompt 附「Go语言开发 → Go runtime / goroutine scheduling」示例），arXiv 与 MCP 检索均用英化后的词（MCP 查询改 `${terms} latest research papers`）；无中文词跳过、LLM 失败回退原词不炸本轮，进度条显示「检索词英化中…」。
- **白名单并入 MCP 原文**：`whitelistFromText` 自 collectScience 下沉为 collectDeep 导出件（正则抽原文链接，origin+path 归一同口径），深读线白名单 = arXiv 候选 ∪ MCP 原文抽取——MCP 来源论文从此可入库，防编造性质不变（仍是真实检索结果里存在的链接）。
- 顺修一处来源误标：不在 metaMap 的条目（MCP 来源）source 兜底由 'arxiv' 改 'mcp'。

**验证**：`tsc -p tsconfig.node.json` 通过（web 侧 typecheck 报的 3 错在并行会话在途新文件 useSelectionBubble.ts/PaperReader.tsx，非本轮改动）；`npm run build` 通过。

**效果预期**：「Go语言开发」类中文领域下一轮巡检 arXiv 渠道即复活；MCP 渠道命中不再被白名单误杀。冒烟待下一轮海选观察「候选/入选/新增」三数与「检索词英化」日志行。
