## 优化建议区第39轮：格言库菜单跟随点击处（渲染层小改）

> 创建于 2026-09-12 01:27

**需求**：`docs/project/优化建议区.md` 待完成区唯一条目——文笔坊-格言库单击格言条召唤功能菜单，菜单固定出现在行最右端，点行中间召唤后还要把鼠标移到右侧才能操作，不便；希望菜单出现在**鼠标点击处的正下方**。

**实施**（需求明确的小改，未开 brainstorming，两文件零后端改动）：

- **ActionMenu 通用件扩展**（`src/components/ActionMenu.tsx`）：新增可选 `anchorPoint: {x, y}` 坐标锚定（与 `anchorEl` 二选一）。点锚定 = 菜单**左缘对齐点击 x、顶部在点击 y 下方 6px**（原生右键菜单惯例）；防溢出在既有规则上扩展——点锚定**右溢向左回移**（`left + w > innerWidth - 8` 时回移至右缘内 8px）、底溢翻到点击 y 上方（翻转参考点由锚上缘改点击 y）、左缘下限 8px 复用；`anchorEl` 元素锚定分支（右缘对齐 + 底溢上翻）行为逐字不变，藏书架（字体/阅读背景菜单）与记账本两处既有使用方零影响。effect 依赖 `[anchorEl, anchorPoint]`。
- **格言库召唤链路**（`src/modules/mottos/MottosModule.tsx`）：`menuFor` 状态由 `{id, anchor: HTMLElement}`（行/⋯ 按钮元素）改存 `{id, point: {x, y}}`（点击坐标）；行单击在 260ms 防抖闭包内取 `e.clientX/clientY`（点击时刻捕获，防抖窗口内鼠标微移不影响落位）、⋯ 按钮点击同款取坐标立即开菜单；渲染处 `anchorEl` 改传 `anchorPoint`。单击防抖给双击让路、双击开笔记、互斥单开、外点/滚轮/Esc/resize 关闭等交互零改动。

**落位退化分析**：点行中间 → 菜单就在鼠标正下方弹出；点 ⋯（近右缘）→ 右溢回移后落位与原行为基本重合，自然退化无突变。

**验证**：`npm run typecheck` 双 tsconfig 通过、`npm run build` 通过（10.1s）。运行时未实测，**待冒烟**：行中间/左端/右端点击看菜单落位、⋯ 按钮落位与原观感对照、窗口底部行点击上翻、双击开笔记不误弹菜单、藏书架与记账本菜单回归。

## 优化建议区第39轮反馈修订：格言库菜单消费式关闭

> 创建于 2026-09-12 01:36

**需求**：第39轮冒烟前反馈——菜单已召唤后再点格言条（含误触场景），当前是「关旧菜单 + 立刻开新菜单」，缺缓冲；希望菜单开着时点击菜单外任意地方只承担关闭，仅无菜单时点击行才召唤。

**实施**（仅 `MottosModule.tsx`，ActionMenu 通用件零改动）：

- **判定陷阱**：ActionMenu 外点关闭挂在 document mousedown **捕获段**，click 触发时菜单 state 已被清空，click 里查 state 判断不出「本次点击时菜单本来开着」。
- **对策**：MottosModule 挂一个同位（document、capture）mousedown 监听，把「按下瞬间菜单是否开着」记入 `menuOpenAtDownRef`；本面板挂载必然早于 ActionMenu（菜单只能由点击召唤），同 target 同 phase 监听按注册序执行，保证**先记后关**。flag 每次 mousedown 重记，click 评估的永远是本次按下的快照，无陈旧值问题。
- **配套**：`menuForRef` 镜像菜单开态（捕获段被清的是 state，ref 需与开/关同步）；开/关收敛 `openMenu`/`closeMenu` 两助手（改 ref + state），全文件 `setMenuFor` 直调清零；行单击（260ms 防抖内）与 ⋯ 按钮两处先查 `menuOpenAtDownRef` 再召唤，命中即 return（外点 mousedown 已完成关闭）。
- **语义变化**：原「同 id 再点切换关闭」的 toggle 语义移除——菜单开着时点同行/他行/⋯ 一律纯关闭。

**边界确认**：Esc/滚轮/resize 关闭后点行正常召唤（下次按下重记 flag）；双击开笔记防抖互斥不变；点菜单项自身不受影响（mousedown 在菜单内，外点不关）。

**验证**：`npm run typecheck` 双 tsconfig 通过、`npm run build` 通过。**待冒烟**：菜单开着点行/⋯/另一行均只关不开、关闭后再点行正常召唤、Esc 关闭后点行正常召唤、双击开笔记不误弹菜单。

## 优化建议区第39轮反馈修订二：标签编辑条三路收起

> 创建于 2026-09-12 01:48

**需求**：行内标签编辑条（菜单「标签」展开的行下方编辑行）加完标签后退出不便——唯一退出路径是再开菜单点「标签」图标切换。

**实施**（`MottosModule.tsx` + `App.css` 一条，三路收起）：

- **①外点收起**：扩展上一节建立的 document mousedown 捕获监听——编辑条开着时按下点在条外（任意处）即 `exitTagEdit()`（清 tagEditId + tagInput）；并记 `tagEditAtDownRef` flag，`onRowClick` 据此让**本次行点击只承担收起、不召唤菜单**（消费式口径与菜单一致；⋯ 按钮不拦——显式菜单意图，点 ⋯ 收条+开菜单一步到位）。条内按下（胶囊 ×/虚线胶囊/输入框/完成键）`inside=true` 不打扰，连加多标签不受影响。`tagEditRowRef` 经 ref 回调指向当前展开的编辑条 div（卸载自动置 null）。
- **②Esc**：挂编辑条**容器级** onKeyDown（冒泡接住——焦点在输入框或胶囊按钮上均生效；初版挂输入框被否，胶囊点击后焦点在按钮上 Esc 会失灵）。
- **③「完成」按钮**：编辑条尾部 check 图标 icon-btn（title「完成标签编辑」）；App.css 补 `.tag-edit-row .tag-done { flex-shrink: 0 }` 防多胶囊换行时被挤掉。
- **顺带**：输入框 `autoFocus`（菜单点「标签」后直接打字）；placeholder 补「Esc 收起」提示；收起统一收敛到 `exitTagEdit`（两 state 一起清，防残留串到下次编辑）。

**结构核实**：`tag-edit-row` 是行容器的**兄弟节点**（Fragment 内并列渲染），条内点击本就不冒泡到行单击处理器——不存在「点输入框误弹菜单」旧患，退出逻辑无需冒泡拦截。双击开笔记不受影响（首击收条被消费、次击照常触发 dblclick）。

**验证**：`npm run typecheck` 双 tsconfig 通过、`npm run build` 通过。**待冒烟**：菜单开编辑条后直接打字、条外点击只收不起菜单、点 ⋯ 收条+开菜单、胶囊连加多个不收条、Esc（输入框/胶囊焦点两态）收起、完成按钮收起、收起后再点行正常召唤菜单。

## 内置终端冒烟 bug 修复：收起再重开后输入回显向下偏移

> 创建于 2026-09-12 03:04

**症状**（开发者冒烟反馈）：开终端打字 → `Ctrl+J` 收起 → 再 `Ctrl+J` 重开 → 继续打字，输入回显位置向下偏移、显示错乱。

**根因**：面板收起 = 容器 `display:none`，ResizeObserver 照常回调但 `FitAddon.fit()` 在 0 尺寸容器上**不抛错**，而是缩到 `MINIMUM_ROWS`（2 行 2 列），且旧代码把这个 2×2 同步给了 pty（`terminal:resize`）——PowerShell 的 ConPTY 控制台被压缩成 2×2 再在重开时拉回正常尺寸，两次畸形 resize 让 ConPTY 重绘与 xterm 光标状态失同步，回显行位错乱。

**修复**（仅 `TerminalTab.tsx`）：
- `tryFit` 增加零尺寸守卫：`container.clientWidth/Height === 0` 直接 return（不 fit、不动 pty）——收起态下终端与 pty 尺寸冻结，重开后 ResizeObserver 拿到真实尺寸才 fit；
- pty resize 去重：`sentSizeRef` 记录最近已发尺寸，cols/rows 未变化不重复发 `terminal:resize`，消除重开时无谓的 ConPTY 重绘（这也是偏移的共犯）。

**验证**：`npm run typecheck` 双 tsconfig 通过。自动复现验证因开发者本人 dev 实例在跑（单实例锁 + `--user-data-dir` 参数 Electron 不采纳）未能二次起隔离实例——渲染层改动 dev 热更新直接生效，**待开发者即时复现**：开终端打字 → Ctrl+J 收 → Ctrl+J 开 → 继续打字，回显应严格接在提示符后不再偏移。
