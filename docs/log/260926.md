## 德扑引擎三修复（行动权推进/单挑首行动/幽灵底池）+ 牌桌交互增强

> 创建于 2026-09-26 00:48

背景：开发者反馈「有些轮没有加注等环节直接出结果，完全操作不了只能看运气」。排查（引擎 esbuild bundle + 逐步探针）发现「全下跑马」只是表象，真正元凶是**三个既有引擎 bug**：

- **行动权推进缺失（核心）**：`syncAwaiting` 只校验不推进 `toAct`——行动后 `toAct` 仍停在刚行动者身上、其 `acted=true` 不在 pending 里，随即被判「本街行动完毕」收街。**每条街只行动一人一次**，其余人（常含玩家）整手零操作，牌局火速冲摊牌——即「完全操作不了」的根因。修复：新增 `advanceTurn`，`humanAct` / `advance('ai')` 行动后把行动权交给下一位待行动者（`applyRaise` 重开行动的 `acted` 重置口径不变，BB 选项、加注后重新轮转均验证正确）。
- **单挑翻前首行动错位**：`dealerIdx + (headsUp ? 0 : 2)` 假设座位相邻，四座位存活两人时错选大盲先动。修复：改由 `bbP` 实际座位 `nextSeat` 找下家——单挑绕回庄家/SB 先动（单挑规则），满桌仍是 BB 下家。
- **幽灵底池**：玩家破产出局后 `startHand` 跳过其重置，`totalBet` 残留（实测一手残留 660）；之后「其余玩家弃牌」结手按 `ΣtotalBet` 发池、摊牌分池按 `totalBet>0` 建层，均把死玩家残留当活底池**凭空多发筹码**。修复：`finishHand` 结清时全员 `bet/totalBet` 归零。

顺带：跑马由「一次性发完 5 张」改**逐街发牌**（UI 160ms 节拍逐步揭牌）+ `notice` 提示条（「已有玩家全下、无人可再投注——剩余公共牌逐街发完后直接摊牌」）；删除 `settleRound` 尾部递归与恒假的 `owesCall` 死代码。

交互增强（PokerPane + yule.css，全走主题变量）：座位动作标签 `lastAction`（小盲/大盲/过牌/跟注 X/下注 X/加注到 X/全下 X/全下盲注/弃牌，跨街保留）、行动者座位主题色描边高亮、顶栏当前街名（翻前/翻牌/转牌/河牌）、「本手动态」流水（新→旧 + 街分隔）、待行动提示（等待谁/轮到你·底池·需跟注）、加注提交前钳制本街合法区间（防滑条旧值误提交 +1 微加注）、旧快照恢复 `normalizeState` 补 `lastAction/actionLog/notice` 默认值；玩法弹窗补「全下跑马」与「界面说明」两节。

验证：临时仿真四组 ALL PASS（首行动口径；30 局随机策略资金守恒 + 1557 条多动作街样本 + 我全程有参与；200 手单挑 call-call 全打到摊牌；20 局全下压力 20/20 触发跑马且逐街发牌/全下后免行动），临时件已删。typecheck 本轮文件全绿（`mahjong/tiles.ts` 一处报错系并行会话麻将房在途，非本轮）。待开发者冒烟：正常打一局感受下注轮完整流转；让对手或自己全下看跑马提示条与逐街揭牌。
