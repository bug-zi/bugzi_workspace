## 背景与痛点

任务2原文引用的「当前 prompt」是 v1.0 specs §6.2 原始版（title 10~25 字 + summary ≤50 字）。第18轮（260906）已做过一轮大改（口味注入 + 两阶段管线），但开发者实测后仍不满意——**本任务是对新管线产出的二轮反馈**。

实测数据（DB 9/6 两批，10 条留 8 删 2）显示钟摆从一端荡到了另一端：

| 批次 | 管线 | 标题风格 | 病灶 |
| --- | --- | --- | --- |
| 9/2~9/4（id 5~21） | v1.0 旧管线 | 「XX复盘/追踪/打卡 + 工具/助手/平台」 | 拼装句式、平庸（第18轮已治） |
| 9/6（id 22~31） | 第18轮新管线 | 「从税册里挖出一位失真的神」「越探望越黯淡的数字花种」 | **文艺概念装置风**——新毛病 |

开发者勾选的三个真实痛点（「不是可开发的项目」**未**勾选——线下实验/文艺方向本身可接受）：

1. **标题故弄玄虚**：纯隐喻标题，看完不知道要做什么；
2. **summary 像谜语**：≤60 字还要塞第一步抓手，压缩过度（「先扫描一面傩面并录三段口述，让眉、角、口成为唱腔与村史的交互入口」），且 10/10 条「先…」开头，另一种模板味；
3. **新型同质化**：两批 10 条全是文艺装置风——CRUD 同质化换成了文艺同质化。

同质化的代码根因：①「形态分散」规则只在发散阶段约束 12 条候选，自评阶段按新颖度/兴奋度自由挑 5 条，文艺条天然高分，多样性塌缩；②跨批次只有标题避免清单，无「气质」层换口味机制。

## 已确认的关键决策

| 决策点 | 结论 |
| --- | --- |
| 标题规范 | **文艺+实体锚点**：前半可文艺，后半必须落到看得见的实体/数量（如「税册里的雨神：8张证物卡」）；禁止纯隐喻（开发者选定，全直白型与纯评审软约束已否决） |
| summary 模板 | **两句模板 + 放宽到 ≤100 字**：第一句大白话说清「这是什么+好玩/值得在哪」，第二句「第一步：」给最小动作；禁「先…」开头、禁文艺化压缩（开发者选定） |
| 同质化破法 | **批内配额 + 跨批风向标**双管：评审阶段硬配额（5 条 ≥3 种形态、同形态 ≤2 条），代码内置基调词池每批随机抽 1~2 个注入（开发者选定） |
| 风向标可见性 | **静默注入 + toast 可见**：生成后 toast 顺带「本期风向：X」；无任何新增交互步骤（开发者选定；完全静默与自学习闭环已否决——后者列 V2 画像方向预留） |
| 卡片预览 | 第12轮的 100 字提到 **120 字**，让「第一步」大概率在卡片上可见（summary 已放宽到 100 字） |

## 设计详情

### §1 发散阶段（12 条粗点子，temp 0.95 不变）prompt 规范重写

**标题规则**（替换现有规则 7 前半）：

- 结构 = **画面 + 实体锚点**：前半可有画面感/氛围，后半必须落到看得见摸得着的实体（卡片、电台、程序、语音房、比赛、图鉴、博物馆、原型……）或具体数量（8张、7分钟、一晚）
- 长度维持 10~25 字
- prompt 内置正反例（few-shot）：
  - 正例：「税册里的雨神：8张证物卡」「匿名电台：只开七分钟，一生一次」
  - 反例：「从税册里挖出一位失真的神」——纯隐喻，读完不知要做什么

**summary 规则**：

- 两句模板：第一句大白话说清「这是什么 + 好玩/值得在哪」；第二句以「第一步：」开头给最小可动手动作
- ≤100 字；像跟朋友解释；**禁止「先…」开头**；禁止文艺化压缩（每个名词都要落到具体动作/物件）
- md 正文仍只存 summary（两句间单换行）；卡片预览的空白压平逻辑（`:60` 的 `replace(/\s+/g,' ')`）自动变单行，弹窗内 markdown 软换行同样安全

**风向标注入**：

- 代码内置 14 个基调词（常量数组，不落库）：`实用主义 / 纸上原型 / 数据控 / 声音实验 / 时间胶囊 / 荒诞幽默 / 城市观察 / 怀旧电子 / 桌面游戏 / 手作实感 / 极简主义 / 社群之夜 / 慢生活 / 解谜推理`
- 每批 `Math.random()` 抽 1~2 个（与万象库随机挑板块同款轻量做法），注入为「本批风向」
- 注入约束：12 条中 **3~5 条靠拢风向即可**，其余自由——防止风向本身变成新的同质化源头
- 与手动「方向指引」冲突时指引优先（注入文案写明「若与本批风向冲突，以方向指引为准」）

### §2 自评阶段（挑 5 条，temp 0.4 不变）改造

- **候选携 form 标签**：发散 JSON schema 变为 `{"inspirations":[{"title":"…","summary":"…","form":"…"}]}`；form 从固定枚举选，与现有形态列表一致：`实用工具 / 游戏与玩具 / 内容创作 / 数据可视化 / 实验探索 / 艺术表达 / 社群活动`
- **批内配额进评审规则**：5 条至少覆盖 3 种 form、同 form ≤2 条（12 候选本就 ≥4 形态，配额可满足）
- 四维打分（新颖度/契合口味/具体度/兴奋度）保留，新增第五维**标题可读性**：不看 summary 能否猜到要做什么——与 §1 硬句式双保险
- summary 打磨规则同步换两句模板（旧「≤60 字含第一步抓手」废除）
- 评审输出同样带 form（title 沿用候选原文、form 沿用候选）

### §3 管线与容错

- `parseInspirationArray` 兼容 form：form 缺失/非法 → `'未分类'`，**不丢条目**（必填仍只有 title/summary，沿用现有口径）
- **降级路径升级**：自评两趟均失败时，不再 `candidates.slice(0,5)` 裸取，改为代码侧按 form 配额贪心挑 5 条（同 form ≤2、优先多形态覆盖）——降级也不带病；极端情况（候选 form 全为「未分类」等导致配额不可满足）按原顺序取前 5 条兜底
- `GenerateInspirationsResult` 增加 `winds: string[]`；渲染层 toast 变为「已生成 N 条灵感，已入草稿区；本期风向：纸上原型 · 声音实验」（单 toast 追加从句，winds 为空不追加；winds 空仅发生在池抽取异常的场景，正常必有 1~2 个）
- IPC 三件套（`electron/ipc.ts` / `electron/preload.ts` / `src/renderer/api.d.ts`）返回类型同步

### §4 不动的部分

口味注入（画像/格言/万象/指引）、避免清单（标题级）、第18轮七条规则中不冲突的条款（恰好 12 条、形态分散、具体可执行、禁拼装句式、禁平庸、口味呼应）、标题精确查重（含回收站 + 批内互斥）、入库位置（草稿区末尾）与 md 模板、refine 完善、两趟温度（0.95/0.4）、两趟调用与重试结构。

## 不在范围内（明确排除）

- **风向标自学习闭环**（记录每批风向与保留率、长期偏向喜欢的基调）——需要 DB 新表与多轮使用数据才有信号，属 V2 用户画像大方向的子课题，本轮不做
- refine（AI 完善）prompt——任务2只涉生成
- 卡片/弹窗 UI 结构、summary 分节渲染——两句模板靠 md 软换行即可，无需分节
- 格言库 prompt 约束（临时草稿另列的「禁止'不是…而是'句型」等）——与灵感泉各自独立处理

## 验证方式

1. `npm run typecheck` 通过
2. 冒烟：连点两批「来5条灵感」，逐项核对——
   - 标题：每条含实体锚点，无纯隐喻；
   - summary：两句结构、有「第一步：」、无「先…」开头、大白话不谜语；
   - 批内：5 条 form ≥3 种、无单一形态占 3 条以上；
   - 跨批：两批气质可见轮换（toast 风向不同），标题风格不再全批一个味道；
   - toast 展示本期风向；
   - 降级路径不回归（断网/自评失败时仍入库且满足配额）——可临时改代码模拟验证后还原
