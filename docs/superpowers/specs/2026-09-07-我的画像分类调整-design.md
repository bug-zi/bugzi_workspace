# 我的画像 · 分类调整与初始化 设计记录（2026-09-07）

## 背景

开发者写了完整自述《需求（功能模块）/致知己/我的画像.md》（原始文档，开发者维护，AI 只读不改）。
原画像类别 6 项（专业背景/学习方向/职业规划/偏好习惯/价值观/其他）为「AI 对话零散提炼」设计，
装不下自述中的丰富维度（成长背景/性格能力/爱好/生活方式/社交出行全挤在「偏好习惯」和「其他」）。
现 `profile_facts` 表为空表，无旧数据迁移负担。

## 决策（已与开发者确认）

1. **类别清单改为细分 9 类 + 兜底**：基本档案 / 性格特质 / 擅长能力 / 兴趣爱好 / 生活方式 /
   社交出行 / **学习与技能**（原「学习方向」，因承接技术栈/项目/在学现状而改名）/ 职业规划 / 价值观 / 其他。
2. **初始化方式**：AI 拆条 → 开发者逐条审核 → 一次性 node 脚本写入 `bugzi.db`（source='manual'）。
   不做「长文导入」产品功能。
3. **初始化时顺带补充 3 个维度**（开发者补写一段话，AI 拆条并入）：技术栈与项目现状、
   阅读音乐口味细分、当前在学与短期准备。未选：城市与生活偏好（以后可补）。

## 条目拆分原则

- 原子化：一条 = 一个可独立检索的事实（PROFILE_LOOKUP 按条命中）
- 长度 ≤60 字（profileDigest 截断线）；职业时间线拆里程碑多条
- 简洁陈述句，不写「我」；source='manual'
- 初始规模约 28 条 + 3 个待补槽位

## 初始化流程

1. AI 出条目初稿（按类别分组）✅ 本次会话完成
2. 开发者逐条审（删/改/合并）+ 补写 3 个维度的一段话
3. 终版汇总过目
4. 关闭 App → 一次性脚本 INSERT（WAL 并发风险，App 必须关闭）
5. 开 App 验证：个人中心画像区 + 致知己对话 PROFILE_LOOKUP 检索

## 后续成长路径

- 手填（datalist 建议新类目）/ AI 对话提炼（PROFILE_SUGGEST 指令已同步）/ 再写长文喊 AI 拆
- `designs-specs.md`（个人中心）画像小节随实现同步更新（AI 维护文档，开发者审核）
