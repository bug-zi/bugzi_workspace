# docs/superpowers 目录说明与归档机制

本目录存放 superpowers 工作流（brainstorming / writing-plans）会话产出的**设计记录（specs/）与实施计划（plans/）**。维护方：AI（机制正本即本文档；`CLAUDE.md` 文档体系表有对应条目）。

## 目录结构

```
docs/superpowers/
├── README.md            # 本文档：归档机制正本（永不归档）
├── specs/               # 设计记录 · 活跃区（待实现 / 设计进行中）
│   └── archive/         # 已落地或已废弃的设计记录
└── plans/               # 实施计划 · 活跃区（待执行 / 执行中）
    └── archive/         # 已执行完毕或废弃的实施计划
```

- 文件命名：`YYYY-MM-DD-<主题>-design.md`（specs）、`YYYY-MM-DD-<主题>.md`（plans）；日期前缀保证全局唯一，**归档不改名**。
- 活跃区根目录一眼可见「当前还有什么没做完」。

## 归档判定

| 判定 | 依据 | 动作 |
|---|---|---|
| 落地归档 | spec 状态行或日终日志明确记录「实施完成」（typecheck 通过即算，**不等人工冒烟**——260907 开发者定稿） | 移入 archive/，状态行追加归档记录 |
| 废弃归档 | **开发者明确说**「废弃 / 被新设计取代」（AI 不自行判定废弃） | 移入 archive/，状态行标注「已废弃（原因）」 |
| 留守 | 待实现、brainstorming / 执行进行中 | 不动 |
| 拿不准 | 依据不明 | 不动，报告开发者 |

配套规则：spec 落地归档时，其对应 plan（`**Spec:**` 字段指向该文档者）一并归档。

## 触发时机（全自动，无需开发者口令）

AI 在以下固定动作时**顺带清点**本目录：

1. **写 / 追加日终日志时**——记录「实施完成」的那一刻就是归档时刻；
2. **在本目录写新 spec / plan 时**。

开发者也可随时说「归档一下」触发即时清点（兜底）。

## 归档动作（固定四步）

1. `mv` 至 `specs/archive/`（或 `plans/archive/`），文件名不变；
2. 文档顶部状态区追加一行：`- 已归档：YYMMDD 随 <功能> 落地`（废弃则 `- 已归档：YYMMDD 废弃（<原因>）`）；
3. 全库检索 `superpowers[/\\](specs|plans)`，更新**活动文档**（模块 designs-specs、CLAUDE.md、本 README）中的路径引用；**历史日志（docs/log/）不改**，同批移动的关联引用（如归档 plan 指向归档 spec）顺手更新；
4. 当天日终日志记一笔。

## 回改通道

人工冒烟后若需回改已归档文档：直接在 archive/ 内改，或移回活跃区（状态行同步改回），日志记录。**归档只是位置变化，文件永不删除。**
